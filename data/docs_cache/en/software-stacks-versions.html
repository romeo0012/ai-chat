Software Stack Versions Within this page, you can find a list of the latest software stacks and engines provided by the platform. These are the officially supported and regularly updated software solutions that you can use to create your environments. The stacks are delivered as Docker images, which are stored in the platform’s public registry (Docker Hub). The exact specifics of the stack update and security handling are described in the dedicated section below. Software Stacks VersionsLoad Balancers Application Servers Databases Additional Stacks Engines Stack Updates and Security Handling Note: All the platform-certified software stacks are based on the AlmaLinux 9 base OS images by default. This ensures support for all up-to-date functionality, modern security standards, and compatibility with the latest software solutions. The AlmaLinux 9 base images are not available on the platform versions prior to 8.3, the CentOS 7 base OS (reached EOL on 30th June 2024) is used instead. If you want access to both options, please contact your hosting provider to upgrade the platform. Each software stack remains supported by the platform up to the end-of-life (EOL) date notified by the respective upstream maintainer. After the EOL, stacks are no longer available for the new environment creation, but the already existing ones remain fully operable (including redeploy, cloning, and horizontal scaling).

Stack CVE Scanning: All new images of platform-certified stacks undergo mandatory CVE (Common Vulnerabilities and Exposures) scanning against the latest vulnerability database to identify and address potential security vulnerabilities before being made available for use.Vulnerability databases are synchronized regularly to ensure up-to-date coverage. Images containing critical or high-severity vulnerabilities are not published until the fixes have been applied. Medium- and low-severity findings are assessed individually and may not block publication. Existing Images: After publishing a stack image, the platform does not modify or remove it, which ensures the stability and reliability of existing environments. CVE fixes are applied only in new stack versions released after upstream updates.Deprecated or end-of-life stack versions (including CentOS 7-based ones) are not updated, even if new CVEs are reported. Such stacks rely on operating systems that no longer receive vendor-provided security updates, so newly disclosed vulnerabilities are not addressed within those stack versions. To obtain security fixes, it is necessary to migrate to a newer supported stack version. CVEs disclosed after the publication of an image are handled through the regular release process as described in the “Stack Release Frequency” section.

Existing Containers: After creating a container from the stack image, the platform does not modify it, as it may affect user applications. It is the responsibility of the environment owner to choose the appropriate stack version for their purpose.

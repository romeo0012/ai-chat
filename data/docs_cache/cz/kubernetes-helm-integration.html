Kubernetes Klaster: Integrace Helmu
Kubernetes nabízí mnoho možností nasazení aplikací. Jednou z nejčastějších metod je použití správce balíčků Helm. Pokud hledáte spustit populární nebo známou řešení v vašem Kubernetes klastru, pravděpodobně se můžete na nějít jako předkonfigurovaný balíček, který můžete za několik minut instalovat. Helm vám pomáhá instalovat aplikace Kubernetes z vzdálených repozitářů, ale také vytvářet místní Helm grafy. Helm je k dispozici na všech uzlech řídicího panelu Kubernetes Klastru výchozím způsobem a nevyžaduje žádnou další konfiguraci. Pro práci s Helmem stačí se připojit k uzlu (např. pomocí Web SSH), a můžete začít pracovat s Helmem. Verze balíčovacího manažeru se automaticky aktualizuje během aktualizace Kubernetes Klastru. Helm pracuje s třemi hlavními pojmy: Chart je Helm balíček obsahující všechny definice zdrojů nutné k spuštění aplikace, nástroje nebo služby v Kubernetes klastru. Repozitář je místo, kde mohou být sbírané a sdílené grafy. Release je instance grafu běžící v Kubernetes klastru. Jediný graf může být instalován mnohokrát do stejného klastru (s vlastním jedinečným názvem release), například mnoho instancí databáze. Helm instaluje grafy do Kubernetes, vytváří novou release pro každou instalaci. A pro hledání nových grafů můžete hledat v repozitářích Helm grafů.

Do přechod na Kubernetes a vytvářet novou verzi pro každou instalaci. A pro hledání nových grafů můžete hledat repozitáře grafů Helm. V tomto průvodci budeme pokrývat všechny hlavní fáze práce s Helm: hledání grafů a práci s repozitáři, instalace nových aplikací Helm, správa existujících aplikací. Tip: Helm je užitečný nejen pro své připravené řešení, ale také jako nástroj pro verzování a standardizaci vývoje projektů. Nejprve, když pracujete na malém projektu, přístup pomocí skriptované nasazovací metody může být dostačující pro vaše potřeby. Však složitost může rychle narůst, požadující stále více úprav v vašich souborech YAML. Například i nasazení do prostředí testovacího a produkčního požaduje úpravy jako URL databáze. V některém okamžiku můžete cítit, že je obtížné sledovat interakci a závislosti komponent. Obvykle to znamená, že složitost vašeho prostředí přesahuje vaše vlastní nasazovací skripty. V takovém případě může být dobré rozmyslet se Helm jako potenciální řešení, které nahradí vaše vlastní skripty. Průvodce Vývojem Grafů Helm vysvětlí, jak vytvořit vlastní grafy.

Hledání Grafů Helm
Je zde mnoho přednastavených řešení, která mohou být instalována do Kubernetes Clusteru za několik minut. Správce balíčků Helm má centrální úložiště s mnoha připravenými řešeními. Další možností je práce s vlastními repozitáři.

Nainstalován v Kubernetes Clusteru za minutky. Správce balíčků Helm má centrální centrum s mnoha připravenými řešeními. Také můžete pracovat s vlastními repozitáři. Helm přináší mocnou příkaz helm search, který může být použit k vyhledání dvou různých zdrojů typů: helm search hub hledá Artifact Hub (veřejná repozitář balíčků Helm), která zobrazuje balíčky Helm pro desítky repozitářů Například můžete najít všechny veřejně dostupné balíčky pro WordPress spuštěním:
1 helm search hub wordpress
helm search repo hledá repozitáře, které jste přidali do svého místního klienta Helmu (pomocí helm repo add). Tento výzkum se provádí pomocí lokálních dat a žádný veřejný připojení k síti není nutné
Helm 3 (používaný od verze Kubernetes 1.18.10) již nezahrnuje výchozí repozitář balíčků. Můžete použít příkazy helm repo k přidání, seznamování a odstraňování repozitářů. Například, nechť přidáme populární repozitáře Bitnami:
1 helm repo add bitnami https://charts.bitnami.com/bitnami
Můžete zjistit, které repozitáře jsou nakonfigurované pomocí příkazu helm repo list:
1 helm repo list
Protože repozitáře balíčků často změňují, můžete ujistit se, že je vaše Helm klient aktuální spuštěním:
1 helm repo update
Instalace balíčku Helm
Chcete-li instalovat nový balíček, použijte příkaz helm install. Ve své základní podobě přijímá dva argumenty: {name} - vydání jména, které jste si vyberete (např. mywordpress) {chart} - jméno balíčku, který chcete nainstalovat (např. wordpress)

příkaz. Nejjednodušší je, že přijímá dvě argumenty: {name} - název vydání, který si vyberete (např., mywordpress) {chart} - název grafu, který chcete nainstalovat (např., bitnami/wordpress) Další možností je poskytnutí možností grafu k personalizaci aplikace (více informací v části Správa Helm). Například, nechť změníme název blogu pomocí parametru --set wordpressBlogName='Můj blog!' 1 helm install --set wordpressBlogName='Můj blog!' mywordpress bitnami/wordpress Instalace grafu vytvoří nový objekt vydání. Pokud chcete, aby Helm vám vytvořil název, nezanechte název vydání a použijte parametr --generate-name. Během instalace helm klient vytiskne užitečné informace o vytvořených prostředcích, stavu vydání a jakýmkoli dalším kročkám konfigurace. Nyní následujte kroky, aby se naša instancie WordPress správně spouštěla. Tip: Výchozí nastavení aplikace Helm WordPress vytvoří službu LoadBalancer, která zpracovává všechny provozní data z připojeného veřejného IP. Pokud v Kubernetes clusteru existuje pouze jeden veřejný IP adresa (jako v nastavení pro vývoj) a přístup prostřednictvím SLB je vypnutý, předinstalované aplikace s nakonfigurovanými kontrolery vstupu budou nek dispozici. V takovém případě nejjednodušší možností je přidat další veřejný IP adresu do kontejneru pracovníka (kromě první, která je již používána službou LoadBalancer WordPress) a přístup k nakonfigurovaným vstupům pomocí něj.

Chcete-li přidat další veřejnou IP adresu do kontejneru práce (kromě první, která je již používána službou LoadBalancer WordPress) a přístup k nakonfigurovaným vstupům pomocí ní. Alternativně můžete přidat další prácička s veřejnou IP adresou do clusteru Kubernetes. V obou případech budou nainstalované aplikace dostupné pomocí druhé veřejné IP adresy. Poznámka: WordPress je poměrně složitá řešení, která vyžaduje další komponenty, jako je například Uložiště a veřejná IP adresa. Pokud nebyly poskytnuty při instalaci clusteru Kubernetes, mohou být přidány přes panel platformy. Získat URL WordPressu a přihlašovací údaje provedete následující kroky: 1 2

export SERVICE_IP=$(kubectl get svc --namespace default mywordpress --template "{{ range (index .status.loadBalancer.ingress 0) }}{{ . }}{{ end }}")
printf "URL WordPressu: http://$SERVICE_IP/\nURL správy WordPressu: http://$SERVICE_IP/admin\nUživatelské jméno: user\nHeslo: $(kubectl get secret --namespace default mywordpress -o jsonpath="{.data.wordpress-password}" | base64 --decode)\n"

Nyní použijte získaná data k přístupu k vaší WordPressové stránce a správě. Jako můžete vidět, je název naší vlastní blogové stránky (Můj Blog!) automaticky přiřazen. Správa aplikací Helm Helm poskytuje několik příkazů k práci s nainstalovanými grafiky. Seznam akcí zahrnuje upgrade a recovery, kontrolu stavu a hodnot, atd. Tip: Pokud chcete získat další informace o příkazech, přečtěte si pomoc Helmu vbudované v pomocí - helm help.

Tip: Můžete kontrolovat výchozí seznam hodnot pro balíček pomocí následujícího příkazu (pomocí utilitu less můžete snadno procházet odpověď):

1 helm show values bitnami/wordpress | less
  1. Můžete použít příkaz helm upgrade k aktualizaci vydání na novou verzi grafonu nebo změně konfigurace vydání. Během procesu se Helm pokusí provést nejméně invazivní aktualizaci tím, že aktualizuje pouze ty věci, které se změnily od posledního vydání.

Verze nebo změňte konfiguraci vaší vydání Helmu. Během procesu se Helm pokusí provést nejméně invazivní aktualizaci tím, že aktualizuje pouze ty věci, které byly změněny od poslední verze. Tip: Pokud je potřeba, můžete použít příkaz upgrade s vlajkou --reset-values, aby se resetovaly jakékoliv vlastní hodnoty a použily se hodnoty, které jsou v chartu. Vzhledem k tomu, jak je naším WordPress chartu z části instalace, musíte při aktualizaci vydání poskytnout aktuální hesla: 1 2 3

export WORDPRESS_HESLO=$(kubectl get tajomka --namespace "výchozí" mywordpress -o jsonpath="{.data.wordpress-heslo}" | base64 --decode)
export MARIADB_HESLO_ADMIN=$(kubectl get tajomka --namespace "výchozí" mywordpress-mariadb -o jsonpath="{.data.mariadb-heslo-admin}" | base64 --decode)
export MARIADB_HESLO=$(kubectl get tajomka --namespace "výchozí" mywordpress-mariadb -o jsonpath="{.data.mariadb-heslo}" | base64 --decode)

Nyní můžete hesla poskytnout pomocí vlajky --set:
1 helm upgrade --set wordpressHeslo=$WORDPRESS_HESLO,mariadb.auth.hesloAdmin=$MARIADB_HESLO_ADMIN,mariadb.auth.heslo=$MARIADB_HESLO mywordpress bitnami/wordpress

Tip: Když potřebujete poskytnout mnoho vlastních parametrů, může být užitečnější je specifikovat v odděleném souboru YAML. Pro příklad WordPress můžete připravit následující hodnoty-template.yaml:

wordpressPassword: ${WORDPRESS_HESLO}
mariadb:
auth:
rootPassword: ${MARIADB_HESLO_ADMIN}
password: ${MARIADB_HESLO}

Pak můžete tento soubor použít pomocí vlajky --values:
1 helm upgrade --values values-template.yaml mywordpress bitnami/wordpress

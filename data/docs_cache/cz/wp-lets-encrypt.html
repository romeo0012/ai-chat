Přejdeme se na SSL Let's Encrypt s automatickým obnovováním pro WordPress. Dnes je SSL nutností pro každou webovou stránku v produkci a vydávání a obnovování certifikátů jsou už běžné úkoly. Nástroje jako Let's Encrypt používají open-source Certbot s authenticátorem standalone k snadné automatizaci těchto operací. Hlavní nevýhodou zde může být možné odpočet webové aplikace serveru během automatického obnovování certifikátu a ověřování domény. Chceme-li překonat problém s uptimem během aktualizace SSL certifikátu, Virtuozzo Application Management vytvořilo vlastní Let's Encrypt Add-On s pokročilým algoritmem nulového odpočtu při obnovování. Důvody odpočtu při aktualizaci SSL certifikátu pomocí Certbot
Hlavním účelem nástroje certbot je konfigurovat HTTPS server a automaticky získat důvěryhodný certifikát bez lidské interakce. Provede následující úkoly:

  • Umožňuje ověřit, že jste v kontrole s webovou stránkou
  • Získá certifikát a jej konfiguruje na webový server
  • Sleduje expiraci certifikátu a jej aktualizuje
  • Pomáhá uživatelům zrušit svůj certifikát (pokud to potřebují)
  • Nutilé obnovování certifikátu, pokud je to nutné

Nejprve certbot iniciuje vydání SSL certifikátu tím, že odesílá Certificate Signing Requests (CSR). Poté spustí Certificate Management Agent (CMA), který je Python web server, který poslouchá zadaný port, aby mohl zpracovat ověřovací požadavek od Let's Encrypt CA.

(CSR). Potom spustí Certificate Management Agent (CMA), což je Pythonový webový server, který poslouchá zadaný port, aby obsluhoval požadavky na ověření od Let’s Encrypt CA. Před získáním certifikátu je nutné dokázat, že obnovování bylo zahájeno správcem domény. Ověřovací požadavky se vždy odehrávají na portu 80, který obvykle obsadí aplikace poslouchající HTTP provoz. Proto musí běžet webový server, na kterém je spuštěn CMA, dočasně zastaven, aby mohl být spuštěn CMA místo toho. Tato implementace tedy způsobuje dobu nefunkce aplikace. Další problém, který může způsobit dobu nefunkce, je to, že Pythonový webový server se může stát zastavěn, když se pokusí ovládat neověřovací požadavek HTTP, který může pocházet od jakéhokoliv uživatele. To se stává, protože Certbot spouští webový server v režimu s jedním vláknem. Proto může obsluhovat pouze jeden požadavek vstupní. Řešení k zabránění doby nefunkce během aktualizace certifikátu SSL Chcete-li vynechat zmíněné problémy, vytvořila Virtuozzo Application Management vlastní doplněk Let’s Encrypt, který zahrnuje vylepšenou algoritmu. Předpokládá se použití pravidel routování k integrování mezilehlého reverzního proxy do řetězce provozu, aby se filtrovalo HTTP provoz. Proxy je konfigurován k routování požadavku na Pythonový web server od Let’s Encrypt CA pouze. Ostatní provoz je routován k aplikaci uživatele. Povolení podpory proxy obrácené na zpátečnou stranu a definování pravidel filtrování provozu HTTP. Každá žádost, která přijde s podřetězcem “/.well-known/acme-challenge/”, bude směrovaná k Pythonovém webovému serveru, který posluchá na portu 12348, aby získal ověřovací soubor z skrytého adresáře .well-known/acme-challenge/. Tento typ žádostí vytváří pouze certifikátní autorita Let’s Encrypt. Ostatní provoz HTTP bude směrovaný k webové aplikaci, která poslouchá na portu 80. V případě samostatného kontejneru WordPress (s certifikovanými šablonami LLSMP nebo LEMP) je tok provozu zobrazen v následujícím ilustraci. Existuje další metoda vydání nových certifikátů nebo aktualizace existujících, která se nazývá webroot. Tato metoda je preferovaná pro silně načáslé webové stránky (tudíž brzy bude přidána k clusteru WordPress jako výchozí) protože nezakrývá práci webových serverů a vynechává riziko zastavení nebo snížení výkonu. Webroot lze použít s certifikovanými PHP software stacky, jako je tomu v balíčcích WordPress. Když je spuštěn, získá Certbot cestu k kořenovému adresáři webu. Poté vytvoří Certbot strukturu adresářů tam pro ukládání dočasných souborů:
1 ${webroot-path}/.well-known/acme-challenge
Server Let's Encrypt kontroluje přítomnost tohoto souboru v určené lokalitě s požadavkem tohoto typu:
1 http://příklad.cz/.well-known/acme-challenge/KJr5D^ReTW4kY_Z6UIIkjlmlmOkyQgPr_7ArlLgtZE7Fg
Pokud existuje požadovaný dočasný soubor (např. “KJr5D^ReTW4kY_Z6UIIkjlmlmOkyQgPr_7ArlLgtZE7Fg”), potom bude úspěšně ověřena vlastnictví domény a vydán a nahrán certifikát na web uživatele. Po dokončení ověřovacího procesu získá Certbot certifikátový soubor.

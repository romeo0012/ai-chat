Konfigurieren des Zugriffs auf HTTPS für Harbor
Wichtig: Verwendung von bereits vorhandenen Drittanbieter-Zertifikaten
Wenn Sie bereits ein TLS-Zertifikat und Schlüssel von einer vertrauenswürdigen Stelle (z.B. Let's Encrypt, DigiCert, GoDaddy) besitzen, können Sie die Schritte zur Erstellung einer selbstsignierten Zertifikatdatei auf dieser Seite überspringen. Bitte legen Sie Ihre Zertifikat- und Schlüsseldateien auf dem Harbor-Host platzieren und geben Sie ihre Pfade im harbor.yml-Datei, wie in ./configure-yml-file.md beschrieben, an. Dies ist die empfohlene Vorgehensweise für alle Produktionsumgebungen. Standardmäßig schickt Harbor keine Zertifikate mit. Es ist möglich, Harbor ohne Sicherheit zu bereitstellen, sodass Sie es über HTTP verbinden können. Es ist jedoch nur in abgeschlossenen Test- oder Entwicklungsumgebungen akzeptabel, die keinen Zugang zu einem externen Internet haben. Verwenden Sie HTTP in Umgebungen, die nicht abgeschlossen sind, wird Ihnen man-in-the-middle-Angriffe ausgesetzt. In Produktionsumgebungen sollte immer HTTPS verwendet werden. Um HTTPS zu konfigurieren, müssen Sie SSL-Zertifikate erstellen. Sie können Zertifikate verwenden, die von einer vertrauenswürdigen Drittanbieter-Zertifizierungsstelle (CA) signiert wurden, oder Sie können selbstsignierte Zertifikate verwenden. Sie können andere CA-Anbieter verwenden, z.B. Let's Encrypt. Zum Konfigurieren von HTTPS müssen Sie SSL-Zertifikate erstellen. Sie können Zertifikate verwenden, die von einer vertrauenswürdigen Drittanbieter-Zertifizierungsstelle (CA) signiert wurden, oder Sie können selbstsignierte Zertifikate verwenden. Dieser Abschnitt beschreibt, wie Sie OpenSSL verwenden, um eine CA zu erstellen, und wie Sie Ihre CA zum Signieren eines Serverzertifikats und eines Clientzertifikats verwenden. Sie können andere CA-Anbieter verwenden, z.B. Let's Encrypt. Die folgenden Schritte gehen davon aus, dass der Hostname Ihrer Harbor-Registry Ihrdomain.com ist, und dass seine DNS-Eintragung auf dem Host zeigt, auf dem Sie Harbor ausführen.

  1. Installieren Sie OpenSSL, falls Sie es noch nicht installiert haben.

   sudo apt-get install openssl
  1. Erstellen Sie eine CA.

   openssl genpkey -algorithm RSA -out ca.key
   

   openssl req -x509 -new -nodes -key ca.key -sha256 -days 1024 -out ca.crt
  1. Erstellen Sie ein Serverzertifikat und einen privaten Schlüssel.

   openssl genpkey -algorithm RSA -out server.key
   

   openssl req -new -key server.key -out server.csr

Füllen Sie das CSR-Formular aus und signieren Sie es mit Ihrer CA.

  1. Signieren Sie das Serverzertifikat mit Ihrer CA.

   openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out server.crt
  1. Erstellen Sie ein Clientzertifikat und einen privaten Schlüssel.

   openssl genpkey -algorithm RSA -out client.key
   

   openssl req -new -key client.key -out client.csr

Füllen Sie das CSR-Formular aus und signieren Sie es mit Ihrer CA.

  1. Signieren Sie das Clientzertifikat mit Ihrer CA.

   openssl x509 -req -in client.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out client.crt
  1. Platzieren Sie die Zertifikate und Schlüssel auf dem Harbor-Host und geben Sie ihre Pfade im harbor.yml-Datei, wie in ./configure-yml-file.md beschrieben, an.
  1. Starten Sie Harbor neu.

   docker-compose up -d
  1. Prüfen Sie, ob Harbor über HTTPS verfügbar ist.

   curl -k https://yourdomain.com

Sie sollten eine Antwort erhalten, die mit "HTTP/1.1 200 OK" beginnt.

Beispiel: Let's Encrypt. Die untenstehenden Verfahren gehen davon aus, dass der Hostname Ihres Harbor-Registries yourdomain.com ist, und dass sein DNS-Eintrag auf dem Hostgerät läuft, auf dem Sie Harbor ausführen. Generiere ein Zertifikat der Zertifizierungsstelle. In einer Produktionsumgebung sollten Sie ein Zertifikat von einer Zertifizierungsstelle erhalten. In einer Test- oder Entwicklungsumgebung können Sie Ihr eigenes Zertifikat generieren. Um ein Zertifikat der Zertifizierungsstelle zu generieren, führen Sie die folgenden Befehle aus. Generiere ein Zertifikat der Zertifizierungsstelle private key.

openssl genrsa -out ca.key 4096

Generiere das Zertifikat der Zertifizierungsstelle. Anpassen Sie die Werte in der -subj-Option, um Ihre Organisation zu reflektieren. Wenn Sie Ihren Harbor-Host über einen FQDN verbinden, müssen Sie diesen als gemeinsamen Namen (CN) Attribut angeben.

openssl req -x509 -new -nodes -sha512 -days 3650 \
-subj "/C=CN/ST=Beijing/L=Beijing/O=example/OU=Personal/CN=MyPersonal Root CA" \
-key ca.key \
-out ca.crt

Generiere ein Server-Zertifikat. Das Zertifikat enthält meistens ein .crt-File und ein .key-File, z.B. yourdomain.com.crt und yourdomain.com.key. Generiere ein private key.

openssl genrsa -out yourdomain.com.key 4096

Generiere eine Zertifikatsignaturanfrage (CSR). Anpassen Sie die Werte in der -subj-Option, um Ihre Organisation zu reflektieren. Wenn Sie Ihren Harbor-Host über einen FQDN verbinden, müssen Sie diesen als gemeinsamen Namen (CN) Attribut angeben und ihn in den Key- und CSR-Dateinamen einbeziehen.

openssl req -sha512 -new \
-subj "/C=CN/ST=Beijing/L=Beijing/O=example/OU=Personal/CN=yourdomain.com" \
-key yourdomain.com.key \
-out yourdomain.com.csr

Es gilt, die Schlüssel und CSR-Dateinamen entsprechend zu benennen.

openssl req -sha512 -new \
-subj "/C=CN/ST=Beijing/L=Beijing/O=example/OU=Personal/CN=yourdomain.com" \
-key yourdomain.com.key \
-out yourdomain.com.csr

Generiere eine x509 v3 Erweiterungsdokumentdatei. Unabhängig davon, ob Sie entweder einen FQDN oder eine IP-Adresse zum Verbinden mit Ihrem Harbor-Host verwenden, müssen Sie dieses Dokument erstellen, damit Sie eine Zertifikat für Ihren Harbor-Host erzeugen können, das den Anforderungen des Subject Alternative Name (SAN) und x509 v3 Erweiterung entspricht. Ersetzen Sie die DNS-Einträge, um Ihre Domain zu reflektieren.

cat &gt; v3.ext &lt;&lt;-EOF
authorityKeyIdentifier=keyid,issuer
basicConstraints=CA:FALSE
keyUsage = digitalSignature, nonRepudiation, keyEncipherment, dataEncipherment
extendedKeyUsage = serverAuth
subjectAltName = @alt_names
[alt_names]
DNS.1=yourdomain.com
DNS.2=yourdomain
DNS.3=hostname
EOF

Verwende die v3.ext-Datei, um ein Zertifikat für Ihren Harbor-Host zu generieren. Ersetzen Sie den yourdomain.com in den CSR und CRT-Dateinamen mit dem Namen Ihres Harbor-Hosts.

openssl x509 -req -sha512 -days 3650 \
-extfile v3.ext \
-CA ca.crt -CAkey ca.key -CAcreateserial \
-in yourdomain.com.csr \
-out yourdomain.com.crt

Stellen Sie die Zertifikate für Harbor und Docker bereit. Nachdem Sie die ca.crt, yourdomain.com.crt und yourdomain.com.key-Dateien für Ihr selbstsigniertes Zertifikat erstellt haben, müssen Sie sie Harbor und dem Docker-Dämon bereitstellen. Erstellen Sie den Zertifikat-Verzeichnis für Harbor.

Um Ihre selbstsignierte Zertifikate an Harbor und dem Docker-Daemon zu übergeben, müssen Sie sie bereitstellen. Erstellen Sie den Zertifikatsordner für Harbor. Der Standardordner /data/cert/ ist die Ort, an dem Harbor seine Zertifikate sucht, aber dieser Ordner existiert nicht standardmäßig. Sie müssen ihn zuerst erstellen.

sudo mkdir -p /data/cert/

Kopieren Sie das Server-Zertifikat und die Schlüsseldatei in den Harbor-Ordner.

cp yourdomain.com.crt /data/cert/
sudo cp yourdomain.com.key /data/cert/

Konfigurieren Sie den Docker-Daemon, um die Zertifikate zu vertrauen. Damit der Docker-Client Bilder pushen und pullen kann, muss auch der Docker-Daemon die Zertifikate vertrauen. Um das zu ermöglichen, müssen Sie das Server-Zertifikat von .crt in .cert umwandeln, da der Docker-Daemon diesen Erweiterungsbereich erfordert.

openssl x509 -inform PEM -in yourdomain.com.crt -out yourdomain.com.cer

Erstellen Sie nun einen speziellen Ordner für Ihre Harbor-Domäne und kopieren Sie alle drei Zertifikatdateien in diesen Ordner.

mkdir -p /etc/docker/certs.d/yourdomain.com/
cp yourdomain.com.cert /etc/docker/certs.d/yourdomain.com/
cp yourdomain.com.key /etc/docker/certs.d/yourdomain.com/
cp ca.crt /etc/docker/certs.d/yourdomain.com/

Starten Sie den Docker-Dienst neu.

systemctl restart docker

Sie könnten auch das Zertifikat auf Systemebene vertrauen müssen. Weitere Informationen finden Sie unter Troubleshooting der Harbor-Installation. Das folgende Beispiel zeigt die endgültige Verzeichnisstruktur des Docker-Daemons, der Ihre benutzerdefinierten Zertifikate verwendet.

/etc/docker/certs.d/
└── yourdomain.com:port
    ├── yourdomain.com.cert
    ├── yourdomain.com.key
    └── ca.crt

Der endgültige Verzeichnisbaum für Docker, der Ihre benutzerdefinierten Zertifikate verwendet: /etc/docker/certs.d/ └── yourdomain.com:port
├── yourdomain.com.cert
├── yourdomain.com.key
└── ca.crt

Wenn Sie noch nicht Harbor bereitgestellt haben, sehen Sie sich Configure the Harbor YML File an, um Informationen über die Konfiguration von Harbor zu erhalten, um die Zertifikate zu verwenden, indem Sie den Hostnamen und die https-Attribute in harbor.yml angeben. Wenn Sie Harbor bereits mit HTTP bereitgestellt haben und es um eine Umkonfiguration für HTTPS geht, führen Sie die folgenden Schritte aus. Führen Sie das prepare-Skript aus, um HTTPS zu aktivieren. Harbor verwendet eine nginx-Instanz als umgeleiteten Proxy für alle Dienste. Sie verwenden das prepare-Skript, um nginx für HTTPS zu konfigurieren. Das prepare-Skript befindet sich im Harbor-Installer-Paket, auf der gleichen Ebene wie das install.sh-Skript.

./prepare

Wenn Harbor laufen soll, stoppt und entfernt Sie die bestehende Instanz. Ihre Bilddaten bleiben im Dateisystem erhalten, sodass keine Daten verloren gehen.

docker compose down -v

Neustart von Harbor: docker compose up -d

Überprüfen Sie die HTTPS-Verbindung nach der Einrichtung von HTTPS für Harbor, indem Sie die folgenden Schritte ausführen. Öffnen Sie einen Browser und geben Sie https://yourdomain.com ein. Es sollte die Harbor-Schnittstelle anzeigen. Einige Browser zeigen möglicherweise eine Warnung, die angibt, dass die Zertifikatsbehörde (CA) unbekannt ist. Das geschieht, wenn Sie eine selbstsignierte CA verwenden, die nicht von einer vertrauenswürdigen dritten Partei CA stammt. Sie können das CA in den Browser importieren, um die Warnung zu entfernen.

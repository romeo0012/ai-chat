Nové instalace jsou konfigurovány k spuštění s vloženou databází H2 s komponenty uloženými v místním souborovém systému. Spuštění skriptu z příkazového řádku není odolný proti závadám serveru. Tento příkaz by měl vytvářet každý chybějící soubor nebo adresář.Rozbalte archiv pomocí následujícího příkazu: 

tar xvz --keep-directory-symlink -f

Zde je krátký přehled příkazu.Extrahovat (x) soubory z určeného archivu.Zobrazit detaily (v) výstupu, ukazující každý soubor, jako se extrahuje.Dekomprimovat (z) archiv pomocí gzip před extrakcí.Operovat na určeném souboru (f) (archiv).Příkaz --keep-directory-symlink zachovává existující symlinky adresářů, zatímco je adresář naplněn extrahovanými soubory.

Použijte gzip pro archivaci před extrakcí. Operujte na určeném souboru (f) (archiv). Opci --keep-directory-symlink-symlink zachovává existující symlinky adresářů při naplnění adresáře, kterými ukazují soubory extrahované. Neprovádějte Nexus Repository pro produkční nasazení z domovského adresáře uživatele; běžná praxe je používat adresář /opt. Pro celý popis všech souborů a adresářů v archivu se přečtěte Directories.

Jako uživatel, který spouští Nexus Repository, stáhněte nebo kopírujte balíček do adresáře Instalace Nexus Repository 3. Pro celý popis se přečtěte Stránku Stahování.

tar xvz --keep-directory-symlink -f ./nexus-unix-aarch64-3.78.0-14.tar.gz
tar xvz --keep-directory-symlink -f ./nexus-mac-x86-64-3.78.0-14.tar.gz
tar xvz --keep-directory-symlink -f ./nexus-mac-aarch64-3.78.0-14.tar.gz

Spouštění Nexus RepositoryTM

Archiv v adresáři Aplikace zahrnuje skript pro spuštění aplikace. Tento skript přijímá následující příkazy:

start, stop, run, restart, force-reload

Chcete-li spustit Nexus Repository:

./nexus start

Zprávy o zpracování se vypisují do souboru logovacího aplikace.

Chcete-li zastavit běh Nexus Repository:

./nexus stop

Tento skript přijímá následující příkazy: start, stop, run, restart, force-reload

Chcete-li spustit Nexus Repository:
./nexus start

Výstup se zobrazí v souboru splnění aplikace.

Chcete-li zastavit běh Nexus Repository:
./nexus stop

Příkazem run můžete aplikaci spustit s výstupem do aktuálního shellu pro testování:
./nexus run

Použitím příkazu run zůstane aplikace spuštěná v aktuálním shellu. Aplikaci můžete zastavit pomocí CTRL+C v konzole.

Běh jako služba
Nexus Repository musí být konfigurován k běhu jako služba při instalaci softwaru pro produkční použití. Tím se zajistí, že služba se spustí správně po restartu serveru.

Viz Běh jako služba
Microsoft Windows

Archiv lze rozbalit pomocí utilit kompresi Windows nebo třetí strany, jako je například 7zip. Nexus Repository není instalován do adresáře Program Files.

Můžete instalovat Nexus Repository do adresáře AppData\Local uvnitř domovské adresáře určitého uživatele nebo do adresáře kořenového systému (například C:\nexus ). Ujistěte se, že systémový uživatel má plnou oprávnění k aplikaci a adresářům.

Použijte bin\install-nexus-service.bat k instalaci Nexus Repository na svém Windows serveru. Při aktualizaci odinstalujte předtím starší verze před spuštěním tohoto skriptu. Instalátor Nexus Repository nepodporuje použití mezer v cestě pro server nebo JVM.

příkaz nexus.

Windows server. Při aktualizaci odinstalujte předchozí verze před spuštěním tohoto skriptu. Instalační program Nexus Repository nepodporuje použití mezer v cestě pro server nebo JVM.Použijte nexus.exe executable v příkazu spustit službu s následujícími příkazy:

Spustit službu: .\nexus.exe //ES//SonatypeNexusRepository
Zastavit službu: .\nexus.exe //SS//SonatypeNexusRepository
Odinstalovat službu: .\nexus.exe //DS//SonatypeNexusRepository

Poznámka: Po instalaci Nexus Repository jako služby se změny v nexus.vmoptions již nezachycují službou.Služba musí být znovu instalována, aby se mohla modifikovat konfigurace po instalaci instalačním programem.

Přístup k uživatelskému rozhraní
Při spuštění Nexus Repository se můžete připojit k webové aplikaci uživatelského rozhraní pomocí prohlížeče navigací do adresy URL:
http://<ip_adresa_serveru>:<port>
Pokud chcete to testovat na serveru, na kterém je Nexus Repository hostovan, použijte adresu localhost.
http://localhost:8081/
Můžete potřebovat použít adresu loopback 127.0.0.1, pokud je DNS hostname serveru přiřazen.

Nexus Repository zahrnuje správce s plnými oprávněními.

Připojený a navštivte lokální host. http://localhost:8081/ Můžete potřebovat použít adresu loopback 127.0.0.1 v závislosti na DNS hostnámě assigned k serveru.Sada Nexus Repository zahrnuje uživatele správce s plnými oprávněními. Uživatelské jméno je admin a inicialní heslo se nachází v dočasném souboru s názvem admin.password umístěném v adresáři $data-dir.

Po instalaci Nexus Repository proveďte následující úkoly, aby se zajistila bezpečnost instance Nexus Repository.

Změna hesla správce

Nexus Repository vytvoří unikátní náhodné heslo během inicializace systému, aby se systém udržel v bezpečném stavu. Přihlašovací heslo musí být změněno před použitím Nexus Repository prostřednictvím start wizard v uživatelském rozhraní nebo REST API. Soubor admin.password je uložen v adresáři $data-dir.

Nastavení přístupu pro nezidentifikované uživatele

Při použití uživatelského rozhraní je dalším krokem wizardu nastavení, zda je v systému povoleno přístup pro nezidentifikované uživatele. Pokud nekonfigurované, systém umožní neověřeným uživatelům přístup k obsahu repozitářů.

Změna adresy e-mailu správce

Uživatel správce přichází s výchozí adresou e-mailu nakonfigurovanou a, protože tato adresa nebude příliš užitečná pro kohokoliv, podívejte se na Working with Your User Profile pro podrobnosti.

Nastavení nastavení SMTP

Repository manager může odesílat e-maily s přihlašovacími údaji a obnovením hesel.

Adresa nebude být příliš užitečná pro nikoho, viz Práce s vaším uživatelským profilem pro podrobnosti.Nastavte nastavení SMTP
Řadič manager může odesílat e-maily s obnovením uživatelského jména a hesla. Chcete-li povolit tuto funkci, budete muset nastavit SMTP Host a Port, a také libovolné nutné parametry ověřování, které potřebuje řadič manager k připojení k e-mailovému serveru.
Nastavte výchozí nastavení HTTP a HTTPS proxy
V mnoha nasazeních lze dosáhnout internetu a tudíž i všech remotních repozitářů, které potřebuje řadič manager pro proxy, pouze prostřednictvím HTTP nebo HTTPS proxy serveru vnitřní společnosti. V těchto případech je třeba nastavit detaily k tomuto proxy serveru pro řadič manager, aby mohl proxyovat remote repozitáře vůbec.
Nastavte zásady zálohování pro váš server
Čtěte a využívejte Backup a Restore. Věci se mohou stát a vždy je vhodné zálohovat vaše konfigurace a data na plánované intervaly.
Nastavte pravidla routování
Nastavte pravidla routování k prevenci problémů, jako je například útok na odklonění názvů, kde zlý uživatel vytvoří balíčky v registru s názvy používanými pro vaše vnitřní projekty.
Požadujte tokeny pro přístup k repozitáři
Vyhledejte možnost konfigurace přístupu na základě tokenů.

Docker - Odstranění neúplných nahrávek
Admin - Kompresi databáze blob

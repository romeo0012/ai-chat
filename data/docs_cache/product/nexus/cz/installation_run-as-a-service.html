It is good practice to run that service or daemon as a specific user that has only the required access rights.Installation from the distribution archive does not include the configuration of a service. The following sections provide instructions for configuring the service manually. Independent of the operating system the steps are:Create an operating system user with limited access rights dedicated to running the repository manager as a serviceEnsure a suitable Java runtime environment is installedConfigure the service and ensure it starts as part of the operating system boot processLinuxConfigure Nexus Repository to run as a service with init.d or systemd . Both are startup frameworks used in Linux-based systems such as Ubuntu and CentOS. They are, essentially, init scripts that load commands to manage the service daemon. Before running the service configure an absolute path for your server files. Then create a nexus user with sufficient access rights to run the service.In bin/nexus.rc assign the user between the quotes in the line below. From version 3.80 onwards, the nexus.rc is not provided in the distribution so that file must be created.

Spusťte výchozí prioritu, aby se přidala služba Nexus, než ji spustíte.systemd
Tento příklad je skript, který používá systemd k spuštění služby Nexus Repository. Vytvořte soubor s názvem nexus.service a přidejte následující obsah, poté uložte soubor do adresáře /etc/systemd/system/:

[Unit]
Description=služba Nexus
After=network.target

[Service]
Type=forking
LimitNOFILE=65536
ExecStart=/opt/sonatype/nexus/bin/nexus start
ExecStop=/opt/sonatype/nexus/bin/nexus stop
User=nexus
Restart=on-abort
TimeoutSec=600

[Install]
WantedBy=multi-user.target

Aktivujte službu pomocí následujících příkazů:
sudo systemctl daemon-reload
sudo systemctl enable nexus.service
sudo systemctl start nexus.service

Po spuštění služby pro jakékoliv Linuxové operační systémy ověřte, zda byla spuštěna úspěšně.
tail -f /opt/sonatype-work/nexus3/log/nexus.log

Příkaz tail ověřuje, zda byla služba úspěšně spuštěna. Pokud to bylo úspěšné, byste měli zobrazit zprávu, která vám informuje, že služba poslouchá HTTP.

Tato část se týká pouze verzí Nexus Repository do 3.77.2. Neplatí pro verze 3.78.0 a vyšší.
Při spuštění jako služba na Linuxu Nexus Repository vytvoří soubor, který drží proces ID v adresáři operačního systému /tmp.

Neplatí pro verze 3.78.0 a vyšší.Pokud je Nexus Repository spuštěn jako služba na Linuxu, vytvoří soubor, který obsahuje ID procesu v adresáři operačního systému /tmp. Tento soubor bude mít název ve tvaru:prefix: "i4jdaemon_"suffix: absolutní cesta k skriptu spuštění Nexus Repository s oddělovači cest v části cesty nahrazenými podtržítkyExample: Temporární adresář je /tmp a cesta k spuštění skriptu je v /opt/nexus/nexus-3.14.0-04/bin/nexus, pak vytvořený soubor bude v "/tmp/i4jdaemon__opt_nexus_nexus-3.14.0-04_bin_nexus".Pokud se nedaří psát do souboru s ID procesu služba spuštění bude tichým způsobem selhat, bez jakékoliv záznamů do souboru nexus.log.Pokud je proces Nexus Repository již zastavený a služba selhává při spouštění, nejprve potvrďte, že do souboru nexus.log nebývá přidáváno žádné výpisy. Pokud ne, pak kontrolujte existenci předchozího souboru s ID procesu. Pokud tento soubor existuje, odstraňte ho nejprve před pokusem o spuštění služby.Adresář, do kterého je tento soubor vytvořen, může opčinálně být změněn upravitím $install-dir/bin/nexus.vmoptions a přidáním řádku jako tento:-Dinstall4j.pidDir=/some/absolute/path/to/a/directoryAdresář určený vlastností musí již existovat pro vlastnost fungovat - adresář nebude vytvořen automaticky.Instalační balíčky pro Linux z komunity

Před verzí 3.78.0

Verze 3.78.0 zahrnuje mnoho změn v tom, jak je Nexus Repository sestavováno. Nástroje pro sestavení balíčku nexus.exe vyžadují jinou konfiguraci, jak je uvedeno výše.

Použijte následující příkaz pro verze před 3.78.0:

start, stop, run, restart, force-reload, status

Služba se nazývá nexus výchozím názvem. Je k dispozici v konzolovém aplikaci pro správu služeb jako Windows Services. Můžete ji zahájit, zastavit a restartovat tam také a nakonfigurovat ji k spuštění součástí zahájení systému operace. Alternativně můžete spravovat službu na příkazovém řádku:

nexus.exe /start <volitelný-název-služby>
nexus.exe /stop <volitelný-název-služby>
nexus.exe /uninstall <volitelný-název-služby>

Parametr <volitelný-název-služby> s hodnotou například nexus3 můžete použít.

Mac OS

Standardní způsob spuštění služby v Mac OS je použitím launchd, programu, který spouští, zastavuje a spravuje daemony a skripty v prostředích Apple OS X.

Použití Mac OS X
Standardní způsob spuštění služby na Mac OS X je použitím launchd, programu, který spouští, zastavuje a spravuje daemony a skripty v prostředích Apple OS X. Chcete-li spustit službu, musíte vytvořit XML dokument s příponou .plist, který definuje jej vlastnosti.

Následující plist soubor pro správce repozitářů instalovaný v /opt:

&lt;!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd"&gt;
&lt;plist version="1.0"&gt;
 &lt;dict&gt;
  &lt;key&gt;Label&lt;/key&gt;
  &lt;string&gt;com.sonatype.nexus&lt;/string&gt;
  &lt;key&gt;ProgramArguments&lt;/key&gt;
  &lt;array&gt;
   &lt;string&gt;/opt/nexus/bin/nexus&lt;/string&gt;
   &lt;string&gt;start-launchd&lt;/string&gt;
  &lt;/array&gt;
  &lt;key&gt;RunAtLoad&lt;/key&gt;
  &lt;true/&gt;
 &lt;/dict&gt;
&lt;/plist&gt;

Po uložení souboru jako com.sonatype.nexus.plist v /Library/LaunchDaemons/ musíte změnit vlastnictví a práva přístupu:

sudo chown root:wheel /Library/LaunchDaemons/com.sonatype.nexus.plist
sudo chmod 644 /Library/LaunchDaemons/com.sonatype.nexus.plist

Pokud chcete nastavit jiného uživatele pro spuštění Repozitáře Nexus a přizpůsobit oprávnění a nastavení RUN_AS_USER v skriptu spouštění Nexus Repository, můžete to udělat. S tímto nastavením se Nexus Repository spustí jako služba při spuštění systému.

Chcete-li ho ručně spustit po konfiguraci, můžete to udělat:

sudo launchctl load /Library/LaunchDaemons/com.sonatype.nexus.plist

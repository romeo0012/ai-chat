Sonatype Nexus Repository installieren

Installation

Für die Produktionsnutzung muss Nexus RepositoryTM so konfiguriert werden, dass es als Dienst gestartet wird, sodass es nach einem Neustart des Servers wieder aufgenommen wird. Es ist eine gute Praxis, den Dienst oder Daemon als spezifischen Benutzer zu starten, der nur die erforderlichen Zugriffsrechte hat.

Die Installation aus dem Verteilungsarchiv enthält keine Konfiguration eines Dienstes. Die folgenden Abschnitte bieten Anweisungen für die manuelle Konfiguration des Dienstes. Unabhängig vom Betriebssystem sind die Schritte:

  1. Erstellen Sie einen Benutzer des Betriebssystems mit beschränkten Zugriffsrechten, der nur zum Starten des Repository-Managers als Dienst vorgesehen ist.
  1. Stellen Sie sicher, dass ein geeignetes Java Runtime Environment installiert ist.
  1. Konfigurieren Sie den Dienst und sicherstellen Sie, dass er beim Starten des Betriebssystems automatisch gestartet wird.

Linux

#### Konfigurieren von Nexus Repository als Dienst mit init.d oder systemd

Beide sind Startframeworks, die in Linux-basierten Systemen wie Ubuntu und CentOS verwendet werden. Sie sind, essentiell, Init-Skripts, die Befehle laden, um den Dienst-Dämon zu verwalten. Vor dem Starten des Dienstes sollte ein absoluter Pfad für Ihre Serverdateien festgelegt werden. Dann sollte ein nexus-Benutzer mit ausreichenden Rechten erstellt werden, um den Dienst zu starten.

In bin/nexus.rc sollte der Benutzer zwischen den Anführungszeichen in der Zeile unten zugewiesen werden. Ab der Version 3.80 sind keine nexus.rc-Dateien mehr in der Verteilung enthalten, sodass diese Datei erstellt werden muss.

USER="nexus"

Dienst.In bin/nexus.rc weise den Benutzer zwischen Anführungszeichen in der Zeile unten zu. Ab der Version 3.80 wird der nexus.rc nicht mehr in der Verteilung bereitgestellt, daher muss dieser Datei entsprechend angepasst werden.

run_as_user="nexus"

Verlinke den $installdir auf /opt/sonatype/nexus:

ln -s /opt/sonatype/nexus-3.78-1-01 /opt/sonatype/nexus

Stelle die Position (angezeigt oben als "/opt/nexus-3.78-1-01'") entsprechend Ihrer Installationsposition ein. Stellen Sie sicher, dass der Benutzer, der Nexus Repository ausführt, die notwendigen Berechtigungen auf diesem Pfad hat.

chkconfig

Dieses Beispiel verwendet chkconfig, ein Werkzeug, das die init-Skripte in init.d ansprechen, um den nexus-Dienst zu starten. Führen Sie diese Befehle aus, um das Service aktivieren:

cd /etc/init.d
sudo chkconfig --add nexus
sudo chkconfig --levels 345 nexus on
sudo service nexus start

Die zweite Befehlszeile fügt nexus als Service hinzu, der mit dem Befehl gestartet und beendet werden kann. chkconfig verwaltet die Symbolische Links in /etc/rc[0-6].d, die die Dienste steuern, die bei einem Neustart oder Übergang zwischen Run-Leveln gestartet werden sollen. Die dritte Befehlszeile fügt nexus zu den Run-Leveln 3, 4 und 5 hinzu. Dann startet der Befehl den Nexus Repository.

update-rc.d

Dieses Beispiel verwendet update-rc.d, ein Werkzeug ähnlich dem chkconfig.

cd /etc/init.d
sudo update-rc.d nexus defaults
sudo service nexus start

In der zweiten Zeile fügt Sie eine Priorität "defaults" zu, um den nexus-Service vor dem Starten zu starten.

systemd

Dieses Beispiel ist ein Skript, das systemd verwendet, um den Nexus Repository-Dienst zu starten. Erstellen Sie eine Datei namens nexus.service.

[Unit]
Description=Nexus Repository Manager
After=network.target

[Service]
User=nexus
ExecStart=/opt/sonatype/nexus-3.78-1-01/bin/nexus start
ExecStop=/opt/sonatype/nexus-3.78-1-01/bin/nexus stop
Restart=always

[Install]
WantedBy=multi-user.target

Dieser Service startet den Nexus Repository Manager nach dem Netzwerkziel und stoppt ihn mit dem Befehl "nexus stop". Der Service startet den Repository Manager immer wieder, wenn er gestoppt wird. Der Service wird in der multi-user-Zielgruppe registriert.

Führen Sie eine Standardpriorität aus, um das Nexus-Dienst vor dem Starten zu adden. systemd
Dieses Beispiel ist ein Skript, das systemd verwendet, um den Nexus Repository-Dienst auszuführen. Erstellen Sie eine Datei namens nexus.service und fügen Sie den folgenden Inhalt hinzu, speichern Sie die Datei anschließend im Verzeichnis /etc/systemd/system/:

[Unit]
Description=nexus service
After=network.target
[Service]
Type=forking
LimitNOFILE=65536
ExecStart=/opt/sonatype/nexus/bin/nexus start
ExecStop=/opt/sonatype/nexus/bin/nexus stop
User=nexus
Restart=on-abort
TimeoutSec=600
[Install]
WantedBy=multi-user.target

Aktivieren Sie den Dienst mit den folgenden Befehlen:

sudo systemctl daemon-reload
sudo systemctl enable nexus.service
sudo systemctl start nexus.service

Nach dem Starten des Dienstes für jedes Linux-basierte Betriebssystem überprüfen Sie, ob der Dienst erfolgreich gestartet wurde.

tail -f /opt/sonatype-work/nexus3/log/nexus.log

Der tail-Befehl überprüft, ob der Dienst erfolgreich gestartet wurde. Wenn erfolgreich, sollten Sie eine Meldung erhalten, die Ihnen mitteilt, dass er sich für HTTP anhört.

Warnung
Stellen Sie den passenden Zugriff für den Benutzer fest, der den nexus-Dienst ausführt.

PID-Datei
Dieser Abschnitt ist nur für Nexus Repository-Versionen bis 3.77.2 relevant. Er gilt nicht für Versionen 3.78.0 und darüber.
Beim Starten als Dienst auf Linux wird Nexus Repository eine Datei erstellen, die einen Prozess-ID-Wert im Betriebssystem-Verzeichnis /tmp speichert.

Nicht gilt für Versionen 3.78.0 und darüber. Wenn Nexus Repository auf Linux als Dienst gestartet wird, erstellt es eine Datei, die einen Prozess-ID-Wert in der Betriebssystem-/tmp-Verzeichnis speichert. Diese Datei hat den Namen in der Form:prefix: "i4jdaemon_"suffix: der absolute Pfad zum Nexus-Startskript mit Pfadteil-Trennzeichen durch Unterstriche ersetzt. Beispiel: Der temporäre Speicherort ist /tmp und der Pfad zum Starten des Skripts befindet sich bei /opt/nexus/nexus-3.14.0-04/bin/nexus, dann wird die erstellte Datei bei "/tmp/i4jdaemon__opt_nexus_nexus-3.14.0-04_bin_nexus" sein. Wenn die Datei des Dienst-PID-Werts nicht geschrieben werden kann, wird die Dienst-Startup automatisch schweigend fehlschlagen, ohne irgendeine Log-Ausgaben in das nexus.log geschrieben zu werden. Wenn der Nexus-Repository-Prozess bereits beendet ist und der Dienst nicht starten kann, überprüfe zuerst, ob kein Log-Output in das nexus.log-Datei hinzugefügt wird. Wenn nicht, dann überprüfe dann auf einen vorhandenen Pid-File. Wenn dieses File vorhanden ist, lösche es zuerst vor dem Versuch, den Dienst zu starten.

Das Verzeichnis, in dem diese Datei erstellt wird, kann optional durch Bearbeiten von $install-dir/bin/nexus.vmoptions und Hinzufügen einer Zeile wie folgt geändert werden:-Dinstall4j.pidDir=/some/absolute/path/to/a/directory

Die von der Eigenschaft angegebene Pfad-Muster muss bereits vorhanden sein, damit die Eigenschaft funktioniert - das Verzeichnis wird automatisch nicht erstellt.

Konfigurieren einer externen JDKS
Sonatype bietet Verteilungen mit Laufzeitumgebungen für jedes spezifische Betriebssystem an. Um eine externe Laufzeitumgebung zu verwenden, legt Sie den Pfad für eine spezifische Java-Laufzeitumgebung in der Umgebungsvariablen APP_JAVA_HOME fest.
Die Referenz an dieser Variablen findet sich in dem Skript bin/nexus.

Das Startskript, das Nexus Repository auf Windows-Plattformen startet, ist bin\nexus.exe. Das Skript enthält Standardbefehle für den Start und Stopp des Dienstes.
Verwenden Sie das Skript install-nexus-service.bat, das sich im bin-Verzeichnis befindet, um Nexus Repository auf Ihrem Windows-Server zu installieren und zu aktualisieren. Bei der Aufwertung von einer Version vor Nexus Repository 3.79.1 sollte die vorherige Version zuvor entfernt werden, bevor das Skript ausgeführt wird.

cd C:\path\to\bin
install-nexus-service.bat

Um den Pfad des Datenverzeichnisses anzupassen, sollte der Pfad beim Ausführen des Install-Befehls mit eingeschlossen werden:

install-nexus-service.bat C:\my-sonatype-work

Um den Dienst zu löschen, führen Sie folgenden Befehl aus:

sc delete SonatypeNexusRepository

Beim Installieren von Nexus Repository als Dienst werden Änderungen an nexus.vmoptions nicht mehr von dem Dienst aufgenommen.

C:\meine-sonatype-arbeitsverzeichnis
Um den Dienst zu löschen, führen Sie den folgenden Befehl aus: 

sc delete SonatypeNexusRepository

Hinweis: Wenn Nexus Repository als Dienst installiert ist, werden Änderungen an den nexus.vmoptions nicht mehr von dem Dienst aufgenommen. Um die Konfiguration zu ändern, muss der Dienst neu installiert werden.

Starten des Nexus Repository Dienstes als Windows Dienst
Nach der Installation des Dienstes können Sie ihn starten und stoppen, indem Sie den Windows Dienst-Steuerungspanel verwenden. Um den Dienst vom Befehlzeilentool zu stoppen, führen Sie den folgenden Befehl aus: 

nexus.exe stop SonatypeNexusRepository

Um den Dienst vom Befehlzeilentool zu starten, führen Sie den folgenden Befehl aus: 
nexus.exe start SonatypeNexusRepository

Mit einer anderen Java Laufzeitumgebung arbeiten
Der Nexus Repository Binary enthält die empfohlene Java Laufzeitumgebung, jedoch kann dies geändert werden, um eine andere unterstützte Laufzeitumgebung zu verwenden. Verwenden Sie entweder der folgenden beiden Optionen:
  • Setzen Sie die Umgebungsvariable APP_JAVA_HOME auf den absoluten Pfad der JDK, die Sie verwenden möchten.
  • Modifizieren Sie die nexus.rc-Datei und geben Sie den absoluten Pfad zur JDK, die Sie verwenden möchten, in der app_java_home-Variable an. Ab der Version 3.80 ist die nexus.rc-Datei nicht mehr in der Verteilung enthalten, daher muss diese Datei erstellt werden.

#app_java_home=C:\Pfad\Zum\Anderen\JDK17\install

Konfigurieren Sie die Speichergröße für den Nexus Repository Dienst auf Windows
Beim Starten von Nexus Repository 3 als Windows Dienst können Sie die JVM-Speichergrößenoptionen -Xms (initialer Speicher) und -Xmx (maximaler Speicher) in der nexus.vmoptions-Datei verwenden, um die Speichergröße des Dienstes anzupassen.

auf Windows
Beim Laufen von Nexus Repository 3 als Windows-Dienst kannst du die JVM-Speichergrößen über die Optionen -Xms (initialer Heap) und -Xmx (maximale Heap) in der Datei nexus.vmoptions anpassen. Der Windows-Dienst-Manager akzeptiert nur Speicherwerte in Megabytes (MB) mit dem 'm'-Suffix. Verwendung von 'g' oder anderen Einheiten wird Fehler auslösen. Hier ist ein Beispiel, das eine initiale Heapgröße von 1GB und eine maximale Heapgröße von 4GB festlegt:
-Xms1024m -Xmx4096m

Nexus.exe-Befehle vor Release 3.78.0
Release 3.78.0 enthält viele Änderungen in der Art und Weise, wie Nexus Repository erstellt wird. Das Werkzeug, um das nexus.exe-Paket zu erstellten, benötigt eine alternative Konfiguration, wie oben aufgeführt.
Verwende den folgenden Befehl für Versionen vor 3.78.0.
start, stop, run, restart, force-reload, status
Der Dienst heißt standardmäßig nexus. Er ist im Windows-Konsole-Anwendung verfügbar, um Dienste wie Windows-Dienste zu verwalten, wie auch zu starten, zu stoppen und zu restarten. Alternativ kannst du den Dienst auf der Befehlszeile verwalten:
nexus.exe /start <optional-service-name>
nexus.exe /stop <optional-service-name>
nexus.exe /uninstall <optional-service-name>
Der Parameter <optional-service-name> mit einem Wert wie z.B. nexus3 kann verwendet werden.

Mac OS
Die standardmäßige Art, einen Dienst auf Mac OS zu starten, ist es, launchd zu verwenden, ein Programm, das Startet, Stoppt und verwaltet Daemons und Skripts in Apple OS X-Umgebungen.

Standardmäßig wird auf Mac OS ein Dienst über launchd gestartet, einem Programm, das Dämonen und Skripts in Apple OS X-Umgebungen startet, stoppt und verwaltet. Um den Dienst auszuführen, muss ein XML-Dokument erstellt werden, das mit der Dateiendung .plist benannt und dessen Eigenschaften definiert sind.

Ein Beispiel für ein plist-Datei für den in /opt installierten Repository-Manager wird hier gezeigt:

&lt;!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd"&gt;
&lt;plist version="1.0"&gt;
 &lt;dict&gt;
  &lt;key&gt;Label&lt;/key&gt;
  &lt;string&gt;com.sonatype.nexus&lt;/string&gt;
  &lt;key&gt;ProgramArguments&lt;/key&gt;
  &lt;array&gt;
   &lt;string&gt;/opt/nexus/bin/nexus&lt;/string&gt;
   &lt;string&gt;start-launchd&lt;/string&gt;
  &lt;/array&gt;
  &lt;key&gt;RunAtLoad&lt;/key&gt;
  &lt;true/&gt;
 &lt;/dict&gt;
&lt;/plist&gt;

Nach Speichern des Files als com.sonatype.nexus.plist in /Library/LaunchDaemons/ muss die Eigentums- und Zugriffsrechte geändert werden:

sudo chown root:wheel /Library/LaunchDaemons/com.sonatype.nexus.plist
sudo chmod 644 /Library/LaunchDaemons/com.sonatype.nexus.plist

Es wird empfohlen, einen anderen Benutzer für Nexus Repository einzurichten und die Berechtigungen und den RUN_AS_USER-Einstellung im nexus-Startskript anzupassen. Mit dieser Konfiguration startet der Nexus Repository-Dienst bei Bootzeit als Dienst.

Um den Dienst manuell nach der Konfiguration zu starten, kann folgendes verwendet werden:

sudo launchctl load /Library/LaunchDaemons/com.sonatype.nexus.plist

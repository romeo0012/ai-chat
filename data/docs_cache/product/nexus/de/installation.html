Der Nexus Repository-Verteilungspaketarchiv kombiniert die Anwendung und die erforderlichen Ressourcen in einem Archivdatei. Wenn Nexus RepositoryTM auf einer lokalen Arbeitsstation getestet wird, können die Dateien extrahiert und in einem Umgebung, die einen Java-Laufzeitumgebung unterstützt, ausgeführt werden.

Es müssen viele Entscheidungen vor dem Bereitstellen von Nexus Repository berücksichtigt werden. Neue Installationen werden standardmäßig mit einem eingebetteten H2-Datenbank und Komponenten im lokalen Dateisystem konfiguriert. Das Startskript aus der Befehlszeile ist nicht resilient gegen Serverabstürze. Während dies für Testzwecke möglicherweise ausreicht, sind sie nicht für Produktionsdeployments geeignet.

Überprüfen Sie die Planung Ihrer Bereitstellung Dokumentation, bevor Sie fortfahren.

Entpacken des Archivs

Die Verteilungspakete sind so konzipiert, dass sie aus der Befehlszeile entpackt werden, um vorhandene Dateien im Verzeichnis nicht zu ersetzen oder zu überschreiben. Der Befehl soll alle fehlenden Dateien oder Verzeichnisse erstellen.

Entpacken Sie das Archiv mit dem folgenden Befehl:

tar xvz --keep-directory-symlink -f

Hier ist eine kurze Zusammenfassung des Befehls.

Extrahieren (x) Dateien aus dem angegebenen Archiv.

Ausgabe von detaillierten (v) Ausgaben, die jede Datei zeigt, während sie extrahiert wird.

Entpacken Sie das Archiv mit gzip (z) vor der Extraktion.

Operieren Sie auf dem angegebenen Datei (f) (das Archiv).

Die Option --keep-directory-symlink erhalten Sie bestehende Verzeichnis-Symlinks während Sie das Verzeichnis, das sie zeigen, mit den extrahierten Dateien füllen.

Die Archivdatei muss vor der Extraktion mit gzip komprimiert sein. Führe auf dem angegebenen Datei (f) (die Archivdatei) die folgenden Schritte aus:

gzip -d &lt; f

Verwende die Option --keep-directory-symlink um vorhandene Verknüpfungen von Verzeichnissen zu erhalten und das Zielverzeichnis mit den extrahierten Dateien zu füllen:

tar xvz --keep-directory-symlink -f ./nexus-unix-x86-64-3.78.0-14.tar.gz
tar xvz --keep-directory-symlink -f ./nexus-unix-aarch64-3.78.0-14.tar.gz
tar xvz --keep-directory-symlink -f ./nexus-mac-x86-64-3.78.0-14.tar.gz
tar xvz --keep-directory-symlink -f ./nexus-mac-aarch64-3.78.0-14.tar.gz

Es wird empfohlen, Nexus Repository nicht aus einem Benutzer-Heimverzeichnis für Produktionsbereitstellungen zu starten; eine übliche Praxis ist es, das Verzeichnis /opt zu verwenden.

Siehe [Verzeichnisse](#) für eine vollständige Beschreibung aller Dateien und Verzeichnisse in der Archivdatei.

Als Benutzerkonto, das Nexus Repository ausführt, laden Sie oder kopieren Sie den Bundle in den Installationsordner von Nexus Repository 3.

Siehe die [Downloads](https://www.sonatype.com/downloads) Seite.

Extrahiere die Archivdatei mit einem Befehl, der spezifisch für Ihr Bundleformat ist:

tar xvz --keep-directory-symlink -f ./nexus-unix-x86-64-3.78.0-14.tar.gz
tar xvz --keep-directory-symlink -f ./nexus-unix-aarch64-3.78.0-14.tar.gz
tar xvz --keep-directory-symlink -f ./nexus-mac-x86-64-3.78.0-14.tar.gz
tar xvz --keep-directory-symlink -f ./nexus-mac-aarch64-3.78.0-14.tar.gz

Die Extraktion der Archivdatei füllt das Anwendungsverzeichnis und den Elternordner des Standarddatenverzeichnisses aus:

../nexus-3.78.0-14
./sonatype-work

Laufen Sie Nexus RepositoryTM

In dem Archivverzeichnis der Anwendung befindet sich ein Skript, um die Anwendung zu starten. Dieses Skript akzeptiert die folgenden Befehle:

start
stop
run
restart
force-reload

Um das Nexus Repository zu starten:

./nexus start

Die Protokollierung wird in das Anwendungsprotokolldatei geschrieben.

Um das laufende Nexus Repository zu stoppen:

./nexus stop

Dieses Skript akzeptiert die folgenden Befehle: start, stop, run, restart, force-reload

Um den Nexus Repository zu starten: ./nexus start
Die Ausgabe wird in das Anwendungslogfile ausgegeben.
Um den Nexus Repository, der im Hintergrund läuft, zu stoppen: ./nexus stop
Mit dem Befehl run laufen die Anwendung mit der Ausgabe in der aktuellen Shell für Testzwecke. Mit dem Befehl run bleibt die Anwendung im aktuellen Shellfenster laufen. Die Anwendung kann mit STRG+C im Konsolenfenster beendet werden.

Als Dienst laufen
Der Nexus Repository muss konfiguriert werden, um als Dienst laufen zu können, wenn das Softwarepaket für die Produktionsnutzung installiert wird. Dadurch wird sichergestellt, dass der Dienst nach einem Neustart des Servers wieder aufgestartet wird.
Weitere Informationen finden Sie unter Run as a Service
Microsoft Windows Umgebungen
Das Archiv kann mit dem Windows-Kompressionsprogramm oder einem dritten-Party-Programm wie 7zip entpackt werden. Der Nexus Repository wird nicht in der Programme-Verzeichnis-Direktory installiert.
Sie können den Nexus Repository in der AppData\Local-Direktory eines bestimmten Benutzers-Heimverzeichnisses installieren oder eine Ordner in der Systemwurzel verwenden (z.B., C:\nexus ). Stellen Sie sicher, dass der Systembenutzer Vollzugriff auf die Anwendung und Verzeichnisse hat.
Verwenden Sie den bin\install-nexus-service.bat, um den Nexus Repository auf Ihrem Windows-Server zu installieren. Bei einer Upgrade-Aktion sollten Sie die vorherigen Versionen zuerst entfernen, bevor Sie dieses Skript ausführen. Der Nexus Repository-Installer unterstützt nicht den Einsatz von Leerzeichen im Pfad für den Server oder JVM.

Zugriff auf die Benutzeroberfläche
Beim Starten von Nexus Repository kann die web-basierte Benutzeroberfläche über einen Webbrowser aufgerufen werden, indem Sie den Dienst-URL navigieren:
http://<host_ip>:<port>
Um dies auf dem Server zu testen, auf dem Nexus Repository gehostet wird, navigieren Sie zu localhost.
http://localhost:8081/
Sie müssen möglicherweise den Schleifenadressen 127.0.0.1 verwenden, je nachdem, wie der DNS-Hostname des Servers zugewiesen ist.

Nexus Repository enthält einen administrativen Benutzer mit Vollzugriff.

Navigieren Sie zu der lokalen Adresse. http://localhost:8081/ Wenn Sie auf die DNS-Hostname des Servers angewiesen sind, können Sie stattdessen die Schleifenwende-Adresse 127.0.0.1 verwenden. Nexus Repository enthält einen administrativen Benutzer mit Vollzugriff. Der Benutzername ist admin und das Initial-Kennwort finden Sie in einer temporären Datei namens admin.password, die im $data-dir-Verzeichnis liegt.

Nach Installation von Nexus Repository sollten Sie die folgenden Aufgaben erledigen, um die Sicherheit Ihrer Nexus Repository-Instanz sicherzustellen.

Ändern Sie das Admin-Kennwort
Nexus Repository erstellt während des ersten Starts des Systems ein eindeutiges zufälliges Kennwort, um das System in einem sicheren Zustand zu halten. Das Systembesitzer muss das Initial-Kennwort aus dem Dateisystem abrufen, um sich anzumelden. Das Kennwort muss vor der Nutzung von Nexus Repository über den Start-Assistenten im Benutzeroberflächen-Interface oder über die REST-API geändert werden. Die Datei admin.password wird im $data-dir gespeichert.

Konfigurieren Sie die Anonymzugriffserlaubnis
Wenn Sie das Benutzeroberflächen-Interface verwenden, gibt es in der Wizard eine weitere Schritt, um festzustellen, ob unauthentifizierte Benutzer im System Zugriff auf die Repository-Inhalte haben dürfen. Bis zu dieser Konfiguration erlaubt das System es unauthentifizierten Benutzern, die Inhalte von Repositories zu lesen.

Ändern Sie die administrativen E-Mail-Adresse
Der admin-Benutzer kommt mit einer standardmäßigen E-Mail-Adresse konfiguriert, die für niemanden allzu nützlich sein wird, siehe Arbeiten mit Ihrem Benutzerprofil für Details.

Konfigurieren Sie die SMTP-Einstellungen
Der Repository-Manager kann E-Mails mit Benutzernamen und Kennwort-Wiederherstellung senden.

Adresse wird für die meisten Nutzer nicht sehr nützlich sein, siehe Arbeiten mit Ihrem Benutzerprofil für Details.

Konfigurieren Sie die SMTP-Einstellungen
Der Repository-Manager kann Benutzername und Passwort-Wiederherstellungs-E-Mails senden. Um diese Funktion zu aktivieren, müssen Sie einen SMTP-Host und Port sowie alle notwendigen Authentifizierungsparameter konfigurieren, die der Repository-Manager benötigt, um sich mit dem Mail-Server zu verbinden.

Konfigurieren Sie die Standard-HTTP und HTTPS-Proxy-Einstellungen
In vielen Bereitstellungen kann der Internetzugang und somit alle entfernten Repositorien, die der Repository-Manager proxen muss, nur über einen HTTP oder HTTPS-Proxy-Server innerhalb der Bereitstellungsgesellschaft erreicht werden. In diesen Fällen müssen die Verbindungsdetails zu diesem Proxy-Server für den Repository-Manager konfiguriert werden, damit er entfernte Repositorien proxen kann.

Einrichten einer Backup-Prozedur für Ihren Server
Lesen Sie und nutzen Sie Backup und Wiederherstellen. Dinge passieren und es ist immer empfehlenswert, Ihre Konfigurationen und Daten regelmäßig zu sichern.

Einrichten von Routing-Regeln
Stellen Sie Routing-Regeln ein, um Probleme wie eine Name-Hijacking-Attacke zu verhindern, bei der ein schädlicher Nutzer Pakete in einem Registry mit Namen verwendet, die von Ihren internen Projekten verwendet werden.

Anfordern von Benutzer-Tokens für Repository-Zugriff
Überlegen Sie es, tokenbasiertes Zugriff zu konfigurieren.

Einrichten von Wartungstasks
Stellen Sie die folgenden wichtigen Wartungstasks ein:
Maven - Löschen unbenötigter SNAPSHOTS
Docker - Löschen unvollständiger Uploads
Admin - Komprimieren blob-Speicher

Einrichten von Reinigungs-Politik
In Ihren Repository-Einstellungen stellen Sie Reinigungs-Politik ein.

Über die folgenden wichtigen Wartungstätigkeiten hinweg:

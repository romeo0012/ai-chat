Sonatype Nexus Repository Systemanforderungen

Wichtig:
Ab der Version 3.87.x des Nexus Repository Manager wird der AWS SDK für S3 Blob-Speicher von der Version 1.12.658 auf 2.33.5 aktualisiert, da das AWS SDK für Java 1.x am 31. Dezember 2025 das Ende des Lebenszyklus erreicht. Dieser Änderung unterliegen Nutzer von S3-kompatiblen Blob-Speichern, die nicht AWS-kompatibel sind. Kunden, die S3-kompatible Speicherung verwenden sollten die Kompatibilität mit dem AWS SDK für Java 2.x bei der Upgrade-Verarbeitung überprüfen.

Dieses Thema behandelt die Systemanforderungen für den Nexus Repository.

Unterstützte Nexus Repository-Versionen
Die Unterstützten Versionen werden in der Sonatype Sunsetting Information erklärt. Die unterstützten Versionen sind auf der Versionstatusseite aufgeführt.

Unterstützte Betriebssysteme
Sonatype Nexus Repository unterstützt die Linux, Windows und MacOS Betriebssysteme. Sonatype hat keine Testungen oder Unterstützung für andere Betriebssysteme durchgeführt.

Benutzen Sie ein dediziertes Benutzerkonto
Wir empfehlen, ein dediziertes Betriebssystem-Benutzerkonto zu verwenden, um jeden einzelnen Prozess auf einem gegebenen Host zu starten. Der Nexus Repository-Prozessbenutzer muss eine gültige Shell erzeugen können.

Nexus Repository sollte nicht als root-Benutzer gestartet werden.

Erforderliche Dateihandle-Grenzen
Der Nexus Repository verbraucht mehr Dateihandles als der Standardwert, der von Linux oder MacOS Betriebssystemen zugelassen wird. Einige Containerplattformen (z.B., Amazon ECS) überschreiben die Standardgrenzen, die auf dem Container gesetzt werden. Durch Auslaufen von Dateihandlern kommt es zu Datenverlust.

Unterstützte Betriebssysteme
Das Nexus Repository ist nur auf Linux- oder MacOS-Betriebssystemen lauffähig. Einige Container-Plattformen (z.B., Amazon ECS) überschreiben die standardmäßigen Grenzen, die auf den Container gesetzt werden. Wenn man ausreichend Datei-Deskriptoren ausläuft, kann es zu Datenverlust kommen. Um die Anzahl der offenen Datei-Deskriptoren für den Benutzer, der Nexus Repository ausführt, zu erhöhen, siehe den Abschnitt Anpassen der Datei-Handle-Grenzen.

Unterstützte Web-Browser
Unserer Politik ist es, die neueste moderne Browserversion Ihrer unterstützten Betriebssysteme zu unterstützen, bei der Veröffentlichung des Nexus Repository-Versions. Keine Unterstützung für Virenscanner. Sonatype unterstützt nicht offiziell noch empfiehlt die Verwendung von Virenscannern mit Nexus Repository. Wir haben 10-mal längere Startzeiten auf Windows-Servern und einen signifikanten Leistungsverlust beobachtet, wenn man einen Virenscanner verwendet, um das Installationsverzeichnis zu überwachen.

Unterstützte Java-Versionen
Nexus Repository wird auf und unterstützt OpenJDK und erfordert Java 21. Nexus Repository ist mit beiden Intel und AMD CPU-Architekturen kompatibel. Ab der Version 3.78.0 enthält der Nexus Repository-Paket die empfohlene JVM.

Siehe Java-Kompatibilitäts-Matrix.

CPU-Leistung
Die Leistung ist hauptsächlich durch IO (Disk und Netzwerk) begrenzt, anstatt durch CPU. Verfügbare CPUs werden die Ausführung von langwierigen Operationen und den Thread-Count beeinflussen. Siehe die Thread-Zuweisungsalgorithmen des Web-Containers.

Siehe die Speicherempfehlungen nach Profilgröße für CPU-Empfehlungen nach Bereitstellung.

Verfügbare CPU's werden Einfluss auf lang laufende Operationen und Thread-Zähler nehmen. Siehe die Thread-Zuweisungsalgorithmen des Web-Containers. Siehe die Abschnitt "Speicherempfehlungen nach Größe des Profils" für CPU-Empfehlungen bei der Bereitstellung.

Speicheranforderungen
Im Allgemeinen sollte auf bis zu zwei Dritteln des verfügbaren RAM auf Nexus Repository zugeordnet werden; damit bleibt ein Drittel des RAM für Systemprozesse und Buffers frei.

Die Speicheranforderungen variieren je nach Profilgröße. Es gibt keine einzelne definierte Anforderung aufgrund der Komplexität aller möglichen Einsatzfälle. Der folgende Abschnitt gibt die Speicher- und CPU-Empfehlungen für jeden Knoten in klein, mittel, groß und sehr groß angegeben.

Hoch verfügbare Bereitstellungen müssen diese Anforderungen für alle Knoten in der Cluster erfüllen.

Siehe unser Thema "Übersicht über den Speicher des Nexus Repository" für Details über die verschiedenen Arten von Speicher, die Nexus Repository verwendet, und Beispiele für Java-spezifische Speicheranforderungen.

Für alle Knoten im Cluster. Siehe unsere Nexus Repository Speicherübersicht Thema für Details über die verschiedenen Arten von Speicher, die der Nexus Repository verwendet und Beispiele für Java-spezifische Speicheranforderungen.

Datenbankanforderungen
Der Nexus Repository unterstützt zwei Datenbankoptionen: einen eingebetteten H2-Datenbank oder einen externen PostgreSQL-Datenbank.

Eingebettete H2-Datenbank Einschränkungen
Neue Installationen werden standardmäßig mit einer H2-Datenbank konfiguriert. Der Nexus Repository, der mit der eingebetteten H2-Datenbank betrieben wird, unterstützt bis zu 200,000 Anfragen pro Tag oder 100,000 Komponenten.
Arbeitslasten, die diese Einschränkungen übersteigen, werden nicht unterstützt. Container-basierte Bereitstellungen sind bei H2-Bereitstellungen nicht unterstützt.

PostgreSQL-Anforderungen (Empfohlen)
Wir empfehlen allen Bereitstellungen, eine externe PostgreSQL-Datenbank zu verwenden. Für optimale Leistung sollte der Nexus Repository eine niedrige Verzögerung zur Datenbank haben. Wenn eine Cloud-Datenbank verwendet wird, muss der Nexus Repository-Knoten in derselben Region sein.

Datenbank. Für optimales Leistungsverhalten sollte der Nexus Repository eine niedrig-verzögerte Verbindung zur Datenbank aufweisen. Bei der Verwendung einer cloudbasierten Datenbank muss der Nexus Repository-Knoten in der gleichen Region sein. Es muss eine Version von PostgreSQL verwendet werden, die noch von PostgreSQL unterstützt wird, wie in ihren Versionierungsdokumentationen definiert. Der Nexus Repository unterstützt es nicht, PostgreSQL in einem aktiven/aktiven Cluster auszuführen. Die 2-Knoten-PostgreSQL-Konfiguration, die in der Profilgröße angegeben ist, ist ein aktiver Schreiber und ein Leseknoten, für schnelleres Failover und Backup-Zwecken.

Erforderliche PostgreSQL-Datenbank-Benutzerrechte
Der Benutzer muss Eigentümer der Datenbank sein. Operationen wie Upgrades oder Schemaänderungen erfordern Eigentumsrechte. Der Einsatz eines nicht-Eigentümer-Benutzers wird von Sonatype nicht getestet oder unterstützt.

Erforderliche Trigram-Modul für PostgreSQL-Datenbank
Nexus Repository 3-Instanzen, die PostgreSQL-Datenbanken verwenden müssen, haben das pg_trgm (Trigram) Modul. Dieses Modul wird möglicherweise nicht mit PostgreSQL standardmäßig installiert sein, was bei einem Versuch, zu upgraden, zu einer Ausnahme führen wird.
Siehe Installing the Trigram Module für Installationsanweisungen.

Erweiterte Datenbank-Speicherplatz-Tuning
Siehe Advanced Database Memory Tuning für Beispiele für erweiterte Datenbank-Speicherplatz-Tuning basierend auf verschiedenen Profilgrößen.

Legacy Orient-Datenbank
Die von Sonatype Nexus Repository eingebettete Legacy-OrientDB-Datenbank ging im August 2024 in den erweiterten Wartungsmodus.
Nexus Repository-Kunden müssen von OrientDB auf einen unterstützten Datenbanken wechseln.
Bleiben Sie auf der Nexus Repository 3.70.x-Version, bis Sie von OrientDB weggewechselt sind. Versionen 3.71.0 und höher unterstützen OrientDB nicht.

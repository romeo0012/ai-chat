Installiere NGINX Ingress Controller mithilfe von Manifests
Diese Anleitung erklärt, wie Sie Manifests verwenden, um den F5 NGINX Ingress Controller zu installieren, anschließend sowohl allgemeine als auch benutzerdefinierte Ressourcen zu erstellen und eine Rollenbasierte Zugriffssteuerung einzurichten.

Vor dem Start
Wenn Sie NGINX Plus verwenden, erhalten Sie die NGINX Ingress Controller JWT und erstellen Sie ein Lizenzgeheimnis.

Holen Sie sich das NGINX Controller Image
Wir empfehlen die aktuellste stabile Version des NGINX Ingress Controller, die auf der GitHub-Repository-Veröffentlichungen-Seite verfügbar ist. Wählen Sie eine der folgenden Methoden, um das NGINX Ingress Controller Image zu erhalten:

NGINX Ingress Controller:
Laden Sie das Image nginx/nginx-ingress von DockerHub herunter.

NGINX Plus Ingress Controller:
Sie haben zwei Optionen für dieses, beide erfordern eine NGINX Ingress Controller Abonnement.
Laden Sie NGINX Ingress Controller von der F5 Registry Thema herunter.
Fügen Sie ein NGINX Ingress Controller Image Ihrem Cluster hinzu:
Um ein eigenes Image zu erstellen, folgen Sie dem Build NGINX Ingress Controller Thema.

Klonen Sie das Repository
Klonen Sie das NGINX Ingress Controller Repository mithilfe des unten gezeigten Befehls und ersetzen Sie <version_number> durch die spezifische Veröffentlichung, die Sie verwenden möchten.

Copy
git clone https://github.com/nginx/kubernetes-ingress.git --branch <version_number>

Beispiel: Wenn Sie Version 5.5.1 verwenden möchten, ist der Befehl:

Copy
git clone https://github.com/nginx/kubernetes-ingress.git --branch v5.5.1

Diese Anleitung basiert auf der aktuellen Veröffentlichung. Ändern Sie den aktiven Verzeichnis.

Erstellt einen ConfigMap, um Ihre NGINX-Einstellungen zu individualisieren: Kopiere kubectl apply -f deployments/common/nginx-config.yaml

Erstellt ein IngressClass-Ressource. Der NGINX Ingress Controller startet nicht ohne ein IngressClass-Ressource. Kopiere kubectl apply -f deployments/common/ingress-class.yaml

Wenn Sie diese NGINX Ingress Controller-Instanz Ihrem Kubernetes-Cluster als Standard wollen, entkommentieren Sie die ingressclass.kubernetes.io/is-default-class Annotation. Dadurch wird dem IngressClass automatisch zugewiesen, wenn neue Eingangsbereiche nicht einen ingressClassName angeben.

Ihre Cluster-Standard, kommentiere die Annotation ingressclass.kubernetes.io/is-default-class aus. Dadurch wird IngressClass automatisch zu neuen Ingressen zugewiesen, die keinen ingressClassName spezifizieren. Um sicherzustellen, dass die Pods des NGINX Ingress Controller in den Ready-Zustand gelangen, müssen Sie benutzerdefinierte Ressourcendefinitionen (CRDs) für verschiedene Komponenten erstellen. Alternativ können Sie dieses Anforderungsfeld deaktivieren, indem Sie das -enable-custom-resources Befehlszeilenargument auf false festlegen. Es gibt zwei Möglichkeiten, die benutzerdefinierten Ressourcendefinitionen zu installieren:

  1. Verwenden Sie eine URL, um ein einzelnes CRD yaml-Datei-Format anzuwenden, was wir empfehlen.
  1. Anwenden Sie Ihre lokale Kopie der CRD yaml-Datei-Formate, was erfordert, dass Sie das Repository klonen müssen.

Die Kern-CRDs sind die folgenden:

  • VirtualServer
  • VirtualServerRoute
  • TransportServer
  • Policy
  • GlobalConfiguration

Installieren Sie CRDs aus einem einzelnen YAML

kubectl apply -f https://raw.githubusercontent.com/nginx/kubernetes-ingress/v5.5.1/deploy/crds.yaml

Installieren Sie CRDs nach dem Klonen des Repositories

kubectl apply -f config/crd/bases/k8s.nginx.org_virtualservers.yaml
kubectl apply -f config/crd/bases/k8s.nginx.org_virtualserverroutes.yaml
kubectl apply -f config/crd/bases/k8s.nginx.org_transportservers.yaml
kubectl apply -f config/crd/bases/k8s.nginx.org_policies.yaml
kubectl apply -f config/crd/bases/k8s.nginx.org_globalconfigurations.yaml

Lesen Sie die Schritte in Upgrade von 3.x auf 4.x vor dem Ausführen des CRD-Upgrades und führen Sie die Schritte, wenn sie angewendbar sind.

StatefulSets enthalten Anspruchsbereiche für den Speicher von nginx-Cache über volumeClaimTemplates. Es kann erforderlich sein, eine StorageClass in Ihrem Cluster zu konfigurieren oder den Abschnitt volumeClaimTemplates in der Manifestdatei zu ändern, um Ihren Speicheranforderungen entsprechend zu passen. Andere Speicher (z.B. solche, die für App Protect-Module erforderlich sind), werden in der regulären volumes-Sektion konfiguriert, nicht in volumeClaimTemplates. Um den NGINX Ingress Controller zu überprüfen, ob er läuft, führen Sie folgenden Befehl aus:

kubectl get pods --namespace=nginx-ingress

Zugriff auf NGINX Ingress Controller mithilfe einer Deployment oder StatefulSet
Für Deployments und StatefulSets gibt es zwei Optionen, um auf NGINX Ingress Controller-Pods zuzugreifen. Option 1: Erstellung einer NodePort-Dienst
Weitere Informationen zum NodePort-Dienst finden Sie in der Kubernetes-Dokumentation. Um einen Dienst des Typs NodePort zu erstellen, führen Sie folgenden Befehl aus:

kubectl create -f deployments/service/nodeport.yaml

Kubernetes reserviert automatisch zwei Ports auf jedem Knoten im Cluster. Sie können den NGINX Ingress Controller über die IP-Adresse jedes Knotens in Kombination mit diesen Ports erreichen. Option 2: Erstellung eines LoadBalancer-Dienstes
Weitere Informationen zum LoadBalancer-Dienst finden Sie in der Kubernetes-Dokumentation.

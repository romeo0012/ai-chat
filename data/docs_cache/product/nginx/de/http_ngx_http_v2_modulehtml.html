Dieses Modul wird standardmäßig nicht gebaut und muss mit dem --with-http_v2_Module-Konfigurationsparameter aktiviert werden. Bekannte Probleme Vor Version 1.9.14 konnte die Speicherung eines Client-Anfrage-Körpers nicht deaktiviert werden, unabhängig von den Werten der Directives proxy_request_buffering, fastcgi_request_buffering, uwsgi_request_Buffering und scgi_request_Buffering. Vor Version 1.19.1 wurde das lingering_close-Mechanismus nicht verwendet, um HTTP/2-Verbindungen zu steuern. Beispielkonfiguration server { listen 443 ssl; http2 on; ssl_certificate server.crt; ssl_certificate_key server.key; } Bitte beachten Sie, dass die Übertragung von HTTP/2-Verbindungen über TLS erfordert, dass die TLS-Erweiterung "Application-Layer Protocol Negotiation" (ALPN) unterstützt wird, die seit OpenSSL-Version 1.0.2 verfügbar ist. Bitte beachten Sie auch, dass wenn der ssl_prefer_server_Ciphers-Directive der Wert "on" gesetzt ist, die Verschlüsselungen mithin RFC 9113, Appendix A black list und von Clients unterstützt werden müssen.

Wichtig ist, dass wenn der Directive ssl_prefer_server_ciphers der Wert „on“ gesetzt ist, die Ciphers konfiguriert werden müssen, um mit RFC 9113, Abschnitt A Schwarze Liste und von Clients unterstützt zu sein. Direktiv-Syntax: http2 on | off; Standard: http2 off; Kontext: http, server
Dieses Directive ist ab Version 1.25.1 verfügbar. Aktiviert das HTTP/2-Protokoll.
Direktiv-Syntax: http2_body_preread_size size; Standard: http2_body_preread_size 64k; Kontext: http, server
Dieses Directive ist ab Version 1.11.0 verfügbar. Setzt die Größe des Buffers pro jedem Anforderung, in dem der Anforderungskörper vor dem Beginn der Verarbeitung gespeichert werden kann.
Direktiv-Syntax: http2_chunk_size size; Standard: http2_chunk_size 8k; Kontext: http, server, location
Dieses Directive setzt die maximale Größe der Blöcke, in die der Antwortkörper geschnitten wird. Eine zu niedrige Größe führt zu höherem Overhead. Eine zu hohe Größe behindert Priorisierung durch HOL-Blocking.
Direktiv-Syntax: http2_idle_timeout time; Standard: http2_idle_timeout 3m; Kontext: http, server
Dieses Directive ist ab Version 1.19.7 veraltet. Die keepalive_timeout-Directive sollte stattdessen verwendet werden. Setzt den Zeitraum der Inaktivität, nach dem die Verbindung geschlossen wird.

Syntax: http2_max_concurrent_streams Zahl; Standard: http2_max_concurrent_streams 128; Kontext: http, server Setzt die maximale Anzahl an gleichzeitigen HTTP/2-Streams in einer Verbindung.

Syntax: http2_max_field_size Größe; Standard: http2_max_field_size 4k; Kontext: http, server Dieses Direktiv ist seit Version 1.19.7 veraltet. Die large_client_header_buffers-Direktive sollte stattdessen verwendet werden. Es begrenzt die maximale Größe eines HPACK-komprimierten Anforderungskopf-Feldes. Die Grenze gilt für beide Name und Wert. Bemerkung: Wenn Huffman-Kodierung angewendet wird, kann die tatsächliche Größe der entschlüsselten Namen- und Wertzeichenfolgen größer sein. Für die meisten Anforderungen sollte die Standardgrenze genügend sein.

Die large_client_header_buffers-Direktive sollte stattdessen verwendet werden. Es begrenzt die maximale Größe der gesamten Anforderungskopf-Liste nach HPACK-Entschlüsselung. Für die meisten Anforderungen sollte die Standardgrenze genügend sein.

Dieses Direktiv erschien in Version 1.11.6.

Dieses Direktiv ist ab Version 1.11.6 verfügbar. Dieses Direktiv ist seit Version 1.19.7 veraltet. Stattdessen sollte die keepalive_requests Direktive verwendet werden. Diese Direktive legt die maximale Anzahl an Anfragen (einschließlich Push-Anfragen) fest, die über eine HTTP/2-Verbindung gesendet werden können, nachdem die Anzahl der Anfragen die maximale erreicht hat. Danach wird die nächste Anfrage des Clients zur Schließung der Verbindung und zum Neustellen einer neuen Verbindung führen. Die Schließung von Verbindungen periodisch ist notwendig, um die pro-Verbindung Speicherzuweisungen freizugeben. Daher sollte eine zu hohe maximale Anzahl an Anfragen zu einem übermäßigen Speicherverbrauch führen und nicht empfohlen werden. Syntax: http2_push uri | off; Default: http2_push off; Kontext: http, server, location

Dieses Direktiv ist ab Version 1.13.9 verfügbar. Dieses Direktiv ist seit Version 1.25.1 veraltet. Stattdessen kann die early_hints Direktive verwendet werden. Diese Direktive sendet (pusht) voraus ein Anfrageanforderung an die angegebene uri zusammen mit der Antwort auf die ursprüngliche Anfrage. Nur relative URIs mit absolutem Pfad werden verarbeitet, z.B.: http2_push /static/css/main.css; Der Wert der uri kann Variablen enthalten. Mehrere http2_push Direktiven können auf derselben Konfigurationsebene angegeben werden. Das off-Parameter storniert den Effekt der http2_push Direktiven, die von der vorherigen Konfigurationsebene geerbt wurden. Syntax: http2_push_preload on | off; Default: http2_push_preload off; Kontext: http, server, location

Dieses Direktiv ist ab Version 1.13.9 verfügbar. Dieses Direktiv ist seit Version 1.25.1 veraltet.

Nur OpenSSL 1.0.2 oder höher unterstützt separate Zertifikatsketten für verschiedene Zertifikate. Mit älteren Versionen kann nur eine Zertifikatskette verwendet werden. Seit Version 1.15.9 können Variablen verwendet werden, wenn OpenSSL 1.0.2 oder höher verwendet wird:

ssl_certificate_key $ssl_server_name.key;

Es ist zu beachten, dass die Verwendung von Variablen impliziert, dass für jede SSL-Handshake ein Zertifikat geladen wird, was möglicherweise einen negativen Einfluss auf die Leistung haben kann. Stattdessen kann der Wert data:$variable angegeben werden, um ein Zertifikat aus einer Variable zu laden, ohne intermediäre Dateien zu verwenden (ab Version 1.15.10). Es ist zu beachten, dass unangemessene Verwendung dieser Syntax ihre Sicherheitsimplicationen haben kann, wie zum Beispiel das Schreiben von geheimen Schlüsseldaten in den Fehlerprotokoll. Es ist wichtig zu beachten, dass aufgrund der Einschränkungen des SSL/TLS-Protokolls für die maximale Interoperabilität mit Clients, die keine SNI verwenden, virtuelle Server mit verschiedenen Zertifikaten auf verschiedenen IP-Adressen lauschen sollten.

Kontext: http, Server
Legt die Typen und Größen der Caches fest, die Sessionparameter speichern. Ein Cache kann jeden der folgenden Typen sein:

  • off: Der Einsatz eines Session-Caches ist strikt verboten: nginx gibt dem Client mitteilen, dass Sessions nicht wiederverwendet werden dürfen.
  • none: Der Einsatz eines Session-Caches wird sanft verboten: nginx gibt dem Client mit, dass Sessions wiederverwendet werden können, allerdings speichert es die Sessionparameter nicht im Cache.
  • builtin: Ein Cache, der in OpenSSL gebaut ist; wird von nur einem Arbeitsprozess verwendet. Die Cachegröße wird in Sessions angegeben. Wenn keine Größe gegeben ist, beträgt sie 20480 Sessions. Der Einsatz des internen Caches kann zu Speicherfragmentierung führen.
  • shared: Ein Cache, der zwischen allen Arbeitsprozessen geteilt wird. Die Cachegröße wird in Bytes angegeben; ein Megabyte kann etwa 4000 Sessions speichern. Jeder geteilte Cache sollte einen beliebigen Namen haben. Ein Cache mit dem gleichen Namen kann in mehreren virtuellen Servern verwendet werden.

Diese Direktive erschien in der Version 1.3.7. Gibt einen Dateipfad mit vertrauenswürdigen CA-Zertifikaten im PEM-Format an, die verwendet werden, um Clientzertifikate und OCSP-Antworten zu überprüfen, wenn ssl_stapling aktiviert ist. Im Gegensatz zum Zertifikat, das durch ssl_client_certificate festgelegt wird, wird die Liste dieser Zertifikate nicht den Clients gesendet.
Syntax: ssl_verify_client on | off | optional | optional_no_ca; Standard: ssl_verify_client off; Kontext: http, server
Aktiviert die Überprüfung von Clientzertifikaten. Das Überprüfungsergebnis wird in der Variable $ssl_client_verify gespeichert. Der optional Parameter (0.8.7+) fordert das Clientzertifikat und überprüft es, wenn das Zertifikat vorhanden ist.

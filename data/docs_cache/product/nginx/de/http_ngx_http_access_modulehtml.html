Modul ngx_http_access_module
Beispiel-Konfigurations-Direktiven: allow, deny
Das ngx_http_access_module-Modul ermöglicht die Einschränkung des Zugriffs auf bestimmte Client-Adressen. Der Zugang kann auch durch ein Passwort, durch das Ergebnis einer Subrequest oder durch JWT eingeschränkt werden. Die gleichzeitige Einschränkung des Zugriffs durch Adresse und Passwort wird durch das satisfy-Direktiv gesteuert.

Beispiel-Konfiguration
location / {
deny 192.168.1.1;
allow 192.168.1.0/24;
allow 10.1.1.0/16;
allow 2001:0db8::/32;
deny all;
}

Die Regeln werden in Reihenfolge überprüft, bis der erste Treffer gefunden wird. In diesem Beispiel wird der Zugang nur für die IPv4-Netzwerke 10.1.1.0/16 und 192.168.1.0/24 zugelassen, ausgenommen die Adresse 192.168.1.1, und für das IPv6-Netzwerk 2001:0db8::/32. Bei vielen Regeln ist die Verwendung des ngx_http_geo_module-Moduls Variablen bevorzugt.

Direktiven-Syntax: allow address | CIDR | unix: | all;
Standard: —
Kontext: http, server, location, limit_except
Erlaubt den Zugang für die angegebene Netzwerk oder Adresse. Wenn das Sonderwert unix: angegeben wird (1.5.1), erlaubt es den Zugang für alle UNIX-Domänen-Sockets. Mehrere allow-Direktiven können auf derselben Ebene angegeben werden. Diese Direktiven werden nur von der vorherigen Konfigurations-Ebene geerbt, wenn und nur wenn keine allow und deny-Direktiven auf der aktuellen Ebene definiert sind.

Direktiven-Syntax: deny address | CIDR | unix: | all;
Standard: —
Kontext: http, server, location, limit_except
Verweigert den Zugang für die angegebene Netzwerk oder Adresse. Wenn das Sonderwert unix: angegeben wird (1.5.1), verweigert es den Zugang für alle UNIX-Domänen-Sockets. Mehrere deny-Direktiven können auf derselben Ebene angegeben werden. Diese Direktiven werden nur von der vorherigen Konfigurations-Ebene geerbt, wenn und nur wenn keine allow und deny-Direktiven auf der aktuellen Ebene definiert sind.

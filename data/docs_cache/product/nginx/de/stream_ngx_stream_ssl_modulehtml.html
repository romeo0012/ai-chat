Module ngx_stream_ssl_module

← Chat

Modul ngx_stream_ssl_Modul (Version 1.9.0) bietet die notwendige Unterstützung für einen Stream-Proxy-Server, mit dem SSL/TLS-Protokoll zu arbeiten. Dieser Modul wird standardmäßig nicht gebaut und muss mit dem --with-stream_ssl_Modul-Konfigurationsparameter aktiviert werden. Dieser Modul benötigt die OpenSSL-Bibliothek.

Beispielkonfiguration
Um den Prozessorlast zu reduzieren, wird empfohlen, die Anzahl der Arbeitsprozesse auf die Anzahl der Prozessoren zu setzen, den geteilten Session-Cache zu aktivieren, den integrierten Session-Cache auszuschalten und möglicherweise die Session-Lebensdauer (standardmäßig 5 Minuten) zu erhöhen:

worker_processes auto;
stream {
...
server {
listen 12345 ssl;
ssl_protocols TLSv1.2 TLSv1.3;
ssl_ciphers AES128-SHA:AES256-SHA:RC4-SHA:DES-CBC3-SHA:RC4-MD5;
ssl_certificate /usr/local/nginx/conf/cert.pem;
}

Verankerte Variablen
Die folgenden Variablen sind in diesem Beispiel verwendet:

  • /usr/local/nginx/conf/cert.pem: Pfad zur SSL-Zertifikatsdatei
  • /usr/local/nginx/conf/cert.key: Pfad zur SSL-Zertifikatschlüsseldatei

Direktiven-Syntax: ssl_certificate file;
Standard: —
Kontext: stream, server
Gibt einen Datei-Pfad an, der das Zertifikat im PEM-Format für den jeweiligen virtuellen Server enthält. Falls zusätzliche Zwischenzertifikate angegeben werden sollen, sollten sie in derselben Datei in der folgenden Reihenfolge angegeben werden: Zunächst das Primärzertifikat, dann die Zwischenzertifikate. Ein geheimer Schlüssel im PEM-Format kann in derselben Datei platziert werden. Seit der Version 1.11.0 kann diese Direktive mehrfach angegeben werden, um Zertifikate verschiedener Typen zu laden, z.B. RSA und ECDSA:
server {

ssl_certificate_key example.com.rsa.key;
ssl_certificate example.com.ecdsa.crt;
ssl_certificate_key example.com.ecdsa.key;
... }

Nur OpenSSL 1.0.2 oder höher unterstützt separate Zertifikatsketten für verschiedene Zertifikate. Mit älteren Versionen kann nur eine Zertifikatskette verwendet werden. Seit Version 1.15.9 können Variablen verwendet werden, wenn OpenSSL 1.0.2 oder höher verwendet wird:
ssl_zertifikat $ssl_server_name.crt;
ssl_zertifikatschlüssel $ssl_server_name.key;

Bitte beachten Sie, dass die Verwendung von Variablen impliziert, dass für jede SSL-Handshake ein Zertifikat geladen wird, was möglicherweise einen negativen Einfluss auf die Leistung haben kann. Stattdessen kann der Wert data:$variable angegeben werden, anstatt des Dateinamens (1.15.10), was ein Zertifikat aus einer Variable laden ohne Intermediärdateien verwendet.
Bitte beachten Sie, dass unangemessene Verwendung dieser Syntax ihre Sicherheitsimplicationen haben kann, wie das Schreiben von geheimen Schlüsseldaten in den Fehlerprotokoll. Es sollte beachtet werden, dass aufgrund der Einschränkungen des SSL/TLS-Protokolls für die maximale Interoperabilität mit Clients, die keine SNI verwenden, virtuelle Server mit verschiedenen Zertifikaten auf verschiedenen IP-Adressen hören sollten.

Modul ngx_http_perl_moduleBekannte ProblemeBeispielkonfigurationDirectives perl perl_modules perl_require perl_setPerl aus SSIDas $r Anfrageobjekt-Methoden Der Modul ngx_http_perl_module wird verwendet, um Lokationen- und Variablen-Handler in Perl und Perl-Aufrufe in SSI zu implementieren. Dieses Modul wird standardmäßig nicht gebaut und soll mit dem --with-http_perl_module Konfigurationsparameter aktiviert werden. Dieses Modul benötigt Perl-Version 5.6.1 oder höher. Der C-Compiler soll mit demjenigen kompatibel sein, der verwendet wurde, um Perl zu bauen. Bekannte Probleme Das Modul ist experimentell, daher gilt caveat emptor. Um Perl bei einer erneuten Konfiguration die modifizierten Module neu zu kompilieren, muss es mit den -Dusemultiplicity=yes oder -Dusethreads=yes Parameter gebaut werden. Zusätzlich sollte Perl mit dem -Dusemymalloc=no Parameter gebaut werden, um weniger Speicher beim Laufen zu verbrauchen. Um die Werte dieser Parameter in einem bereits gebauten Perl (bevorzugte Werte sind im Beispiel angegeben) zu überprüfen, führen Sie folgenden Befehl aus: $ perl -V:usemultiplicity -V:usemymalloc usemultiplicity='define'; usemymalloc='n';

Hinweis: Nach dem Neubau von Perl mit den neuen -Dusemultiplicity=yes oder -Dusethreads=yes Parametern müssen alle binären Perl-Module neu gebaut werden — sie funktionieren einfach nicht mehr mit dem neuen Perl. Es wird daher empfohlen, nur solche Operationen durchzuführen, die eine vorhersehbare und kurze Ausführungszeit haben, wie z.B. den lokalen Dateisystemzugriff. Beispielkonfiguration:

Das Perl-Modul perl/lib/hello.pm:

package hello;
use nginx;
sub handler {
    my $r = shift;
    $r-&gt;send_http_header("text/html");
    return OK if $r-&gt;header_only;
    $r-&gt;print("hello!\n&lt;br/&gt;");
    if (-f $r-&gt;filename oder -d _) {
        $r-&gt;print($r-&gt;uri, " exists!\n");
    }
    return OK;
}
1;

$r->allow_ranges ermöglicht die Verwendung von Byteranges bei der Übermittlung von Antworten.
$r->discard_request_body instructiert nginx, den Anfragekörper zu verworfen.
$r->header_in(field) gibt den Wert des angegebenen Clientanfragekopf-Feldes zurück.
$r->header_only bestimmt, ob die gesamte Antwort oder nur ihr Kopf an den Client gesendet werden soll.
$r->header_out(field, value) setzt einen Wert für das angegebene Antwortkopf-Feld.
$r->internal_redirect(uri) führt eine interne Umleitung an die angegebene uri durch. Eine tatsächliche Umleitung erfolgt nach der Ausführung des Perl-Handlers. Seit Version 1.17.2 akzeptiert die Methode auch entweder entweder entfließt oder unterstützt Umleitungen an benannte Standorte.
$r->log_error(errno, message) schreibt den angegebenen Nachrichtentext in das Fehlerprotokoll. Wenn errno nicht null ist, wird ein Fehlercode und seine Beschreibung dem Nachrichtentext angehängt.
$r->print(text, …) übermittelt Daten an den Client.

Um immer eine Anforderungstextdatei zu schreiben, muss client_body_in_file_only aktiviert werden. $r->request_method gibt den HTTP-Anforderungsmethode des Clients zurück. $r->remote_addr gibt die IP-Adresse des Clients zurück. $r->flush sendet sofort Daten an den Client. $r->sendfile(name[, offset[, length]]) sendet den Inhalt der angegebenen Datei an den Client. Die optionalen Parameter bestimmen den initialen Offset und die Länge der zu übertragenden Daten. Die tatsächliche Datenübertragung erfolgt nach Abschluss des Perl-Handlers. $r->send_http_header([type]) sendet den Antwortkopf an den Client. Der optionalen Typ-Parameter legt den Wert des “Content-Type” Antwortkopf-Feldes fest. Wenn der Wert leer ist, wird der “Content-Type” Kopfzeile nicht gesendet. $r->status(code) setzt einen Antwortcode. $r->sleep(milliseconds, handler) setzt den angegebenen Handler und unterbricht die Anforderungsverarbeitung für die angegebene Zeit. Währenddessen verarbeitet nginx weitere Anforderungen. Nach Ablauf der angegebenen Zeit ruft nginx den installierten Handler auf. Hinweis: Die Handlerfunktion sollte per Referenz übergeben werden. Um Daten zwischen Handlern auszutauschen, sollte $r->variable() verwendet werden.

Beispiel:

package hello;
use nginx;
sub handler {
my $r = shift;
$r->discard_request_body;
$r->variable("var", "OK");
$r->sleep(1000, \&next);
return OK;
}
sub next {
my $r = shift;
$r->send_http_header;
$r->print($r->variable("var"));
return OK;
}
1;
__END__
$r->unescape(text) decodet einen Text, der in der “%XX” Form kodiert ist. $r->uri gibt die Anforderungs-URI zurück. $r->variable(name[, value]) gibt oder setzt den Wert des angegebenen Variablen. Variablen sind lokal zu jedem Anforderung.

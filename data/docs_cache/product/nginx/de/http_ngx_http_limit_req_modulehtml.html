Module ngx_http_limit_req_module

← Chat

Modul ngx_http_limit_req_module (Version 0.7.21) wird verwendet, um die Anforderungsverarbeitungsrate pro einer definierten Schlüssel zu begrenzen, insbesondere die Verarbeitungsrate von Anforderungen, die von einer IP-Adresse kommen. Die Begrenzung erfolgt mittels des "leaky bucket"-Verfahrens. Beispielkonfiguration

http {
    limit_req_zone $binary_remote_addr zone=one:10m rate=1r/s;
    ...
    server {
        ...
        location /search/ {
            limit_req zone=one burst=5;
        }
    }
}

Syntax: limit_req zone=name [burst=number] [nodelay | delay=number];
Standard: —
Kontext: http, server, location
Setzt die gemeinsame Speicherzone und die maximale Anzahl an Burst-Anforderungen. Wenn die Anforderungsrate die für eine Zone konfigurierte Rate übersteigt, wird ihre Verarbeitung verzögert, sodass Anforderungen bei einer definierten Rate verarbeitet werden. Übermäßige Anforderungen werden verzögert, bis ihre Anzahl die maximale Burst-Größe überschreitet, in dem Fall wird die Anforderung mit einem Fehler beendet. Standardmäßig ist die maximale Burst-Größe gleich null. Beispiel: die Direktiven limit_req_zone $binary_remote_addr zone=one:10m rate=1r/s; server { location /search/ { limit_req zone=one burst=5; } erlaubt nicht mehr als 1 Anforderung pro Sekunde im Durchschnitt, mit Bursts nicht mehr als 5 Anforderungen.

zone=eins burst=5; } erlaube nicht mehr als 1 Anfrage pro Sekunde im Durchschnitt, mit Bursts nicht überschreitend 5 Anfragen. Wenn die Verzögerung von überschüssigen Anfragen während der Anfragebegrenzung nicht gewünscht ist, sollte der Parameter nodelay verwendet werden: limit_req zone=eins burst=5 nodelay; Der Delay-Parameter (1.15.7) legt eine Grenze fest, ab der überschüssige Anfragen verzögert werden. Der Standardwert ist null, d.h. alle überschüssigen Anfragen werden verzögert. Es können mehrere limit_req-Direktiven vorhanden sein. Beispielhaft wird die folgende Konfiguration die Verarbeitungsrate der Anfragen aus einer einzelnen IP-Adresse und zugleich die Verarbeitungsrate des virtuellen Servers begrenzen:

limit_req_zone $binary_remote_addr zone=perip:10m rate=1r/s;
limit_req_zone $server_name zone=perserver:10m rate=10r/s;
server {
...
limit_req zone=perip burst=5 nodelay;
limit_req zone=perserver burst=10;
}

Diese Direktiven werden nur aus der vorherigen Konfigurationsstufe geerbt, wenn und nur wenn keine limit_req-Direktiven auf der aktuellen Stufe definiert sind.
Syntax: limit_req_dry_run on | off; Default: limit_req_dry_run off; Kontext: http, server, location
Diese Direktive erschien in der Version 1.17.1. Aktiviert den Trockenläufen-Modus. In diesem Modus wird die Verarbeitungsrate der Anfragen nicht begrenzt, jedoch wird in der gemeinsamen Speicherzone die Anzahl der überschüssigen Anfragen wie üblich gezählt.
Syntax: limit_req_log_level info | warn | notice | error; Default: limit_req_log_level error; Kontext: http, server, location
Diese Direktive erschien in der Version 0.8. Aktiviert den Log-Level.

info | Hinweis | Warnung | Fehler; Standard: limit_req_log_level Fehler; Kontext: http, server, location
Diese Direktive ist ab Version 0.8.18 verfügbar. Sie setzt die gewünschte Protokollierstufe für Fälle ein, in denen der Server aufgrund einer zu hohen Rate oder Verzögerungen Anfragen nicht verarbeiten will. Die Protokollierstufe für Verzögerungen ist um ein Stufe niedriger als für Ablehnungen; z.B. wenn “limit_req_log_level Hinweis” angegeben wird, werden Verzögerungen mit der info-Stufe protokolliert. Syntax: limit_req_log_level level; Default: limit_req_log_level Fehler.

Syntax: limit_req_status code; Default: limit_req_status 503; Kontext: http, server, location
Diese Direktive ist ab Version 1.3.15 verfügbar. Sie setzt den Statuscode, der in Antwort auf abgelehnte Anfragen zurückgegeben wird.
Syntax: limit_req_zone key zone=name:size rate=rate [sync]; Default: — Kontext: http
Setzt Parameter für eine gemeinsame Speicherzone, die die Zustände für verschiedene Schlüssel speichert. Insbesondere speichert die Zustandsdaten die aktuelle Anzahl an überschüssigen Anfragen. Der Schlüssel kann aus Text, Variablen und deren Kombination bestehen. Anfragen mit einem leeren Schlüsselwert werden nicht berücksichtigt. Bis zur Version 1.7.6 konnte der Schlüssel genau eine Variable enthalten. Verwendung Beispiel: limit_req_zone $binary_remote_addr zone=one:10m rate=1r/s;
Hier werden die Zustände in einer 10 Megabyte-Zone “one” gespeichert, und der Durchschnittliche Anfrageverarbeitungsrate für diese Zone darf nicht mehr als 1 Anfrage pro Sekunde betragen. Die IP-Adresse des Clients dient als Schlüssel.
Hinweis: Statt $remote_addr wird hier $binary_remote_addr verwendet.

Zweit. Eine Client-IP-Adresse dient als Schlüssel. Bemerkung: Statt $remote_addr wird hier stattdessen die $binary_remote_addr-Variable verwendet. Die Größe der $binary_remote_addr-Variable beträgt immer 4 Bytes für IPv4-Adressen oder 16 Bytes für IPv6-Adressen. Der Speicherplatz, der für den gespeicherten Zustand reserviert ist, beträgt 64 Bytes auf 32-Bit-Plattformen und 128 Bytes auf 64-Bit-Plattformen. Ein Megabyte-Bereich kann etwa 16.000 64-Byte-Zustände oder etwa 8.000 128-Byte-Zustände speichern. Wenn die Speicherplatzkapazität des Bereichs aufgebraucht ist, wird der am wenigsten gerade genutzte Zustand entfernt. Wenn trotzdem ein neuer Zustand nicht erstellt werden kann, wird die Anfrage mit einem Fehler beendet. Die Rate wird in Anfragen pro Sekunde (r/s) angegeben. Wenn weniger als eine Anfrage pro Sekunde gewünscht wird, wird sie in Anfragen pro Minute (r/m) angegeben. Beispiel: Halb-Anfrage pro Sekunde ist 30r/m. Der sync-Parameter (1.15.3) ermöglicht die Synchronisierung der gemeinsamen Speicherbereichszone. Der sync-Parameter ist als Teil unserer kommerziellen Abonnement-Option verfügbar. Zusätzlich können wir als Teil unserer kommerziellen Abonnement-Option ab Version 1.17.7 über die API die Statusinformationen für jede solche gemeinsame Speicherbereichszone abrufen oder zurücksetzen. Die Variable $limit_req_status speichert das Ergebnis der Anfrageverarbeitungsratebegrenzung (1.17.6): PASSED, DELAYED, REJECTED, DELAYED_DRY_RUN oder REJECTED_DRY_RUN.

Das Modul ngx_http_referer_module dient dazu, Zugriff auf eine Seite für Anfragen mit ungültigen Werten in dem "Referer"-Headerfeld zu verweigern. Es sollte beachtet werden, dass die Fälschung einer Anfrage mit einem passenden "Referer"-Feldwert recht einfach ist, und so dient dieses Modul nicht dazu, solche Anfragen vollständig zu blockieren, sondern den Massenfluss von Anfragen, die von regulären Browsern gesendet werden. Es sollte auch beachtet werden, dass reguläre Browser möglicherweise den "Referer"-Feld nicht für gültige Anfragen senden.

Beispielkonfiguration 

valid_referers none;
blocked;
server_names *.beispiel.com beispiel.*;
www.beispiel.org/galleries/ ~\.google\.;
if ($invalid_referer) {
    return 403;
}

Directives Syntax:
referer_hash_bucket_size size;
Default: referer_hash_bucket_size 64;
Context: server, location
Diese Direktive ist ab Version 1.0.5 verfügbar. Setzt die Größe der Buckets für die gültigen Referer-Hash-Tabellen. Die Details zur Einrichtung von Hash-Tabellen werden in einer separaten Dokumentation bereitgestellt.

Syntax:
referer_hash_max_size size;
Default: referer_hash_max_size 2048;
Context: server, location
Diese Direktive ist ab Version 1.0.5 verfügbar. Setzt die maximale Größe der gültigen Referer-Hash-Tabellen. Die Details zur Einrichtung von Hash-Tabellen werden in einer separaten Dokumentation bereitgestellt.

Einstellung von Hash-Tabellen werden in einem separaten Dokument beschrieben. Syntax: valid_referers none | blocked | server_names | string ...; Standard: — Kontext: server, location

Diese Direktive legt die Werte des "Referer" Anforderungskopf-Feldes fest, die das eingebettete $invalid_referer-Variable auf leere Zeichenfolge setzen. Andernfalls wird die Variable auf "1" gesetzt. Die Suche nach einem Treffer ist unabhängig von der Groß-/Kleinschreibung. Die Parameter können wie folgt aussehen:

none: Das "Referer"-Feld fehlt im Anforderungskopf
blocked: Das "Referer"-Feld ist im Anforderungskopf vorhanden, aber sein Wert wurde von einem Firewall oder Proxy-Server gelöscht; solche Werte sind Zeichenfolgen, die nicht mit "http://" oder "https://" beginnen;
server_names: Das "Referer"-Anforderungskopf-Feld enthält einen der Servernamen;
arbitrary string definiert einen Servernamen und einen optionalen URI-Präfix. Ein Servername kann ein "*" am Anfang oder Ende haben. Während der Überprüfung wird der Port des Servers im "Referer"-Feld ignoriert;
regular expression: Der erste Symbol soll ein "~" sein. Es sollte beachtet werden, dass eine Ausdrucksübereinstimmung gegen den Text nach dem "http://" oder "https://" verglichen wird. Beispiel:

valid_referers none blocked server_names *.example.com example.* www.example.org/galleries/ ~\.google\.

Eingebettete Variablen:
$invalid_referer: Leere Zeichenfolge, wenn das "Referer"-Anforderungskopf-Feldwert als gültig angesehen wird, andernfalls "1".

Der Modul ngx_http_ssi_module ist ein Filter, der SSI (Server Seite Einschließen) Befehle in durchlaufenden Antworten verarbeitet. Aktuell ist die Liste der unterstützten SSI Befehle unvollständig.

Beispiel-Konfiguration

location / {
ssi on;
...
}

Direktiven

Syntax: ssi on | off;
Standard: ssi off;
Kontext: http, server, location, if in location

Aktiviert oder deaktiviert die Verarbeitung von SSI Befehlen in Antworten.

Syntax: ssi_last_modified on | off;
Standard: ssi_last_modified off;
Kontext: http, server, location

Diese Direktive wurde in Version 1.5.1 eingeführt. Erlaubt es, den "Last-Modified" Headerfeld der originalen Antwort während der SSI Verarbeitung zu erhalten, um Antwortspeicherung zu erleichtern. Standardmäßig wird das Headerfeld entfernt, da Inhalte der Antwort während der Verarbeitung modifiziert werden können und dynamisch generierte Elemente oder Teile enthalten, die unabhängig von der originalen Antwort geändert werden können.

Syntax: ssi_min_file_chunk Größe;
Standard: ssi_min_file_chunk 1k;
Kontext: http, server, location

Setzt die Mindestgröße für Teile einer Antwort, die auf Disk gespeichert werden, ab der es sinnvoll ist, sie mit sendfile zu senden.

Größe für Teile einer Antwort, die auf dem Disketten Speicher gespeichert sind, ab welcher Stelle es sinnvoll ist, sie mit sendfile zu senden. Syntax: ssi_silent_errors on | off; Standard: ssi_silent_errors off; Kontext: http, server, location
Wenn aktiviert, unterdrückt es die Ausgabe der Zeichenfolge “[ein Fehler ist beim Verarbeiten des Direktivs aufgetreten]”, wenn ein Fehler während der SSI-Verarbeitung auftritt. Syntax: ssi_types mime-type ...; Standard: ssi_types text/html; Kontext: http, server, location
Erlaubt die Verarbeitung von SSI-Befehlen in Antworten mit den angegebenen MIME-Typen zusätzlich zu “text/html”. Der Sonderwert “*” passt sich jedem MIME-Typ an (0.8.29). Syntax: ssi_value_length length; Standard: ssi_value_length 256; Kontext: http, server, location
Setzt die maximale Länge von Parameterwerten in SSI-Befehlen. SSI-Befehle haben folgenden allgemeinen Format: <!--# command parameter1=value1 parameter2=value2 ... -->
Unterstützte Befehle:
block
Definiert einen Block, der als Stub im include-Befehl verwendet werden kann. Der Block kann andere SSI-Befehle enthalten. Der Befehl hat folgenden Parameter: name block name. Beispiel: <!--# block name="one" --> stub <!--# endblock -->
config
Setzt einige Parameter, die während der SSI-Verarbeitung verwendet werden, nämlich:
errmsg
Eine Zeichenfolge, die ausgegeben wird, wenn ein Fehler während der SSI-Verarbeitung auftritt. Standardmäßig wird die folgende Zeichenfolge ausgegeben: [ein Fehler ist beim Verarbeiten des Direktivs aufgetreten]
timefmt
Eine Formatzeichenfolge, die an die strftime()-Funktion übergeben wird, um die Ausgabe von Datum und Uhrzeit zu ermöglichen.

Vorkommen während der Verarbeitung der Direktive] timefmt ist ein Formatzeichenstreng, das dem strftime()-Funktion übergeben wird, um Datum und Uhrzeit auszugeben. Als Standard wird folgendes Format verwendet: "%A, %d-%b-%Y %H:%M:%S %Z" Das Format "%s" ist geeignet, um die Zeit in Sekunden auszugeben. echo gibt den Wert einer Variablen aus. Der Befehl hat die folgenden Parameter:

  • var: Variablenname
  • encoding: die Kodierungsart
  • Mögliche Werte sind none, url, und entity. Als Standard wird entity verwendet.
  • default: ein nicht standardmäßiger Parameter, der eine Zeichenkette setzt, die auszugeben ist, wenn eine Variable undefiniert ist. Als Standard wird "(none)" ausgegeben. Der Befehl <!--# echo var="name" default="no" --> ersetzt die folgende Folge von Befehlen: <!--# if expr="$name" --> <!--# echo var="name" --> <!--# else -->no<!--# endif -->

wenn Performs a conditional inclusion. Die folgenden Befehle werden unterstützt:

  • <!--# if expr="..." --> ...
  • <!--# elif expr="..." --> ...
  • <!--# else --> ...
  • <!--# endif -->

Nur eine Ebene der Nestung ist derzeit unterstützt. Der Befehl hat folgenden Parameter: expr: Ausdruck. Ein Ausdruck kann sein:

  • Variablenexistenzprüfung: <!--# if expr="$name" -->
  • Vergleich einer Variablen mit einem Text: <!--# if expr="$name = text" -->
  • <!--# if expr="$name != text" -->
  • Vergleich einer Variablen mit einem regulären Ausdruck: <!--# if expr="$name = /text/" -->
  • <!--# if expr="$name != /text/" -->

Wenn ein Text Variablen enthält, werden ihre Werte substituiert.

if expr="$name = /text/" --&gt; &lt;!--# if expr="$name != /text/" --&gt; Wenn ein Text Variablen enthält, werden deren Werte substituiert. Eine reguläre Ausdruckszeichenfolge kann Positions- und benannte Kapitüren enthalten, die später über Variablen verwendet werden können, z.B.: &lt;!--# if expr="$name = /(.+)@(?P&lt;domain&gt;.+)/" --&gt; &lt;!--# echo var="1" --&gt; &lt;!--# echo var="domain" --&gt; &lt;!--# endif --&gt; include Inkludiert das Ergebnis einer anderen Anfrage in eine Antwort. Der Befehl hat folgende Parameter: file spezifiziert einen eingebundenen Datei, z.B.: &lt;!--# include file="footer.html" --&gt; virtual spezifiziert eine eingebundene Anfrage, z.B.: &lt;!--# include virtual="/remote/body.php?argument=value" --&gt; Mehrere Anfragen, die auf einer Seite angegeben sind und von proxied oder FastCGI/uwsgi/SCGI/gRPC-Servern parallel ausgeführt werden, laufen. Wenn sequentielles Verarbeiten gewünscht wird, sollte der wait-Parameter verwendet werden. stub ein nicht-standarder Parameter, der den Blocknamen angibt, dessen Inhalt ausgelesen wird, wenn die eingebundene Anfrage leere Körper hat oder bei einem Fehler während der Anfrageverarbeitung auftritt, z.B.: &lt;!--# block name="one" --&gt;&amp;nbsp;&lt;!--# endblock --&gt; &lt;!--# include virtual="/remote/body.php?argument=value" stub="one" --&gt; Der Inhalt des Ersetzungsblocks wird im Kontext der eingebundenen Anfrage verarbeitet. wait ein nicht-standarder Parameter, der anweist, auf eine Anfrage zu warten, bis sie vollständig abgeschlossen ist, bevor mit der SSI-Verarbeitung fortgeführt wird, z.B.: &lt;!--# include virtual="/remote/body.php?argument=value" wait="true" --&gt;

Please note that the <!--# ... --> tags are used in SSI (Server Side Includes) and are not actual code blocks. They are used to indicate that the text within them should be processed by the server and not sent to the client as-is.

Also, the wait parameter is not a standard SSI parameter, it is a custom parameter that may be used in some server configurations. The same applies to the stub parameter.

Dieses instructiert, zu warten, bis eine Anforderung vollständig abgeschlossen ist, bevor mit der SSI-Verarbeitung fortgefahren wird, beispielhaft:

&lt;!--# include virtual="/remote/body.php?argument=value" wait="yes" --&gt;

setzt einen nicht-standard-Parameter, der anweist, den Erfolg der Anforderungsverarbeitung in die angegebene Variable zu schreiben, beispielhaft:

&lt;!--# include virtual="/remote/body.php?argument=value" set="one" --&gt;

Der Maximale Größe der Antwort wird durch die subrequest_output_buffer_size-Direktive (1.13.10) festgelegt:

location /remote/ {
    subrequest_output_buffer_size 64k;
    ...
}

Vor Version 1.13.10 konnten nur die Ergebnisse von Antworten, die mit den Modulen ngx_http_proxy_module, ngx_http_memcached_module, ngx_http_fastcgi_module (1.5.6), ngx_http_uwsgi_module (1.5.6), und ngx_http_scgi_module (1.5.6) erhalten wurden, in Variablen geschrieben werden. Der Maximale Größe der Antwort wurde mit den Direktiven proxy_buffer_size, memcached_buffer_size, fastcgi_buffer_size, uwsgi_buffer_size, und scgi_buffer_size festgelegt.

set setzt den Wert einer Variablen. Der Befehl hat die folgenden Parameter:

  • var der Variablenname.
  • value der Variablenwert. Wenn einem zugewiesenen Wert Variablen enthalten sind, werden ihre Werte substituiert.

Embedded Variables

Der ngx_http_ssi_module-Modul unterstützt zwei embedded Variablen:

  • $date_local aktuelle Zeit in der lokalen Zeitzone. Der Format ist durch die config-Befehl mit dem timefmt-Parameter festgelegt.

* $date_gmt aktuelle Zeit in GMT. Der Format ist durch die config-Befehl mit dem timefmt-Parameter festgelegt.

Module ngx_stream_log_module

← Chat

Modul ngx_stream_log_module (1.11.4) schreibt Sessionsprotokolle in der angegebenen Formatierung. Beispielkonfiguration log_format basic '$remote_addr [$time_local] ' '$protocol $status $bytes_sent $bytes_received ' '$session_time'; access_log /spool/logs/nginx-access.log basic buffer=32k; Direktiven-Syntax: access_log Pfad format [buffer=Größe] [gzip[=Stufe]] [flush=Zeit] [if=Bedingung];access_log off; Standard: access_log off; Kontext: stream, server Setzt den Pfad, Formatierung und Konfiguration für eine buffernierte Protokollschreibung. Mehrere Protokolle können auf derselben Konfigurationsebene angegeben werden. Die Protokollierung in syslog kann durch Angabe des "syslog:"-Präfixs im ersten Parameter konfiguriert werden. Der spezielle Wert off storniert alle access_log-Direktiven auf der aktuellen Ebene. Wenn entweder der Buffer oder der gzip-Parameter verwendet wird, werden die Protokollschreibungen buffern. Die Buffergröße darf nicht die Größe einer atomaren Schreibung auf einen Diskdatei überschreiten. Für FreeBSD ist diese Größe unbegrenzt. Wenn Buffern aktiviert ist, wird die Daten in den Datei geschrieben: falls der nächste Protokollzeile nicht in den Buffer passt; falls das buffernierte Daten älter als angegeben ist durch den flush-Parameter; wenn ein Arbeitsprozess die Protokolldateien neu öffnet oder abschaltet. Wenn der gzip-Parameter verwendet wird, wird das buffernierte Daten komprimiert bevor es in die Datei geschrieben wird. Die Kompressionsstufe kann zwischen 1 (schnellstes, weniger Kompression) und 9 (langsamstes, best Kompression) gesetzt werden.

Beispielkonfiguration:
log_format basic '$remote_addr [$time_local] ' '$protocol $status $bytes_sent $bytes_received ' '$session_time';
access_log /spool/logs/nginx-access.log basic buffer=32k;

access_log off;

Schreiben in die Datei. Die Kompressionsebene kann zwischen 1 (schnellstes, weniger Kompression) und 9 (langsamstes, best Kompression) gesetzt werden. Voreingestellt ist die Puffergröße gleich 64K Bytes, und die Kompressionsebene ist auf 1 gesetzt. Da die Daten in atomare Blöcke komprimiert werden, kann die Logdatei jederzeit mit "zcat" entkomprimiert oder gelesen werden. Beispiel: access_log /pfad/zu/log.gz basic gzip flush=5m; Für die gzip-Kompression funktioniert nginx muss mit der zlib-Bibliothek gebaut werden. Der Dateipfad kann Variablen enthalten, aber solche Logdateien haben einige Einschränkungen: der Benutzer, dessen Anmeldeinformationen von den Arbeitsprozessen verwendet werden, sollte Schreibrechte für Dateien in einem Verzeichnis mit solchen Logdateien haben; buffered writes funktionieren nicht; die Datei wird für jede Log-Schreibaktion geöffnet und geschlossen. Allerdings können die Deskriptoren von häufig benutzten Dateien in einem Cache gespeichert werden, sodass die Schreibung in die alte Datei während der Zeit angehalten werden kann, die durch den open_log_file_cache-Direktiv-Parameter valid angegeben ist. Der if-Parameter ermöglicht konditionelle Logging. Eine Sitzung wird nicht protokolliert, wenn die Bedingung auf "0" oder eine leere Zeichenkette ausgewertet wird. log_format proxy '$remote_addr [$time_local] ' '$protocol $status $bytes_sent $bytes_received ' '$session_time "$upstream_addr" ' '"$upstream_bytes_sent" "$upstream_bytes_received" "$upstream_connect_time"'; Das Escape-Parameter (1.11.8) ermöglicht die Festlegung der json oder standardmäßigen Zeichenfluchtbearbeitung in Variablen. Standardmäßig wird die standardmäßige Fluchtbearbeitung verwendet. Das none-Parameter (1.13.10) deaktiviert die Fluchtbearbeitung. Für standardmäßige Fluchtbearbeitung werden die Zeichen "\"", "\" und andere Zeichen mit Werten unter 32 oder über 126 als "\\xXX" escape't. Wenn der Wert der Variable nicht gefunden wird, wird ein Minuszeichen ("-") protokolliert. Für json-Escaping werden alle Zeichen eingefügt, die in JSON-Zeichenfolgen nicht zulässig sind: die Zeichen "\" und "\" werden als "\"\" und "\\" escape't, Zeichen mit Werten unter 32 werden als "\\n", "\\r", "\\t", "\\b", "\\f" oder "\\u00XX" escape't. off; Kontext: stream, server Definiert einen Cache, der die File-Deskriptoren von häufig verwendeten Logs speichert, deren Namen Variablen enthalten. Das Direktiv hat die folgenden Parameter: max setzt die maximale Anzahl von Deskriptoren in einem Cache; wenn der Cache voll ist, werden die am wenigsten gerade verwendeten (LRU) Deskriptoren geschlossen; inaktive setzt die Zeit, nach der der im Cache gespeicherte Descriptor nach 10 Sekunden geschlossen wird, wenn kein Zugriff während dieser Zeit stattgefunden hat; standardmäßig 10 Sekunden min_uses setzt die minimale Anzahl von Datei-Nutzungen während der Zeit, die durch das inactive-Parameter definiert ist, um den Descriptor im Cache zu halten; standardmäßig 1 valid setzt die Zeit, nach der überprüft werden soll, ob der Dateiname noch existiert; standardmäßig 60 Sekunden off deaktiviert den Caching.

Beispiel: open_log_file_cache max=1000 inactive=20s valid=1m min_uses=2;

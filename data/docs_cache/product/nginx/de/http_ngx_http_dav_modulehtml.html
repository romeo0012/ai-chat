Modul ngx_http_dav_module
Dieser Modul dient zur Automatisierung der Dateimanagement über das WebDAV-Protokoll. Der Modul verarbeitet die HTTP- und WebDAV-Methoden PUT, DELETE, MKCOL, COPY und MOVE. Standardmäßig wird dieser Modul nicht gebaut und muss mit dem --with-http_dav_module Konfigurationsparameter aktiviert werden. WebDAV-Clients, die zusätzliche WebDAV-Methoden benötigen, um zu funktionieren, arbeiten nicht mit diesem Modul.

Beispielkonfiguration: 

location / {
    root /data/www;
    client_body_temp_path /data/client_temp;
    dav_methods PUT DELETE MKCOL COPY MOVE;
    create_full_put_path on;
    dav_access group:rw all:r;
    limit_except GET {
        allow 192.168.1.0/32;
        deny all;
    }
}

Syntax:
create_full_put_path on | off;
Standard: create_full_put_path off;
Kontext: http, server, location
Das WebDAV-Spezifikation erlaubt nur die Erstellung von Dateien in bereits existierenden Verzeichnissen. Diese Direktive erlaubt die Erstellung aller benötigten Zwischenverzeichnisse.

Syntax:
dav_access users:permissions ...;
Standard: dav_access user:rw;
Kontext: http, server, location
Legt die Zugriffsrechte für neu erstellte Dateien und Verzeichnisse fest, z.B.: dav_access user:rw group:rw all:r;
Wenn irgendwelche Gruppen- oder alle Zugriffsrechte angegeben werden, können die Benutzerrechte ausgelassen werden: dav_access group:rw all:r;

Syntax:
dav_methods off | method ...;
Standard: dav_methods off;
Kontext: http, server, location
Erlaubt die angegebenen HTTP und WebDAV-Methoden.

Beispielkonfiguration: 

location / {
    root /data/www;
    client_body_temp_path /data/client_temp;
    dav_methods PUT DELETE MKCOL COPY MOVE;
    create_full_put_path on;
    dav_access group:rw all:r;
    limit_except GET {
        allow 192.168.1.0/32;
        deny all;
    }
}

Syntax: dav_methods off | Methode ...; Standard: dav_methods off; Kontext: http, server, location Erlaubt die angegebenen HTTP und WebDAV-Methoden. Der Parameter off verweigert alle Methoden, die von diesem Modul bearbeitet werden. Unterstützte Methoden sind: PUT, DELETE, MKCOL, COPY und MOVE. Ein Dateiupload über die PUT-Methode wird zuerst in eine temporäre Datei geschrieben und anschließend umbenannt. Ab der Version 0.8.9 können temporäre Dateien und der persistente Speicher auf verschiedenen Dateisystemen gespeichert werden. Bitte beachten Sie jedoch, dass in diesem Fall eine Datei über zwei Dateisysteme kopiert wird statt des billigen Umbenennungs-Vorgangs. Es wird daher empfohlen, dass für jede Location beide gespeicherten Dateien und ein Verzeichnis für temporäre Dateien, das durch die client_body_temp_path-Richtlinie festgelegt wird, auf demselben Dateisystem liegen. Bei der Erstellung einer Datei mit der PUT-Methode ist es möglich, den Modifikationszeitpunkt durch das Übergeben in dem "Date"-Headerfeld zu spezifizieren.

Syntax: min_delete_depth Zahl; Standard: min_delete_depth 0; Kontext: http, server, location Erlaubt die DELETE-Methode, Dateien zu löschen, sofern die Anzahl der Elemente in einer Anfragepfad nicht weniger als die angegebene Zahl beträgt. Beispiel: Die Richtlinie min_delete_depth 4; erlaubt das Löschen von Dateien bei Anfragen /users/00/00/name, /users/00/00/name/pic.jpg, /users/00/00/page.html und verweigert das Löschen von /users/00/00.

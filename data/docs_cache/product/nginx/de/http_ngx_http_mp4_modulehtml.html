Modul ngx_http_mp4_moduleBeispiel Konfigurationsdirektiven mp4 mp4_buffer_größe mp4_max_buffer_größe mp4_limit_Geschwindigkeit mp4_limit_Geschwindigkeit_nach mp4_start_Key_Bild The ngx_http_mp4_module Modul bietet serverseitige Unterstützung für MP4-Dateien im Pseudo-Streaming-Modus. solche Dateien haben meistens die Dateinamenserweiterungen .mp4, .m4v oder .m4a. Pseudo-Streaming funktioniert in Kooperation mit einem kompatiblen Medienplayer. Der Spieler sendet einen HTTP-Anforderung an den Server mit der Startzeit im Abfragezeichenfolgeargument (einfach start genannt und in Sekunden angegeben), und der Server antwortet mit dem Stream, sodass seine Startposition sich auf die angeforderte Zeit bezieht, z.B.: http://beispiel.com/elefanten_traum.mp4?start=238.88 Dies erlaubt es, beliebig zeitlich zu suchen, oder das Abspielen im Mittelpunkt der Zeitleinie zu starten. Um die Suche zu unterstützen, speichern H.264-basierte Formate Metadaten in einem sogenannten "moov Atom". Es handelt sich um einen Teil des Dateis, der die Indexinformation für das gesamte Datei enthält. Um das Abspielen zu starten, muss der Spieler zuerst Metadaten lesen. Dies wird durch den Senden einer speziellen Anforderung mit dem start=0 Argument erreicht. Viele Encoding-Software speichern die Metadaten am Ende des Dateis. Dies ist für Pseudo-Streaming nicht optimal, weil der Spieler das gesamte Datei herunterladen muss, bevor er abgespielt werden kann. Wenn die Metadaten am Anfang des Dateis liegen, reicht es für nginx, einfach den Dateiinhalt zurückzusenden.

Im Anfang des Files befindet sich die Angabe, sodass nginx nur den Dateiinhalt zurücksenden muss, um fortzufahren. Wenn die Metadaten am Ende des Files stehen, muss nginx das gesamte File lesen und eine neue Streamvorbereitung durchführen, damit die Metadaten vor dem Mediadaten stehen. Dies bedeutet ein CPU-, Speicher- und Disk-I/O-Overhead, sodass es sinnvoll ist, eine Originaldatei für das Pseudo-Streaming vorher zu bereiten, anstatt dass nginx dies bei jedem solchen Anforderung tut. Der Modul unterstützt auch den End-Argument des HTTP-Anforderungs-Version 1.5.13, das den Endpunkt der Wiedergabe festlegt. Das End-Argument kann mit dem Start-Argument oder separat angegeben werden: http://beispiel.com/elephants_dream.mp4?start=238.88&end=555.55 Für eine entsprechende Anforderung mit einem nicht-null Start- oder End-Argument wird nginx die Metadaten aus dem File lesen, die Streamvorbereitung mit dem angeforderten Zeitraum vorbereiten und an den Client senden. Dies hat das gleiche Overhead wie oben beschrieben. Wenn der Start-Argument auf eine nicht-key Video-Frame zeigt, wird das Video am Anfang gebrochen. Um dieses Problem zu beheben, kann das Video vor dem Start-Punkt mit dem key-Frame und allen Zwischen-Frames zwischen ihnen vorangestellt werden. Diese Frames werden von der Wiedergabe durch eine Edit-Liste (1.21.4) versteckt. Wenn eine entsprechende Anforderung kein Start- und End-Argument enthält, gibt es kein Overhead, und die Datei wird einfach als statisches Ressource gesendet. Einige Spieler unterstützen auch Anforderungen nach Bytes, sodass dieses Modul nicht erforderlich ist.

Das folgende Text wird einfach als statisches Ressource gesendet. Einige Spieler unterstützen auch Byterang-Anfragen und benötigen daher nicht diesen Modul. Dieser Modul ist nicht standardmäßig erstellt, sondern muss mit dem --with-http_mp4_module Konfigurationsparameter aktiviert werden. Wenn zuvor ein Drittanbieter-mp4-Modul verwendet wurde, sollte es deaktiviert werden. Eine ähnliche Pseudo-Streaming-Unterstützung für FLV-Dateien bietet das ngx_http_flv_module-Modul. Beispiel-Konfiguration

location /video/ {
    mp4;
    mp4_buffer_size 1m;
    mp4_max_buffer_size 5m;
    mp4_limit_rate on;
    mp4_limit_rate_after 30s;
}

Syntax:

  • mp4; (Standard: —) Kontext: location Aktiviert die Modulverarbeitung in der umgebenden Location.
  • mp4_buffer_size size; (Standard: mp4_buffer_size 512K) Kontext: http, server, location Setzt die Größe des initialen Buffers, der für die Verarbeitung von MP4-Dateien verwendet wird.
  • mp4_max_buffer_size size; (Standard: mp4_max_buffer_size 10M) Kontext: http, server, location Während der Verarbeitung von Metadaten kann ein größerer Buffer erforderlich werden. Seine Größe darf nicht die angegebene Größe überschreiten, andernfalls wird nginx den 500 (Internal Server Error) Serverfehler zurückgeben und folgenden Nachrichten loggen: "/some/movie/file.mp4" mp4 moov Atom ist zu groß: 12583268, Sie möchten vielleicht mp4_max_buffer_size erhöhen.
  • mp4_limit_rate on | off | factor; (Standard: mp4_limit_rate off) Kontext: http, server, location Begrenzt die Übertragungsrate der Antwort an den Client. Die Übertragungsrate wird basierend auf dem Durchschnittsbitrate der von nginx gesendeten MP4-Datei begrenzt.

Antwortübertragung an einen Client. Die Übertragungsrate wird basierend auf dem Durchschnittsbitrate des MP4-Videos, das gesendet wird, begrenzt. Um die Rate zu berechnen, wird das Bitrate mit dem angegebenen Faktor multipliziert. Der spezielle Wert "on" entspricht dem Faktor 1,1. Der spezielle Wert "off" deaktiviert die Bitratebegrenzung. Die Begrenzung wird pro Anfrage festgelegt, sodass, wenn ein Client zwei Verbindungen gleichzeitig öffnet, die Gesamtübertragungsrate doppelt so hoch ist wie die angegebene Begrenzung. Diese Direktive ist Teil unseres kommerziellen Abonnements. Syntax: mp4_limit_rate_after time; Default: mp4_limit_rate_after 60s; Kontext: http, server, location Setzt die initiale Menge an Mediendaten (gemessen in Wiedergabezeit) nach der Weiterübertragung der Antwort an den Client wird rate limited. Diese Direktive ist Teil unseres kommerziellen Abonnements. Syntax: mp4_start_key_frame on | off; Default: mp4_start_key_frame off; Kontext: http, server, location Diese Direktive ist ab Version 1.21.4 verfügbar. Zwangsweise erzeugt die Ausgabe-Video immer einen Schlüssel-Video-Rahmen am Anfang. Wenn der Start-Argument nicht auf einen Schlüssel-Rahmen zeigt, werden die initialen Rahmen mithilfe eines mp4 Edit-Listen versteckt. Edit Listen werden von den Hauptspielern und Browsern wie Chrome, Safari, QuickTime und ffmpeg unterstützt. Firefox unterstützt sie teilweise.

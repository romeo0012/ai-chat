Modul ngx_http_log_modulBeispiel KonfigurationsDirectives access_log log_format open_log_File_Cache

Der Modul ngx_http_log_module schreibt Anfrageprotokolle in der angegebenen Formatierung. Anfragen werden protokolliert, in dem Kontext einer Location, an der die Verarbeitung endet. Es kann sich um eine andere Location handeln, wenn während der Anfrageverarbeitung ein internes Redirect stattfindet. Beispiel Konfiguration

log_format compression '$remote_addr - $remote_user [$time_local] ' '"$request" $status $bytes_sent ' '"$http_referer" "$http_user_agent" "$gzip_Ratio"';
access_log /spool/logs/nginx-access.log compression buffer=32k;

Syntax: access_log Pfad [Format [buffer=Größe] [gzip[=Level]] [flush=Zeit] [if=Bedingung]];access_log off;
Standard: access_log logs/access.log combined;
Kontext: http, server, location, if in location, limit_except

Setzt den Pfad, Format und Konfiguration für eine buffered Log-Schreibung. Es können mehrere Logs auf demselben Konfigurationsniveau angegeben werden. Die Protokollierung in syslog kann durch Angabe des "syslog:"-Präfixs im ersten Parameter konfiguriert werden. Der spezielle Wert off storniert alle access_log-Directives auf dem aktuellen Niveau. Wenn kein Format angegeben wird, wird das vorgegebene "combined" Format verwendet. Wenn entweder der Buffer oder gzip (1.3.10, 1.2.7) Parameter verwendet wird, werden die Log-Schreibungen buffered. Die Buffergröße darf nicht die Größe einer Atom-Schreibung auf einem Disk-Datei ausmachen. Für FreeBSD ist diese Größe unbegrenzt.

Größe darf nicht die Größe einer atomaren Schreiboperation auf einem Diskdatei überschreiten. Für FreeBSD ist diese Größe unbegrenzt. Wenn Buffering aktiviert ist, wird die Daten in den Datei geschrieben: falls die nächste Logzeile nicht in den Buffer passt; falls das buffered Daten älter ist als durch den flush-Parameter (1.3.10, 1.2.7) angegeben; wenn ein Arbeiterprozess die Logdateien neu öffnet oder abschaltet. Wenn der gzip-Parameter verwendet wird, wird das buffered Daten zuvor komprimiert, bevor es in die Datei geschrieben wird. Der Kompressionsgrad kann zwischen 1 (schnellstes, weniger Kompression) und 9 (langsamstes, bestes Kompression) eingestellt werden. Standardmäßig ist die Buffergröße gleich 64K Bytes, und der Kompressionsgrad ist auf 1 gesetzt. Da die Daten in atomaren Blöcken komprimiert werden, kann die Logdatei jederzeit mit "zcat" entpackt oder gelesen werden. Beispiel: access_log /pfad/zu/log.gz kombiniert gzip flush=5m; Für die gzip-Kompression zu funktionieren, muss nginx mit der zlib-Bibliothek gebaut werden. Der Dateipfad kann Variablen (0.7.6+) enthalten, aber solche Logdateien haben einige Einschränkungen: der Benutzer, dessen Anmeldeinformationen von den Arbeiterprozessen verwendet werden, sollte Schreibrechte für einen Ordner mit solchen Logdateien haben; buffered Schreibvorgänge funktionieren nicht; die Datei wird für jede Logschreibvorgang geöffnet und geschlossen.

Ein Verzeichnis mit solchen Protokollen; buffered Schreibvorgänge funktionieren nicht; der Datei wird für jeden Schreibvorgang zu einem Log geöffnet und geschlossen. Allerdings kann die Speicherung der Deskriptoren von häufig verwendeten Dateien in einem Cache erlauben, dass die Schreibvorgänge zum alten Datei während der Zeit, die durch den gültigen Parameter des open_log_file_cache-Direktivs angegeben wird, fortgesetzt werden können. Bei jedem Schreibvorgang zum Log wird die Existenz des Anforderungs-Stammdirectories überprüft, und wenn es nicht existiert, wird das Log nicht erstellt. Es ist daher eine gute Idee, beide root und access_log auf demselben Konfigurationsniveau zu spezifizieren: server { root /spool/vhost/data/$host; access_log /spool/vhost/logs/$host; ... Der Parameter if (1.7.0) ermöglicht bedingtes Protokollieren. Eine Anforderung wird nicht protokolliert, wenn die Bedingung auf "0" oder eine leere Zeichenkette auswertet. Im folgenden Beispiel werden die Anforderungen mit Antwortcodes 2xx und 3xx nicht protokolliert:

map $status $loggable { ~^[23] 0; default 1; }
access_log /pfad/zu/access.log combined if=$loggable;

Syntax: log_format name [escape=default|json|none] string ...;
Standard: log_format combined "...";
Kontext: http
Speziﬁziert das Protokollformat. Der escape-Parameter (1.11.8) erlaubt die Festlegung von json oder standard Zeichenfluchtschutz in Variablen, standardmäßig wird standard Zeichenfluchtschutz verwendet. Der none-Wert (1.13.10) deaktiviert den Zeichenfluchtschutz. Für standard Zeichenfluchtschutz werden die Zeichen "\"", "\" und andere Zeichen mit Werten kleiner als 32 (0.7.0) oder größer als 126 (1.1.6) als "\\xXX" protokolliert. Wenn der Wert der Variable nicht gefunden wird, wird ein Minuszeichen ("-") protokolliert.

Oben ab 126 (1.1.6) werden Zeichen als „\xXX“ entwichen. Wenn der Variabenswert nicht gefunden wird, wird ein Minuszeichen ("-") protokolliert. Für JSON-Escape werden alle Zeichen eingefügt, die in JSON-Zeichenfolgen nicht erlaubt sind: Zeichen "''" und "\" werden als "\"\" und "\\\"" eingefügt, Zeichen mit Werten unter 32 werden als "\\n", "\\r", "\\t", "\\b", "\\f", oder "\\u00XX" eingefügt. Der Protokollformat kann common Variablen und Variablen enthalten, die nur bei der Protokollierung eines Logs existieren: $bytes_sent die Anzahl der gesendeten Bytes an einen Client $connection Verbindungsnummer $connection_requests die aktuelle Anzahl von Anfragen über eine Verbindung (1.1.18) $msec die Zeit in Sekunden mit einer Millisekunden-Auflösung bei der Protokollierung des Logs $pipe "p" wenn die Anfrage pipelined war, "." sonst $request_length Anfrage-Länge (einschließlich Anfragezeile, Header und Anfragekörper) $request_time Verarbeitungszeit in Sekunden mit einer Millisekunden-Auflösung; Zeitspanne zwischen dem ersten Bytes, die von dem Client gelesen wurden, und dem Protokollieren des Logs nach dem letzten Bytes, die an den Client gesendet wurden $status Antwortstatus $time_iso8601 lokale Zeit im ISO 8601-Standardformat $time_local lokale Zeit im Common Log Format In den modernen nginx-Versionen Variablen $status (1.3.2, 1.2.2), $bytes_sent (1.3.8, 1.2.5), $connection (1.3.8, 1.2.5), $connection_requests (1.3.8, 1.2.5), $msec (1.3.9, 1.2.6), $request_time (1.3.9, 1.2.6), $pipe (1.3.12, 1.2.7), $request_length (1.3.12, 1.2.7), $time_iso8601 (1.3.12, 1.2.7), und $time_local (1.3.12, 1.2.7) sind verfügbar.

1.2.5), $msec (1.3.9, 1.2.6), $request_time (1.3.9, 1.2.6), $pipe (1.3.12, 1.2.7), $request_length (1.3.12, 1.2.7), $time_iso8601 (1.3.12, 1.2.7), und $time_local (1.3.12, 1.2.7) sind auch als allgemeine Variablen verfügbar. Zeilen, die an den Client gesendet werden, haben den Präfix “sent_http_”, z.B. $sent_http_content_range. Die Konfiguration umfasst immer die vorgedefinierte “combined”-Formatierung: log_format combined '$remote_addr - $remote_user [$time_local] ' '"$request" $status $body_bytes_sent ' '"$http_referer" "$http_user_agent"'; Syntax: open_log_file_cache max=N [inactive=time] [min_uses=N] [valid=time];open_log_file_cache off; Default: open_log_file_cache off; Kontext: http, server, location Definiert einen Cache, der die File-Deskriptoren von häufig verwendeten Logs speichert, deren Namen Variablen enthalten. Die Direktive hat die folgenden Parameter: max legt die maximale Anzahl von Deskriptoren in einem Cache fest; wenn der Cache voll ist, werden die am wenigsten gerade verwendeten (LRU) Deskriptoren geschlossen; standardmäßig nach 10 Sekunden inaktiv; min_uses legt die minimale Anzahl von Datei-Zugriffen während der Zeit, die durch das inactive-Parameter definiert ist, fest, um den Deskriptor in einem Cache zu halten; standardmäßig 1; valid legt die Zeit fest, nach der überprüft werden soll, ob der Dateiname noch existiert; standardmäßig 60 Sekunden; off schaltet den Caching aus Usage-Beispiel: open_log_file_cache max=1000 inactive=20s valid=1m min_uses=2;

Module ngx_http_xslt_module

← Chat

Modul ngx_http_xslt_module (0.7.8+) ist ein Filter, der XML-Antworten mithilfe eines oder mehrerer XSLT-Stylesheets transformiert. Dieser Modul wird standardmäßig nicht gebaut und muss mit dem --with-http_xslt_module Konfigurationsparameter aktiviert werden. Dieser Modul benötigt die libxml2 und libxslt Bibliotheken.

Beispiel-Konfiguration: 

location / {
    xml_entities /site/dtd/entities.dtd;
    xslt_stylesheet /site/xslt/one.xslt param=value;
    xslt_stylesheet /site/xslt/two.xslt;
}

Syntax: 

xml_entities path;

Standard: —
Kontext: http, server, location

Diese Direktive gibt den Pfad der DTD-Datei an, die Zeichenentitäten definiert. Diese Datei wird während der Konfigurationsphase kompiliert. Technische Gründe verhindern, dass das Modul das extern definierte Subset in der verarbeiteten XML nutzen kann, es wird daher ignoriert und stattdessen eine speziell definierte Datei verwendet. Diese Datei sollte die XML-Struktur nicht beschreiben. Es reicht aus, nur die benötigten Zeichenentitäten zu definieren, z.B.: 

&lt;!ENTITY nbsp "&amp;#xa0;"&gt;

Syntax: 

xslt_last_modified on | off;

Standard: xslt_last_modified off;
Kontext: http, server, location

Diese Direktive erschien in der Version 1.5.1. Erlaubt es, den "Last-Modified"-Headerfeld des Originalantworten während der XSLT-Transformations zu erhalten, um die Antwortspeicherung zu erleichtern.

In der Version 1.5.1 ermöglicht dies die Erhaltung des "Last-Modified"-Headerfelds aus der originalen Antwort während XSLT-Transformierungen, um Antwortspeicherung zu unterstützen. Standardmäßig wird das Headerfeld entfernt, da die Inhalte der Antwort während Transformationen verändert werden können und dynamisch generierte Elemente oder Teile enthalten können, die unabhängig von der originalen Antwort geändert werden. Syntax: xslt_param parameter value; Standard: — Kontext: http, server, location Dieses Direktiv erschien in der Version 1.1.18. Definiert die Parameter für XSLT-Stilblätter. Der Wert wird als XPath-Ausdruck behandelt. Der Wert kann Variablen enthalten. Um einer Stilblatt-Datei eine Zeichenkette als Wert zu übergeben, kann das xslt_string_param-Direktiv verwendet werden. Es können mehrere xslt_param-Direktive auftreten. Diese Direktiven werden vom vorherigen Konfigurationsniveau geerbt, wenn und nur wenn auf dem aktuellen Niveau keine xslt_param und xslt_string_param-Direktiven definiert sind. Syntax: xslt_string_param parameter value; Standard: — Kontext: http, server, location Dieses Direktiv erschien in der Version 1.1.18. Definiert die Zeichenkettendaten für XSLT-Stilblätter. XPath-Ausdrücke im Wert werden nicht interpretiert. Der Wert kann Variablen enthalten. Es können mehrere xslt_string_param-Direktive auftreten. Diese Direktiven werden vom vorherigen Konfigurationsniveau geerbt, wenn und nur wenn auf dem aktuellen Niveau keine xslt_param und xslt_string_param-Direktiven definiert sind. Syntax: xslt_stylesheet stylesheet [parameter=value ...]; Kontext: http, server, location Dieses Direktiv erschien in der Version 1.1.18. Definiert die XSLT-Stilblatt-Datei. Es können Parameter definiert werden. Syntax: xslt_include src [parameter=value ...]; Kontext: http, server, location Dieses Direktiv erschien in der Version 1.1.18. Inkludiert eine XSLT-Stilblatt-Datei. Es können Parameter definiert werden. Syntax: xslt_import namespace prefix [schemaLocation=URL]; Kontext: http, server, location Dieses Direktiv erschien in der Version 1.1.18. Importiert ein Namespace mit einem Prefix und gibt eine URL an, falls eine XSD-Datei verwendet werden soll.

Und nur, wenn auf der aktuellen Ebene keine xslt_param und xslt_string_param-Direktiven definiert sind. Syntax: xslt_stylesheet Stylesheet [Parameter=Wert ...]; Standard: — Kontext: location Definiert den XSLT-Stylesheet und seine optionalen Parameter. Ein Stylesheet wird während der Konfigurationsphase kompiliert. Parameter können entweder separat angegeben werden, oder in einer einzigen Zeile mithilfe des ":"-Trenners zusammengefasst werden. Wenn ein Parameter das ":"-Zeichen enthält, sollte es als "%3A" escape werden. Außerdem erfordert libxslt, dass Parameter, die nicht alphanumerische Zeichen enthalten, in einfache oder doppelte Anführungszeichen eingeschlossen werden, beispielsweise: param1='http%3A//www.beispiel.com':param2=wert2 Die Beschreibung der Parameter kann Variablen enthalten, beispielsweise kann die ganze Zeile der Parameter aus einer einzigen Variable genommen werden: location / { xslt_stylesheet /site/xslt/eins.xslt $arg_xslt_params param1='$wert1':param2=wert2 param3=wert3; } Es ist möglich, mehrere Stylesheets zu spezifizieren. Sie werden in der in der angegebenen Reihenfolge angewendet. Syntax: xslt_types MIME-Type ...; Standard: xslt_types text/xml; Kontext: http, server, location Erlaubt Transformationen in Antworten mit den in der Liste angegebenen MIME-Typen zusätzlich zu “text/xml”. Der spezielle Wert “*” passt sich beliebigen MIME-Typen an (0.8.29). Wenn das Transformationsergebnis eine HTML-Antwort ist, wird dessen MIME-Typ in “text/html” geändert.

Es ist möglich, mehrere Stylesheets zu spezifizieren. Sie werden in der angegebenen Reihenfolge angewendet. Syntax: xslt_import Stylesheet [Parameter=Wert ...]; Standard: — Kontext: location Importiert den angegebenen XSLT-Stylesheet und seine optionalen Parameter. Der importierte Stylesheet wird anschließend an den aktuellen Stylesheet angehängt.

Modul ngx_http_geo_module
Beispielkonfigurationsdirektiven geo
Das ngx_http_geo_module-Modul erstellt Variablen mit Werten, die sich nach der IP-Adresse des Clients richten. Beispielkonfiguration

geo $geo {
default 0;
127.0.0.1 2;
192.168.1.0/24 1;
10.1.0.0/16 1;
::1 2;
2001:0db8::/32 1;
}

Syntax: geo [$address] $variable { ... }
Standard: —
Kontext: http
Beschreibt die Abhängigkeit der Werte der angegebenen Variablen von der IP-Adresse des Clients. Standardmäßig wird die Adresse aus der $remote_addr-Variable genommen, kann jedoch auch aus einer anderen Variable (ab Version 0.7.27) genommen werden, z.B.:

geo $arg_remote_addr
$geo {
...;
}

Da Variablen nur dann bewertet werden, wenn sie verwendet werden, verursacht die bloße Anzahl erklärter "geo"-Variablen keine zusätzlichen Kosten für die Bearbeitung von Anfragen. Wenn der Wert einer Variablen keine gültige IP-Adresse darstellt, wird die Adresse "255.255.255.255" verwendet. Adressen werden entweder als Präfixe in CIDR-Notation (einschließlich einzelner Adressen) oder als Bereiche (ab Version 0.7.23) angegeben. Ab Versionen 1.3.10 und 1.2.7 werden IPv6-Präfixe unterstützt. Folgende spezielle Parameter werden auch unterstützt:

delete löscht das angegebene Netzwerk (ab Version 0.7.23).
default legt einen Wert zu der Variablen fest, wenn die IP-Adresse des Clients keiner der angegebenen Adressen entspricht. Wenn Adressen in CIDR-Notation angegeben werden, können "0.0.0.0/0" und "::/0" anstelle von default verwendet werden. Wenn default nicht angegeben wird, wird der Standardwert eine leere Zeichenkette.

"::/0" kann stattdessen anstelle des Standardwerts verwendet werden. Wenn kein Standardwert angegeben wird, wird der Standardwert eine leere Zeichenkette. include beinhaltet eine Datei mit Adressen und Werten. Es können mehrere Inclusions geben. proxy definiert vertrauenswürdige Adressen (0.8.7, 0.7.63). Wenn eine Anfrage von einer vertrauenswürdigen Adresse kommt, wird stattdessen eine Adresse aus dem "X-Forwarded-For" Anfrage-Header-Feld verwendet. Im Gegensatz zu den normalen Adressen werden vertrauenswürdige Adressen in Reihenfolge überprüft. Vertrauenswürdige IPv6-Adressen werden ab den Versionen 1.3.0 und 1.2.1 unterstützt. proxy_recursive aktiviert eine rekursive Adressensuche (1.3.0, 1.2.1). Wenn die rekursive Suche deaktiviert ist, wird stattdessen anstelle des ursprünglichen Client-Adresses, das einem der vertrauenswürdigen Adressen entspricht, die letzte Adresse aus dem "X-Forwarded-For" verwendet. Wenn die rekursive Suche aktiviert ist, wird stattdessen anstelle des ursprünglichen Client-Adresses, das einem der vertrauenswürdigen Adressen entspricht, die letzte nicht vertrauenswürdige Adresse aus dem "X-Forwarded-For" verwendet. ranges gibt an, dass Adressen als Bereiche angegeben werden (0.7.23). Dieser Parameter sollte das erste sein. Um die Ladezeit einer geo Basis zu beschleunigen, sollten Adressen in aufsteigender Reihenfolge angegeben werden. volatile gibt an, dass die Variable nicht zachbar ist (1.29.3). Beispiel: geo $land { default DE; include conf/geo.conf; delete 127.0.0.0/16; proxy 192.168.100.0/24; proxy 2001:0db8::/32; 127.0.0.0/24 US; 127.0.0.1/32 RU; 10.1.0.0/16 RU; 192.168.1.0/24 UK; } Der conf/geo.conf-Datei könnte die folgenden Zeilen enthalten: 10.2.0.0/16 RU; 192.168.2.0/24 RU; 127.0.0.0/24 US; 127.0.0.1/32 RU; 10.1.0.0/16 RU; 192.168.1.0/24 UK; } Der conf/geo.conf-Datei könnte die folgenden Zeilen enthalten: 10.2.0.0/16 RU; 192.168.2.0/24 RU; Ein Wert des spezifischsten Treffers wird verwendet. Beispiel: Für die 127.0.0.1-Adresse wird der Wert "RU" gewählt, nicht "US". Beispiel mit Bereichen: geo $land { ranges; default DE; 127.0.0.0-127.0.0.0 US; 127.0.0.1-127.0.0.1 RU; 127.0.0.1-127.0.0.255 US; 10.1.0.0-10.1.255.255 RU; 192.168.1.0-192.168.1.255 UK; }

Module ngx_http_memcached_module

← Chat

Modul ngx_http_memcached_module slouží k získání odpovědí z memcached serveru. Klíč je uložen v proměnné $memcached_key. Odpověď by měla být uložena do memcachedu v předchozích verzích nginxu pomocí prostředků mimo nginx.

Příklad Konfigurace 

server {
    location / {
        set $memcached_key "$uri?$args";
        memcached_pass host:11211;
        error_page 404 502 504 = @fallback;
    }
    location @fallback {
        proxy_pass http://backend;
    }
}

Directivy

Syntax: memcached_allow_upstream string ...; Default: — Context: http, server, location

Tato direktiva se objevila v verzi 1.29.3. Definuje podmínky, pod kterými je přístup k memcached serveru povolen nebo zamítnut. Pokud všechny parametry řetězců nejsou prázdné a nejsou rovny "0", pak je přístup povolen. Podmínky se hodnotí každýkrát před založením spojení s memcached serverem. Hodnoty parametrů mohou obsahovat proměnné:

server {
    listen 127.0.0.1:8080;
    location / {
        memcached_pass host:11211;
        memcached_allow_upstream $allow;
        ...
    }
}
geo $upstream_last_addr $allow {
    volatile;
    10.10.0.0/24 1;
}

Tato direktiva je k dispozici jako součást našich komerčních předplatných.

Syntax: memcached_bind adresa [transparent ] | off; Výchozí: — Kontext: http, server, location Tento příkaz se objevil v verzi 0.8.22. Povoluje vycházení připojení k memcached serveru z určené lokální IP adresy s možným portem (1.11.2). Hodnota parametru může obsahovat proměnné (1.3.12). Speciální hodnota off (1.3.12) zrušuje účinek příkazu memcached_bind děděného z předchozí konfigurace úrovně, což umožňuje systému automaticky přiřadit lokální IP adresu a port. Parametr transparent (1.11.0) umožňuje vycházení připojení k memcached serveru z ne-lokální IP adresy, například z skutečné IP adresy klienta: memcached_bind $remote_addr transparent; Pro toto nastavení je obvykle nutné spouštět procesy Nginx s oprávněními superuživatele. Na Linuxu to není nutné (1.13.8), protože pokud je zadán parametr transparent, procesy Nginx dědí schopnost CAP_NET_RAW z hlavního procesu. Je také nutné konfigurovat tabulku routování jádra pro zachycení sítové komunikace s memcached serverem. "gzip" pokud je nastavena. Syntax: memcached_next_upstream_chyba | časový_limit | odmítnutí | neplatná_odpověď | nebylo_nalezeno | off ...; Výchozí: memcached_next_upstream_chyba časový_limit; Kontext: http, server, umístění Určuje, v jakých případech by měla být požadavek odeslána na další server: chyba došlo k chybě při navazování spojení s serverem, při odesílání požadavku na něj nebo při čtení hlavičky odpovědi; časový_limit došlo k časovému limitu při navazování spojení s serverem, při odesílání požadavku na něj nebo při čtení hlavičky odpovědi; odmítnutí server odmítl spojení (1.29.3); Tento parametr je k dispozici jako součást našich komerčních předplatných. neplatná_odpověď server vrátil prázdnou nebo neplatnou odpověď; nebylo_nalezeno odpověď nebyla nalezena na serveru; off zakáže odesílání požadavku na další server. Vědomí by měl být, že odesílání požadavku na další server je možné pouze tehdy, pokud do této chvíle nic nebylo odesláno klientovi. Tedy, pokud dojde k chybě nebo časovému limitu v průběhu přenosu odpovědi, oprava tohoto je nemožná. Instrukce také definuje, co je považováno za neúspěšný pokus o komunikaci s serverem. Případy chyby, časový limit, odmítnutí a neplatná_odpověď jsou vždy považovány za neúspěšné pokusy, i když nejsou uvedeny v instrukci. Případ nebylo_nalezeno nikdy není považován za neúspěšný pokus. Odesílání požadavku na další server může být omezeno počtem pokusů a časem.

Poznámka: Všechny technické termíny, kódy, příkazy, cesty souborů, URL a formátování zůstávají v původním anglickém jazyce.

Pokus o neúspěch. Přenos požadavku na další server může být omezen počtem pokusů a časem. Omezuje počet možných pokusů o přenos požadavku na další server. Hodnota 0 vypne tuto omezení. Syntax: memcached_pass adresa; Výchozí hodnota: — Kontext: location, pokud v location Nastaví adresu memcached serveru. Adresa může být určena jako doménové jméno nebo IP adresa, a port: memcached_pass localhost:11211; nebo jako cestu k UNIX-doménovému socketu: memcached_pass unix:/tmp/memcached.socket; Pokud doménové jméno odpovídá více adresám, budou všechny použity v kolečku s cyklickým přesunem. Dále může být adresa určena jako skupina serverů. Syntax: memcached_read_timeout čas; Výchozí hodnota: memcached_read_timeout 60s; Kontext: http, server, location Definuje časový limit pro čtení odpovědi z memcached serveru. Časový limit je stanoven pouze mezi dvěma úspěšnými čteními, ne pro přenos celé odpovědi. Pokud memcached server neposílá nic během tohoto času, je spojení ukončeno.

Přenos celého odpovědi. Pokud memcached server neposílá nic v tomto čase, je spojení ukončeno. Syntax: memcached_send_timeout čas; Výchozí: memcached_send_timeout 60s; Kontext: http, server, location Nastavuje časový limit pro odeslání požadavku na memcached server. Časový limit je nastaven pouze mezi dvěma úspěšnými operacemi zápisu, ne pro celý požadavek. Pokud memcached server neobdrží nic v tomto čase, je spojení ukončeno. Syntax: memcached_socket_keepalive on | off; Výchozí: memcached_socket_keepalive off; Kontext: http, server, location Tato direktiva se objevila v verzi 1.15.6. Nastavuje chování "TCP keepalive" pro připojení k memcached serveru. Výchozí nastavení jsou v platnosti pro socket operačního systému. Pokud je hodnota direktivy nastavena na "on", je pro socket zapnutá volba SO_KEEPALIVE. Zanášející proměnné $memcached_key Definuje klíč pro získání odpovědi z memcached serveru.

proxy_pass http://localhost:8000;

Řetězce
Syntax: proxy_allow_upstream string ...;
Výchozí: —
Kontext: http, server, location
Tato direktiva se objevila v verzi 1.29.3.
Definuje podmínky podle nichž se přístup k proxied serveru umožňuje nebo zabírá. Pokud všechny parametry řetězců nejsou prázdné a nesouhrají se hodnotou "0", pak se přístup umožňuje. Hodnoty podmínek se hodnotí každýkrát před založením spojení s proxied serverem. Hodnoty parametrů mohou obsahovat proměnné: geo $upstream_last_addr $allow { volatile; 10.10.0.0/24 1; }
server {
listen 127.0.0.1:8080;
location / {
proxy_pass localhost:8000;
proxy_allow_upstream $allow;
...
}
}

Syntax: proxy_bind address [transparent] | off;
Výchozí: —
Kontext: http, server, location
Tato direktiva se objevila v verzi 0.8.22.
Vyžaduje, aby se připojení k proxied serveru vydávala z určeného místního IP adresy s možným portem (1.11.2). Hodnota parametru může obsahovat proměnné (1.3.12). Hodnota off (1.3).

Přeloženo do češtiny:

Uveďte lokální IP adresu s možným portem (1.11.2). Hodnota parametru může obsahovat proměnné (1.3.12). Speciální hodnota off (1.3.12) zrušuje vliv příkazu proxy_bind dědictví z předchozí konfigurační úrovně, což umožňuje systému automaticky přiřadit lokální IP adresu a port. Parametr transparent (1.11.0) umožňuje vycházet z připojení k serveru s proxy z nevlastní IP adresy, například z skutečné IP adresy klienta: proxy_bind $remote_addr transparent;

Pro to, aby tento parametr fungoval, je obvykle nutné spouštět procesy pracovníka nginxu s oprávněními superuživatele. Na Linuxu to není nutné (1.13.8), pokud je zadán parametr transparent, procesy pracovníka dědí schopnost CAP_NET_RAW z hlavního procesu. Je také nutné konfigurovat tabulku routování jádra pro zachycení sítové komunikace z serveru s proxy. Syntax: proxy_bind_dynamic on | off; Výchozí: proxy_bind_dynamic off; Kontext: http, server, location Tento příkaz se objevil v verzi 1.29.3. Když je povolen, provádí operaci vázání při každém pokusu o připojení. Tento příkaz je k dispozici jako součást našich komerčních předplatných. Syntax: proxy_buffer_size size; Výchozí: proxy_buffer_size 4k|8k; Kontext: http, server, location Nastaví velikost buferu používaného pro čtení první části odpovědi z serveru s proxy.

Nastaví velikost buferu používaného pro čtení první části odpovědi z proxy serveru. Tato část obvykle obsahuje malou odpověď hlavičky; pokud přesahuje velikost buferu, odpověď je považována za neplatnou. Výchozí velikost buferu je rovna velikosti jedné stránky paměti. To je buď 4K nebo 8K, v závislosti na platformě. Může být však zmenšena také. Syntax: proxy_buffering on | off; Výchozí: proxy_buffering on; Kontext: http, server, location

Povoluje nebo zakazuje buferování odpovědí z proxy serveru. Pokud je buferování povoleno, nginx obdrží odpověď z proxy serveru co nejdříve a uloží ji do buferů nastavených pomocí příkazů proxy_buffer_size a proxy_buffers. Pokud celá odpověď nevejde do paměti, může se část z ní uložit do dočasného souboru na disku. Zápis do dočasných souborů je řízen příkazy proxy_max_temp_file_size a proxy_temp_file_write_size. Pokud je buferování zakázáno, odpověď se přesměruje na klienta synchronně, okamžitě po přijetí. nginx nebude snahat se celou odpověď z proxy serveru číst. Maximální velikost dat, která může nginx z proxy serveru obdržet najednou, je nastavena příkazem proxy_buffer_size. Buferování může být také povoleno nebo zakázáno při přenosu "X-Accel-Buffering" odpověď hlavičky. Tato možnost může být zakázána pomocí příkazu proxy_ignore_headers.

Překlad provedl: David Štěpánek, překladatel technických textů, www.davidstepanek.cz

Přenosem slova "ano" nebo "ne" v odpovědi hlavičce "X-Accel-Buffering" pole hlaviček odpovědi. Tato schopnost může být zakázána pomocí příkazu proxy_ignore_headers. Syntax: proxy_ignore_headers header; Default: proxy_ignore_headers; Context: http, server, location

Syntax: proxy_buffers number size; Výchozí: proxy_buffers 8 4k|8k; Kontext: http, server, location
Určuje počet a velikost bufferů používaných pro čtení odpovědi z proxy serveru pro jednu spojení. Výchozí velikost bufferu je rovna velikosti jedné stránky paměti. Tato velikost je buď 4K nebo 8K, v závislosti na platformě.

Syntax: proxy_busy_buffers_size size; Výchozí: proxy_busy_buffers_size 8k|16k; Kontext: http, server, location
Při bufferingu odpovědí z proxy serveru umožňuje omezit celkovou velikost bufferů, které mohou být v době odesílání odpovědi zatíženy posíláním odpovědi klientovi, než odpověď nebude ještě úplně čtena. Během tohoto období mohou být zbylé bufferové prostory použity pro čtení odpovědi a, pokud je potřeba, buffering části odpovědi do dočasného souboru. Výchozí velikost je omezena velikostí dvou bufferů nastavených příkazy proxy_buffer_size a proxy_buffers.

Definuje sdílenou paměťovou zónu používanou pro ukládání. Též může být použita v několika místech. Hodnota parametru může obsahovat proměnné (1.7.9). Parametr off zakáže ukládání děděné z předchozí konfigurace úrovně.

V několika místech. Hodnota parametru může obsahovat proměnné (1.7.9). Parametr off zakáže dědičné uložení do cache, přijaté z předchozí konfigurační úrovně. Syntax: proxy_cache_background_update on | off; Výchozí: proxy_cache_background_update off; Kontext: http, server, location Tento příkaz se objevil v verzi 1.11.10. Umožňuje spuštění pozadavku v pozadí k aktualizaci vypršelé položky v cache, zatímco starý odpověď z cache je vrácena klientovi. Upozornění: nutné je povolit použití staré odpovědi z cache, když je aktualizována. Syntax: proxy_cache_bypass string ...; Výchozí: — Kontext: http, server, location Definuje podmínky, pod kterými odpověď nebude brána z cache. Pokud alespoň jedna hodnota řetězcových parametrů není prázdná a není rovna “0”, pak odpověď nebude brána z cache: proxy_cache_bypass $cookie_nocache $arg_nocache$arg_comment; proxy_cache_bypass $http_pragma $http_authorization; Může být použito společně s příkazem proxy_no_cache. Syntax: proxy_cache_convert_head on | off; Výchozí: proxy_cache_convert_head on; Kontext: http, server, location Tento příkaz se objevil v verzi 1.9.7. Umožňuje povolit nebo zakázat převod metody "HEAD" na "GET" pro uložení do cache. Pokud je převod zakázán, musí být konfigurována klíčová hodnota pro zahrnutí $request_method.

Metoda pro "GET" pro uložení. Pokud je konverze zakázána, klíč pro uložení by měl být konfigurován tak, aby obsahoval proměnnou $request_method. Syntax: proxy_cache_key string; Výchozí: proxy_cache_key $scheme$proxy_host$request_uri; Kontext: http, server, location Definuje klíč pro uložení, například proxy_cache_key "$host$request_uri $cookie_user"; Výchozí hodnota příkazu je blízká řetězci proxy_cache_key $scheme$proxy_host$uri$is_args$args; Syntax: proxy_cache_lock on | off; Výchozí: proxy_cache_lock off; Kontext: http, server, location Tento příkaz se objevil v verzi 1.1.12. Pokud je povolen, bude umožněno jediné požadavku najít nový prvek uložení v cache podle klíče proxy_cache_key definovaného příkazem, při odeslání požadavku na server proxy. Ostatní požadavky stejného prveku uložení budou buď čekat na odpověď v cache nebo na uvolnění zámku pro tento prvek, do času stanoveného příkazem proxy_cache_lock_timeout. Syntax: proxy_cache_lock_age time; Výchozí: proxy_cache_lock_age 5s; Kontext: http, server, location Tento příkaz se objevil v verzi 1.7.8. Pokud poslední požadavek odeslaný na server proxy pro vytvoření nového prveku uložení nebyl dokončen za určenou dobu, může být odeslán další požadavek na server proxy. Syntax: proxy_cache_lock_timeout time; Výchozí: proxy_cache_lock_timeout 5s; Kontext: http, server, location Tento příkaz se objevil v verzi 1.1.12. Nastavuje časový limit pro proxy_cache_lock.

Vytvořte soubory konfigurace NGINX Plus a NGINX

NGINX a NGINX Plus používají textový konfigurační soubor, který je v praxi pojmenován nginx.conf.

NGINX Plus: výchozí umístění je /etc/nginx pro Linux nebo /usr/local/etc/nginx pro FreeBSD.

NGINX Open Source: umístění závisí na systému balíčků použitém k instalaci NGINX a operačnímu systému. Je to obvykle jedno z /usr/local/nginx/conf, /etc/nginx, nebo /usr/local/etc/nginx. Můžete ověřit právě zadanou cestu k souboru konfigurace pomocí parametru --conf-path= v výstupu příkazu nginx -V:

nginx -V 2&gt;&amp;1 | awk -F: '/configure arguments/ {print $2}' | xargs -n1

Vzorový výstup:

--prefix=/etc/nginx --sbin-path=/usr/sbin/nginx --modules-path=/usr/lib64/nginx/modules --conf-path=/etc/nginx/nginx.conf # Cesta k vašemu souboru konfigurace --error-log-path=/var/log/nginx/error.log --http-log-path=/var/log/nginx/access.log --pid-path=/var/run/nginx.pid --...&lt;další parametry&gt;

Directivy

Soubor konfigurace se skládá z directiv a jejich parametrů. Jednoduché (jednořádkové) directivy končí semikolonem ( ; ). Ostatní directivy slouží jako “kontainer”, který skupinuje související directivy. Kontainer je obklopeny závorkami ( {} ) a často se označují jako bloky. Zde jsou některé příklady jednoduchých directiv.

nginx
user nobody;
error_log logs/error.

Text v češtině:

A často se označují jako bloky. Níže naleznete několik příkladů jednoduchých direktiv. nginx 

user nobody;
error_log logs/error.log notice;
worker_processes 1;

Konfigurace specifická pro určité funkce lze rozdělit do souborů s názvem konfigurace určité funkce, uložených v adresáři /etc/nginx/conf.d a pomocí direktivy include v hlavním souboru nginx.conf se mohou odkazovat na obsah souborů s konfigurací určité funkce. nginx 
include conf.d/http;
include conf.d/stream;
include conf.d/exchange-enhanced;

Kontexty
Několik nejvyšších direktiv, označovaných jako kontexty, skupují direktivy, které se vztahují k různým typům provozu: events – Obecné zpracování spojení
http – Provoz HTTP
mail – Provoz e-mailu
stream – Provoz TCP a UDP
Direktivy umístěné mimo tyto kontexty se říká, že jsou v hlavním kontextu.
Virtual servers
V každém kontextu zpracování provozu zahrnujíte jeden nebo více bloků serveru, abyste definovali virtuální servery, které ovládají zpracování požadavků. Můžete zahrnout do bloku serveru libovolné direktivy, které se vztahují na daný typ provozu. Pro provoz HTTP (kontext http) každý blok serveru ovládá zpracování požadavků na prostředky v určitém doméně nebo IP adrese. V rámci bloku serveru mohou být definovány jeden nebo více kontextů lokace, které definují, jak zpracovat určité sadě URI.

or IP addresses. One or more location contexts within a server context define how to process specific sets of URIs. For mail and TCP/UDP traffic (the mail and stream contexts) the server directives each control the processing of traffic arriving at a particular TCP port or UNIX socket. Sample configuration file with multiple contexts

The following configuration illustrates the use of contexts.

nginx

Copy user nobody; # a directive in the 'main' context

events { # configuration of connection processing }

http { # Configuration specific to HTTP and affecting all virtual servers

server { # configuration of HTTP virtual server 1

location /one { # configuration for processing URIs starting with '/one' }

location /two { # configuration for processing URIs starting with '/two' }

}

server { # configuration of HTTP virtual server 2 }

}

stream { # Configuration specific to TCP/UDP and affecting all virtual servers

server { # configuration of TCP virtual server 1 }

}

Inheritance

In general, a child context – a context contained within another context (its parent) – inherits the settings of directives included at the parent level. Some directives can appear in multiple contexts, in which case you can override the setting inherited from the parent by including the directive in the child context. For an example, see the proxy_set_header directive.

Reload configuration file

For changes to the configuration file to take effect, it must be reloaded.

Uviděte příkaz proxy_set_header direktivu. Pro změny v konfiguračním souboru je nutné ho obnovit. Musí být obnoven konfigurační soubor. Můžete buď obnovit proces nginx nebo odeslat signál reload k aktualizaci konfigurace bez přerušení zpracování aktuálních požadavků. Další informace najdete v tématu Kontrola procesů nginx v reálném čase. S NGINX Plus můžete dynamicky upravovat balancování zatížení mezi servery v skupině upstream bez obnovení konfigurace. Můžete také použít API NGINX Plus a klíčový-hodnotový úložiště k dynamickému ovládání přístupu, například podle adresy klienta.

Module ngx_stream_upstream_module

← Chat

Modul ngx_stream_upstream_module (1.9.0) se používá k definování skupin serverů, které mohou být odkazovány příkazem proxy_pass. Příklad Konfigurace

upstream backend {
    hash $remote_addr consistent;
    server backend1.example.com:12345 weight=5;
    server backend2.example.com:12345;
    server unix:/tmp/backend3;
    server backup1.example.com:12345 backup;
    server backup2.example.com:12345 backup;
}
server {
    listen 12346;
    proxy_pass backend;
}

Dynamicky konfigurovatelná skupina s periodickými kontrolami stavu dostupné je součástí našich komerčních předplatných:

resolver 10.0.0.1;
upstream dynamic {
    zone upstream_dynamic 64k;
    server backend1.example.com:12345 weight=5;
    server backend2.example.com:12345 fail_timeout=5s slow_start=30s;
    server 192.0.2.1:12345 max_fails=3;
    server backend3.example.com:12345 resolve;
    server backend4.example.com service=http resolve;
    server backup1.example.com:12345 backup;
    server backup2.example.com:12345 backup;
}
server {
    listen 12346;
    proxy_pass dynamic;
    health_check;
}

Syntaxe příkazů: upstream name { ... }
Výchozí: — Kontext: stream
Definuje skupinu serverů. Servery mohou poslouchat různé porty. Dále mohou být smíchány servery poslouchající TCP a UNIX-doménové sockety. Příklad: upstream backend { server backend1.example.com:12345 weight=5; server 127.0.0.1 }

přidání, servery poslouchající na TCP a UNIX-doménových socketech mohou být smíšené. Příklad:

upstream backend {
  server backend1.example.com:12345 weight=5;
  server 127.0.0.1:12345 max_fails=3 fail_timeout=30s;
  server unix:/tmp/backend2;
  server backend3.example.com:12345 resolve;
  server backup1.example.com:12345 backup;
}

Vychozí metoda rozdělení připojení je pomocí zatížení round-robin s váhou. V předchozím příkladu bude každých 7 připojení rozděleno následovně: 5 připojení k backend1.example.com:12345 a jedno připojení k každé druhé a třetí serveru. Pokud dojde k chybě při komunikaci s serverem, bude připojení přesunuto na další server a tak dále až do zkoušení všech funkčních serverů. Pokud dojde k selhání při komunikaci s všemi servery, bude připojení ukončeno.

Syntaxe: server adresa [parametry]; Výchozí: — Kontext: upstream Definuje adresu a další parametry serveru. Adresa může být určena jako doménové jméno nebo IP adresa s povinným portem, nebo jako cesta k UNIX-doménovému socketu určená po prefixu "unix:". Doména, která se rozšiřuje na více IP adres, definuje servery jedenkrát. Následující parametry mohou být definovány:

  • weight=číslo nastavuje váhu serveru, výchozí hodnota je 1.
  • max_conns=číslo omezuje maximální počet souběžných připojení k proxovanému serveru (1.11.5). Výchozí hodnota je nula, což znamená, že není omezeno.

Maximální počet souběžných připojení k serveru, který je proxyován (1.11.5). Hodnota výchozí je nula, což znamená, že nejsou omezení. Pokud serverová skupina nebyla umístěna v sdílené paměti, omezení funguje pro každý pracovní proces. Před verzí 1.11.5 byl tento parametr k dispozici jako součást našich komerčních předplatných. max_fails=číslo nastaví počet neúspěšných pokusů o spojení s serverem, které by se měly stát v časovém intervalu daném parametrem fail_timeout, aby se server považoval za nedostupný v časovém intervalu také daném parametrem fail_timeout. Výchozí hodnota je nastavena na 1 pokus. Nula zde znamená, že se pokusy nepočítají. Zde jde o chybu nebo časový limit při navázání spojení s serverem. fail_timeout=čas nastaví časový interval, během kterého by se měly stát určité počet neúspěšných pokusů o spojení s serverem, aby se server považoval za nedostupný; a časový interval, během kterého server bude považován za nedostupný. Výchozí hodnota je nastavena na 10 sekund. backup označuje server jako zálohový server. Přípojky k zálohovému serveru budou přesměrovány, když primární servery nejsou dostupné. Tento parametr nelze použít společně s metodami hash a náhodného rozdělení zátěže. down označuje server jako trvale nedostupný.

Hodnota výchozí je nula, tedy rychlý start je vypnutý. Tento parametr nelze použít společně s metodami hash a náhodného rozložení zatížení. Pokud je v skupině pouze jeden server, parametry max_fails, fail_timeout a slow_start jsou ignorovány, a takový server nikdy nebude považován za nezdravého.

Module ngx_http_limit_req_module

← Chat

Modul ngx_http_limit_req_module (verze 0.7.21) se používá k omezení frekvence zpracování požadavků podle určeného klíče, zejména požadavků přicházejících z jedné IP adresy. Omezení se provádí metodou "průtokové kolo".

Příklad Konfigurace 

http {
    limit_req_zone $binary_remote_addr zone=one:10m rate=1r/s;
    ...
    server {
        ...
        location /search/ {
            limit_req zone=one burst=5;
        }
    }
}

Synaxe direktiv:

limit_req zone=name [burst=number] [nodelay | delay=number];

Výchozí nastavení: —

Kontext: http, server, location

Nastavuje sdílenou paměťovou zónu a maximální počet požadavků v burstě. Pokud se frekvence požadavků překročí frekvenci konfigurovanou pro zónu, je zpracování požadavků zpožďováno tak, aby byly požadavky zpracovávány danou frekvenci. Pokud překročí počet požadavků maximální počet v burstě, je požadavek ukončen s chybovým kódem. Výchozí hodnota pro maximální počet požadavků v burstě je nula. Například, příklad níže umožňuje maximálně 1 požadavek za sekundu v průměru s burstami neexcedujícími 5 požadavků.

limit_req_zone $binary_remote_addr zone=one:10m rate=1r/s;
server {
    location /search/ {
        limit_req zone=one burst=5;
    }
}

Pokud se nechtá zdržování překročení požadavků při omezení požadavků nechtá, parametr nodelay by měl být použit: limit_req zóna=jedna burst=5 nodelay; Parametr zdržení (1.15.7) určuje hranici překročení požadavků, která se zdržují. Hodnota výchozí je nula, tedy všechny překročení požadavků se zdržují. Může se vyskytovat několik příkazů limit_req. Například následující konfigurace omezí rychlost zpracování požadavků přicházejících z jedné IP adresy a současně rychlost zpracování požadavků virtuálního serveru: limit_req_zóna $binary_remote_addr zóna=perip:10m rate=1r/s; limit_req_zóna $server_name zóna=perserver:10m rate=10r/s; server { ... limit_req zóna=perip burst=5 nodelay; limit_req zóna=perserver burst=10; } Tyto příkazy jsou děděny z předchozí konfigurace úrovně, pokud a jen pokud na současné úrovni nejsou definovány žádné příkazy limit_req. Syntax: limit_req_dry_run on | off; Výchozí: limit_req_dry_run off; Kontext: http, server, location Tento příkaz se objevil v verzi 1.17.1. Povolí režim suchého běhu. V tomto režimu není omezena rychlost zpracování požadavků, ale v paměti sdílené zóně se počítá počet překročení požadavků obvykle. Syntaxe: limit_req_status kód; Výchozí: limit_req_status 503; Kontext: http, server, umístění Tento příkaz se objevil v verzi 1.3.15. Nastavuje kód stavu, který se vrátí v odpovědi na odmítnuté požadavky. Syntaxe: limit_req_zone klíč zóna=jméno:velikost frekvence=frekvence [sync]; Výchozí: — Kontext: http Nastavuje parametry pro sdílenou paměťovou zónu, která bude uchovávat stavy pro různé klíče. V participlu uchovává stav aktuálního počtu překročených požadavků. Klíč může obsahovat text, proměnné a jejich kombinace. Požadavky s prázdnou hodnotou klíče nejsou zahrnuté. Před verzí 1.7.6 mohl klíč obsahovat přesně jednu proměnnou. Příklad použití: limit_req_zone $binary_remote_addr zóna=jedna:10M frekvence=1r/s; Zde jsou stavy uloženy do 10 megabajtové zóny "jedna", a průměrná rychlost zpracování požadavků pro tuto zónu nemůže přesáhnout 1 požadavek za sekundu. IP adresa klienta slouží jako klíč. Poznámka: místo $remote_addr je zde použitá proměnná $binary_remote_addr.

Druhý. Adresa klienta slouží jako klíč. Poznamenejte si, že zde místo $remote_addr se používá proměnná $binary_remote_addr. Velikost proměnné $binary_remote_addr je vždy 4 bajty pro IPv4 adresy nebo 16 bajtů pro IPv6 adresy. Velikost uloženého stavu je vždy 64 bajtů na 32bitových platformách a 128 bajtů na 64bitových platformách. Jedna megabajtová zóna může uložit asi 16 tisíc 64bajtových stavů nebo asi 8 tisíc 128bajtových stavů. Pokud dochází k vyčerpání úložiště zóny, odstraňuje se nejméně často používaný stav. Pokud ani po odstraňování nejméně často používaného stavu nový stav vzniknout nemůže, požadavek je ukončen s chybou. Rychlost je určena počtem požadavků za sekundu (r/s). Pokud se požaduje méně než jeden požadavek za sekundu, určuje se počtem požadavků za minutu (r/m). Například položka požadavku za sekundu je 30r/m. Parametr sync (1.15.3) umožňuje synchronizaci zóny paměti sdílené paměti. Parametr sync je k dispozici jako součást našich komerčních předplatných. Dále, jako součást našich komerčních předplatných, mohou být získány nebo obnoveny informace o stavu každé takové zóny paměti sdílené paměti pomocí API od verze 1.17.7. Proměnná $limit_req_status uchovává výsledek omezení rychlosti zpracování požadavků (1.17.6): PROSPÉLO, ZPOZDĚNILo, ODRAŽENO, ZPOZDĚNILo SUCHÝ BĚH, nebo ODRAŽENO SUCHÝ BĚH.

Překlad:

Master a pracovní procesy jsou zobrazeny jako jeden obdélník, NGINX pro jednodušší zobrazení. VirtualServer a VirtualServerRoute zdroje jsou zobrazeny podobně. Zpracování nového Ingress zdroje se skládá ze následujících kroků: každý krok odpovídá šipce na diagramu s tím samým číslem: Uživatel vytvoří nový Ingress zdroj. NGINX Ingress Controller proces má Cache zdrojů v clusteru. Cache zahrnuje pouze zdroje, které se týká NGINX Ingress Controller, například Ingressy. Cache zůstává v synchronizaci s Kubernetes API sledováním změn v zdrojích. Jakmile Cache má nový Ingress zdroj, upozorní Control Loop na změně zdroje. Control Loop získá nejnovější verzi Ingress zdroje z Cache. Protože Ingress zdroj odkazuje na jiné zdroje, jako jsou TLS Tajné klíče, Control loop získá nejnovější verze těchto odkazovaných zdrojů také. Control Loop vytvoří TLS certifikáty a klíče z TLS Tajných klíčů a zapíše je do souborového systému. Control Loop vytvoří a zapíše NGINX konfigurační soubory, které odpovídají Ingress zdroji, a zapíše je do souborového systému. Control Loop restartuje NGINX a čeká, až NGINX úspěšně restartuje. Během restartování: NGINX čte TLS certifikáty a klíče. NGINX čte konfigurační soubory. Control Loop vydá událost pro Ingress zdroj a aktualizuje jeho stav.

Jak přehrát NGINX a potvrdit úspěch Přehrání NGINX a potvrzení úspěchu NGINX binář (nginx) podporuje operaci přehrání s opcí -s reload.   • Odeslete požadavek HTTP na NGINX, aby se zjistilo, zda nový proces pracovníka odpovídá. Toto znamená, že NGINX přehrál úspěšně: tento způsob vyžaduje další konfiguraci NGINX, popsanou níže.

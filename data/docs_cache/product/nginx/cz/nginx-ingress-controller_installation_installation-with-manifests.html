Použití App Protect DoS

Pokud chcete použít App Protect DoS, nainstalujte Arbitraře App Protect DoS pomocí poskytnutých manifestů ve stejném prostoru názvů jako NGINX Ingress Controller. Pokud instalujete více NGINX Ingress Controllerů ve stejném prostoru názvů, musí se sdílet stejný Arbitrator, protože v jednom prostoru názvů může být pouze jeden Arbitrator.

Nastavení role-based access control (RBAC)

K dokončení těchto kroků potřebujete admin práva ke clusteru. Odkazujte se na dokumentaci vašeho Kubernetes platformy k nastavení admin práv. Pro Google Kubernetes Engine (GKE) můžete odkazovat na jejich Role-Based Access Control průvodce.

Vytvořte prostředky jádra vlastními definicemi prostředků (CRDs), aby se vaše pody NGINX Ingress Controller dostaly do stavu Ready. Alternativně můžete zakázat tuto požadavek nastavením argumentu příkazového řádku -enable-custom-resources na false. Můžete si CRDs nainstalovat pomocí dvou metod:

  1. Použitím URL pro aplikaci jednoho CRD yaml souboru, což je doporučeno.
  1. Použitím vlastní kopie CRD yaml souborů, což vyžaduje klonování repozitáře.

Následující CRDs jsou jádro:

  • VirtualServer
  • VirtualServerRoute
  • TransportServer
  • Policy
  • GlobalConfiguration

Nainstalujte CRDs z jednoho YAML souboru: 

kubectl apply -f https://raw.githubusercontent.com/nginx/kubernetes-ingress/v5.5.1/deploy/crds.yaml

Před spuštěním CRD upgrade provedete kroky, které jsou uvedeny v Upgrade from 3.x to 4.x, pokud je to nutné.

Nainstalujte CRDs po klonování repozitáře: 

kubectl apply -f config/crd/bases/k8s.nginx.org_virtualservers.yaml
kubectl apply -f config/crd/bases/k8s.nginx.org_virtualserverroutes.yaml
kubectl apply -f config/crd/bases/k8s.nginx.org_transportservers.yaml
kubectl apply -f config/crd/bases/k8s.nginx.org_policies.yaml
kubectl apply -f config/crd/bases/k8s.nginx.org_globalconfigurations.yaml

Module ngx_stream_core_module

← Chat

Modul ngx_stream_core_module je dostupný od verze 1.9.0. Tento modul není vytvářen všude výchozí, je nutné ho povolit pomocí parametru --with-stream konfigurace. Následující konfigurace je pouze ukázkovou.

Pracovní procesy auto; chybový log /var/log/nginx/error.log info; události { pracovní spojení 1024; } stream { upstream backend { hash $remote_addr consistent; server backend1.example.com:12345 weight=5; server 127.0.0.1:12345 max_fails=3 fail_timeout=30s; server unix:/tmp/backend3; } upstream dns { server 192.168.0.1:53535; server dns.example.com:53; } server { posluchávač 12345; proxy_connect_timeout 1s; proxy_timeout 3s; proxy_pass backend; } server { posluchávač 127.0.0.1:53 udp reuseport; proxy_timeout 20s; proxy_pass dns; } server { posluchávač [::1]:12345; proxy_pass unix:/tmp/stream. }

Poznámka: Embedded Variables nejsou v tomto příkladu přeloženy, protože se jedná o kód, který je v tomto případě nezpracovatelný.

Nastavuje adresu a port pro socket, na kterém server přijímá spojení. Je možné zadat pouze port. Adresa může být také hostname, například: listen 127.0.0.1:12345; listen *:12345; listen 12345; # stejně jako *:12345 listen localhost:12345; Adresy IPv6 jsou zadávány v kruhových závorkách: listen [::1]:12345; listen [::]:12345; UNIX-doménové sockety jsou zadávány s předponou "unix:": listen unix:/var/run/nginx.sock; Portové rozsahy (1.15.10) jsou zadávány s prvním a posledním portem oddělenými tečkou: listen 127.0.0.1:12345-12399; listen 12345-12399; Parametr default_server, pokud je přítomný, způsobí, že server se stane výchozím serverem pro danou adresu:portovou pár (1.25.5). Pokud žádný z příkazů nemá parametr default_server, pak první server s adresou:portovou párem bude výchozím serverem pro tuto pár. Parametr ssl umožňuje určit, že všechny přijímané spojení na tomto portu budou pracovat v režimu SSL.

Rozkaz listen může mít několik dalších parametrů specifických pro volání systémových funkcí socketu. Tyto parametry mohou být určeny v libovolném rozkazu listen, ale pouze jednou pro danou pár adresa:port. setfib=číslo tento parametr (1.25.5) nastaví asociovaný routovací tabulku, FIB (SO_SETFIB volání), pro poslucháč. Neaktivujte tuto funkci, pokud server nemůže zpracovávat stejný SYN balíček s daty vícekrát. backlog=číslo nastaví parametr backlog volání listen(), které omezuje maximální délku fronty pro frontu čekajících spojení. Možné hodnoty jsou dataready a httpready. deferred instruuje k použití deferred accept() (volba TCP_DEFER_ACCEPT socket option) na Linux (1.25.5). bind tohoto parametru instruuje k provedení samostatného volání bind() pro danou pár adresa:port. Je skutečností, že pokud jsou v nginxu několik příkazů listen s tímž portem, ale různými adresami a jeden z příkazů listen slyší na všechny adresy pro daný port (*:port), nginx bude bind() pouze na *:port. Je nutné poznamenat, že v tomto případě se provede volání getsockname() systémového volání, aby se určila adresa, která přijala spojení. Pokud jsou použity parametry setfib, fastopen, backlog, rcvbuf, sndbuf, accept_filter, deferred, ipv6only, reuseport, multipath, nebo so_keepalive, pro daný pár adresa:port se vždy provede samostatné volání bind().

multipath či parametry so_keepalive se používají potom pro danou adresu:port dvojici se vždy provede oddělený volání funkce bind(). ipv6only=on|off je parametr, který určuje (pomocí IPV6_V6ONLY volajícího socket option) zda IPv6 socket sluchající na divoké adrese [::] přijme pouze IPv6 spojení nebo obě IPv6 a IPv4 spojení. Tento parametr je vypnutý vždycky všude. Může být nastaven jen jednou při spuštění. reuseport je parametr (1.9.1), který instruuje k vytvoření individuálního sluchacího socketu pro každý proces pracovníka (pomocí volajícího socket option SO_REUSEPORT na Linuxu 3.9+ a DragonFly BSD, nebo SO_REUSEPORT_LB na FreeBSD 12+), což umožňuje jádru rozdělit přicházející spojení mezi procesy pracovníky. Toto funguje jen na Linuxu 3.9+, DragonFly BSD a FreeBSD 12+ (1.15.1). Neoprávněné použití této volby může mít své bezpečnostní implikace. multipath je parametr (1.29.7), který konfiguruje protokol Multipath TCP (IPPROTO_MPTCP) pro sluchací socket. To funguje jen na Linuxu 5.6+. Přidání nebo odebrání tohoto parametru také povolí volající socket option SO_REUSEPORT, což může mít své bezpečnostní implikace. so_keepalive=on|off|[keepidle]:[keepintvl]:[keepcnt] je parametr, který konfiguruje chování "TCP keepalive" pro sluchací socket. Pokud tento parametr chybí, pak nastavení pro socket budou v platnosti operačního systému. Pokud je nastaven na hodnotu "on", je pro socket povolena volající socket option SO_KEEPALIVE.

Pro připojení. Pokud je nastaveno na hodnotu "on", je pro připojení zapnutá volba SO_KEEPALIVE. Pokud je nastaveno na hodnotu "off", je pro připojení vypnutá volba SO_KEEPALIVE. Na takových systémech (v současnosti Linux, NetBSD, Dragonfly, FreeBSD a macOS) mohou být konfigurovány pomocí parametrů keepidle, keepintvl a keepcnt.

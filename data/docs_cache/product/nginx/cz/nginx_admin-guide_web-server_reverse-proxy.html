NGINX Reverse Proxy

Tento článek popisuje základní konfiguraci proxy serveru. Učíte se, jak přenést požadavek z NGINX na server proxying přes různé protokoly, upravit hlavičky požadavku klienta odeslané na server proxying a konfigurovat buferování odpovědí, které přicházejí z serveru proxying. Úvod Proxying je obvykle použito k rozložení zátěže mezi několika serverů, k zobrazení obsahu z různých webů nebo k přesunu požadavků k serverům aplikací přes protokoly jiné než HTTP. Přenos požadavku na server proxying, když NGINX proxies požadavek, dělá následující:

  • Odesílá požadavek na zadaný server proxying
  • Získává odpověď
  • Odesílá odpověď zpět k klientovi

Mohou být požadavky proxying přenášeny na server HTTP (jiný server NGINX nebo jakýkoli jiný server) nebo na server ne-HTTP (může běžet aplikace vyvinutá pomocí určitého rámce, jako je PHP nebo Python) pomocí určitého protokolu. Podporované protokoly zahrnují FastCGI, uwsgi, SCGI a memcached. Chcete-li přenést požadavek na server proxying HTTP, používá se příkaz proxy_pass v rámci location. Například:

nginx 

location /some/path/ {
    proxy_pass http://www.example.com/link/;
}

Tento příklad konfigurace způsobí, že se všechny požadavky zpracované v tomto location přenesou na server proxying v určené adrese. Tato adresa může být zadána jako doménové jméno nebo IP adresa. Adresa může také zahrnovat port:

nginx 

location ~ \.php {
    proxy_pass http://127.0.0.1:9000;
}

Tento příklad konfigurace způsobí, že se všechny požadavky na soubory s příponou .php zpracovávají jako požadavky na server proxying na adresu 127.0.0.1:9000.

Pokud je URI uveden společně s adresou, nahrazuje se část adresy požadavku, která odpovídá parametru umístění. Například požadavek s URI /some/path/page.html bude proxován na http://www.example.com/link/page.html. Pokud však adresa je uvedena bez URI, nebo není možné určit část adresy pro nahrazení, celý požadavek URI je přenesen (možná upravený). Chcete-li požadavek odeslat na server proxování jiného než HTTP, byste měli použít odpovídající **_pass direktivu: fastcgi_pass odesílá požadavek na FastCGI server, uwsgi_pass odesílá požadavek na server uwsgi, scgi_pass odesílá požadavek na server SCGI, memcached_pass odesílá požadavek na server memcached. Poznamenejte si, že v těchto případech mohou být pravidla pro určení adres odlišná. Můžete také potřebovat přenést další parametry na server (pro další detaily se podívejte na referenční dokumentaci). Direktiva proxy_pass může být také použita k přenosu požadavků na skupinu pojmenovaných serverů. V tomto případě jsou požadavky rozděleny mezi servery v skupině podle zadaného metody. Přenos Hlaviček Požadavku Výchozí nastavení NGINX upravuje dvě hlavičky v požadavcích proxování, "Host" a "Connection", a odstraňuje hlavičky, jejichž hodnoty jsou prázdné řetězce.

Přepisuje dvě hlavičky v požadavcích proxy, "Host" a "Connection", a odstraňuje hlavičky, jejichž hodnoty jsou prázdnými řetězci. "Host" je nastaven na hodnotu proměnné $proxy_host, a "Connection" je nastaven na close. Chcete-li změnit tyto nastavení, stejně jako upravit další hlavičky, použijte direktivu proxy_set_header. Tato direktiva můžete definovat v lokaci nebo vyšší. Může být také definována v kontextu serveru konkrétního nebo v bloku http. Například:

nginx 

location /some/path/ {
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_pass http://localhost:8000;
}

V této konfiguraci je pole "Host" nastaveno na proměnnou $host. Chcete-li zabránit, aby hlavička byla odeslána na server proxy, nastavte ji na prázdný řetězec následovně:

nginx 

location /some/path/ {
    proxy_set_header Accept-Encoding "";
    proxy_pass http://localhost:8000;
}

Konfigurace Bufferingu
Ve výchozím nastavení NGINX bufferuje odpovědi z proxy serverů. Odpověď je uložena do vnitřních bufferů a není odeslána na klienta, dokud se celá odpověď neobtěží. Buffering pomáhá optimální výkon s pomalými klienty, které mohou zneužít čas proxy serveru, pokud by odpověď byla odeslána z NGINX na klienta synchronně. Však když je buffering povolen, NGINX umožňuje proxy serveru zpracovávat odpovědi rychle, zatímco NGINX uchovává odpovědi pro tak dlouho, kolik potřebují klienti stáhnout.

Pokud je povolen buffering, NGINX umožňuje proxy serveru rychle zpracovávat odpovědi, zatímco NGINX uchovává odpovědi pro tak dlouho, kolik potřebují klienti stáhnout.

Chcete rychle zpracovávat odpovědi, zatímco NGINX ukládá odpovědi pro tak dlouho, kolik potřebují klienti k jejich stažení. Odpovědí za to je příkaz proxy_buffering, který je odpovědný za povolení a zakázání bufferingu. Výchozí hodnota je nastavena na on a buffering je povolené. Příkazy proxy_buffers a proxy_buffer_size ovládají, jak NGINX ukládá a bufferuje data. Příkaz proxy_buffers ovládá velikost a počet bufferů přidělených pro požadavek. První část odpovědi z proxovaného serveru je uložena do samostatného bufferu, jehož velikost je nastavena pomocí příkazu proxy_buffer_size. Tato část obvykle obsahuje malou hlavičku odpovědi a může být menší než buffer pro zbytek odpovědi. Následující příklad zvětšuje výchozí počet bufferů a zmenšuje velikost bufferu pro první část odpovědi.

nginx

location /some/path/ {
 proxy_buffers 16 4k;
 proxy_buffer_size 2k;
 proxy_pass http://localhost:8000;
}

Pokud je buffering zakázán, je odpověď odeslána klientovi synchronně, zatímco je odpověď z proxovaného serveru přijímána. Tento chování může být přijatelné pro rychlé interaktivní klienty, které potřebují začít přijímat odpověď co nejdříve.

Chování toto může být přijatelné pro rychlé interaktivní klienty, které potřebují začít obdržovat odpověď co nejdříve. Chcete-li vypnout buffering v určitém umístění, umístěte příkaz proxy_buffering direktivu v umístění s parametrem off, jak je uvedeno níže: nginx

location /some/path/ {
    proxy_buffering off;
    proxy_pass http://localhost:8000;
}

V tomto případě používá NGINX pouze buffer konfigurovaný pomocí proxy_buffer_size k uložení aktuální části odpovědi. Obvyklým použitím reverzního proxy je poskytnutí balancování zatížení. Vybrání IP adresy odchozího počítače Pokud vaši proxy server má více sítových rozhranů, můžete potřebovat vybrat určitou konkrétní IP adresu pro připojení k proxied serveru nebo upstream. To může být užitečné, pokud proxied server za NGINX je konfigurován k přijímání spojení z určitých IP sítí nebo rozsahů IP adres. V takových případech můžete určit příkaz proxy_bind a IP adresu potřebné sítové rozhraní: nginx

location /app1/ {
    proxy_bind 127.0.0.1;
    proxy_pass http://example.com/app1/;
}
location /app2/ {
    proxy_bind 127.0.0.2;
    proxy_pass http://example.com/app2/;
}

IP adresa může být také určena pomocí proměnné. Například proměnná $server_addr přenese IP adresu sítového rozhraní, které přijalo požadavek: nginx

location /app3/ {
    proxy_bind $server_addr;
    proxy_pass http://example.com/app3/;
}

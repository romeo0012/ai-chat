Základní konfigurace
Tento dokument ukazuje základní definici zdroje Ingress pro F5 NGINX Ingress Controller. Balancuje požadavky pro dvě služby jako součást jedné aplikace. yaml

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: cafe-ingress
spec:
  ingressClassName: nginx
  tls:
  - hosts:
    - cafe.example.com
    secretName: tls-secret
  rules:
  - host: cafe.example.com
    http:
      paths:
      - path: /tea
        pathType: Prefix
        backend:
          service:
            name: tea-svc
            port:
              number: 80
      - path: /coffee
        pathType: Prefix
        backend:
          service:
            name: coffee-svc
            port:
              number: 80

Toto je přehled, co znamená definice zdroje Ingress: Pole metadata.name definuje název zdroje cafe-ingress. Pole spec.tls nastavuje SSL/TLS terminační balancování: Pole hosts přiřazuje certifikát a klíč k doméně cafe.example.com. Pole secretName odkazuje na zdroj tajného klíče podle jeho názvu, cafe-secret. Tajný klíč musí patřit do stejného prostoru názvů jako Ingress a mít typ kubernetes.io/tls a obsahovat klíče tls.crt a tls.key, které obsahují certifikát a soukromý klíč, jak je popsáno zde. Pokud tajný klíč neexistuje nebo je neplatný, NGINX zabrání jakékoli snaze zřídit TLS spojení s doménami, kterým je tajný klíč přiřazen. Pole spec.rules definuje host s doménovým jménem cafe.example.com.

Přesunout se na hosty, na které se tajemství připlatí. Pole spec.rules definuje hosta s doménovým jménem cafe.example.com. Pole cesty definuje dvě pravidla na základě cest: Pravidlo s cestou /tea instruuje NGINX, aby rozdělilo žádosti s URI /tea mezi pody služby tea, která je nasazena s názvem tea-svc v clusteru. Pravidlo s cestou /coffee instruuje NGINX, aby rozdělilo žádosti s URI /coffee mezi pody služby coffee, která je nasazena s názvem coffee-svc v clusteru. Obě pravidla instruují NGINX, aby rozdělila žádosti na port 80 odpovídající služby (pole servicePort). Chcete-li se dočíst více o zdroji Ingress, přečtěte si dokumentaci Kubernetesu pro zdroje Ingress. Pro úplné instrukce k nasazení zdrojů Ingress a Secret v clusteru, přečtěte si úplný příklad v repozitáři GitHubu. Nové funkce k dispozici v Kubernetesu 1.18 Od verze Kubernetesu 1.18 můžete použít následující nové funkce: Pole host podporuje domény s wildcardem, například *.example.com. Pole cesty podporuje různé způsoby odpovídání s novým polem pathType, které přijímá následující hodnoty: Prefix pro přesnou odpovídání, Exact pro přesné odpovídání a ImplementationSpecific, které je výchozí typ a je stejné jako Prefix.

Pro prozatné shodu, Exact pro shodu přesného odpovídání a ImplementationSpecific, což je výchozí typ a je stejné jako Prefix. Například: yaml Copy - path: /čaj pathType: Prefix backend: serviceName: čaj-svc servicePort: 80 - path: /čaj/zelený pathType: Exact backend: service: name: čaj-svc port: číslo: 80 - path: /káva pathType: ImplementationSpecific backend: service: name: káva-svc port: číslo: 80

Pole ingressClassName je nyní podporováno: yaml Copy apiVersion: networking.k8s.io/v1 kind: Ingress metadata: name: kavárna-ingress spec: ingressClassName: nginx tls: - hosts: - kavárna.example.com secretName: kavárna-secret rules: - host: kavárna.example.com . . .

Použití tohoto pole vyžaduje vytvoření odpovídajícího zdroje IngressClass. Další informace naleznete v části Vytváření běžných zdrojů v tématu Instalace pomocí Manifestů. Omezení
NGINX Ingress Controller klade následující omezení na zdroje Ingress:

  • Pole host je požadováno vždy jako výchozí. Chcete-li umožnit zdrojům Ingress omítat pole host, použijte argument příkazového řádku -allow-empty-ingress-host. Když je -allow-empty-ingress-host povolen, není podporováno spec.tls na zdrojích Ingress bez hosta. Chcete-li konfigurovat TLS, použijte místo toho argument příkazového řádku -default-server-tls-secret.
  • Hodnota host musí být jedinečná mezi všemi zdroji Ingress a VirtualServer, pokud není zdroj Ingress minionem slučitelným.

Text v češtině:

Pole host musí být unikátní mezi všemi zdroji Ingress a VirtualServer, pokud není Ingress zdrojem sloučitelným minionem. Další informace naleznete v tématu Host a kolizí posluchačů. Pole cesta v spec.rules[].http.paths[] je požadováno pro typ cesty Exact a Prefix. Typ cesty ImplementationSpecific je považován za ekvivalentní typu cesty Prefix, s výjimkou toho, že když je tento typ konfigurován, pole cesta v spec.rules[].http.paths[] není povinné. cesta se nastaví na /, pokud nebude nastaveno, ale bude nastaven typ cesty ImplementationSpecific. Další konfigurace NGINX Ingress Controller generuje konfiguraci NGINX tím, že spustí šablonový soubor, který obsahuje možnosti konfigurace. Tyto možnosti jsou nastaveny pomocí zdroje Ingress a ConfigMap NGINX Ingress Controlleru. Zdroj Ingress umožňuje použít pouze základní funkce NGINX: routování podle hostitele a cesty a terminační SSL. Pro další konfiguraci máte dvě možnosti: Anotace mohou být použity k přepsání adres URL požadavků nebo k vložení dalších hlaviček odpovědi. Snippety mohou být použity k vložení ráwnější konfigurace NGINX, změnou generovaných souborů. Dále je možné upravit šablonový soubor, což je popsáno v tématu Custom templates.

Module ngx_http_grpc_module

← Chat

Modul ngx_http_grpc_module umožňuje odesílání požadavků na gRPC server (1.13.10). Tento modul vyžaduje modul ngx_http_v2_module.

Příklad Konfigurace
server {
listen 9000;
http2 on;
location / {
grpc_pass 127.0.0.1:9000;
}
}

Následující příkazy mají syntaxi:
grpc_allow_upstream address;
Default: —
Context: http, server, location
Tato příkazová řetězce se objevila v verzi 1.29.3.
Definuje podmínky, pod kterými je přístup k gRPC serveru povolen nebo zamítnut. Pokud všechny řetězcové parametry nejsou prázdné a nejsou rovny "0", pak je přístup povolen. Hodnoty parametrů mohou obsahovat proměnné: geo $upstream_last_addr $allow { volatile; 10.10.0.0/24 1; }
server {
listen 127.0.0.1;
}

Server byl vytvořen. Hodnoty parametrů mohou obsahovat proměnné:

geo $upstream_last_addr $allow {
    volatile;
    10.10.0.0/24 1;
}
server {
    listen 127.0.0.1:8080;
    http2 on;
    location / {
        grpc_pass localhost:9000;
        grpc_allow_upstream $allow;
        ...
    }
}

Tato direktiva je k dispozici jako součást našich komerčních předplatných. Syntaxe:

grpc_bind address [transparent ] | off;

Výchozí hodnota: —

Kontext: http, server, location

Vytváří připojení k gRPC serveru z určitého lokálního IP adresy s možným portem. Hodnota parametru může obsahovat proměnné. Hodnota off zrušuje účinek předchozího nastavení grpc_bind direktivy, což umožňuje systému automaticky přiřadit lokální IP adresu a port. Parametr transparent umožňuje připojení k gRPC serveru z ne-lokální IP adresy, například z skutečné IP adresy klienta:

grpc_bind $remote_addr transparent;

Pro toto nastavení je obvykle nutné spouštět procesy nginx s oprávněními superuživatele. Na Linuxu to není nutné, pokud je parametr transparent zadán, procesy nginx dědí schopnost CAP_NET_RAW z hlavního procesu. Je také nutné konfigurovat tabulku routování jádra pro zachycení sítové komunikace z gRPC serveru.

Syntaxe:

grpc_bind_dynamic on | off;

Výchozí hodnota: grpc_bind_dynamic off

Kontext: http, server, location

Překlad:

Pokud je nutné zpracovat pole, mohou se použít následující direktivy:

  • grpc_reject_unauthenticated – odmítne připojení, pokud není poskytnut platný token pro ověření. Syntax: grpc_reject_unauthenticated on | off; Default: grpc_reject_unauthenticated off; Context: http, server, location
  • grpc_pass_header – umožní přenos určitých hlaviček z gRPC serveru. Syntax: grpc_pass_header field ...; Default: — Context: http, server, location

Pokud je nutné povolit přenos polí, mohou se použít následující hlavičky: “X-Accel-Redirect” a “X-Accel-Charset”. Syntax: grpc_pass_header field X-Accel-Redirect; Syntax: grpc_pass_header field X-Accel-Charset;

Pokud není povoleno, zpracování těchto hlaviček má následující efekt: “X-Accel-Redirect” provede vnitřní přesměrování na určenou URI; “X-Accel-Charset” nastaví požadovaný kódovací soubor odpovědi.

  • grpc_intercept_errors – určuje, zda gRPC server odpovědi s kódy většími nebo rovnými 300 by měly být odeslány klientovi nebo zpracovány nginxem pomocí direktivy error_page. Syntax: grpc_intercept_errors on | off; Default: grpc_intercept_errors off; Context: http, server, location

Syntax: grpc_next_upstream error | timeout | denied | invalid_header | http_500 | http_502 | http_503 | http_504 | http_403 | http_404 | http_429 | non_idempotent | off ... – určuje, jaké odpovědi gRPC serveru by měly být zpracovány nginxem.

Neplatná hlavička Server vrátil prázdnou nebo neplatnou odpověď; http_500 Server vrátil odpověď s kódem 500; http_502 Server vrátil odpověď s kódem 502; http_503 Server vrátil odpověď s kódem 503; http_504 Server vrátil odpověď s kódem 504; http_403 Server vrátil odpověď s kódem 403; http_404 Server vrátil odpověď s kódem 404; http_429 Server vrátil odpověď s kódem 429; neidempotentní Normálně požadavky s neidempotentním metodou (POST, LOCK, PATCH) se na další server nepředávají, pokud byl požadavek odeslán na server vzhůru; Tento možností explicitně povolí znovu odesílání takových požadavků; off Zakáže předání požadavku na další server.

Server horního původu; tato možnost explicitně umožňuje opakování takových požadavků; vypnutím je zakázáno přenášení požadavku na další server. Vědomím si by měl každý, že přenášení požadavku na další server je možné pouze tehdy, pokud do klienta ještě nic nebylo odesláno. Tedy pokud dochází k chybě nebo časovému limitu v průběhu přenosu odpovědi, její oprava není možná. Instrukce také definuje, co je považováno za neúspěšný pokus o komunikaci s serverem. Případy chyby, časového limitu, denied a invalid_header jsou vždy považovány za neúspěšné pokusy, i když nejsou uvedeny v instrukci. Případy http_500, http_502, http_503, http_504 a http_429 jsou považovány za neúspěšné pokusy pouze tehdy, pokud jsou uvedeny v instrukci. Případy http_403 a http_404 nikdy nejsou považovány za neúspěšné pokusy. Přenášení požadavku na další server může být omezeno počtem pokusů a časem. Syntax: grpc_next_upstream_timeout čas; Výchozí hodnota: grpc_next_upstream_timeout 0; Kontext: http, server, location Omezuje dobu, po kterou může být požadavek přenesen na další server. Hodnota 0 vypne tuto omezení. Syntax: grpc_next_upstream_tries počet; Výchozí hodnota: grpc_next_upstream_tries 0; Kontext: http, server, location Omezuje počet možných pokusů o přenos požadavku na další server. Hodnota 0 vypne tuto omezení. Syntax: grpc_pass adresa; Výchozí hodnota: — Kontext: location, pokud v location Nastaví adresu gRPC serveru.

Umístění Tato direktiva se objevila v verzi 1.27.4. Definuje mezipaměť, která ukládá SSL certifikáty a tajné klíče určené proměnnými. Tato direktiva má následující parametry: max nastavuje maximální počet prvků v mezipaměti; při přetečení mezipaměti jsou odstraňovány nejméně často používané (LRU) prvky; inactive definuje čas po uplynutí kterého je prvk z mezipaměti odstraňován, pokud nebyl přístupný v tomto čase; výchozí hodnota je 10 sekund; valid definuje čas, během kterého je prvk v mezipaměti považován za platný a může být znovu použit; výchozí hodnota je 60 sekund. Certifikáty, které přesáhnou tento čas, budou znovu nahrávány nebo opětovně ověřovány; off vypne mezipaměť.

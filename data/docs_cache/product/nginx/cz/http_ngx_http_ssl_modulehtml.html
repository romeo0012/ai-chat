Modul ngx_http_ssl_module Příklad Konfigurační Direktivy ssl, ssl_buffer_size, ssl_certificate, ssl_certificate_cache, ssl_certificate_compression, ssl_certificate_key, ssl_ciphers, ssl_client_certificate, ssl_conf_command, ssl_crl, ssl_dhparam, ssl_early_data, ssl_ecdh_curve, ssl_ech_file, ssl_key_log, ssl_ocsp, ssl_ocsp_cache, ssl_ocsp_responder, ssl_password_file, ssl_prefer_server_ciphers, ssl_protocols, ssl_reject_handshake, ssl_session_cache, ssl_session_ticket_key, ssl_session_tickets, ssl_session_timeout, ssl_stapling, ssl_stapling_file, ssl_stapling_responder, ssl_stapling_verify, ssl_trusted_certificate, ssl_verify_client, ssl_verify_depth Chyba zpracování Vložených Proměnných Název modulu ngx_http_ssl_module poskytuje nutnou podporu pro HTTPS. Tento modul se nevytváří vždy v základní konfiguraci, by měl být povolen pomocí konfiguračního parametru --with-http_ssl_module. Tento modul vyžaduje knihovnu OpenSSL. Příklad Konfigurace Kvůli snížení zátěže procesoru je doporučeno nastavit počet procesů pracovníků na počet procesorů, povolit trvalé spojení, povolit sdílenou cache sesíí, zakázat vlastní cache sesíí, a možná zvětšit trvalost sesíí (výchozí hodnota je 5 minut):

worker_processes auto;
http {
    ...
    server {
        listen 443 ssl;
        keepalive_timeout 70;
        ssl_protocols TLSv1.2 TLSv1;
    }
}

Poznámka: Výchozí hodnota pro ssl_protocols je TLSv1.1 a TLSv1.2.

Životnost (výchozí hodnota: 5 minut): worker_processes auto; http { ... server { posluchač 443 ssl; časová_otrava 70; protokoly_ssl TLSv1.2 TLSv1.3; šifry_ssl AES128-SHA:AES256-SHA:RC4-SHA:DES-CBC3-SHA:RC4-MD5; certifikát_ssl /usr/local/nginx/conf/cert.pem; certifikát_klíč_ssl /usr/local/nginx/conf/cert.key; cache_sesí_ssl sdílená:SSL:10m; časová_otrava_sesí 10m; ... }

Syntax directiv: ssl on | off; Výchozí hodnota: ssl off; Kontext: http, server
Tato direktiva byla v verzi 1.15.0 zastaralá a odstraněna v verzi 1.25.1. Místo toho by měl být použit parametr ssl v příkazu listen.

Syntax: ssl_buffer_size velikost; Výchozí hodnota: ssl_buffer_size 16k; Kontext: http, server
Tato direktiva se objevila v verzi 1.5.9. Nastavuje velikost buferu používaného pro odesílání dat. Výchozí velikost buferu je 16k, což odpovídá minimálnímu přetížení při odesílání velkých odpovědí. K minimalizaci Time To First Byte může být prospěšné použít menší hodnoty, například: ssl_buffer_size 4k;

Syntax: ssl_certificate soubor; Výchozí hodnota: — Kontext: http, server
Určuje soubor s certifikátem v PEM formátu pro daný virtuální server. Pokud by se k primárnímu certifikátu měly přidat i mezilehlé certifikáty, byly by se měly umístit v tomto souboru v následujícím pořadí: primární certifikát je první, poté následují mezilehlé certifikáty. Tajný klíč v PEM formátu může být umístěn ve stejném souboru. Od verze 1.11.

Příklad:

ssl_certificate /usr/local/nginx/conf/cert.pem;
ssl_certificate_key /usr/local/nginx/conf/cert.key;

V tomto příkladu by se certifikát a tajný klíč nacházely v stejném souboru.

V následujícím pořadí: primární certifikát přichází nejprve, poté intermediární certifikáty. Tajný klíč v formátu PEM může být umístěn ve stejném souboru. Od verze 1.11.0 může tento příkaz být opakovaně určen pro načtení certifikátů různých typů, například RSA a ECDSA: server { posluchač 443 ssl; server_name example.com; ssl_certifikát example.com.rsa.crt; ssl_certifikát_klíč example.com.rsa.key; ssl_certifikát example.com.ecdsa.crt; ssl_certifikát_klíč example.com.ecdsa.key; ... } Pouze OpenSSL 1.0.2 nebo vyšší podporuje oddělené řetězce certifikátů pro různé certifikáty. S staršími verzemi lze použít pouze jeden řetězec certifikátů. Od verze 1.15.9 mohou být v souborovém názvu použity proměnné, pokud se používá OpenSSL 1.0.2 nebo vyšší: ssl_certifikát $ssl_server_name.crt; ssl_certifikát_klíč $ssl_server_name.key; Upozornění: použití proměnných znamená, že pro každý SSL handshake bude načten certifikát a to může mít negativní vliv na výkon. Hodnota data:$proměnná může být určena místo souboru (1.15.10), což zatěžuje certifikát z proměnné bez použití meziterminálových souborů. Upozornění: neoprávněné použití tohoto syntaxe může mít své bezpečnostní implicace, například zápis dat tajného klíče do chybového logu. Vědomí si byste měli, že z důvodu omezení protokolu SSL/TLS pro maximální kompatibilitu s klienty, které nevyužívají SNI, virtuální servery s různými certifikáty by měly poslouchat na různých IP adresách.

Proměnná je k dispozici pouze pro nové relace. $ssl_sigalgs vrací seznam algoritmů podpisu podporovaných klientem (1.31.2). Známé hodnoty jsou uvedeny podle názvů, neznámé jsou uvedeny v šestnáctkové soustavě, například: 0xfe00:rsa_pkcs1_sha256:rsa_pss_rsae_sha256:ecdsa_secp256r1_sha256 Proměnná je plně podporována pouze při použití OpenSSL verze 4.0 nebo vyšší. Pro OpenSSL verze 1.0.2+ jsou hodnoty vždy uvedeny v šestnáctkové soustavě. S staršími verzemi bude hodnota proměnné prázdná řetězec. Proměnná je k dispozici pouze pro nové relace.

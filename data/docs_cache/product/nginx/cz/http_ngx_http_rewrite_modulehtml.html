Modul ngx_http_rewrite_module Direktivy:

Poradí zpracování: Directivy tohoto modulu určené na úrovni serveru se provádějí v pořadí sekvenci; opakovaně: se hledá lokace na základě adresy požadavku; Directivy tohoto modulu určené v nalezené lokaci se provádějí v pořadí sekvenci; cyklus se opakuje, pokud byla adresa požadavku upravena, ale nevíce než 10krát.

Syntax: break;
Default: —
Context: server, location, if
Zastaví zpracování současného seznamu Directiv ngx_http_rewrite_module. Pokud je Directive určena v lokaci, další zpracování požadavku pokračuje v této lokaci.
Příklad: pokud ($pomalý) { limit_rate 10k; break; }

Syntax: if (podmínka) { ... }
Default: —
Context: server, location
Uvedená podmínka se vyhodnotí. Pokud je pravdivá, se Directivy tohoto modulu uvedené v závorkách provádějí, a požadavek obdrží konfiguraci uvedenou v bloku if. Konfigurace uvnitř if-bloků dědí se z předchozí úrovně konfigurace. Podmínka může být jakýkoli z následujících: název proměnné; false, pokud hodnota proměnné je prázdná řetězec nebo "0";
Před verzí 1.0.

Poznámka: Zachovávejte technické termíny, kódové bloky, příkazy, cesty souborů a URLs přesně jako jsou. Zachovávejte strukturu odstavců.

Následující: jméno proměnné; nepravdivé, pokud hodnota proměnné je prázdnou řetězcovou hodnotou nebo "0"; Před verzí 1.0.1, každá řetězcová hodnota začínající na "0" byla považována za nepravdivou hodnotu. Porovnání proměnné s řetězcem pomocí operátorů "=" a "!="; odpovídání proměnné pravidelnému výrazu pomocí operátorů "~" (pro citlivé odpovídání) a "~*" (pro necitlivé odpovídání). Pravidelné výrazy mohou obsahovat zachycení, která jsou dostupná pro pozdější znovu použití v proměnných $1..$9. Negativní operátory "!~" a "!~*" jsou také k dispozici. Pokud pravidelný výraz obsahuje znaky "}" nebo ";", celý výraz by měl být obklopený jedním nebo dvěma uvozovkami. Kontrola existence souboru pomocí operátorů "-f" a "!-f"; kontrola existence adresáře pomocí operátorů "-d" a "!-d"; kontrola existence souboru, adresáře nebo symbolického odkazu pomocí operátorů "-e" a "!-e"; kontrola existence spustitelného souboru pomocí operátorů "-x" a "!-x". Příklady:

if ($http_user_agent ~ MSIE) {
    rewrite ^(.*)$ /msie/$1 break;
}
if ($http_cookie ~* "id=([^;]+)(?:;|$)") {
    set $id $1;
}
if ($request_method = POST) {
    return 405;
}
if ($slow) {
    limit_rate 10k;
}
if ($invalid_referer) {
    return 403;
}

Hodnota proměnné $invalid_referer je nastavena hodnotou z příkazu valid_referers. Syntaxe: return kód [text];return kód URL;return URL; Výchozí: — Kontext: server, location, if Ukončí zpracování a vrátí zadaný kód klientovi.

Text v anglickém originále:

Rewrite direktivy jsou provedeny v pořadí, v jakém se objevují v konfiguračním souboru. Můžete zastavit další zpracování direktiv pomocí flagů. Pokud se v replacement stringu objeví "http://", "https://" nebo "$scheme", zpracování se zastaví a se vrátila bude odpověď pro klienta. Volitelný parametr flag může být jeden z následujících: last zastaví zpracování aktuální sady ngx_http_rewrite_module direktiv a začne hledat novou lokaci odpovídající změněné URI; break zastaví zpracování aktuální sady ngx_http_rewrite_module direktiv jako break direktivou; redirect vrátí dočasnou odpověď s kódem 302; používá se, pokud replacement string nezačíná "http://", "https://" nebo "$scheme"; permanent vrátí trvalou odpověď s kódem 301. Celá odkazová URL se vytváří podle požadavku schématu ($scheme) a direktiv server_name_in_redirect a port_in_redirect. Příklad: server { ... rewrite ^(/download/.*)/media/(.*)\..*$ $1/mp3/$2.mp3 last; rewrite ^(/download/.*)/audio/(.*)\..*$ $1/mp3/$2.ra last; return 403; ... }

Pokud jsou tyto direktivy umístěny do "/download/" lokace, pak by měl být flag last nahrazen break, jinak nginx provede 10 cyklů a vrátí chybovou odpověď 500: location /download/ { rewrite ^(/download/.*)/media/(.*)\..*$ $1/mp3/$2.mp3 break; rewrite ^(/download/.*)/audio/(.*)\..*$ $1/mp3/$2.ra break; return 403; ... }

Nginx bude provádět 10 cyklů a vrátí chybový kód 500:

location /download/ {
    rewrite ^(/download/.*)/media/(.*)\..*$ $1/mp3/$2.mp3 break;
    rewrite ^(/download/.*)/audio/(.*)\..*$ $1/mp3/$2.ra break;
    return 403;
}

Pokud je v náhradní řetězci zahrnut nový požadavek na argumenty, původní požadavek na argumenty jsou připojeny po nich. Pokud to není přání, umístění otazníku v konci náhradního řetězce toto zabraňuje, například:

rewrite ^/users/(.*)$ /show?user=$1? last;

Pokud regulární výraz obsahuje znaky “}” nebo “;”, celý výraz by měl být obklopen jednou nebo dvěma uvozovkami.

Syntax: rewrite_log on | off; Default: rewrite_log off; Context: http, server, location, if

Zapne nebo vypne zaznamování názvů direktiv modulu ngx_http_rewrite_module do souboru error_log na úrovni upozornění.

Syntax: set $variable value; Default: — Context: server, location, if

Nastaví hodnotu pro zadanou proměnnou. Hodnota může obsahovat text, proměnné a jejich kombinace.

Syntax: uninitialized_variable_warn on | off; Default: uninitialized_variable_warn on; Context: http, server, location, if

Určuje, zda se zobrazují varovné zprávy o neinicializovaných proměnných.

Vnitřní implementace

Názvy direktiv modulu ngx_http_rewrite_module jsou při konfiguraci převedeny do vnitřních instrukcí, které jsou během zpracování požadavku interpretovány. Interpretační stroj je jednoduchá virtuální strojovka.

Překlad:

Fáze konfigurace se převede do vnitřních instrukcí, které se interpretují během zpracování žádosti. Interpretačním strojem je jednoduchá virtuální strojovka. Například následující direktivy:

location /download/ {
    if ($forbidden) {
        return 403;
    }
    if ($slow) {
        limit_rate 10k;
    }
    rewrite ^/(download/.*)/media/(.*)\..*$ /$1/mp3/$2.mp3 break;
}

budou přeloženy do následujících instrukcí:

proměnná $forbidden
porovnání s nulou
return 403
konec kódu
proměnná $slow
porovnání s nulou
shoda s regulárním výrazem
kopírování "/"
kopírování $1
kopírování "/mp3/"
kopírování $2
kopírování ".mp3"
konec regulárního výrazu
konec kódu

Pokud podmínka je pravdivá, žádosti jsou přiřazeny této konfiguraci, kde limit_rate je rovno 10k.

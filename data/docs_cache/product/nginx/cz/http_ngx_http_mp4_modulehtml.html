Module ngx_http_mp4_module

← Chat

Modul ngx_http_mp4_module poskytuje serverovou podporu pro pseudo-streaming pro soubory MP4. Tyto soubory obvykle mají přípony .mp4, .m4v nebo .m4a. Pseudo-streaming funguje v spolupráci s kompatibilním médiím hráčem. Hráč odesílá požadavek HTTP na server s časem startu uvedeným v řetězci dotazu (jmenovitě start a uvedeném v sekundách), a server odpovídá tokem tak, aby jeho začátek odpovídal požadovanému času, například: http://example.com/elefanty_sen.mp4?start=238.88 Tímto způsobem lze provést náhodné posunutí v libovolném čase, nebo spustit přehrávání v polovině časové osy. K podpoře posunutí je nutné podporovat formáty na bázi H.264. Tyto formáty ukládají metadata do takzvaného "moov atomu". Jedná se o část souboru, která obsahuje indexová informace pro celý soubor. K spuštění přehrávání je nutné, aby hráč nejprve četl metadata. Toto se provádí odesláním specializovaného požadavku s argumentem start=0. Většina kódovacích programů vkládá metadata do konce souboru. To není optimální pro pseudo-streaming, protože hráč musí stáhnout celý soubor před spuštěním přehrávání. Pokud metadata jsou umístěna v počátečním části souboru, stačí, aby nginx začal vracet obsah souboru.

Umístěno v počátečním řádku souboru, stačí nginxu jednoduše vracet obsah souboru. Pokud metadata jsou umístěny v konci souboru, musí nginx celý soubor číst a připravit nový proud, aby metadata přicházely před médiadata. Toto zahrnuje nějaké přetížení CPU, paměti a I/O disku, takže je dobré připravit původní soubor pro pseudo-streaming v předchozím stavu, místo toho, aby nginx to prováděl na každém podobném požadavku. Modul také podporuje poslední argument požadavku HTTP (1.5.13), který nastavuje konec přehrávání. Poslední argument může být určen společně s počátečním argumentem nebo samostatně: http://example.com/elefanty_sny.mp4?start=238.88&end=555.55

Pokud se k odpovídajícímu požadavku s nenulovým počátečním nebo koncovým argumentem připojí, nginx čte metadata z souboru, připraví proud s požadovaným časovým rozsahem a odešle ho klientovi. To má stejné přetížení, jaké bylo popsáno výše. Pokud počáteční argument ukazuje na neklíčový rámec videa, začátek takového videa bude rozbit. Chybu tohoto problému lze opravit tím, že se k počátečnímu bodu připojí klíčový rámec a všechny mezery mezi nimi. Tyto rámce budou skryty při přehrávání pomocí seznamu úprav (1.21.4). Pokud se k odpovídajícímu požadavku nepřipojí počáteční a koncový argument, není přetížení, a soubor je odeslán prostě jako statický zdroj. Některé hrače také podporují požadavky na rozsah bajtů, a tak nepotřebují tento modul.

Překlad provedl David Švec, překladatel a specialista na technický překlad.

Text v angličtině:

Tento zdroj je odesílán prostě jako statická rezerva. Někteří hráči také podporují požadavky na byte-range, a tak nepotřebují tento modul. Tento modul se nevytváří všude v defaultu, by měl být povolen pomocí konfiguračního parametru --with-http_mp4_module. Pokud byl dříve použit třetístranní modul mp4, by měl být vypnut. Podobnou podporu pseudo-streamingu pro soubory FLV poskytuje modul ngx_http_flv_module. Příklad Konfigurace

location /video/ {
    mp4;
    mp4_buffer_size 1m;
    mp4_max_buffer_size 5m;
    mp4_limit_rate on;
    mp4_limit_rate_after 30s;
}

Syntax:

  • mp4; (výchozí: —) – Kontext: location – Povolí zpracování modulu v okolí location.
  • mp4_buffer_size size; (výchozí: mp4_buffer_size 512K) – Kontext: http, server, location – Nastaví počáteční velikost buferu používaného pro zpracování souborů MP4.
  • mp4_max_buffer_size size; (výchozí: mp4_max_buffer_size 10M) – Kontext: http, server, location – Během zpracování metadat může se nutit větší bufer. Jeho velikost nemůže přesáhnout zadanou velikost, jinak nginx vrátí chybu 500 (Internal Server Error) a zaznamená následující zprávu: "/some/movie/file.mp4" mp4 moov atom je příliš velký: 12583268, můžete si to zvětšit mp4_max_buffer_size
  • mp4_limit_rate on | off | factor; (výchozí: mp4_limit_rate off) – Kontext: http, server, location – Omezuje rychlost odesílání odpovědi klientovi. Rychlost je omezena podle průměrné bitrate MP4 souboru poskytovaného.

Přenos odpovědi k klientovi. Rychlost je omezena na průměrný bitrate MP4 souboru poskytovaného. Chcete-li počítat rychlost, se bitrate násobí zadaným koeficientem. Speciální hodnota "on" odpovídá koeficientu 1,1. Speciální hodnota "off" zakáže omezení rychlosti. Omezení je nastaveno na požadavek a tak, že pokud klient současně otevře dvě spojení, celková rychlost bude dvakrát větší než zadaný limit. Tato direktiva je k dispozici jako součást našich komerčních předplatných. Syntax: mp4_limit_rate_after time; Výchozí hodnota: mp4_limit_rate_after 60s; Kontext: http, server, location Nastaví počáteční množství dat médií (měřeno v čase přehrávání) po dobu, po kterou bude další přenos odpovědi k klientovi omezen. Tato direktiva je k dispozici jako součást našich komerčních předplatných. Syntax: mp4_start_key_frame on | off; Výchozí hodnota: mp4_start_key_frame off; Kontext: http, server, location Tato direktiva se objevila v verzi 1.21.4. Nutila vypisovat výstupní video, aby vždy začalo s klíčovým rámcem videa. Pokud není zadán počáteční rámec klíče, počáteční rámce jsou skryty pomocí mp4 edit listu. Edit lists jsou podporovány hlavními hráči a prohlížeči jako Chrome, Safari, QuickTime a ffmpeg, částečně podporované Firefox.

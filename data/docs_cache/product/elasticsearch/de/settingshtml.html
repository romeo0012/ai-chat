Konfigurieren von Elasticsearch

Elasticsearch liefert gute Standardeinstellungen und benötigt sehr wenig Konfiguration. Die meisten Einstellungen können auf einem laufenden Cluster über das Cluster update settings API geändert werden. Die Konfigurationsdateien sollten Einstellungen enthalten, die spezifisch für einen Knoten sind (z.B. node.name und Pfade), oder Einstellungen, die ein Knoten benötigt, um einem Cluster beitreten zu können, wie z.B. cluster.name und network.host.

Hinweis
Dieses Thema beschreibt, wie Sie eine selbstbetriebliche Elasticsearch-Cluster konfigurieren. Andere Bereitstellungstypen müssen mit anderen Schritten konfiguriert werden. Um zu erfahren, wie Sie elasticsearch.yml für andere Bereitstellungstypen konfigurieren, beachten Sie Elastic Stack-Einstellungen. JVM und log4j-Konfiguration sind nicht in allen Bereitstellungstypen verfügbar. Um zu erfahren, wie Sie begrenzte JVM-Optionen in Elastic Cloud auf Kubernetes konfigurieren, beachten Sie Manage compute resources.

Konfigurationsdateien
Elasticsearch hat drei Konfigurationsdateien:

  • elasticsearch.yml für die Konfiguration von Elasticsearch
  • jvm.options für die Konfiguration von Elasticsearch-JVM-Einstellungen
  • log4j2.

(Die Originaltextpassagen, die Code, Kommandos, Dateipfade und URLs enthalten, wurden unverändert übernommen.)

Einstellungskonfiguration. Konfigurationsdateien Elasticsearch besitzt drei Konfigurationsdateien: elasticsearch.yml für die Konfiguration von Elasticsearch, jvm.options für die Konfiguration von Elasticsearch JVM-Einstellungen und log4j2.properties für die Konfiguration von Elasticsearch-Protokollierung. Diese Dateien befinden sich im config-Verzeichnis, dessen Standardort abhängt von der Art der Installation (Archivverteilung oder Paketverteilung). Archivverteilungen
Für die Archivverteilungen liegt der Standardort des config-Verzeichnisses bei $ES_HOME/config. Der Ort des config-Verzeichnisses kann über die ES_PATH_CONF-Umgebungsvariable geändert werden:

ES_PATH_CONF=/pfad/zu/meiner/config
./bin/elasticsearch

Alternativ kann die ES_PATH_CONF-Umgebungsvariable über die Befehlszeile oder über Ihre Shell-Profildatei gesetzt werden.

Paketverteilungen
Für die Paketverteilungen liegt der Standardort des config-Verzeichnisses bei /etc/elasticsearch. Der Ort des config-Verzeichnisses kann durch die ES_PATH_CONF-Umgebungsvariable geändert werden, jedoch reicht es nicht aus, die Umgebungsvariable in Ihrer Shell zu setzen. Stattdessen wird diese Variable aus den folgenden Orten geladen:

Debian: /etc/default/elasticsearch
RPM: /etc/sysconfig/elasticsearch

Um den Standardort des config-Verzeichnisses zu ändern, muss die ES_PATH_CONF=/etc/elasticsearch-Eintrag in der entsprechenden Datei für Ihre Paketverteilung geändert werden.

Konfigurationsdateiformat
Das Konfigurationsformat von elasticsearch.yml ist YAML.

relevant Datei für Ihre Paketumgebung, um den Speicherort der Konfigurationsverzeichnis zu ändern. Dateiformat
Das Konfigurationsdateiformat für Elasticsearch ist YAML. Hier ist ein Beispiel für die Änderung des Pfads der Daten- und Log-Verzeichnisse in Elasticsearch:

path:
  data: /var/lib/elasticsearch
  logs: /var/log/elasticsearch

Einstellungen können auch flach gestellt werden:

path:
  data: /var/lib/elasticsearch
  logs: /var/log/elasticsearch

In YAML können nichtskalare Werte als Folgen formatiert werden:

discovery:
  seed_hosts:
    - 192.168.1.10:9300
    - 192.168.1.11
    - seeds.mydomain.com

Selbstverständlich können Sie auch nichtskalare Werte als Arrays formatieren:

discovery:
  seed_hosts:
    - "192.168.1.10:9300"
    - "192.168.1.11"
    - "seeds.mydomain.com"

Umgebungsvariablen-Substitution
Umgebungsvariablen, die innerhalb des elasticsearch.yml-Konfigurationsdatei mit der ${...} Notation bezeichnet werden, werden durch den Wert der Umgebungsvariable ersetzt. Beispiel:

node.name: ${HOSTNAME}
network.host: ${ES_NETWORK_HOST}

Werte für Umgebungsvariablen müssen einfache Zeichenketten sein. Verwenden Sie eine Kommas getrennte Zeichenkette, um Werte zu geben, die der Komponente als Liste gelesen werden sollen. Beispiel: Elasticsearch teilt die folgende Zeichenkette in eine Liste von Werten für die ${HOSTNAME}-Umgebungsvariable auf:

export HOSTNAME="host1,host2"

Standardmäßig wird die Konfigurationsvalidierung fehlschlagen, wenn eine in der Konfigurationsdatei verwendete Umgebungsvariable beim Start der Komponente nicht vorhanden ist.

Konfigurationsvalidierung scheitert, wenn in der Konfigurationsdatei verwendete Umgebungsvariablen nicht vorhanden sind, wenn das Komponentenstarten beginnt. Dieses Verhalten kann geändert werden, indem man eine Standardwerte für die Umgebungsvariable verwendet, indem man das Syntax ${MY_ENV_VAR:defaultValue} verwendet. Cluster- und Knoten-Einstellungstypen
Cluster- und Knoteneinstellungen können anhand der Konfigurationsweise unterteilt werden: Dynamisch
Sie können dynamische Einstellungen auf einem laufenden Cluster über die Cluster-Update-Einstellungen-API konfigurieren und aktualisieren. Sie können auch dynamische Einstellungen lokal auf einem noch nicht gestarteten oder heruntergefahrenen Knoten über elasticsearch.yml konfigurieren. Mit der Cluster-Update-Einstellungen-API können Sie persistente Einstellungen anwenden, die sich über Cluster-Neustart hinweg anwenden, oder transiente Einstellungen, die nach einem Cluster-Neustart zurückgesetzt werden. Sie können auch transiente oder persistente Einstellungen zurücksetzen, indem Sie ihnen einen null-Wert zuweisen, indem Sie die API verwenden. Wenn Sie die gleiche Einstellung über mehrere Methoden konfigurieren, wird Elasticsearch die Einstellungen in der folgenden Prioritätsreihenfolge anwenden: Transiente Einstellung Persistente Einstellung elasticsearch.yml-Einstellung Standardwert-Wert Beispiel: Sie können eine transiente Einstellung verwenden, um eine persistente Einstellung oder eine elasticsearch.yml-Einstellung zu überschreiben. Allerdings wird eine Änderung an einer elasticsearch.yml-Einstellung nicht eine definierte transiente oder persistente Einstellung überschreiben. Warnung: Wir empfehlen es nicht mehr, transiente Cluster-Einstellungen zu verwenden. Verwenden Sie stattdessen persistente Cluster-Einstellungen.

Definierter Übergangs- oder Persistenz-Einstellung. Warnung: Wir empfehlen es nicht mehr, transiente Kluster-Einstellungen zu verwenden. Stattdessen verwenden Sie statische Kluster-Einstellungen. Wenn ein Cluster instabil wird, können transiente Einstellungen unerwartet geleert werden, was zu einer möglicherweise unerwünschten Kluster-Konfiguration führen kann. In einem selbstverwalteten Cluster sollten Sie die API für Kluster-Einstellungen aktualisieren, um dynamische Kluster-Einstellungen zu konfigurieren, und nur elasticsearch.yml für statische Kluster-Einstellungen und Knoten-Einstellungen verwenden. Die API erfordert keinen Neustart und garantiert, dass der Wert einer Einstellung auf allen Knoten identisch ist.

Statisch
Statische Einstellungen können nur auf einem noch nicht gestarteten oder heruntergefahrenen Knoten über elasticsearch.yml konfiguriert werden. Statische Einstellungen müssen auf jedem relevanten Knoten im Cluster gesetzt werden.

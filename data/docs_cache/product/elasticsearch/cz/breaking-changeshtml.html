9.1.0 Discovery-Plugins: Migruje discovery-ec2 plugin k AWS SDK v2
Plugin discovery-ec2 nyní používá AWS SDK v2 místo v1, protože AWS plánuje deprecovat SDK v1 před koncem období podpory Elasticsearch 8.19. AWS SDK v2 zavádí několik změn chování, které se týkají konfigurace. Důsledky: Pokud používáte plugin discovery-ec2, vaše dosavadní nastavení mohou již nebýt kompatibilní. Pozoruhodné změny zahrnují, ale nejsou omezeny na: AWS SDK v2 nepodporuje protokol EC2 IMDSv1. AWS SDK v2 nepodporuje systémové vlastnosti aws.secretKey nebo com.amazonaws.sdk.ec2MetadataServiceEndpointOverride. AWS SDK v2 neumožňuje určit volbu mezi HTTP a HTTPS, takže nastavení discovery.ec2.protocol již není účinné. AWS SDK v2 neumožňuje použití přístupového klíče bez tajného klíče nebo naopak. Akce: Testujte aktualizaci v neprodukčním prostředí. Adaptujte svou konfiguraci na novou funkionalitu SDK. Toto zahrnuje, ale není omezeno na následující položky: Pokud používáte IMDS k určení zón dostupnosti uzlu nebo k získání přihlašovacích údajů pro přístup k API EC2, ujistěte se, že podporuje protokol IMDSv2. Pokud to platí, ukončte použití vlastnosti aws.secretKey a com.amazonaws.sdk.

Pokud máte další otázky, neváhejte se mně ptát.

Přístupová zóna uzlu nebo získání přihlašovacích údajů pro přístup k API EC2, ujistěte se, že podporuje protokol IMDSv2. Pokud to je nutné, ukončete použití vlastností systému aws.secretKey a com.amazonaws.sdk.ec2MetadataServiceEndpointOverride. Pokud to je nutné, nastavte, aby se chcete používat nezabezpečený protokol HTTP, aby mohl přístup k API EC2, nastavte discovery.ec2.endpoint na URL, která začíná http://. Buďte připraveni poskytnout oba přístupový klíč a tajný klíč pomocí nastavení klíčového skladu discovery.ec2.access_key a discovery.ec2.secret_key, nebo nekonfigurujte žádné z těchto nastavení. Další informace naleznete v #122062.

ES|QL: ES|QL nyní vrací částečné výsledky v případě výchozu výchozího chování V předchozích verzích selhaly ES|QL dotazy úplně při vyskytnutí jakékoliv chyby. Od verze 8.19.0 ES|QL vrací částečné výsledky místo toho. Důsledky: Volající musí kontrolovat is_partial vlajku v odpovědi, aby určili, zda výsledek je úplný. Použití úplných výsledků bez kontroly této vlajky může vést k nesprávným předpokladům o odpovědi. Akce: Pokud částečné výsledky pro vaši scénář nejsou přijatelné, můžete tento chování zakázat:

  • Nastavením allow_partial_results=false v adrese URL dotazu na každou požadavek, nebo
  • Nastavením nastavení clusteru esql.query.allow_partial_results na false.

Další informace naleznete v #127351 (problém: #122802)

Zakazuje se použití závorek v neuvěřitelných indexových vzorcích v ES|QL

Pro vyhnutí se nejasnosti s syntaxí podotazů, ES|QL již neumožňuje používat ( a ) v neuvěřitelných indexových vzorcích.

(problém: #122802) Zakazuje rodičovské závorky v necitraných indexových vzorcích v ES|QL Chcete-li uniknout nejednoznačností s syntaxí podotazky, ES|QL již neumožňuje používat ( a ) v necitraných indexových vzorcích. Důsledek: Otázky, které obsahují závorky v necitraných názvech indexů, budou nyní vytvářet výjimku při analýze. Řešení: Aktualizujte dotazy, které obsahují závorky v názvech indexů, aby byly citrané. Například použijte FROM "("foo")" místo FROM (foo). Další informace naleznete v #130427 (problém: #130378) Zakazuje se smíchání citraných a necitraných komponent v FROM indexových vzorcích v ES|QL ES|QL již neumožňuje smíchat citrané a necitrané části v FROM indexových vzorcích (například FROM remote:"index"). Dříve byly takové vzorce parsovány nekonzistentně a mohly způsobit nepravdivé chybové zprávy v době běhu. Důsledek: Otázky používající částečně citrané indexové vzorce—například citrané pouze index nebo pouze vzdálený cluster—budou odmítnuty při analýze. Tato změna zjednodušuje zpracování gramatiky a uniká nejasným chybovým zprávám. Řešení: Ujistěte se, že indexové vzorce jsou buďto citrané nebo necitrané. Například: Platné: FROM "remote:index" nebo FROM remote:index Neplatné: FROM remote:"index", FROM "remote":index Další informace naleznete v #127636 (problém: #122651) skip_unavailable nyní chytá všechny chyby v době běhu vzdáleného clusteru v ES|QL Když je nastaveno skip_unavailable na true, ES|QL nyní považuje všechny chyby z doby běhu z tohoto clusteru za nekritické. Dříve se tento nastavení týkalo pouze problémů s připojením (tedy například problémů s připojením).

Chyby během spouštění v ES|QL Při nastavení skip_unavailable na true ES|QL nyní považuje všechny chyby během spouštění z dané skupiny za nekritické. Dříve platilo toto nastavení pouze pro problémy s připojením (tedy když skupina byla nek dispozici). Důsledky: Chyby jako například chybějící indexy na vzdálené skupině už nezpůsobí selhání dotazu. AWS SDK v2 vždy používá regionální STS koncový bod, zatímco AWS SDK v2 může použít buď regionální koncový bod nebo globální https://sts.amazonaws.com jeden.

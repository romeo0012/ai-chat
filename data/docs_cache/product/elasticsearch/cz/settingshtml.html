Konfigurace Elasticsearch

Elasticsearch poskytuje dobré výchozí nastavení a požaduje velmi málo konfigurace. Většina nastavení můžete změnit na běžícím klastru pomocí API pro aktualizaci nastavení klastru. Konfigurační soubory by měly obsahovat nastavení, která jsou node-specifická (například node.name a cesty), nebo nastavení, která je potřeba pro to, aby uzel mohl připojit k klastru, jako je cluster.name a network.host. Poznámka Tento téma popisuje, jak nakonfigurovat klastr Elasticsearch samostatně spravovaný. Další typy nasazení musí být nakonfigurovány pomocí různých kroků. Chcete-li se dozvědět, jak nakonfigurovat elasticsearch.yml pro ostatní typy nasazení, přečtěte si Elastic Stack nastavení. Konfigurace JVM a log4j není k dispozici všem typům nasazení. Chcete-li se dozvědět, jak nakonfigurovat omezené JVM nastavení v Elastic Cloud na Kubernetes, přečtěte si Spravovat počítačové zdroje. Dostupná nastavení

Pro úplný seznam nastavení, která můžete použít k nakonfigurování vašeho Elasticsearch klastru, přečtěte si Elasticsearch konfigurační odkaz. Pro seznam nastavení, která musí být nakonfigurována před použitím vašeho klastru v produkci, přečtěte si Důležité nastavení konfigurace. Soubory konfigurace

Elasticsearch má tři konfigurační soubory: elasticsearch.yml pro konfiguraci Elasticsearch jvm.options pro konfiguraci Elasticsearch JVM nastavení log4j2.

Nastavení konfigurace. Konfigurační soubory Elasticsearch mají tři konfigurační soubory: elasticsearch.yml pro konfiguraci Elasticsearch jvm, jvm.options pro konfiguraci nastavení JVM Elasticsearch a log4j2.properties pro konfiguraci záznamu Elasticsearch. Tyto soubory se nacházejí v adresáři config, jehož výchozí umístění závisí na tom, zda je instalace z archivní distribuce (tar.gz nebo zip) nebo balíčkové distribuce (Debian nebo RPM balíčky). Archivní distribuce
Pro archivní distribuce je výchozí umístění adresáře config $ES_HOME/config. Umístění adresáře config lze změnit pomocí proměnné prostředí ES_PATH_CONF: ES_PATH_CONF=/cesta/k/mým/konfiguracím ./bin/elasticsearch Alternativně můžete proměnnou prostředí ES_PATH_CONF exportovat prostřednictvím příkazového řádku nebo prostřednictvím profilu shellu. Balíčkové distribuce
Pro balíčkové distribuce je výchozí umístění adresáře config /etc/elasticsearch. Umístění adresáře config lze změnit nastavením proměnné prostředí ES_PATH_CONF, nicméně nastavení proměnné prostředí v shellu není dostatečné. Místo toho je tato proměnná získávána z jednoho z následujících umístění: Debian: /etc/default/elasticsearch RPM: /etc/sysconfig/elasticsearch Chcete-li změnit umístění adresáře config, musíte upravit ES_PATH_CONF=/etc/elasticsearch záznam v relevantním souboru pro vaši balíčkovou distribuci. Formát konfiguračního souboru
Formát konfiguračního souboru elasticsearch.yml je YAML.

Příslušný soubor pro změnu umístění adresáře konfigurace pro vaši balíček. Formát konfiguračního souboru
Elasticsearch.yml je YAML. Níže je příklad změny umístění adresářů dat a protokolů v Elasticsearch:
cesta:
data: /var/lib/elasticsearch
logy: /var/log/elasticsearch
Nastavení mohou být také ploché následujícím způsobem:
cesta.data: /var/lib/elasticsearch
cesta.logy: /var/log/elasticsearch
V YAML můžete formátovat neskalární hodnoty jako seznamy:
discovery.seed_hosts:

  • 192.168.1.10:9300
  • 192.168.1.11
  • seeds.mydomain.com
    Though less common, you can also format non-scalar values as arrays:
    discovery.seed_hosts: ["192.168.1.10:9300", "192.168.1.11", "seeds.mydomain.com"]
    Zásobník prostředí
    Zásobníky prostředí zadané pomocí značky ${...} v elasticsearch.yml konfiguračním souboru budou nahrazeny hodnotou zásobníku prostředí. Například:
    node.name: ${HOSTNAME}
    network.host: ${ES_NETWORK_HOST}
    Hodnoty zásobníků prostředí musí být jednoduché řetězce. Použijte oddělený seznam pro poskytnutí hodnot, které komponenta bude parsovat jako seznam. Například, Elasticsearch rozdělí následující řetězec na seznam hodnot pro prostředí ${HOSTNAME}:
    export HOSTNAME="host1,host2"
    Ve výchozím nastavení se kontrola platnosti konfigurace nezdaří, pokud je v konfiguračním souboru použit zásobník prostředí, který není k dispozici, když se komponenta spustí.

Při ověřování konfigurace dojde k selhání, pokud se v konfiguračním souboru používá proměnná prostředí, která není přítomna, když komponenta spustí. Tento chování lze změnit použitím výchozí hodnoty pro proměnnou prostředí pomocí syntaxe ${MY_ENV_VAR:defaultValue}. Nastavení clusteru a uzlu lze zařadit do kategorií podle toho, jak jsou konfigurovány: Dinamické. Lze konfigurovat a aktualizovat dynamické nastavení běžícího clusteru pomocí API cluster update settings. Lze také konfigurovat dynamické nastavení místně na nezačátečním nebo zastaveném uzlu pomocí elasticsearch.yml. Aktualizace provedené pomocí API cluster update settings mohou být trvalé, což znamená, že se aplikují po restartu clusteru, nebo dočasné, což znamená, že se resetují po restartu clusteru. Lze také resetovat dočasné nebo trvalé nastavení přiřazením null hodnoty pomocí API. Pokud se stejné nastavení konfiguruje pomocí více metod, Elasticsearch jeplně aplikuje nastavení v následujícím pořadí priorit: Dočasné nastavení Trvalé nastavení elasticsearch.yml nastavení Výchozí hodnota například lze použít dočasné nastavení k přepsání trvalého nastavení nebo nastavení elasticsearch.yml. Však změna nastavení elasticsearch.yml nebude přepsat definované dočasné nebo trvalé nastavení. Upozornění My již nedoporučujeme používat dočasná nastavení clusteru. Použijte trvalá nastavení clusteru místo toho.

Upozornění Používejte se při vytváření clusteru nyní již ne doporučujeme používat nastavení transientní. Použijte namísto toho nastavení trvalá. Pokud se cluster nezastabilizuje, mohou se transientní nastavení neočekávaně vymazat, což může vést k nežádoucí konfiguraci clusteru. V klastru samostatně spravovaném byste měli používat API pro aktualizaci nastavení clusteru pro konfiguraci dynamických nastavení clusteru a používat elasticsearch.yml pouze pro statické nastavení clusteru a nastavení uzlů. API nevyžaduje restart a zajistí, aby hodnota nastavení byla stejná na všech uzlech. Statické Statické nastavení mohou být konfigurovány pouze na uzavřeném nebo zastaveném uzlu pomocí elasticsearch.yml. Statické nastavení musí být nastavena na každém relevantním uzlu v clusteru.

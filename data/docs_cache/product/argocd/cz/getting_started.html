Instalace Argo CD¶ kubectl vytvoří nové namespace argocd a kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml Tento příkaz vytvoří nové argocd namespace, ve kterém budou všechny služby Argo CD a zdroje aplikací. Tento příkaz také Argo CD instaluje tím, že aplikuje oficiální manifesty z větve stable. Použití zabezpečené verze (např. v3.2.0) je doporučeno pro produkční nasazení. Poznámka Proč --server-side --force-conflicts? Flag --server-side je nutný, protože některé CRD Argo CD (např. ApplicationSet) přesahují 262KB limit anotace velikosti, který je na kubectl apply klienta-strany. Server-side apply tohoto omezení vyhnutí se tím, že neukládá anotaci poslední aplikované konfigurace. Flag --force-conflicts umožňuje operaci apply provést vlastní správu polí, která mohla být dříve spravována jinými nástroji (např. Helm nebo předchozí kubectl apply). Toto je bezpečné pro nové instalace a nutné pro aktualizace.

Překlad:

Vlastnictví pole, která mohla dříve být spravována jinými nástroji (například Helm nebo předchozí kubectl apply). Toto je bezpečné pro nové instalace a nutné pro aktualizace. Pozor, že jakékoliv vlastní úpravy, které jste provedli na polech, která jsou definována v manifestech Argo CD (například affinity, env, nebo probes), budou přepsány. Nicméně pole, která nejsou definována v manifestech (například limity zdrojů/požadavky nebo tolerance), budou zachována. Varování Instalační manifesty obsahují ClusterRoleBinding zdroje, které odkazují na obor názvů argocd. Pokud instalujete Argo CD do jiného oboru názvů, ujistěte se, že aktualizujete odkaz na obor názvů. Tip Pokud není potřeba rozhraní, SSO a funkce pro více clusterů, můžete instalovat pouze jádro komponent Argo CD. Tato výchozí instalace bude mít certifikát s vlastním podpisem a nebude možné ho přístupit bez nějaké další práce. Proveďte jednu z následujících:

  • Následujte instrukce k nastavení certifikátu (a ujistěte se, že operační systém klienta důvěřuje tomuto certifikátu).
  • Nastavte operační systém klienta, aby důvěřoval certifikátu s vlastním podpisem.
  • Použijte --insecure flag na všechny Argo CD CLI operace v tomto průvodci.

Přihlášení pomocí rozhraní příkazového řádku¶ Počáteční heslo pro účet admin je automaticky generováno a uloženo v čisté podobě v poli heslo v tajném objektu argocd-initial-admin-secret v instalačním prostoru Argo CD. Můžete si tento heslo snadno získat pomocí následujícího příkazu argocd CLI: argocd admin initial-password -n argocd Varování Vyberte si tajný objekt argocd-initial-admin-secret z prostoru Argo CD po změně hesla. Tajný objekt slouží pouze k uložení inicializovaného hesla v čisté podobě a může být bezpečně smazán v libovolném okamžiku. Pokud je potřeba znovu vytvořit nové heslo pro admina, bude tajný objekt opět vytvořen Argo CD. Pomocí uživatelského jména admin a hesla z výše uvedeného, přihlaste se k IP adresě nebo hostiteli Argo CD: argocd login <ARGOCD_SERVER> Poznámka Rozhraní příkazového řádku musí být schopno komunikovat s Argo CD API serverem.

Heslo z výše uvedeného, přihlaste se ke IP adresě nebo jménu hostitele Argo CD: argocd login <ARGOCD_SERVER>

Poznámka: Prostředí příkazového řádku musí být schopno komunikovat s Argo CD API serverem. Pokud není přímo dostupný, jak je popsáno výše v kroku 3, můžete příkazovému řádku říct, aby ho přístupoval pomocí portového přesměrování prostřednictvím jedné z následujících mechanismů:
1) přidat --port-forward-namespace argocd příkaz do každého příkazu příkazového řádku; nebo
2) nastavit proměnnou prostředí ARGOCD_OPTS: export ARGOCD_OPTS='--port-forward-namespace argocd'.

Změňte heslo pomocí příkazu: argocd account update-heslo

  1. Registrování clusteru pro nasazení aplikací (Volitelné)¶

Tento krok registruje přihlašovací údaje clusteru do Argo CD a je nutný pouze při nasazování do vnějšího clusteru. Při nasazování do vnitřního clusteru (do stejného clusteru, ve kterém běží Argo CD), použijte https://kubernetes.default.svc jako adresu K8s API serveru aplikace. Nejprve zobrazte všechny kontexty clusterů v současném kubeconfig: kubectl config get-kontexty -o název Vyberte název kontextu z výsledku a poskytněte ho příkazu argocd cluster add CONTEXTNAME. Například pro kontext docker-desktop, spusťte: argocd cluster add docker-desktop Tento příkaz instaluje služební účet (argocd-manager), do kube-system namespace daného kubectl kontextu a vazbu služebního účtu na roli clusteru na úrovni správce. Argo CD používá tento služební účet token k provádění svých správních úkolů (např. nasazování/monitorování).

V kube-system prostoru tohoto kubectl kontextu a vázá service account k admin-úrovni ClusterRole. Argo CD používá tento service account token k provedení svých správních úkolů (tj. nasazování/monitorování). Poznámka: Pravidla role argocd-manager-role mohou být upravena tak, aby měla pouze vytváření, aktualizaci, patchování a smazání omezeného počtu prostorů, skupin a druhů. Však pro get, list, watch privilegia jsou nutná na úrovni clusteru pro Argo CD, aby fungovala. 6. Vytváření Apps Via CLI¶ Nejprve nastavte současný prostor na argocd spuštěním následujícího příkazu: kubectl config set-context --current --namespace=argocd Vytvořte příklad hostovny aplikace spuštěním následujícího příkazu: argocd app create guestbook --repo https://github.com/argoproj/argocd-example-apps.git --path guestbook --dest-server https://kubernetes.default.

argocd spustí následující příkaz: kubectl config set-context --current --namespace=argocd Vytvořte ukázkovou aplikaci guestbook pomocí následujícího příkazu: argocd app create guestbook --repo https://github.com/argoproj/argocd-example-apps.git --path guestbook --dest-server https://kubernetes.default.svc --dest-namespace default

  1. Synchronizace (Vyvoz) Aplikace¶ Synchronizace prostřednictvím příkazového řádku¶ Po vytvoření aplikace guestbook můžete nyní zobrazit její stav:

$ argocd app get guestbook

Prostor názvů: výchozí

Synchronizace pomocí CLI¶ Po vytvoření aplikace hostovky můžete nyní zobrazit jej stav: $ argocd app get guestbook
Name: guestbook
Server: https://kubernetes.default.svc
Namespace: default
URL: https://10.97.164.88/applications/guestbook
Repo: https://github.com/argoproj/argocd-example-apps.git
Cíl: Cesta: guestbook
Sync Policy: <none>
Stav synchronizace: OutOfSync od (1ff8a67)
Zdravotní stav: Chybí GROUP KIND NAMESPACE NAME STATUS HEALTH
apps Deployment default guestbook-ui OutOfSync Chybí
Service default guestbook-ui OutOfSync Chybí
Stav aplikace je po vytvoření v OutOfSync stavu, protože aplikace je ještě nenasazena a žádné Kubernetes prostředky nebyly vytvořeny. Chcete-li synchronizovat (nasadit) aplikaci, spusťte: argocd app sync guestbook
Tento příkaz získá manifesty z repozitáře a provede kubectl apply manifestů. Aplikace hostovky je nyní spuštěna a můžete ji nyní zobrazit její zdrojové komponenty, protokoly, události a hodnocený zdravotní stav.

Deklarativní nastavení¶ Aplikace, projekty a nastavení Argo CD mohou být definovány deklarativně pomocí manifestů Kubernetes. Tyto mohou být aktualizovány pomocí příkazu kubectl apply, bez nutnosti dotýkat se nástroje argocd příkazového řádku. Rychlý přehled¶ Všechny zdroje, včetně specifikací aplikace a AppProject, musí být instalovány do oboru názvů Argo CD (výchozí argocd). Aplikace¶
Krátký popis zdroje objektu CRD - představuje instance nasazené aplikace v prostředí Kubernetes.

Instalace - nemůžete mít stejné jméno aplikace pro dvě různé aplikace. Aplikace¶
Aplikace CRD je Kubernetes objekt zdroje, který představuje instance aplikace v prostředí. Definuje se dvěma klíčovými informacemi: odkaz na požadovaný stav v Git (repozitář, revize, cesta, prostředí) odkaz na cíl cluster a namespace. Pro cluster můžete použít buď server nebo název, ale ne oba (což vede k chybě). Za kulisami, když chybí server, je vypočítán na základě názvu a použitý pro libovolné operace. Minimální specifikace aplikace je následující:
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
název: guestbook
namespace: argocd
spec:
projekt: default
zdroj:
repoURL: https://github.com/argoproj/argocd-example-apps.git
cílová revize: HEAD
cesta: guestbook
cíl: server: https://kubernetes.default.svc
namespace: guestbook
Viz application.yaml pro další pole. Pokud jste dokončili první krok Návodu, můžete tento aplikovat pomocí kubectl apply -n argocd -f application.yaml a Argo CD začne nasazovat aplikaci guestbook. Poznámka
Prostor musí odpovídat prostoru instance Argo CD - obvykle to je argocd.

Aplikace v aplikacích¶ Můžete vytvořit aplikaci, která vytváří další aplikace, které vytváří další aplikace. Tím můžete deklarativně spravovat skupinu aplikací, které mohou být nasazeny a konfigurovány současně. Viz nasazování clusteru. Projekty¶ AplikaceProjekt CRD je Kubernetes objekt zdrojového kódu představující logickou skupinu aplikací. Definuje se pomocí následujících klíčových informací:

sourceRepos odkaz na repozitáře, ze kterých aplikace v projektu mohou tahat manifesty.
destinations odkaz na cluster a namespace, do kterých aplikace v projektu mohou nasadit.
roles seznam entit s definicemi jejich přístupu k prostředkům v projektu.

Varování: Projekty, které umožňují nasazovat do namespace Argo CD, uděluji administrátorská oprávnění
Pokud konfigurace destinací projektu umožňuje nasazovat do namespace, ve kterém je Argo CD instalováno, pak aplikace pod tímto projektem mají oprávnění administrátora.

Přeloženo do češtiny:

Pokud konfigurace cílových umístění projektu umožňuje nasazování do prostoru, do kterého je nainstalován Argo CD, pak aplikace pod tímto projektem mají oprávnění na úrovni správce. RBAC oprávnění pro projekty na úrovni správce by měly být pečlivě omezena a přístup k povoleným repozitářům sourceRepos by měl být omezen pouze na správce. Následující specifikace je příkladem:

apiVersion: argoproj.io/v1alpha1
kind: AppProject
metadata:
  name: my-project
  namespace: argocd

Finalizer, který se ujistí, že projekt není smazán, než nebude odkazován žádnou aplikací

finalizers:
  - resources-finalizer.argocd.argoproj.io
spec:
  description: Příklad projektu
  # Povolit manifesty nasazovat z libovolného Git repozitáře
  sourceRepos:
    - '*'
  # Povolit aplikacím nasazovat pouze do prostoru guestbook v tomto clusteru
  destinations:
    - namespace: guestbook
      server: https://kubernetes.default.

Repositories¶
Poznámka: Některé hostery Git - například GitLab a pravděpodobně i vlastní instance GitLab na místním počítači - vyžadují, aby jste zadali .git sufix v adrese repozitáře, jinak odeslou HTTP 301 přesměrování na adresu repozitáře s sufixem .git. Argo CD nebude následovat tyto přesměrování, takže musíte upravit adresu repozitáře, aby byla s sufixem .git. Detaily repozitáře jsou uloženy v tajných informacích. Chcete-li nakonfigurovat repozitář, vytvořte tajnou informaci, která obsahuje detaily repozitáře. Využijte bitnami-labs/sealed-secrets k uložení šifrované definice tajné informace jako Kubernetes manifest. Každý repozitář musí mít pole url a, podle toho, zda se připojíte pomocí HTTPS, SSH, nebo GitHub App, musíte zadat pole username a password (pro HTTPS), sshPrivateKey (pro SSH) nebo githubAppPrivateKey (pro GitHub App). Kredence mohou být omezeny na projekt pomocí volitelného pole project. Pokud je omítnuto, bude kredence použita jako výchozí pro všechny projekty bez omezené kredence.

Varování: Při použití bitnami-labs/sealed-secrets budou odstraněny etikety a musí být znovu přidány, jak je popsáno zde: https://github.com/bitnami-labs/sealed-secrets#sealedsecrets-as-templates-for-secrets

Protože Argo CD použije šablonu přihlašovacích údajů pro libovolný daný repozitář, musí být splněny následující podmínky:

  • Repozitář buď nenastavený vůbec, nebo pokud je nastaven, musí neobsahovat žádná přihlašovací informace (tedy žádný z klíčů sshPrivateKey, username, password ).
  • Konfigurovaná URL šablony přihlašovacích údajů (např. https://github.com/argoproj) musí odpovídát jako předpona URL repozitáře (např. https://github.com/argoproj/argocd-example-apps).

Poznámka: Odpovídání předponám šablony přihlašovacích údajů se provádí na základě nejlepšího odpovídajícího úsilí, takže nejdelší (nejlepší) odpovídající předpona má přednost. Pořadí definice není důležité, na rozdíl od před v1.4 konfigurace.

Adresářové předpony se provádí na základě úsilí o nejlepší shodu, takže nejdelší (nejlepší) shoda má přednost. Pořadí definice není důležité, na rozdíl od před v1.4 konfigurace. Následující klíče jsou platné k odkazování na tajné kredenzí:

Obsah repozitářů Helm Chartů¶ Viz sekce Helm pro vlastnosti, které se vztahují na repozitáře a grafy Helm, které se získávají z registru OCI. Repozitáře používající vlastní TLS certifikáty (nebo podepsané vlastní CA)¶ Můžete spravovat certifikáty TLS, které se používají k ověření autenticity vašich serverů repozitářů v objektu konfigurace s názvem argocd-tls-certs-cm. Oddíl data by měl obsahovat mapu, s názvem serveru repozitáře (ne celý URL) jako klíč a certifikáty v formátu PEM jako data. Pokud se připojíte k repozitáři s URL https://server.example.com/repos/my-repo, byste měli použít server.example.com jako klíč. Certifikáty by měly být buď serverový certifikát (v případě vlastního certifikátu) nebo certifikát CA, který byl použit k podepsání certifikátu serveru. Můžete nakonfigurovat více certifikátů pro každý server, například pokud plánujete certifikátovou rotaci. Nastavte repozitáře s proxy¶ Proxy pro vaši repozitář můžete nastavit v poli proxy repozitářového tajemství, společně s odpovídajícím konfigurací noProxy. Argo CD používá tento proxy/noProxy konfiguraci k přístupu k repozitáři a provádění souvisejících operací helm/kustomize. Argo CD hledá standardní proxy prostředníkové proměnné v repozitáři serveru, pokud chybí konfigurace proxy. Příklad repozitáře s proxy a noProxy:

apiVersion: v1
kind: Secret
metadata:
  name: private-repo
  namespace: argocd
labels:
  argocd.argoproj.io/secret-type: repository
stringData:
  type: git
  url: https://github.com/argoproj/private-repo
  proxy: https://proxy-server-url:8888
  noProxy: ".internal.example.com,company.org,10.123.0.0/16"
  password: my-password
  username: my-username

Poznámka k noProxy: Argo CD používá exec k interakci s různými nástroji, jako je například helm a kustomize. Ne všechny z těchto nástrojů podporují stejnou syntaxi noProxy, jako go balíček httpproxy. V případě, že se potkáte s problémy s tím, že noProxy není respektován, můžete se pokusit použít celý doménu místo wildcard vzorce nebo rozsahu IP adres, aby se našel společný syntax, který všechny nástroje podporují.

Resource Exclusion/Inclusion

Lze vyloučit zdroje z objevování a synchronizace tak, aby Argo CD nebylo vědomo o nich. Například apiGroup/kind events.k8s.io/*, metrics.k8s.io/* a coordination.k8s.io/Lease jsou vždy vyloučeny. Příklady použití: Máte dočasné problémy a chcete vyloučit problémové zdroje. Existují mnoho druhů zdrojů, které negativně ovlivňují výkon Argo CD. Omezte přístup Argo CD k určitým druhům zdrojů, například tajných. Viz security.md#cluster-rbac. Chcete-li to nakonfigurovat, upravte config map argocd-cm: 

kubectl edit configmap argocd-cm -n argocd

Přidejte resource.exclusions, například: 
apiVersion: v1
data:
  resource.exclusions: |
    - apiGroups: - "*"
      kinds: - "*"
      clusters: - https://192.168.0.20
    kind: ConfigMap

Node resource.exclusions je seznam objektů. Každý objekt může mít:
  • apiGroups Seznam globů, aby se shodoval s API skupinou.
  • kinds Seznam typů, aby se shodoval. Může být "*" pro shodu s vším.
  • clusters Seznam globů, aby se shodoval s URL adresou clusteru. Pokud všechny tři shodují, pak je zdroj ignorován.

Dále můžete nakonfigurovat seznam zahrnutých zdrojů pomocí nastavení resource.inclusions. Výchozí hodnota je všechny skupiny/typy zdrojů zahrnuty.

Tři shody, potom se zdroj ignoruje. Kromě vyloučených zdrojů můžete konfigurovat seznam zdrojů ke zahrnutí pomocí nastavení resource.inclusions. Výchozí nastavení zahrnuje všechny skupiny zdrojů/druhy. Nastavení resource.inclusions umožňuje upravit seznam zahrnutých skupin zdrojů/druhů:

apiVersion: v1
data:
  resource.inclusions: |
    - apiGroups: - "*"
      kinds: - Deployment
      clusters: - https://192.168.0.20
      kind: ConfigMap

Nastavení resource.inclusions a resource.exclusions mohou být použita společně. Konečný seznam zdrojů zahrnuje skupiny zdrojů/druhy z nastavení resource.inclusions minus skupiny zdrojů/druhy z nastavení resource.exclusions. Poznámky: Uveďte globy v vašem YAML, aby se vyhnuli chybám při parsování. Neplatné globy způsobí, že celá pravidla bude ignorována. Pokud přidáte pravidlo, které odpovídá existujícím zdrojům, ty se zobrazí v rozhraní jako OutOfSync. Některé vyloučené objekty mohou již být v kontrolním cache. Obnovení kontroléru bude nutné k odstranění jejich zobrazení v Pohledu Aplikace.

Respektovat automaticky RBAC pro kontrolér¶
Argo CD kontrolér může být omezen v objevování/synchronizaci konkrétních zdrojů pomocí pouze RBAC kontroléru, bez nutnosti ručně konfigurovat vyloučení zdrojů.

Tajemství. resource.sensitive.mask.annotations: openshift.io/token-secret.hodnota, api-klíč Automaticky respektuje RBAC pro kontrolér¶ Argo CD kontrolér může být omezen v objevování/synchronizaci konkrétních zdrojů pouze pomocí RBAC kontroléru, bez nutnosti ručně konfigurovat výjimky zdrojů. Tato funkce může být zapnutá nastavením klíče resource.respectRBAC v argocd cm, po jeho nastavení kontrolér automaticky zastaví sledování zdrojů, které nemá oprávnění seznamovat/přístupovat. Možné hodnoty pro resource.respectRBAC jsou:

  • dráždivý : Tato nastavení kontroluje, zda volání seznamu provedené kontrolérem je zakázáno/neautorizováno a pokud je, provede kontrolu oprávnění voláním SelfSubjectAccessReview pro zdroj.
  • normální : Toto zkontroluje, zda odpověď na volání seznamu je zakázána/neautorizována a přeskočí volání SelfSubjectAccessReview, k minimizaci jakýchkoli dalších volání api-serveru.
  • nezastavené/prázdné (výchozí) : Toto vypne funkci a kontrolér bude pokračovat v monitorování všech zdrojů. Uživatelé, kteří jsou ochotni se vyrovnat s vzrůstem počtu volání kube api-serveru, mohou vybrat možnost dráždivý, zatímco uživatelé, kteří se obávají většího počtu volání a jsou ochotni se vzdát přesnosti, mohou vybrat možnost normální.

api-server volání mohou vybrat možnost "strict", zatímco uživatelé, kteří se starají o vyšší počet volání API a jsou ochotni se na přesnost vzdát, mohou vybrat možnost "normal". Poznámka: Pokud je nastaven v režimu "strict", musí kontrolér mít RBAC oprávnění k vytvoření prostředku SelfSubjectAccessReview. Požadavek SelfSubjectAccessReview se bude vytvářet pouze pro akci "list", předpokládá se, že pokud je akce "list" povolena pro prostředek, tak jsou oprávnění k ostatním akcím také k dispozici kontroléru. Příklad argocd cm s nastavením resource.respectRBAC na "strict":

apiVersion: v1
kind: ConfigMap
metadata:
  name: argocd-cm
data:
  resource.respectRBAC: "strict"

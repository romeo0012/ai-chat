Instalace¶ Argo CD má dva typy instalací: multi-tenant a jádro. Multi-Tenant¶ Nejběžnější způsob instalace Argo CD je instalace multi-tenant. Tento typ instalace se obvykle používá k poskytování služeb pro více týmů vývojářů aplikací v organizaci a je udržován týmem platformy. Uživatelé mohou přistupovat k Argo CD prostřednictvím serveru API pomocí webového uživatelského rozhraní nebo příkazového řádku argocd. Pro konfiguraci argocd CLI je potřeba použít příkaz argocd login <server-host>. Dva typy instalačních manifestů jsou poskytovány: Bez vysoké dostupnosti:¶ Není doporučováno pro použití v produkčním prostředí. Tento typ instalace se obvykle používá během testovacího období pro demonstrace a testování. install.yaml - Standardní instalace Argo CD s cluster-admin oprávněními. Použijte tento manifest, pokud plánujete použít Argo CD k nasazení aplikací v tom samém clusteru, ve kterém běží Argo CD (tedy kubernetes.svc.default). Může se still nasadit do vnějších clusterů s zadanými přihlašovacími údaji. Poznámka ClusterRoleBinding v instalačním manifestu je vázán na ServiceAccount v argocd namespace. Budete si vědomi, že při úpravě namespace může dojít k chybám souvisejícím s oprávněními, pokud ClusterRoleBinding není správně upraveno, aby odpovídalo novému namespace. namespace-install.yaml - Instalace Argo CD, která vyžaduje pouze oprávnění na úrovni namespace (nepotřebuje role clusteru).

Přístupová oprávnění, pokud ClusterRoleBinding není správně upravováno, aby odpovídalo novému namespace. namespace-install.yaml - Instalace Argo CD, která vyžaduje pouze oprávnění na úrovni namespace (nepotřebuje clusterové role). Použijte tento manifest set, pokud chcete, aby Argo CD nevytvářelo aplikace v tom samém clusteru, ve kterém běží, a bude se místo toho opírat o zadané clusterové přihlašovací údaje. Příkladem použití tohoto sestavení manifestů je, pokud spouštíte několik instancí Argo CD pro různé týmy, kde každá instance bude nasazovat aplikace do vnějších clusterů. Budou se moci nasazovat do stejného clusteru (kubernetes.svc.default) pomocí poskytnutých přihlašovacích údajů (např. argocd cluster add <CONTEXT> --in-cluster --namespace <VAše NAMESPACE>). S vkládanými rolemi můžete nasazovat pouze Argo CD prostředky (Aplikace, ApplicationSets a AppProjects) do stejného clusteru, protože podporuje pouze GitOps režim s skutečnými nasazováním prováděnými do vnějších clusterů. Můžete to upravit definováním nových rolí a přidáním jejich vazby k argocd-application-controller service account. Pozor, Argo CD CRDs nejsou zahrnuté do namespace-install.yaml. Musíte je instalovat odděleně. Manifesty CRD jsou umístěny v adresáři manifests/crds. Použijte následující příkaz k instalaci: kubectl apply --server-side --force-conflicts -k https://github.com/argoproj/argo-cd/manifests/crds\?

Do přesunutí do prostoru-install.yaml a musí být nainstalovány samostatně. Manifesty CRD se nacházejí v adresáři manifests/crds. Použijte následující příkaz k instalaci:

kubectl apply --server-side --force-conflicts -k https://github.com/argoproj/argo-cd/manifests/crds?ref=stable

Vysoká dostupnost:

Vysoká dostupnost je doporučována pro použití v produkčním prostředí. Tento balík obsahuje stejné komponenty, ale upřesněné pro vysokou dostupnost a odolnost. ha/install.yaml - stejný jako install.yaml, ale s více replikami pro podporované komponenty. ha/namespace-install.yaml - stejný jako namespace-install.yaml, ale s více replikami pro podporované komponenty. Jádro

Instalace jádra Argo CD je hlavně určena k nasazení Argo CD v režimu bez hlavy. Tento typ instalace je nejvhodnější pro administrátory clusteru, kteří nezávisle používají Argo CD a nemusí potřebovat funkce multi-tenancy. Tato instalace obsahuje méně komponent a je snadnější nastavit. Balík neobsahuje server API ani uživatelské rozhraní, a instaluje lehkou (ne-HA) verzi každé komponenty. Manifest instalace je dostupný na core-install.yaml. Další informace o Argo CD Jádro naleznete v dokumentaci. Kustomize

Instalace Argo CD v Vlastním Namespace¶
Pokud chcete instalovat Argo CD v namespacu jiném než v defaultním argocd, můžete použít Kustomize k aplikaci patchu, který aktualizuje ClusterRoleBinding tak, aby odkazovala na správný namespace pro ServiceAccount. Tím se zajistí, že se správná oprávnění nastaví v vašem vlastním namespacu. Níže je ukázka, jak nakonfigurovat svůj kustomization.yaml k instalaci Argo CD v vlastním namespacu:
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: <vaše-vlastní-namespac>
resources:

  • https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
    patches:
  • patch: |-
    - op: replace path: /subjects/0/namespace value: <vaše-vlastní-namespac>
    target: kind: ClusterRoleBinding

Tento patch zajistí, že ClusterRoleBinding správně mapuje na ServiceAccount v vašem vlastním namespacu, což zabraňuje jakýmkoli problémům s oprávněními při nasazení.

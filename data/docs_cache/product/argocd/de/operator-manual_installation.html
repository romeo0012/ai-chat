Installation¶
Argo CD bietet zwei Arten der Installation: multi-tenant und core. Multi-Tenant¶
Die multi-tenant Installation ist die häufigste Art, Argo CD zu installieren. Diese Art der Installation wird typischerweise verwendet, um mehreren Anwendungsentwicklerteams in der Organisation zu dienen und von einer Plattformmannschaft betreut zu werden. Die Endbenutzer können Argo CD über den API-Server mithilfe der Web-UI oder argocd CLI verwenden. Das argocd CLI muss mit dem Befehl argocd login <server-host> konfiguriert werden. Zwei Arten von Installationsmanifesten werden bereitgestellt:

Keine Hochverfügbarkeit:¶
Nicht empfohlen für die Produktion. Diese Art der Installation wird typischerweise während einer Bewertungsperiode für Demonstrationen und Tests verwendet. install.yaml - Standard Argo CD Installation mit cluster-admin Zugriff. Verwenden Sie dieses Manifestset, wenn Sie Argo CD verwenden möchten, um Anwendungen in dem Cluster zu bereitstellen, in dem Argo CD läuft (also kubernetes.svc.default). Es wird auch in externen Clustern mit eingegebenen Credentials bereitstellen können. Hinweis Das ClusterRoleBinding im Installationsmanifest ist an einen ServiceAccount im argocd Namespace gebunden. Sei vorsichtig, wenn Sie das Namespace ändern, denn eine Änderung kann zu Fehlern mit Zugriffsrechten führen, es sei denn, das ClusterRoleBinding wird korrekt angepasst, um die neue Namespace zu reflektieren.

namespace-install.yaml - Installation von Argo CD, die nur Namespace-Ebenen-Berechtigungen erfordert (keine Clusterrollen benötigt).

Zugriffsfehler werden auftreten, wenn die ClusterRoleBinding nicht korrekt angepasst wird, um die neue Namespace zu reflektieren.

namespace-install.yaml - Die Installation von Argo CD erfordert nur Namespace-Ebenen-Berechtigungen (keine Clusterrollen benötigt). Verwenden Sie dieses Manifest-Set, wenn Sie Argo CD nicht dazu verwenden möchten, Anwendungen in dem Cluster zu deployen, in dem Argo CD läuft, und stattdessen nur auf eingegebene Cluster-Kredentialen angewiesen sind. Ein Beispiel für die Verwendung dieses Manifest-Sets ist, wenn Sie mehrere Argo CD-Instanzen für verschiedene Teams betreiben, wobei jede Instanz Anwendungen in externen Clustern deployen wird. Es wird jedoch noch möglich sein, auf das gleiche Cluster (kubernetes.svc.default) zu deployen, indem Sie die bereitgestellten Kredentiale verwenden (z.B. argocd cluster add <KONTEXT> --in-cluster --namespace <IHR NAMESPACE>). Mit den standardmäßig eingeschlossenen Rollen können Sie nur Argo CD-Ressourcen (Anwendungen, ApplicationSets und AppProjects) in demselben Cluster deployen, da es nur den GitOps-Modus unterstützt, bei dem echte Bereitstellungen in externen Clustern durchgeführt werden. Sie können das durch Definieren neuer Rollen und deren Bindung an das argocd-application-controller-Service-Account ändern.

Bitte beachten Sie, dass Argo CD CRDs nicht in namespace-install.yaml enthalten sind und separat installiert werden müssen. Die CRD-Manifests befinden sich in dem Verzeichnis manifests/crds. Verwenden Sie den folgenden Befehl, um sie zu installieren:

kubectl apply --server-side --force-conflicts -k https://github.com/argoproj/argo-cd/manifests/crds\?

In das Namespace-Installationsdatei namespace-install.yaml. Diese müssen getrennt installiert werden. Die CRD-Manifests befinden sich in dem Verzeichnis manifests/crds. Verwenden Sie den folgenden Befehl, um sie zu installieren:

kubectl apply --server-side --force-conflicts -k https://github.com/argoproj/argo-cd/manifests/crds\?ref\=stable

High Availability:¶ Für die Produktionsnutzung wird die High Availability Installation empfohlen. Dieses Paket enthält die gleichen Komponenten, aber sie sind für hohe Verfügbarkeit und Widerstandsfähigkeit optimiert. ha/install.yaml - das gleiche wie install.yaml, aber mit mehreren Repliken für unterstützte Komponenten. ha/namespace-install.yaml - das gleiche wie namespace-install.yaml, aber mit mehreren Repliken für unterstützte Komponenten. Core¶ Die Argo CD Core Installation wird hauptsächlich verwendet, um Argo CD in headless Mode zu deployen. Diese Art der Installation ist am besten für Clusteradministratoren geeignet, die Argo CD eigenständig verwenden und keine Mehrtenanzentumsfunktionen benötigen. Diese Installation umfasst weniger Komponenten und ist einfacher zu setzen. Das Paket enthält keinen API Server oder Benutzeroberfläche und installiert die leichtgewichtige (nicht-HA) Version jeder Komponente. Die Installationsmanifest ist unter core-install.yaml verfügbar. Weitere Informationen zu Argo CD Core finden Sie in der offiziellen Dokumentation. Kustomize¶ Die Argo CD Manifests können auch mithilfe von Kustomize installiert werden. Es wird empfohlen, den Manifest als remotes Ressource einzubeziehen und zusätzliche Anpassungen mithilfe von Kustomize Patches durchzuführen.

Installation von Argo CD in einem benutzerdefinierten Namespace¶
Wenn Sie Argo CD in einem Namespace installieren möchten, der nicht der Standard-argocd ist, können Sie Kustomize verwenden, um ein Patch anzuwenden, das die ClusterRoleBinding aktualisiert, um auf den richtigen Namespace für den ServiceAccount zu verweisen. Dadurch werden die notwendigen Berechtigungen richtig in Ihrem benutzerdefinierten Namespace gesetzt. Hier ist ein Beispiel für die Konfiguration Ihres kustomization.yaml zur Installation von Argo CD in einem benutzerdefinierten Namespace:
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: <Ihr-benutzerdefinierter-Namespace>
resources:

  • https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
    patches:
  • patch: |-
    - op: replace path: /subjects/0/namespace value: <Ihr-benutzerdefinierter-Namespace>
    target: kind: ClusterRoleBinding

Dieses Patch sichert sicher, dass die ClusterRoleBinding auf den ServiceAccount in Ihrem benutzerdefinierten Namespace korrekt verweist, was bei der Bereitstellung zu keinen Berechtigungsproblemen führt.

Helm¶ Das Argo CD kann mithilfe von Helm installiert werden. Der Helm-Chart wird zurzeit von der Community gepflegt und ist unter argo-helm/charts/argo-cd verfügbar.

Bitte lesen Sie sich das Verständnis der Grundlagen an, um diese Werkzeuge kennenzulernen. Anforderungen ¶ Installierter kubectl-Befehlszeilentool. Ein kubeconfig-Datei (Standard-Speicherort ist ~/.kube/config). CoreDNS. Dies kann für microk8s aktiviert werden, indem Sie microk8s enable dns und microk8s stop und microk8s start ausführen. 1. Argo CD installieren ¶ kubectl create namespace argocd kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml Dies wird eine neue argocd Namespace erstellen, in der alle Argo CD-Dienste und Anwendungsressourcen residieren. Es wird auch Argo CD installieren, indem die offiziellen Manifeste aus der stable-Branch angewendet werden. Die Verwendung einer festgelegten Version (z.B. v3.2.0) wird empfohlen für Produktion. Hinweis Warum --server-side --force-conflicts? Der --server-side-Flag ist erforderlich, weil einige Argo CD CRDs (z.B. ApplicationSet) die 262KB-Anmerkungsgröße-Begrenzung des client-seitigen kubectl applys überschreiten. Server-seitiges Anwenden umgeht diese Begrenzung, indem es die letzte-angewendte-Konfiguration-Anmerkung nicht speichert. Der --force-conflicts-Flag erlaubt der Anwenderoperation, Felder zu übernehmen, die möglicherweise von anderen Werkzeugen (z.B. Helm oder einem vorherigen kubectl apply) verwaltet wurden. Dies ist für frische Installationen sicher und notwendig für Upgrades.

Deine Rechte über Felder, die möglicherweise von anderen Werkzeugen (z.B. Helm oder einem vorherigen kubectl apply) verwaltet wurden, werden hierbei sichergestellt. Das ist für Neuinstallationen sicher und für Upgrades notwendig. Achtung: Alle benutzerdefinierten Änderungen an Feldern, die in den Argo CD Manifesten definiert sind (z.B. Affinität, Umgebungsvariablen oder Proben), werden überschrieben. Allerdings werden Felder, die in den Manifesten nicht definiert sind (z.B. Ressourcenbegrenzungen/Anforderungen oder Toleranzen), erhalten. Warnung: Die Installationsmanifeste enthalten ClusterRoleBinding-Ressourcen, die auf den argocd Namespace verweisen. Wenn Sie Argo CD in einem anderen Namespace installieren, müssen Sie den Namespace-Verweis aktualisieren. Tip: Wenn Sie sich nicht für die UI, SSO und multi-Cluster-Funktionen interessieren, können Sie nur die Kernkomponenten von Argo CD installieren. Diese Standardinstallation hat ein selbstsigniertes Zertifikat und kann nicht ohne etwas zusätzliches Arbeiten verwendet werden. Führen Sie eine der folgenden Schritte aus:

  1. Argo CD CLI herunterladen ¶

Herunterladen Sie die neueste Argo CD-Version von <https://github.com/argoproj/argo-cd/releases/latest>. Weitere installationsspezifische Anweisungen finden Sie in der CLI-Installationsdokumentation. Auch für Mac, Linux und WSL ist es verfügbar: brew install argocd
  1. Zugriff auf Argo CD ¶

Standardmäßig ist Argo CD nicht außerhalb des Clusters sichtbar. Um Argo CD über Ihren Browser oder CLI zu erreichen, verwenden Sie eine der folgenden Methoden: Service Typ Load Balancer ¶
Ändern Sie den argocd-server-Service-Typ in LoadBalancer: kubectl patch svc argocd-server -n argocd -p '{"spec": {"type": "LoadBalancer"}}'
Nach einer kurzen Wartezeit wird Ihr Cloud-Anbieter eine externe IP-Adresse dem Dienst zuordnen. Sie können diese IP-Adresse mit folgendem Befehl abrufen: kubectl get svc argocd-server -n argocd -o=jsonpath='{.status.loadBalancer.ingress[0].ip}'
Ingress ¶
Folgen Sie den Anweisungen zur Konfiguration von Argo CD mit Ingress.

Adresse zum Dienst. Sie können die IP-Adresse über folgendes Befehl ausführen: kubectl get svc argocd-server -n argocd -o=jsonpath='{.status.loadBalancer.ingress[0].ip}'
Ingress¶ Folge der Ingress-Dokumentation, um Argo CD mit Ingress zu konfigurieren. Port-Weiterleitung¶ kubectl port-forward kann auch verwendet werden, um sich mit dem API-Server zu verbinden, ohne den Dienst zu exponieren. kubectl port-forward svc/argocd-server -n argocd 8080:443 Der API-Server kann dann über https://localhost:8080 erreicht werden.

Anmelden über die CLI¶ Das Initial-Passwort für das Admin-Konto wird automatisch erzeugt und als klartext in dem Feld password in einem Geheimnis namens argocd-initial-admin-secret in Ihrer Argo CD-Installationsnamespace gespeichert. Sie können dieses Passwort einfach mit dem argocd CLI abrufen: argocd admin initial-password -n argocd

Warnung: Löschen Sie das Geheimnis argocd-initial-admin-secret aus der Argo CD-Namespace, nachdem Sie das Passwort geändert haben. Das Geheimnis dient nur dazu, das initial erzeugte Passwort in klartext zu speichern und kann sicher jederzeit gelöscht werden. Es wird von Argo CD neu erstellt, wenn ein neues Admin-Passwort erneuert werden muss. Mit dem Benutzernamen admin und dem Passwort aus oben melden Sie sich bei der IP-Adresse oder dem Hostnamen von Argo CD an: argocd login <ARGOCD_SERVER>
Hinweis: Die CLI-Umgebung muss mit dem Argo CD API-Server kommunizieren können.

  1. (Optional) Registriere einen Cluster für die Bereitstellung von Apps¶

Dieser Schritt registriert die Credentials eines Clusters bei Argo CD, und ist nur notwendig, wenn Sie auf einem externen Cluster bereitstellen. Wenn Sie intern (auf dem gleichen Cluster wie Argo CD) bereitstellen, sollte https://kubernetes.default.svc als Adresse des K8s-API-Servers des Anwendungs verwendet werden. Zunächst liste alle Cluster-Kontexte in deinem aktuellen kubeconfig auf: kubectl config get-contexts -o name

Wähle einen Kontextnamen aus der Liste und übergebe ihn argocd cluster add CONTEXTNAME. Beispiel: Für den Kontextnamen docker-desktop: argocd cluster add docker-desktop

Das obige Befehl installiert einen ServiceAccount (argocd-manager), in das kube-system-Namespace des jeweiligen kubectl-Kontexts und bindet den Service Account an eine admin-Niveau ClusterRole. Argo CD verwendet diesen Service Account Token, um seine Verwaltungsaufgaben (z.B. Bereitstellung/Monitoring) auszuführen.

Der Namespace kube-system des aktuellen kubectl-Kontexts und bindet den Dienstkonto an eine admin-Ebene ClusterRole. Argo CD nutzt diesen Dienstkonto-Token, um seine Verwaltungsaufgaben (z.B. Bereitstellung/Monitoring) auszuführen. Hinweis: Die Regeln der Rolle argocd-manager-role können so modifiziert werden, dass sie nur die Berechtigungen create, update, patch, delete zu einem begrenzten Satz von Namespaces, Gruppen und Arten hat. Es sind jedoch get, list, watch-Berechtigungen am Cluster-Scope erforderlich, um Argo CD funktionieren zu lassen. 6. Erstellung einer Anwendung aus einem Git-Repository¶ Ein Beispielrepository mit einer Gastbuchanwendung ist verfügbar unter https://github.com/argoproj/argocd-example-apps.git, um zu zeigen, wie Argo CD funktioniert. Hinweis: Die folgende Beispielanwendung ist möglicherweise nur mit AMD64-Architektur kompatibel. Wenn Sie auf einem anderen Architektur (z.B. ARM64 oder ARMv7) laufen, können Sie möglicherweise Probleme mit Abhängigkeiten oder Container-Images bekommen, die nicht für Ihre Plattform gebaut wurden. Überprüfen Sie bitte die Kompatibilität der Anwendung oder erstellen Sie, falls nötig, Architektur-spezifische Images. Erstellung von Apps über die CLI¶ Zunächst legt Sie den aktuellen Namespace auf argocd fest, indem Sie das folgende Befehl ausführen:

kubectl config set-context --current --namespace=argocd

Erstellen Sie die Beispielanwendung Gastbuch mit dem folgenden Befehl:

argocd app create guestbook --repo https://github.com/argoproj/argocd-example-apps.git --path guestbook --dest-server https://kubernetes.default.

Um argocd zu starten, führen Sie den folgenden Befehl aus:

kubectl config set-context --current --namespace=argocd

Erstellen Sie das Beispiel-Anwendungsthema guestbook mit dem folgenden Befehl:

argocd app create guestbook --repo https://github.com/argoproj/argocd-example-apps.git --path guestbook --dest-server https://kubernetes.default.svc --dest-namespace default

Synchronisierung über CLI¶ Nachdem die Gastbuch-Anwendung erstellt wurde, können Sie jetzt ihr Status anzeigen: argocd app get guestbook
Name: guestbook

GROUP KIND NAMESPACE NAME STATUS HEALTH
apps Deployment default guestbook-ui OutOfSync Fehlend

Der Anwendungszustand ist anfangs in OutOfSync-Zustand, da die Anwendung noch nicht bereitgestellt wurde, und keine Kubernetes-Ressourcen erstellt wurden. Um die Anwendung (bereitzustellen), führen Sie folgenden Befehl aus: argocd app sync guestbook
Dieser Befehl holt die Manifeste aus dem Repository und führt eine kubectl apply der Manifeste durch. Die Gastbuch-Anwendung ist jetzt lauffähig und Sie können jetzt ihre Ressourcenkomponenten, Logs, Ereignisse und gesicherte Gesundheitsstatus anzeigen.

Tyto scénáře zahrnují situace, kdy běží na jednom serveru více webových stránek pomocí jménozávislých nebo IP-závislých virtuálních hostů. Následující scénáře zahrnují:

  • Jménozávislé hosty na více než jedné IP adresáři.
  • Službu stejného obsahu na různých IP adresářích (například vnitřní a vnější adresář).
  • Běžení různých webových stránek na různých portech.
  • IP-závislé virtuální hosting
  • Smíšené port-závislé a IP-závislé virtuální hosty
  • Smíšené jménozávislé a IP-závislé vhosty
  • Použití Virtual_host a mod_proxy společně
  • Použití _default_ vhostů
  • Migrace jménozávislého vhostu na IP-závislý vhost
  • Použití ServerPath direktivy
  • Běžení více jménozávislých webových stránek na jednom IP adresáři.

¶ Vaše server má více hostových názvů, které se rozšiřují na jednu adresu, a chcete odpovídat jinak pro www.příklad.com a www.příklad.org. PoznámkaVytváření konfigurací virtuálních hostů na vašem Apache serveru neautomaticky způsobí vytvoření DNS záznamů pro tyto hostové názvy. Musíte mít tyto názvy v DNS, které se rozšiřují na vaši IP adresu, jinak nikdo jiný nebude moci vidět vaši webovou stránku. Můžete vložit záznamy do vašeho hosts souboru pro lokální testování, ale to funguje pouze z počítače s těmito hosts záznamy.

Hvězdičky odpovídají všem adresám, takže hlavní server neodpovídá na žádné požadavky. Vzhledem k tomu, že virtuální host s ServerName www.example.com je první v konfiguračním souboru, má nejvyšší prioritu a může se považovat za výchozí nebo primární server. To znamená, že pokud je obdržen požadavek, který neodpovídá žádné z uvedených direktiv ServerName, bude sloužit tímto prvním <VirtualHost>. Tato konfigurace je to, co budete chtít použít v prakticky všech situacích s názevovou virtualizací. Tato konfigurace však fungovat nebude v případě, že jste poskytovali různé obsahy na základě různých IP adres nebo portů. Poznámka Můžete nahradit * konkrétní IP adresou systému. Tato virtuální hostitelna budou používat pouze pro požadavky HTTP obdržené při připojení k určité IP adrese. Nicméně je to také užitečné použít * na systémech, kde IP adresa není předvídatelná - například pokud máte dynamickou IP adresu u ISP a používáte nějakou variaci dynamického DNS řešení. Od hvězdičky odpovídá jakákoliv IP adresa, takže tato konfigurace funguje bez změn každého, když se změní IP adresa.

Dynamická řešení DNS. Protože * odpovídá libovolné IP adrese, tato konfigurace funguje bez změn, pokud se vaše IP adresa změní. Žádost k 172.20.30.50 s neznámým hostovým jménem nebo bez hlavičky Host: bude sloužena z www.example.com. Sloužení stejného obsahu na různých IP adresách (například vnitřní a vnější adresy). ¶ Serverový počítač má dvě IP adresy (192.168.1.1 a 172.20.30.40). Počítač sedí mezi vnitřním (intranet) sítí a vnějším (internet) sítí. Mimo síti se jméno server.example.com rozšiřuje na vnější adresu (172.20.30.40), ale uvnitř sítě se tentýž název rozšiřuje na vnitřní adresu (192.168.1.1).

server.example.com se rozšiřuje na vnější adresu (172.20.30.40), ale v síti se stejné jméno rozšiřuje na vnitřní adresu (192.168.1.1). Lze si server nakonfigurovat tak, aby odpovídal na vnitřní a vnější požadavky stejným obsahom, pomocí jediného <VirtualHost> oddílu.

<VirtualHost 192.168.1.1 172.20.30.40>
DocumentRoot "/www/server1"
ServerName server.example.com
ServerAlias server
</VirtualHost>

Nyní požadavky z obou sítí budou služeny z jednoho <VirtualHost>. Poznámka: Na vnitřní síti je možné použít jenom název server místo plně kvalifikovaného názvu domény server.example.com. Poznámka také, že v předchozím příkladu můžete nahradit seznam IP adres *, což způsobí, že server odpoví stejně na všechny adresy. Běh různých stránek na různých portech.

Použití Virtual_host a mod_proxy společně
¶ Následující příklad umožňuje front-endovému počítači proxy virtual hostu přes počítač s instalací na jiném počítači. V příkladu je konfigurován virtuální host stejného názvu na počítači v 192.168.111.2.

Použití mod_proxy:
ProxyPass / http://192.168.111.2/
ProxyPassReverse / http://192.168.111.2/

V připomínku jiného počítače. V příkladu je konfigurován virtuální host stejného názvu na počítači na adrese 192.168.111.2. Příkaz ProxyPreserveHost On je použit, aby se přenášel požadovaný hostname, v případě, že procházíme více hostnameů na jednom počítači. <VirtualHost *:*> ProxyPreserveHost On ProxyPass "/" "http://192.168.111.2/" ProxyPassReverse "/" "http://192.168.111.2/" ServerName hostname.example.com </VirtualHost> Použitím _default_ vhostů ¶ _default_ vhosty pro všechny porty Zachycení každého požadavku na libovolný nezadaný IP adresu a port, tedy adresu/portu, která není používána pro žádný jiný virtuální host. <VirtualHost _default_:*> DocumentRoot "/www/default" </VirtualHost> Použitím takového vhostu s divokou kartou portu zabraňuje jakékoli požadavku dorazit na hlavní server. Vhost _default_ nikdy neslouží požadavku, který byl odeslán na adresu/port, který je použit pro hostování na základě názvů (vhost pro tuto adresu/port se objeví poprvé v konfiguračním souboru). Můžete použít AliasMatch nebo RewriteRule k přepsání libovolného požadavku na jednu informační stránku (nebo skript). _default_ vhosty pro různé porty Tožší nastavení, ale server poslouchá na několika portech a chceme použít druhý vhost _default_ pro port 80. <VirtualHost _default_:80> DocumentRoot "/www/default80" # ... </VirtualHost> <VirtualHost _default_:*> DocumentRoot "/www/default" # ...

Použitím direktivy ServerPath ¶ Máme server s dvěma jméno-závislými vhosty. Chcete-li odpovídat správnému virtuálnímu hostiteli, musí klient poslat správný header Host:. Staré klienty HTTP/1.0 neposílají takový header a Apache nemá žádné představy, kterému virtuálnímu hostiteli se klient pokoušel připojit (a slouží požadavku z primárního vhostu). Chceme poskytnout co největší kompatibilitu se starými verzemi, tak vytváříme primární vhost, který vrátí jednu stránku obsahující odkazy s URL předponou na jméno-závislé virtuální hosty.

Vysvětlení:
Z důvodu direktivy ServerPath je žádost na adresu URL http://www.sub1.domain.tld/sub1/ vždy poskytována z vhostu sub1. Žádost na adresu URL http://www.sub1.domain.tld/ je poskytována z vhostu sub1 pouze tehdy, pokud zákazník poslal správný hlavičku Host:. Pokud žádný hlavičky Host: není poslán, zákazník obdrží informační stránku z primárního hostitele. Upozornění: Žádost na adresu URL http://www.sub2.domain.tld/sub1/ je také poskytována z vhostu sub1, pokud zákazník žádný hlavičku Host: neposlal. RewriteRule direktivy se používají k tomu, aby klient, který poslal správný hlavičku Host:, mohl používat obě varianty URL, tedy s nebo bez předpony URL.

Klienti, Servery a URLy ¶ Adresy na webu se vyjadřují pomocí URL - Uniform Resource Locators - které určují protokol (např. http), servername (např. www.apache.org), URL-cestu (např. /docs/current/getting-started.html), a možná dotazovou řetězcovou hodnotu (např. ?arg=hodnota), která se používá k přenosu dalších argumentů na server. Klient (např., webový prohlížeč) se připojí k serveru (např., Vašemu Apache HTTP Serveru), s určeným protokolem, a požádá o prostředek pomocí URL-cesty. URL-cesta může zastupovat libovolný počet věcí na serveru. Může to být soubor (např. getting-started.html), zpracovatel (např. server-status) nebo nějaký druh programového souboru (např. index.php). V níže uvedeném oddílu Web Site Content budeme to diskutovat dále. Server odešle odpověď s kódem stavu a, opčinálně, odpovědí tělo. Kód stavu ukazuje, zda požadavek byl úspěšný, a, pokud ne, jaký typ chybového stavu se stal. Toto informuje klienta, co se s odpovědí dělat. Další informace o možných kódech stavu naleznete v wiki HTTP Serveru.

Web Site Content ¶ Webová obsahová stránka může být jakýkoli soubor, který se nachází v adresáři, který je určen pro službu Apache HTTP Server. Apache HTTP Server může sloužit různé typy souborů jako webové stránky. Tyto typy souborů mohou být HTML, PHP, XML, nebo jiné. Apache HTTP Server může také sloužit statické soubory, jako jsou obrázky, zvuky nebo videa.

Pokud je požadavek na statický soubor, Apache HTTP Server odešle tento soubor jako odpověď. Pokud je požadavek na dynamický soubor, Apache HTTP Server zpracuje tento soubor a odešle výsledek jako odpověď.

Pokud je požadavek na dynamický soubor, Apache HTTP Server může použít různé způsoby zpracování. Například může použít PHP, Perl, Python nebo jiný skriptovací jazyk. Apache HTTP Server může také použít moduly, které umožňují zpracovat různé typy požadavků.

Pokud je požadavek na dynamický soubor, Apache HTTP Server může také použít databázi, aby získal data, která potřebuje zobrazit. Apache HTTP Server může také použít různé metody zabezpečení, aby zabránil neautorizovanému přístupu k datům.

Log Files and Troubleshooting ¶ Apache HTTP Server vytváří log soubory, které mohou být užitečné při řešení problémů. Tyto log soubory obsahují informace o požadavcích, které Apache HTTP Server obsluhuje. Tyto informace mohou být užitečné při řešení problémů s webem.

Pokud se vyskytne problém s webem, můžete si prohlédnout log soubory, abyste se dozvěděli, co se stalo. Pokud se vyskytne chyba, můžete si prohlédnout log soubory, abyste se dozvěděli, jaká chyba se stala a jak ji řešit.

Pokud se vyskytne problém s webem, můžete také použít nástroje pro diagnostiku, které mohou pomoci identifikovat problém. Tyto nástroje mohou být například Apache HTTP Server Tools nebo Apache HTTP Server Status.

Pokud se vyskytne problém s webem, můžete také kontaktovat Apache HTTP Server komunitu, abyste se dozvěděli, jak řešit problém. Apache HTTP Server komunita může pomoci identifikovat problém a nabídnout řešení.

Chcete-li se připojit k serveru, musí klient nejprve servername rozlišit na IP adresu - umístění na Internetu, kde se server nachází. Proto aby vaš webový server byl dosažitelný, je nutné, aby servername byl v DNS. Pokud nevíte, jak to udělat, musíte kontaktovat svého správce sítě nebo poskytovatele služeb Internetu, aby provedli tento krok pro vás. Může být na stejnou IP adresu více hostitelů a na stejnou fyzickou server může být připojeno více IP adres. Proto můžete na stejném fyzickém serveru běžet více než jeden webový server, pomocí funkce zvané virtual hosts. Pokud testujete server, který není přístupný na Internet, můžete hostnames umístit do svého souboru hosts, aby mohly být provedeny lokální rozlišování. Například můžete chtít vložit záznam do svého souboru hosts, aby mapovala žádost o www.example.com na vaši lokální systém, pro účely testování. Tento záznam by vypadal následovně: 127.0.0.1 www.example.com

Soubor hosts by pravděpodobně ležel v adresáři /etc/hosts nebo C:\Windows\system32\drivers\etc\hosts. Další informace o souboru hosts naleznete na Wikipedia.org/wiki/Hosts_(file), a další informace o DNS na Wikipedia.org/wiki/DNS.

Konfigurační soubory a direktivy ¶ Apache HTTP Server se konfiguruje prostřednictvím jednoduchých textových souborů. Tyto soubory mohou být umístěny v různých místech, podle toho, jak přesně jste server instalovali. Obvyklé umístění těchto souborů naleznete v wiki httpd. Pokud jste httpd instalovali z zdrojového kódu, výchozí umístění konfiguračních souborů je /usr/local/apache2/conf. Výchozí konfigurační soubor se obvykle jmenuje httpd.conf. Toto také může být různé v třetístranných distribucích serveru. Konfigurace je často rozdělena do menších souborů pro lepší správu. Tyto soubory se načítají pomocí direktivy Include. Jména nebo umístění těchto podsouborů nejsou magické a mohou se velmi lišit od jedné instalace k jiné. Upořádávejte a rozdělujte tyto soubory podle toho, co nejlépe odpovídá vašim potřebám. Pokud výchozí pořadí souborů, které máte, neodpovídá vašim potřebám, neváhejte je přeuspořádat. Server se konfiguruje umístěním konfiguračních direktiv do těchto konfiguračních souborů. Direktiva je klíčové slovo následované jedním nebo více argumenty, které nastavují jeho hodnotu. Otázka "Kde si toto nastavení umístit?" je obvykle odpovězena tím, že se rozhodnete, kde chcete, aby nastavení bylo účinné.

Webová obsahová stránka ¶ Webová obsahová stránka může mít různé podoby, ale může se dělit do dvou hlavních kategorií: statické a dynamické obsahy. Statické obsahy jsou věci jako HTML soubory, obrázky, soubory CSS a jiné soubory, které se nacházejí v soustavě souborů. Direktiva DocumentRoot určuje, kde v soustavě souborů by měly být tyto soubory umístěny. Tato direktiva je buďto nastavena globálně, nebo pro každý virtuální hostitel. Prozkoumejte své konfigurační soubory, abyste určili, jak je to nastaveno pro váš server. Obvykle se slouží soubor s názvem index.html, který se poskytne, když požadavek na adresář nezadá žádný název souboru. Například, pokud je nastaven DocumentRoot na /var/www/html a požadavek je udán pro http://www.example, pak se poskytne index.html.

Název souboru se určuje. Například pokud je nastaven DocumentRoot na /var/www/html a požadavek je proveden pro http://www.příklad.cz/práce/, bude klientovi poslán soubor /var/www/html/práce/index.html. Dynamický obsah je to, co je vytvořeno v době požadavku a může se měnit z jednoho požadavku na druhý. Existuje mnoho způsobů, jak může být dynamický obsah vytvořen. Různé generátory obsahu jsou k dispozici k vytvoření obsahu. Programy CGI mohou být napsány k vytvoření obsahu pro vaši stránku. Moduly třetích stran jako mod_php mohou být použity k napsání kódu, který provádí různé věci. Mnoho třetích stranních aplikací, napsaných pomocí různých jazyků a nástrojů, je k dispozici ke stažení a instalaci na vašem Apache HTTP Server. Podpora těchto třetích stranních věcí je mimo rozsah tohoto dokumentace, a vyhledáte jejich dokumentaci nebo jiné podporu, abyste odpovědi na vaše otázky o nich získali.

Logy a Troubleshooting ¶

Jako správce Apache HTTP Server je vaším nejdůležitějším majetkem logy, a zejména chybové log. Troubleshooting jakékoliv problému bez chybového logu je jako jízda s uzavřenýma očima. Umístění chybového logu je definováno příkazem ErrorLog, který může být nastaven globálně, nebo pro každý virtuální host. Záznamy v chybovém logu vám říkají, co se stalo špatně, a kdy. Často také vám říkají, jak to opravit.

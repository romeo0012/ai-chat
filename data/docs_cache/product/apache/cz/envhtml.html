Prostředí proměnných v Apache httpd Dostupné jazyky: en | fr | ja | ko | tr Existují dvě druhy proměnných prostředí, které ovlivňují Apache HTTP Server. První jsou proměnné prostředí řízené podle operačního systému. Tyto jsou nastaveny před spuštěním serveru a mohou být použity v rozšířeních v konfiguračních souborech. Mohou se opčinálně poskytnout CGI skriptům a SSI pomocí příkazu PassEnv. Druhý způsob, jak Apache HTTP Server poskytuje mechanismus pro ukládání informací do proměnných s názvem proměnné prostředí. Tato informace může být použita k ovládání různých operací, jako je například záznam času nebo kontrola přístupu. Proměnné se také používají jako mechanismus pro komunikaci s vnějšími programy, jako jsou CGI skripty. Tento dokument diskutuje o různých způsobech manipulace a použití těchto proměnných. Přestože se tyto proměnné označují jako proměnné prostředí, nejsou stejné jako proměnné prostředí řízené podle operačního systému. Místo toho jsou tyto proměnné ukládány a manipulovány v interním httpd struktuře. Stávají se skutečnými proměnnými prostředí operačního systému pouze tehdy, když jsou poskytnuty CGI skriptům a Server Side Include skriptům. Pokud chcete manipulovat operačním systémem prostředí, ve kterém běží samotný server, musíte použít standardní mechanismy pro manipulaci s prostředím poskytnuté operačním systémem shell.

Tento příkaz byl původně implementován v důsledku problému s softwarem WebFolders od společnosti Microsoft, který má problém s přesměrováním na zdroje adresářů pomocí metod DAV. potlačit-chybový-kód-kódování Když Apache vydá přesměrování v odpovědi na požadavek klienta, odpověď obsahuje skutečný text, který se má zobrazit v případě, že klient nemůže (nebo nebude) automaticky sledovat přesměrování. Pokud je přesměrování na stránku, která používá jiné kódování, některé zlomky prohlížečů budou pokusit se použít kódování z textu přesměrování místo skutečné stránky. To může vést k tomu, že řecký text bude špatně zobrazen. Nastavení tohoto prostředí způsobí, že Apache nebude značit kódování pro text přesměrování, a tímto způsobem budou zlomky prohlížečů správně používat kódování stránky cíle. Příklady ¶ Přenos neplatných hlaviček do skriptů CGI Od verze 2.4 je Apache přísnější v tom, jak se HTTP hlavičky převádějí na proměnné prostředí v mod_cgi a dalších modulích: Dříve byly jakékoliv neplatné znaky v názvech hlaviček přeloženy na podtržítka. Toto umožňovalo některé potenciální útoky typu cross-site-scripting prostřednictvím vstřikování hlaviček. Pokud musíte podporovat klienta, který posílá neplatné hlavičky a které nelze opravit, jednoduchý způsob pomocí mod_setenvif a mod_headers umožňuje přijímat tyto hlavičky:

#

Následující zpracovává klienta posílající neplatný header Accept_Encoding.

SetEnvIfNoCase ^Accept.Encoding$ ^(.


SetEnvIfNoCase ^Accept.Encoding$ ^(.

Changing protocol behavior with misbehaving clients
Earlier versions recommended that the following lines be included in httpd.conf to deal with known client problems. Since the affected clients are no longer seen in the wild, this configuration is likely no-longer necessary.

# The following directives modify normal HTTP response behavior. # The first directive disables keepalive for Netscape 2.x and browsers that # spoof it. There are known problems with these browser implementations. # The second directive is for Microsoft Internet Explorer 4.0b2 # which has a broken HTTP/1.1 implementation and does not properly # support keepalive when it is used on 301 or 302 (redirect) responses. # BrowserMatch "Mozilla/2" nokeepalive

BrowserMatch "MSIE 4\.0b2;" nokeepalive downgrade-1.0 force-response-1.0

# The following directive disables HTTP/1.1 responses to browsers which # are in violation of the HTTP/1.0 spec by not being able to understand a # basic 1.1 response. # BrowserMatch "RealPlayer 4\.0" force-response-1.0

BrowserMatch "Java/1\.0" force-response-1.0
BrowserMatch "JDK/1\.0" force-response-1.0

# The following directive disables logging of image requests in the access log #

LogLevel alert
CustomLog "logs/access_log" "%h %l %u %t \"[Client denied] %r\" %s %b" env=HTTP_REFERER

Je toto text:

# # Tato konfigurace obchází problém klienta, který odesílá porušený header Accept_Encoding. # SetEnvIfNoCase ^Accept.Encoding$ ^(.*)$ fix_accept_encoding=$1 RequestHeader set Accept-Encoding %{fix_accept_encoding}e env=fix_accept_encoding
Změna chování protokolu s nevhodnými klienty
Předchozí verze doporučovaly, aby následující řádky byly zahrnuty do souboru httpd.conf k řešení známých problémů klientů. Protože se tyto klienty už v divočině nevyskytují, je tato konfigurace pravděpodobně již nepotřebná.

# Následující direktivy modifikují normální chování HTTP odpovědí. # První direktiva zakazuje keepalive pro Netscape 2.x a prohlížeče, které ho falešně spoofují. Pro tyto prohlížeče jsou známé problémy s těmito implementacemi. # Druhá direktiva je pro Microsoft Internet Explorer 4.0b2, který má porušenou implementaci HTTP/1.1 a nepodporuje keepalive správně, když je použit na 301 nebo 302 (přesměrování) odpovědí. # BrowserMatch "Mozilla/2" nokeepalive

BrowserMatch "MSIE 4\.0b2;" nokeepalive downgrade-1.0 force-response-1.0

# Následující direktiva zakazuje odpovědi HTTP/1.1 pro prohlížeče, které porušují specifikaci HTTP/1.0, protože nejsou schopny pochopit základní odpověď 1.1. # BrowserMatch "RealPlayer 4\.0" force-response-1.0

BrowserMatch "Java/1\.0" force-response-1.0
BrowserMatch "JDK/1\.0" force-response-1.0

# Následující direktiva zakazuje zaznamování žádostí o obrázky v logu přístupu #

LogLevel alert
CustomLog "logs/access_log" "%h %l %u %t \"[Klient odmítnut] %r\" %s %b" env=HTTP_REFERER

Pouze prozodický text byl přeložen do češtiny. Technické termíny, kódy, příkazy, cesty souborů, adresy URL a struktura odstavců byla zachována.

Přeložte žádosti o obrázky do deníku přístupu Tento příklad zabraňuje žádostem o obrázky, aby se neobjevily v deníku přístupu. Lze snadno upravit, aby se zabránilo zaznamenávání určitých adresářů nebo zabránilo zaznamenávání žádostí z určitých hostitelů.

SetEnvIf Request_URI \.gif image-request
SetEnvIf Request_URI \.jpg image-request
SetEnvIf Request_URI \.png image-request

CustomLog "logs/access_log" common env=!image-request

Zabraňování "Krade obrázků"
Tento příklad ukazuje, jak zabránit lidem, kteří nejsou na vašem serveru, aby používali obrázky na vašem serveru jako inline-obrázky na jejich stránkách. Tato konfigurace není doporučována, ale může fungovat v omezených okolích. Předpokládáme, že všechny vaše obrázky jsou v adresáři nazvaném /web/images.

SetEnvIf Referer "^http://www\.example\.com/" local_referal # Povolit prohlížeče, které neposílají informace o Refereru
SetEnvIf Referer "^$" local_referal

<Directory "/web/images">
Require env local_referal
</Directory>

Další informace o této technice naleznete v článku "Zabránění umisťování vašich obrázků na jiné stránky" na ServerWatch.

Poznámka: Tento příklad předpokládá, že všechny vaše obrázky jsou v adresáři nazvaném /web/images. Pokud je to jinak, musíte upravit adresář v příkladu podle potřeby.

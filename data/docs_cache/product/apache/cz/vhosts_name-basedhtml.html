Virtuální hostování na základě názvů vs. IP-adres ¶
Virtuální hostování na základě IP adres používá IP adresu spojení k určení správného virtuálního hosta k poskytnutí. Proto musíte mít pro každý host oddělenou IP adresu. S virtuálním hostováním na základě názvů se server opírá o to, aby klient poslal správný název hostitele jako součást HTTP hlaviček. Tímto způsobem mohou být na stejné IP adrese hostované mnoho různých hostitelů. Virtuální hostování na základě názvů je obvykle jednodušší, protože musíte konfigurovat svůj DNS server tak, aby mapoval každý název hostitele na správnou IP adresu a poté Apache HTTP Server, aby rozpoznával různé názvy hostitelů. Virtuální hostování na základě názvů také snižuje požadavek na nezbytné IP adresy. Proto byste měli používat virtuální hostování na základě názvů, pokud nevyžaduje vaše vybavení explicitně IP-adresové hostování. Historické důvody pro IP-adresové hostování založené na podpoře klienta jsou už neplatné pro obecný účel webového serveru.

Jak server vybere správnou názevovou virtuální hostu ¶ Důležité je poznat, že první krok v rozlišování názevových virtuálních hostů je IP-závislé rozlišování. Rozlišování názevových virtuálních hostů vybere až poté nejvhodnější názevovou virtuální hostu po omezení kandidátů na nejlepší IP-závislou shodu. Použití divoké karty (*) pro IP adresu ve všech VirtualHost direktivách znevýhodňuje IP-závislé mapování. Když přijde požadavek, server najde nejlepší (nejspecifický) odpovídající <VirtualHost> argument podle IP adresy a portu používaného požadavkem. Pokud je více než jeden virtuální host obsahující tuto nejlepší kombinaci adresy a portu, Apache bude další porovnávat direktivy ServerName a ServerAlias s názvem serveru přítomným v požadavku. Pokud jste ServerName direktivu zanechali z jakéhokoliv názevového virtuálního hosta, server bude výchozí název serveru nastavit na plně kvalifikovaný název domény (FQDN) odvozený z názvu systému hostitele. Tento implicitně nastavený název serveru může vést k neintuitivnímu shodování virtuálních hostů a je znepokojující.

Nejlepší je vždycky explicitně zadat ServerName ve všech jménových virtuálních hostech. Pokud VirtualHost nezadá ServerName, bude serverové jméno děděno z bazového serverového konfiguračního souboru. Pokud žádné serverové jméno nebylo zadáno globálně, je detekováno při spuštění prostřednictvím reverzní DNS rozložení prvního posluchacího adresáře. V obou případech se tento děděný serverový název podílejí na rozlišování jménových virtuálních hostů, takže je nejlepší vždycky explicitně zadat ServerName ve všech jménových virtuálních hostech. Například, pokud sloužíte doménu www.example.com a chcete přidat virtuální host other.example.com, který ukazuje na stejný IP adresu, tak můžete to napsat do httpd.conf následovně:

&lt;VirtualHost *:80&gt;
  # Tento první uvedený virtuální host je také výchozí pro *:80
  ServerName www.example.com
  ServerAlias example.com
  DocumentRoot "/www/domain"
&lt;/VirtualHost&gt;
&lt;VirtualHost *:80&gt;
  ServerName other.example.com
  DocumentRoot "/www/otherdomain"
&lt;/VirtualHost&gt;

Můžete-li alternativně zadat explicitní IP adresu místo * v <VirtualHost> příkazech. Například můžete to udělat, abyste některé jménové virtuální hosty spoušteli na jedné IP adrese, a buď IP-závislé, nebo jinou sadu jménových virtuálních hostů na jiné adrese. Mnoho serverů chce být dostupné pod více jmény.

Další sadu virtuálních hostů na další adrese. Mnoho serverů chtějí být přístupné pod více než jedním názvem. Toto je možné pomocí příkazu ServerAlias umístěného v sekcii <VirtualHost>. Například v prvním bloku <VirtualHost> výše uvedeném, příkaz ServerAlias ukazuje, že uvedené názvy jsou další názvy, které mohou lidé použít k zobrazení stejného webu: ServerAlias example.com \*.example.com Potom žádosti pro všechny hosty v doméně example.com budou slouženy virtuálním hostem www.example.com. Wildcardové znaky \* a ? mohou být použity k odpovídání názvům. Zřejmě nemůžete prostě vytvořit názvy a umístit je do ServerName nebo ServerAlias. Musíte nejprve mít svůj server DNS správně nakonfigurovaného, aby mapoval tyto názvy na IP adresu spojenou s vaším serverem. Virtuální hosty pro nejlepší odpovídající sadu <virtualhost>s se zpracovávají v pořadí, ve kterém se objevují v konfiguraci. První odpovídající ServerName nebo ServerAlias se používá, bez žádného jiného přednostního postavení pro wildcards (nebo pro ServerName vs. ServerAlias). Celý seznam názvů v příkazu VirtualHost se považuje za stejné, jako (ne-wildcard) ServerAlias. Nakonec můžete upravit konfiguraci virtuálních hostů umístěním dalších příkazů v kontaineru <VirtualHost>.

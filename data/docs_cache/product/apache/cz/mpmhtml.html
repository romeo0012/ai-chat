Multi-Processing Modules (MPMs)

Následující text popisuje, co je Multi-Processing Module (MPM) a jak jsou používány Apache HTTP Serverem.

Úvod

Apache HTTP Server je navržen jako silný a flexibilní webový server, který může fungovat na velmi širokém spektru platform a různých prostředí. Různé platformy a různé prostředí často vyžadují různé funkce nebo mohou mít různé způsoby implementace stejné funkce nejefektivněji. Apache httpd vždy podporoval širokou škálu prostředí díky své modulární koncepci. Tato koncepce dovoluje správci webu vybrat, které funkce budou součástí serveru, tím, že vybere, které moduly se budou načíst buď při kompilaci nebo běhu. Apache HTTP Server 2.0 rozšiřuje tuto modulární koncepci až na základní funkce webového serveru. Server dodává výběr Multi-Processing Modules (MPMs), které jsou odpovědné za vázání se na sítové porty na stroji, přijímání požadavků a vysílání dětí k zpracování požadavků. Rozšíření modulární koncepce na tuto úroveň serveru umožňuje dvě důležité výhody: Apache httpd může čistěji a efektivněji podporovat širokou škálu operačních systémů.

Server umožňuje dvě důležité výhody: Apache httpd může více čistě a efektivně podporovat širokou škálu operačních systémů. Zvláště Windows verze serveru je nyní velmi efektivnější, protože mpm_winnt může použít nativní sítové funkce místo POSIX vrstvy používané v Apache httpd 1.3. Tato výhoda se týká i ostatních operačních systémů, které implementují specializované MPMs. Server lze lépe upravit podle potřeb konkrétního webu. Například webové stránky, které potřebují velkou škálovatelnost, mohou volit sekvenční MPM jako prefork, zatímco webové stránky, které požadují stabilitu nebo kompatibilitu s starším software, mohou použít prefork MPM. Na úrovni uživatele MPM vypadají jako jiné moduly Apache httpd. Hlavní rozdíl spočívá v tom, že do serveru musí být nahrána pouze jedna MPM v daný čas. Seznam dostupných MPM se objeví na stránce se seznamem modulů.

Výchozí MPM ¶ Následující tabulka uvádí výchozí MPM pro různé operační systémy. Tento MPM bude vybrán, pokud neuděláte jiný výběr při kompilaci.

Netwarempm_netware
os2mpmt_os2
Unixprefork, worker, nebo event, podle schopností platformy
Windowsmpm_winnt
Zde 'Unix' znamená operační systémy podobné Unixu, jako například Linux, BSD, Solaris, Mac OS X atd. V případě Unixu se rozhodne, která MPM bude nainstalována na základě dvou otázek:

  1. Podporuje systém vlákna?
  1. Rozhodnutí o instalaci daného MPM je založeno na dvou otázkách: 1. Podporuje systém vlákna? 2. Podporuje systém vlákna bezpečný polling (Zvláště funkce kqueue a epoll)? Pokud odpověď na obě otázky je 'ano', výchozím MPM bude event. Pokud odpověď na #1 je 'ano', ale na #2 je 'ne', výchozím bude worker. Pokud odpověď na obě otázky je 'ne', pak výchozím MPM bude prefork. V praxi to znamená, že výchozím bude většinou event, protože všechny moderní operační systémy podporují tyto dvě funkce. Výstavba MPM jako statický modul ¶ MPMs mohou být vytvořeny jako statické moduly na všech platformách. Vybraný MPM je zvolen při sestavování a spojený do serveru. Server musí být znovu sestaven, aby se změnil MPM. Chcete-li překonat výchozí volbu MPM, použijte opci --with-mpm=NAME skriptu configure. NAME je název požadovaného MPM. Po sestavení serveru je možné určit, který MPM byl zvolen, pomocí příkazu ./httpd -l. Tento příkaz vytiskne seznam každého modulu, který je sestaven do serveru, včetně MPM. Výstavba MPM jako DSO modul ¶ Na platformách Unix a podobných mohou být MPMs vytvořeny jako DSO moduly a dynamicky nahrány do serveru stejným způsobem jako jiné DSO moduly. Výstavba MPM jako DSO moduly umožňuje změnu MPM aktualizací direktivy LoadModule pro MPM místo znovusestavování serveru. LoadModule mpm_event_module modules/mod_mpm_event.

Chcite se změnit updatováním direktivy LoadModule pro MPM místo přestavováním serveru. LoadModule modul_mpm_event_module modules/mod_mpm_event.so Pokus o načtení více než jednoho MPM vede k selhání při spuštění s následujícím chybovým zprávou. AH00534: httpd: Chyba konfigurace: Načteno více než jeden MPM. Tato funkce je povolena pomocí možnosti --enable-mpms-shared skriptu konfigurace. S argumentem all budou na platformě instalovány všechny možné MPMs. Alternativně může seznam MPMs být zadán jako argument. Vybraný MPM, buď automaticky vybraný nebo zadaný pomocí možnosti --with-mpm skriptu konfigurace, bude načten v generovaném serverovém konfiguračním souboru. Upravte direktivu LoadModule, aby byl vybrán jiný MPM.

Poznámka: Tento text popisuje, jak změnit MPM Apache serveru pomocí updatování direktivy LoadModule namísto přestavování serveru. LoadModule mpm_event_module modules/mod_mpm_event.so je příklad direktivy, která načítá modul MPM_event. Pokus o načtení více než jednoho MPM vede k selhání při spuštění serveru. Tato chyba může být vyřešena upravou direktivy LoadModule, aby byla načtena jiná MPM. Tato funkce je povolena pomocí možnosti --enable-mpms-shared skriptu konfigurace. S argumentem all budou na platformě instalovány všechny možné MPMs. Alternativně může seznam MPMs být zadán jako argument. Vybraný MPM, buď automaticky vybraný nebo zadaný pomocí možnosti --with-mpm skriptu konfigurace, bude načten v generovaném serverovém konfiguračním souboru.

What is IP-based virtual hosting

IP-based virtual hosting is a method to apply different directives based on the IP address and port a request is received on. Most commonly, this is used to serve different websites on different ports or interfaces. In many cases, name-based virtual hosts are more convenient, because they allow many virtual hosts to share a single address/port. See [Name-based vs. IP-based Virtual Hosts](https://httpd.apache.org/docs/current/vhosts/name_based.html) to help you decide.

System requirements

As the term IP-based indicates, the server must have a different IP address/port combination for each IP-based virtual host. This can be achieved by the machine having several physical network connections, or by use of virtual interfaces which are supported by most modern operating systems (see system documentation for details, these are frequently called "ip aliases", and the "ifconfig" command is most commonly used to set them up), and/or using multiple port numbers. In the terminology of Apache HTTP Server, using a single IP address but multiple TCP ports, is also IP-based virtual hosting.

How to set up Apache

There are two ways of configuring apache to support multiple hosts.

  1. Including multiple configuration files: You can create a separate configuration file for each virtual host and include them in the main server configuration file using the Include directive. For example:

# Main server configuration file
Include virtual host configurations

Include /etc/httpd/conf.d/*.conf

Each virtual host configuration file should start with a <VirtualHost> directive specifying the IP address and port number. For example:

# Virtual host configuration for example.com
&lt;VirtualHost 192.168.1.100:80&gt;
    ServerName example.com
    DocumentRoot /var/www/example.com
    ...
&lt;/VirtualHost&gt;
  1. Using the NameVirtualHost and <VirtualHost> directives: You can also configure multiple virtual hosts directly in the main server configuration file using the NameVirtualHost and <VirtualHost> directives. The NameVirtualHost directive specifies the IP address and port number to listen on, and the <VirtualHost> directives specify the virtual hosts. For example:

# Main server configuration file
Listen on IP address and port

NameVirtualHost 192.168.1.100:80
Virtual host configuration for example.com

&lt;VirtualHost 192.168.1.100:80&gt;
    ServerName example.com
    DocumentRoot /var/www/example.com
    ...
&lt;/VirtualHost&gt;
Virtual host configuration for anotherdomain.com

&lt;VirtualHost 192.168.1.100:80&gt;
    ServerName anotherdomain.com
    DocumentRoot /var/www/anotherdomain.com
    ...
&lt;/VirtualHost&gt;

Setting up multiple daemons

Apache can run multiple daemons, each serving a different IP-based virtual host. To start multiple daemons, you can use the apachectl command with the -f option to specify the configuration file for each daemon. For example:

# Start the first daemon serving example.com
apachectl -f /etc/httpd/conf.d/example.com.conf start
Start the second daemon serving anotherdomain.com

apachectl -f /etc/httpd/conf.d/anotherdomain.com.conf start

Setting up a single daemon with virtual hosts

If you want to run a single Apache daemon and serve multiple virtual hosts, you can use the NameVirtualHost and <VirtualHost> directives as described above.

Virtuální hosting na základě IP adres. Jak nakonfigurovat Apache ¶
Existují dvě možnosti konfigurace Apache pro podporu více hostitelů. Buďte pomocí spuštění odděleného daemona httpd pro každý hostname, nebo pomocí spuštění jednoho daemona, který podporuje všechny virtuální hosty. Použijte více daemonů, pokud:

  • Je nutné řešit otázky zabezpečení oddělení, například společnost1 nechce, aby někdo z společnosti2 mohl číst její data kromě webu. V tomto případě budete potřebovat dva daemony, každý s různými nastaveními User, Group, Listen, a ServerRoot. Můžete se vzpomínat na požadavky paměti a počtu popisovačů souborů, aby mohl poslouchat každou IP alias na stroji. Je možné poslouchat pouze "wildcard" adresu nebo konkrétní adresy. Pokud potřebujete poslouchat konkrétní adresu pro jakoukoli důvod, musíte poslouchat všechny konkrétní adresy. (Ačkoli může jeden httpd poslouchat N-1 adres, zatímco druhý poslouchá zbývající adresu.)

Použijte jeden daemon, když:

  • Je přijatelné sdílet konfiguraci httpd mezi virtuální hosty.
  • Služba má obsloužit velký počet požadavků, a tak mohou být významné ztráty výkonu při spuštění oddělených daemonů.

Nastavení více daemonů ¶
Vytvořte oddělenou instalaci httpd pro každého virtuálního hostitele. Pro každou instalaci použijte příkaz Listen v konfiguračním souboru, aby vybral, která IP adresa (nebo virtuální host) slouží tento daemon. Například Listen 192.0.2.

Nastavení jednoho daemona s virtuálními hostiteli ¶ V tomto případě jeden httpd služební požadavky pro hlavní server a pro všechny virtuální hostitele. Direktiva VirtualHost v konfiguračním souboru se používá k nastavení hodnot ServerAdmin, ServerName, DocumentRoot, ErrorLog a TransferLog nebo CustomLog konfiguračních direktiv na různé hodnoty pro každý virtuální host. Například:

<VirtualHost 172.20.30.40:80>
ServerAdmin webmaster@www1.example.com
DocumentRoot "/www/vhosts/www1"
ServerName www1.example.com
ErrorLog "/www/logs/www1/error_log"
CustomLog "/www/logs/www1/access_log" combined
</VirtualHost>
<VirtualHost 172.20.30.50:80>
ServerAdmin webmaster@www2.example.org
DocumentRoot "/www/vhosts/www2"
ServerName www2.example.org
ErrorLog "/www/logs/www2/error_log"
CustomLog "/www/logs/www2/access_log" combined
</VirtualHost>
Je doporučeno použít IP adresu místo hostname v direktivě <VirtualHost> (viz DNS závady). Konkrétní IP adresy nebo porty mají přednost před jejich wildcardovými ekvivalenty, a každý virtuální host, který odpovídá, má přednost před konfigurací základního serveru.

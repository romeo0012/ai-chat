Podporované jazyky pro suEXEC v Apache HTTP Server: en | fr | ja | ko | tr

Funkce suEXEC umožňuje uživatelům Apache HTTP Serveru spouštět CGI a SSI programy pod uživatelskými IDs jinými než uživatelským IDm webového serveru. Obvykle, když se CGI nebo SSI program spouští, spouští se pod stejným uživatelským IDm, které spouští webový server. Použití této funkce může významně snížit rizika zabezpečení, která mohou být spojena s umožněním uživatelům vytvářet a spouštět soukromé CGI nebo SSI programy. Pokud je suEXEC nesprávně nakonfigurováno, může to způsobit libovolné počet problémů a možná vytvořit nové díry v zabezpečení vašeho počítače. Pokud se s řízením programů s oprávněním root nesmíte zabývat a nejsou si vědomi rizik, která představují, nám doporučujeme, abyste se suEXEC nepokoušeli používat.

Po dokončení všech komponent můžete spustit příkaz make install, aby je instalovaly. Obrazovka suEXEC je instalována do adresáře definovaného možností --sbindir. Nastavení paranoidních oprávnění although the suEXEC wrapper will check to ensure that its caller is the correct user as specified with the --with-suexec-caller configure option, there is always the possibility that a system or library call suEXEC uses before this check may be exploitable on your system. To counter this, and because it is best-practice in general, you should use filesystem permissions to ensure that only the group httpd runs as may execute suEXEC.

Zapnutí a Vypnutí suEXEC ¶ Při spuštění httpd, hledá po souboru suexec v adresáři definovaném opcí --sbindir (výchozí hodnota je "/usr/local/apache/sbin/suexec"). Pokud httpd nalezne správně nakonfigurovaný suEXEC wrapper, vytiskne následující zprávu do souboru chyb: [notice] suEXEC mechanismus povolen (wrapper: /cesta/k/suexec) Pokud se tato zpráva nezobrazí při spuštění serveru, je pravděpodobné, že server nenáleží wrapper program v místě, kde očekává, nebo není instalován jako setuid root. Pokud chcete povolit suEXEC mechanismus poprvé a je již běžící Apache HTTP Server, musíte zabít a restartovat httpd. Restartování pomocí jednoduchého signálu HUP nebo USR1 nebude dostačující. Pokud chcete suEXEC mechanismus vypnout, musíte zabít a restartovat httpd po odstranění souboru suexec.

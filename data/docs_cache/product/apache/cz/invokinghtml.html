Začátek Apache Dostupné jazyky: de | en | es | fr | ja | ko | pt-br | tr Na Windows systému Apache bývá obvykle spouštěn jako služba. Další informace naleznete v článku Spuštění Apache jako služba. Na Unixu se program httpd spouští jako demon, který běží nepřerušovaně v pozadí, aby obsluhoval požadavky. Tento dokument popisuje, jak spustit httpd. Jak Apache spouští ¶ Pokud je v konfiguračním souboru uveden port poslechu jako výchozí hodnota 80 (nebo jakýkoli jiný port pod 1024), je nutné mít privilegia správce, aby se mohlo Apache spustit, a protože může se vázat na tuto privilegovanou portu. Po spuštění serveru a provedení několika inicializačních aktivit, jako je otevření svých logovacích souborů, spustí několik dětských procesů, které provádějí práci poslechu a odpovědi na požadavky klientů. Hlavní proces httpd pokračuje v běhu jako uživatel s právy správce, ale dětské procesy běží jako méně privilegovaný uživatel. Toto je řízeno vybraným Modulem Procesování v množství. Doporučeným způsobem spuštění spustitelného souboru httpd je použitím skriptu apachectl kontroly. Tento skript nastaví určité prostředí proměnné, které jsou nutné pro httpd pro správnou funkci pod některými operačními systémy, a pak spouští binární soubor httpd. Skript apachectl přenese všechny argumenty příkazového řádku, takže mohou být také použity jakékoliv možnosti httpd s apachectl.

URL adresáře Apache. Příkaz apachectl přenese všechny argumenty příkazového řádku, takže můžete také použít libovolné možnosti httpd s apachectl. Můžete také přímo upravovat skript apachectl změnou proměnné HTTPD blízko vrcholu, aby určila správnou lokaci bináře httpd a libovolné argumenty příkazového řádku, které by měly být stále přítomny. První věc, kterou provede httpd po spuštění, je lokalizovat a číst konfigurační soubor httpd.conf. Umístění tohoto souboru je nastaveno při kompilaci, ale je možné ho určit i během spuštění pomocí možnosti -f příkazového řádku, například /usr/local/apache2/bin/apachectl -f /usr/local/apache2/conf/httpd.conf Pokud se vše při spouštění daří, server se odpojí od terminálu a příkazový řádek se vrátí prakticky okamžitě. Toto ukazuje, že server je spuštěn. Poté můžete použít prohlížeč k připojení k serveru a zobrazení testovací stránky v adresáři DocumentRoot. Chyby při spouštění ¶ Pokud Apache utrpí těžkou chybu při spouštění, zaznamená popis chyby buď do konzole nebo do ErrorLog a poté ukončí. Jedna z nejběžnějších chybových zpráv je "Nelze se připojit k Portu ...". Tato zpráva je obvykle způsobena buď tím, že se pokoušíte spustit server na privilegovaném portu, když není přihlášen jako uživatel root; nebo tím, že se pokoušíte spustit server, když je už jiná instance Apache nebo nějaký jiný webový server již vázaná na stejný Port.

Pokud je na stejném portu již spuštěna jiná instanci Apache nebo jiný webový server, může to způsobit problémy. Pro další návody k řešení problémů přečtěte si Apache FAQ. Začátek při spuštění systému ¶ Pokud chcete, aby vaše serverová aplikace pokračovala po obnovení systému, byste měli přidat volání apachectl do souborů systémového spouštění (obvykle rc.local nebo soubor v adresáři rc.N). Tímto způsobem se spustí Apache jako root. Než to uděláte, ujistěte se, že je vaše serverová aplikace správně nakonfigurovaná pro bezpečnost a omezení přístupu. Skript apachectl je navržen jako standardní skript SysV init; může přijímat argumenty start, restart a stop a přeložit je do vhodných signálů pro httpd. Takže můžete často jednoduše vytvořit odkaz na apachectl do správného adresáře iniciačních skriptů. Ale ujistěte se, že zkontrolujete právě potřebné požadavky vašeho systému. Také je k dispozici dokumentace k všem modulům zahrnutým s Apache distribucí a příkazům, které poskytují.

Apache HTTP Server wird durch die Platzierung von Direktiven in einfach textbasierte Konfigurationsdateien konfiguriert. Die Hauptkonfigurationsdatei wird normalerweise als httpd.conf bezeichnet. Der Ort dieser Datei wird bei der Compile-Zeit festgelegt, kann jedoch mit dem -f Befehl der Befehlszeile überschrieben werden. Zusätzlich können weitere Konfigurationsdateien hinzugefügt werden, indem die Include-Direktive verwendet wird, und Wildcards können verwendet werden, um viele Konfigurationsdateien einzubinden. Jede Direktive kann in jedem dieser Konfigurationsdateien platziert werden. Änderungen an den Hauptkonfigurationsdateien werden nur von httpd erkannt, wenn es gestartet oder neu gestartet wird. Der Server liest zudem eine Datei mit MIME-Dokumenttypen; der Dateiname wird durch die TypesConfig-Direktive festgelegt, und ist mime.types standardmäßig.

Syntax der Konfigurationsdateien
¶
httpd-Konfigurationsdateien enthalten eine Direktive pro Zeile. Der Backslash "\" kann als letztes Zeichen einer Zeile verwendet werden, um anzugeben, dass die Direktive auf die nächste Zeile fortgesetzt wird. Um als solche Fortsetzung interpretiert zu werden, muss zwischen dem Backslash und dem Ende der Zeile kein anderes Zeichen oder Leerzeichen vorhanden sein. Zeilen, die mit dem Hashzeichen "#" beginnen, werden als Kommentare betrachtet und ignoriert.

Am Ende der Zeile. Zeilen, die mit dem Hash-Zeichen "#" beginnen, werden als Kommentare betrachtet und ignoriert. Kommentare dürfen nicht auf der gleichen Zeile wie eine Konfigurationsdirektive stehen, einschließlich des Starts einer Zeile, die wie in der vorhergehenden Paragraph beschrieben fortgesetzt wird. Kommentierte Zeilen können auch fortgesetzt werden, d.h. die nächste physische Zeile wird ebenfalls als Kommentar interpretiert, weil die logische Zeile mit einem Hash-Zeichen beginnt. Leerzeichen, die vor einer Direktive vorkommen, werden ignoriert, also können Direktiven für Klarheit indiziert werden. Leerzeilen werden auch ignoriert. Argumente zu Direktiven werden durch Leerzeichen getrennt. Wenn ein Argument Leerzeichen enthält, muss das Argument in Anführungszeichen eingeschlossen werden. Klammern oder Ausweichzeichen können sowohl Doppel-Anführungszeichen (") als auch Einzel-Anführungszeichen (') verwendet werden, um ein Argument mit Leerzeichen einzuschließen. Die Anführungszeichen selbst gehören nicht zum Argument. In einer zitierten Zeichenkette werden nur zwei Escape-Sequenzen anerkannt: \\ produziert eine literale Backslash, und \" (oder \' wenn die Zeichenkette einzel-zitiert ist) produziert eine literale Anführungszeichen ohne das Ende der Zeichenkette. Alle anderen Backslash-Sequenzen werden unverändert übergeben – z.B. \n ist die literale zwei Zeichen \n, nicht eine Zeilenumbrüche. Außerhalb von Anführungszeichen hat der Backslash keinen speziellen Sinn und wird als literales Zeichen behandelt. Die einzige Ausnahme ist der Zeilen-Weiterführungs-Backslash am Ende einer Zeile, wie oben beschrieben.

Bemerkt, dass benachbarte angeführte Zeichensträngen ohne Zwischenraum nicht konkateniert werden – sie werden als separate Argumente interpretiert. Beispiel: # Dies ist ZWEI Argumente, nicht eins: Header set X-Foo "bar""baz" Es gibt Direktiven, die Argumente akzeptieren, die Sub-Ausdrücke mit ihrer eigenen Syntax enthalten, wie z.B. RewriteRule-Flags oder ap_expr-Ausdrücke. In solchen Fällen entfernt der Konfigurationsdateiparser zunächst die umgebenden Anführungszeichen und verarbeitet Backslash-Escapes wie oben beschrieben, bevor der Parser der Direktive den Ergebniswert verarbeitet. Wenn es Zweifel gibt, um ein Argument, das Backslashes enthält, mit Einfachankführungszeichen umgeben zu lassen, kann die unerwartete Doppelverarbeitung von Escape-Sequenzen vermieden werden. Direktiven in den Konfigurationsdateien sind unabhängig vom Fall, aber Argumente zu Direktiven sind oft fallunabhängig. Die Werte von Variablen, die mit Define oder shell Umgebungsvariablen definiert wurden, können in Zeilen der Konfigurationsdatei mithilfe des Syntax-Musters ${VAR} verwendet werden. Wenn "VAR" der Name einer gültigen Variablen ist, wird der Wert dieser Variablen an dieser Stelle in der Konfigurationsdatei eingesetzt und die Verarbeitung fortgesetzt, als ob das Textstück direkt in der Konfigurationsdatei vorhanden wäre. Variablen, die mit Define definiert wurden, haben Vorrang vor shell Umgebungsvariablen. Wenn die "VAR"-Variable nicht gefunden wird, bleiben die Zeichen ${VAR} unverändert und ein Warnungseintrag wird erstellt.

Related ModulesRelated Directivesmod_so

mod_so ist eine modulare Server-Software. Das bedeutet, dass nur die grundlegendsten Funktionen in der Kern-Software enthalten sind. Erweiterte Funktionen sind über Modulen verfügbar, die in httpd geladen werden können. Voreingestellt ist ein Standard-Set von Modulen in den Server bei der Kompilierung enthalten.

Dieses kann in httpd geladen werden. Standardmäßig enthält der Server bei der Kompilierung eine Basis-Menge an Modulen. Wenn der Server zur Verwendung von dynamisch geladenen Modulen kompiliert wird, können Modulen separat kompiliert und jederzeit mithilfe des LoadModule-Direktivs hinzugefügt werden. Andernfalls muss httpd neu kompiliert werden, um Modulen hinzuzufügen oder zu entfernen. Konfigurationsbefehle können bedingt auf den Vorhandensein eines bestimmten Moduls umfasst werden, indem sie in einem <IfModule>-Block eingeschlossen werden. Allerdings sind <IfModule>-Blöcke nicht erforderlich, und in manchen Fällen können sie darauf hinweisen, dass man ein wichtiges Modul vergessen hat. Um zu sehen, welche Modulen derzeit in den Server integriert sind, kann man den -l-Option auf der Befehlszeile verwenden. Man kann auch mithilfe der -M-Option auf der Befehlszeile sehen, welche Modulen dynamisch geladen werden. Bereich von Befehlen ¶ Verwandte ModuleVerwandte Befehle<Directory><DirectoryMatch><Files><FilesMatch><Location><LocationMatch><VirtualHost> Direktiven, die in den Hauptkonfigurationsdateien platziert werden, gelten für den gesamten Server. Wenn man die Konfiguration nur für einen Teil des Servers ändern möchte, kann man die Direktiven durch Platzieren in <Directory>, <DirectoryMatch>, <Files>, <FilesMatch>, <Location> und <LocationMatch>-Abschnitten eingrenzen. Diese Abschnitte beschränken die Anwendung der Direktiven, die sie umfassen, auf bestimmte Dateisystemorte oder URLs. Sie können auch vernestet werden, was sehr fein granulierte Konfiguration ermöglicht. httpd kann viele verschiedene Websites gleichzeitig anbieten. Dies heißt Virtual Hosting.

Für fein granulierte Konfiguration ist httpd in der Lage, simultane simultane simultane an verschiedene Websites zu dienen. Dies wird als Virtual Hosting bezeichnet. Direktiven können auch in <VirtualHost>-Abschnitten eingeschlossen werden, damit sie nur für Anfragen einer bestimmten Website gelten. Obwohl die meisten Direktiven in jedem dieser Abschnitte platziert werden können, gibt es Direktiven, die in bestimmten Kontexten nicht sinnvoll sind. Beispielsweise können Direktiven, die die Prozessschöpfung steuern, nur in dem Hauptserver-Kontext platziert werden. Um herauszufinden, in welchen Abschnitten welche Direktiven platziert werden können, überprüfen Sie den Kontext der Direktive. Related ModulesRelated DirectivesAccessFileNameAllowOverride

httpd ermöglicht die dezentrale Verwaltung von Konfigurationen über spezielle Dateien, die innerhalb des Web-Baums platziert werden. Die speziellen Dateien werden normalerweise .htaccess genannt, aber jeder Name kann in der AccessFileName-Direktive angegeben werden. Direktiven, die in .htaccess-Dateien platziert werden, gelten für das Verzeichnis, in dem Sie die Datei platziert haben, und alle Unterverzeichnisse. Die .htaccess-Dateien folgen der gleichen Syntax wie die Hauptkonfigurationsdateien. Da .htaccess-Dateien auf jede Anfrage gelesen werden, treten Änderungen sofort in Kraft. Um herauszufinden, welche Direktiven in .htaccess-Dateien platziert werden können, überprüfen Sie den Kontext der Direktive. Der Serveradministrator kontrolliert weiterhin, welche Direktiven in .htaccess-Dateien platziert werden können, indem er die AllowOverride-Direktive in den Hauptkonfigurationsdateien konfiguriert. Weitere Informationen zu .htaccess-Dateien finden Sie im .htaccess-Tutorial.

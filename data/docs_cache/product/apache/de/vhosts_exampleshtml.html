Verwendung von _default_-vhosts ¶
_default_-vhosts für alle Ports
Fängt jeden Anfrage an, die an eine unbestimmte IP-Adresse und Port gesendet wird, also eine Adresse/Port-Kombination, die für keinen anderen virtuellen Host verwendet wird.

<VirtualHost _default_:*>
DocumentRoot "/www/default"
</VirtualHost>

Verwendung einer solchen default-vhost mit einem Wildcard-Port verhindert, dass jede Anfrage an den Hauptserver gelangt. Eine default-vhost dient nie einer Anfrage, die an eine Adresse/Port gesendet wurde, die für name-basierte vhosts verwendet wird. Wenn die Anfrage einen unbekannten oder keinen Host: Header enthält, wird sie immer von der primären name-basierten vhost (die vhost für diese Adresse/Port in der Konfigurationsdatei erst auftaucht) abgearbeitet. Sie können AliasMatch oder RewriteRule verwenden, um jede Anfrage auf eine einzelne Informationsseite (oder Skript) zu umleiten.

_default_-vhosts für verschiedene Ports
Dieselbe Einrichtung wie oben, aber der Server hört auf mehreren Ports und wir möchten eine zweite default-vhost für Port 80 verwenden.

<VirtualHost _default_:80>
DocumentRoot "/www/default80"
# ...
</VirtualHost>
<VirtualHost _default_:*>
DocumentRoot "/www/default"
# ...
</VirtualHost>

Ein zweiter _default_-Virtueller Host für Port 80.

&lt;VirtualHost _default_:80&gt;
 DocumentRoot "/www/default80"  # ...
&lt;/VirtualHost&gt;
&lt;VirtualHost _default_:*&gt;
 DocumentRoot "/www/default"  # ...
&lt;/VirtualHost&gt;

Der _default_-Virtueller Host für Port 80 (der vor jedem _default_-Virtuellen Host mit einer Wildcard-Portnummer auftreten muss) fängt alle Anfragen auf, die an eine unbestimmte IP-Adresse gesendet wurden. Der Hauptserver wird nie verwendet, um eine Anfrage abzurufen. _default_-Virtuelle Hosts für einen Port

Wir möchten einen _default_-Virtuellen Host für Port 80 haben, aber keine anderen.

&lt;VirtualHost _default_:80&gt;
 DocumentRoot "/www/default"  ...
&lt;/VirtualHost&gt;

Eine Anfrage an eine unbestimmte Adresse auf Port 80 wird von dem _default_-Virtuellen Host abgerufen. Jede andere Anfrage an eine unbestimmte Adresse und Port wird von dem Hauptserver abgerufen. Jede Verwendung von * in einer VirtualHost-Deklaration wird eine höhere Priorität als _default_ haben.

Der vhost kann jetzt über die neue Adresse (als IP-basierter vhost) und über die alte Adresse (als name-basierter vhost) erreicht werden. Mithilfe der ServerPath-Direktive ¶

Wir haben einen Server mit zwei name-basierten vhosts. Um den richtigen virtuellen Host zu treffen, muss der Client den richtigen Host: Header senden. Alte HTTP/1.0-Client senden keinen solchen Header und Apache weiß nicht, welchen vhost der Client versucht zu erreichen (und dient die Anfrage von der primären vhost). Um möglichst viel Rückwärtskompatibilität zu gewährleisten, erstellt man eine primäre vhost, die eine einzelne Seite zurückgibt, die Links mit einem URL-Präfix zu den name-basierten virtuellen Hosts enthält.

<VirtualHost 172.20.30.40>
# primäre vhost
DocumentRoot "/www/subdomain"
RewriteEngine On
RewriteRule "." "/www/subdomain/index.html"
# ...
</VirtualHost>

<VirtualHost 172.20.30.40>
DocumentRoot "/www/subdomain/sub1"
ServerName www.sub1.domain.tld
ServerPath "/sub1/"
RewriteEngine On
RewriteRule "^(/sub1/.*)" "/www/subdomain$1"
# ...
</VirtualHost>

<VirtualHost 172.20.30.40>
DocumentRoot "/www/subdomain/sub2"
ServerName www.sub2.domain.tld
ServerPath "/sub2/"
RewriteEngine On
RewriteRule "^(/sub2/.*)" "/www/subdomain$1"
# ...
</VirtualHost>

Der vhost kann jetzt über die neue Adresse (als IP-basierter vhost) und über die alte Adresse (als name-basierter vhost) erreicht werden. Mithilfe der ServerPath-Direktive können wir versuchen, den richtigen virtuellen Host zu treffen, wenn der Client keinen Host: Header sendet.

"^(/sub1/.*)" "/www/subdomain$1" # ... </VirtualHost>
<VirtualHost 128.194.50.60>
DocumentRoot "/www/subdomain/sub1"
ServerName www.sub1.domain.tld
ServerPath "/sub1/"
RewriteEngine On
RewriteRule "^(/sub1/.*)" "/www/subdomain$1" # ... </VirtualHost>

Durch die ServerPath-Direktive wird eine Anfrage an die URL <http://www.sub1.domain.tld/sub1/> immer von der sub1-vhost bereitgestellt. Eine Anfrage an die URL <http://www.sub1.domain.tld/> wird nur von der sub1-vhost bereitgestellt, wenn der Client einen korrekten Host: Header gesendet hat. Wenn kein Host: Header gesendet wird, erhält der Client die Informationen-Seite von der primären Domäne. Bitte beachten Sie, dass es eine seltsame Eigenschaft gibt: Eine Anfrage an <http://www.sub2.domain.tld/sub1/> wird auch von der sub1-vhost bereitgestellt, wenn der Client keinen Host: Header gesendet hat. Die RewriteRule-Direktiven werden verwendet, um sicherzustellen, dass ein Client, der einen korrekten Host: Header gesendet hat, beide URL-Varianten verwenden kann, also mit oder ohne URL-Präfix.

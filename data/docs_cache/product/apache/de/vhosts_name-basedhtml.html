Name-basierter vs. IP-basierter Virtual Hosts ¶
IP-basierte Virtual Hosts nutzen die IP-Adresse der Verbindung, um die richtige Virtual Host zu serven. Daher benötigt man für jeden Host eine separate IP-Adresse. Mit name-basierter Virtual Hosting hängt der Server an den Client, um den Hostnamen als Teil der HTTP-Headers zu melden. Mit dieser Technik können viele verschiedene Hosts die gleiche IP-Adresse teilen. Name-basierter Virtual Hosting ist normalerweise einfacher, da man nur die DNS-Server konfigurieren muss, um jeden Hostnamen auf die richtige IP-Adresse zu zeigen und anschließend die Apache HTTP Server konfigurieren muss, um die verschiedenen Hostnamen zu erkennen. Name-basierter Virtual Hosting erleichtert auch die Anforderung nach knappen IP-Adressen. Daher sollte man name-basierter Virtual Hosting verwenden, es sei denn, man verwendet Geräte, die explizit IP-basiertes Hosting verlangen. Historische Gründe für IP-basiertes Virtual Hosting aufgrund von Client-Unterstützung sind für einen allgemeinen Zweck Webserver nicht mehr relevant.

Wirtspeicherung. Historische Gründe für die IP-basierte virtuelle Hosting aufgrund der Kundenunterstützung sind nicht mehr für einen allgemein Zweck webserver relevant. Namebasiertes virtuelles Hosting baut auf der IP-basierten virtuellen Hostauswahlalgorithmen auf, bedeutet also, dass Suche nach dem passenden Servernamen nur zwischen virtuellen Hosts erfolgt, die die beste IP-basierte Adresse haben. Wie der Server die passende namebasierte virtuelle Host auswählt ¶ Es ist wichtig zu erkennen, dass der erste Schritt bei der Auflösung des namebasierten virtuellen Hosts die IP-basierte Auflösung ist. Namebasiertes virtuelles Hosting wählt nur den passendsten namebasierten virtuellen Host nach, nachdem die Kandidaten auf die beste IP-basierte Übereinstimmung reduziert wurden. Durch das Verwenden eines Wildcards (*) für die IP-Adresse in allen VirtualHost-Direktiven wird diese IP-basierte Zuordnung irrelevant. Wenn eine Anfrage eintrifft, sucht der Server den passenden (spezifischsten) <VirtualHost>-Argument basierend auf der IP-Adresse und dem verwendeten Port der Anfrage. Wenn es mehr als eine virtuelle Host gibt, die diese beste-match-Adresse und Port-Kombination enthalten, wird Apache weitere Vergleiche der ServerName und ServerAlias-Direktiven mit dem Servernamen in der Anfrage durchführen. Wenn Sie die ServerName-Direktive von jeder namebasierten virtuellen Host auslassen, wird der Server standardmäßig auf eine voll qualifizierte Domainname (FQDN) zurückgreifen, die vom Systemhostnamen abgeleitet wird. Diese implizit gesetzte Servername kann zu unintuitivem virtuellem Host-Zuordnung führen und wird abgelehnt.

Der erste Schritt ist, ein <VirtualHost> Block für jeden unterschiedlichen Host zu erstellen, den Sie dienstleisten möchten. In jedem <VirtualHost> Block müssen Sie mindestens eine ServerName-Direktive, um anzugeben, welcher Host dienstgeleitet wird, und eine DocumentRoot-Direktive, um anzugeben, wo im Dateisystem das Inhalt für diesen Host liegt. Haupt-Host geht weg Jede Anfrage, die kein passendes <VirtualHost> entspricht, wird von der globalen Serverkonfiguration behandelt, unabhängig von dem Hostnamen oder ServerName. Wenn Sie eine name-basierte virtuelle Host-Erweiterung an einen bestehenden Server hinzufügen und die virtuellen Host-Argumente mit vorhandenen IP und Port-Kombinationen übereinstimmen, werden jetzt Anfragen von einer expliziten virtuellen Host behandelt. In diesem Fall ist es meistens sinnvoll, einen Standard-virtuellen Host mit einem ServerName, der dem Basisserver entspricht, zu erstellen. ServerName-Erbschaft Es ist am besten, immer eine ServerName ausdrücklich in jeder namensbasierten virtuellen Host aufzuführen. Wenn kein VirtualHost eine ServerName angibt, wird eine Servername aus der Basisserverkonfiguration geerbt. Wenn keine Servername weltweit angegeben wurde, wird eine bei Startup durch umkehrten DNS-Auflösung des ersten lauschenden Adresses erkannt. In jedem Fall beeinflusst die ererbte Servername die Auflösung namensbasierter virtueller Hosts, deshalb ist es am besten, immer eine ServerName ausdrücklich in jeder namensbasierten virtuellen Host aufzuführen. Beispielhaft sei angenommen, dass Sie die Domäne www.beispiel.de anbieten und die virtuelle Host other.beispiel.de hinzufügen möchten, die auf demselben IP-Adressen zeigt. Dann fügen Sie folgendes in httpd.conf ein:

&lt;VirtualHost *:80&gt;
  # Diese erste aufgeführte virtuelle Host ist auch die Standardkonfiguration für *:80
  ServerName www.beispiel.de
  ServerAlias beispiel.de
  DocumentRoot "/www/domain"
&lt;/VirtualHost&gt;
&lt;VirtualHost *:80&gt;
  ServerName other.beispiel.de
  DocumentRoot "/www/otherdomain"
&lt;/VirtualHost&gt;

Sie können alternativ eine explizite IP-Adresse anstelle des * in <VirtualHost>-Direktiven angeben. Beispielsweise möchten Sie dies möglicherweise tun, um einige namensbasierte virtuellen Hosts auf einer IP-Adresse auszuführen und entweder IP-basierte oder eine andere Gruppe namensbasierter virtueller Hosts auf einer anderen Adresse. Viele Server möchten von mehr als einem Namen erreichbar sein.

Hier ist eine weitere Menge von virtuellen Hosts basierend auf einem anderen Adresspunkt. Viele Server möchten von mehr als einem Namen zugänglich sein. Dies ist möglich mit der ServerAlias-Direktive, die innerhalb des <VirtualHost>-Abschnitts platziert wird. Beispielsweise in dem ersten <VirtualHost>-Block oben, zeigt die ServerAlias-Direktive an, dass die aufgelisteten Namen weitere Namen sind, die Menschen verwenden können, um dasselbe Web-Portal anzusehen: ServerAlias example.com *.example.com. Alle Anfragen für alle Hosts in der example.com-Domäne werden von dem www.example.com-virtuellen Host abgerufen. Die Wildcard-Zeichen * und ? können verwendet werden, um Namen zu matchen. Natürlich können Sie nicht beliebige Namen in ServerName oder ServerAlias einfügen. Sie müssen zuvor Ihren DNS-Server richtig konfigurieren, um diese Namen auf eine IP-Adresse zuzuordnen, die mit Ihrem Server verbunden ist. Name-basierte virtuelle Hosts werden für die beste passende Menge von <virtualhost>s in der Konfiguration bearbeitet. Die ersten passenden ServerName oder ServerAlias werden verwendet, ohne dass Wildkarten (oder ServerName gegenüber ServerAlias) eine andere Priorität haben. Die vollständige Liste von Namen in der VirtualHost-Direktive werden wie ein (nicht wildcard) ServerAlias behandelt. Zum Schluss können Sie die Konfiguration der virtuellen Hosts feinjustieren, indem Sie andere Direktiven innerhalb der <VirtualHost>-Container platzieren. Die meisten Direktiven können in diesen Containern platziert und dann die Konfiguration nur des relevanten virtuellen Hosts ändern.

Um herauszufinden, ob eine bestimmte Direktive erlaubt ist, prüfen Sie den Kontext der Direktive. Konfigurationsdirektiven, die in der Hauptserverkontext (außerhalb jedes <VirtualHost>-Containers) gesetzt werden, werden nur verwendet, wenn sie nicht von den Einstellungen des virtuellen Hosts überschrieben werden.

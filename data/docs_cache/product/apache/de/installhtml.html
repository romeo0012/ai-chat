Der Apache HTTP-Server wird als Quellcode veröffentlicht. Dieser Abschnitt behandelt die Kompilierung und Installation des Servers aus Quellcode auf Unix- und Unix-ähnlichen Systemen. Für Windows siehe Apache HTTP-Server mit Microsoft Windows und Compiling Apache httpd für Microsoft Windows. Für andere Plattformen siehe die Plattformdokumentation. Wenn Sie httpd von einer Verteilungspaket-Datei (RPM, DEB usw.) installieren, kann die Konfigurationsstruktur und die Standardeinstellungen von was hier beschrieben ist abweichen. Siehe unten dritte-Partei-Pakete und konsultieren Sie Ihre Distribution-Dokumentation für Plattenspezifische Details. Wenn Sie von einer kleinen Version auf die nächste Version (z.B. 2.4.66 auf 2.4.67) upgraden, gehen Sie bitte direkt zu der Upgrading-Sektion.

Übersicht für die Unterschwelligen ¶
Laden Sie die neueste Version von https://httpd.apache.org/download.cgi herunter.
Extrahieren Sie $ tar xzf httpd-NN.tar.gz $ cd httpd-NN
Konfigurieren Sie $ ./configure --prefix=PREFIX
Kompilieren Sie $ make
Installieren Sie $ make install
Anpassen Sie $ vi PREFIX/conf/httpd.conf
Testen Sie $ PREFIX/bin/apachectl -k start
NN muss durch die aktuelle Versionnummer ersetzt werden, und PREFIX muss durch den Dateisystempfad ersetzt werden, unter dem der Server installiert werden soll.

Der aktuelle Versionen-Nr. und PREFIX müssen durch den Dateisystempfad ersetzt werden, unter dem der Server installiert werden soll. Wenn PREFIX nicht angegeben wird, wird es standardmäßig auf /usr/local/apache2 festgelegt. Herunterladen ¶
Herunterladen Sie den Quelltarball von der Apache HTTP Server Download-Seite. Nach dem Herunterladen ist es wichtig zu überprüfen, dass Sie eine vollständige und unveränderte Version der Apache HTTP Server haben. Dies kann durch Testen des heruntergeladenen Tarballs gegen die PGP-Unterschrift erreicht werden. Weitere Informationen dazu finden Sie auf der Verifikationsseite.

Extrahieren ¶
Extrahieren Sie das Quellmaterial aus dem Apache HTTP Server Tarball: 

$ tar xzf httpd-NN.tar.gz

Dies erstellt eine neue Unterverzeichnis im aktuellen Verzeichnis, das das Quellcode-Material für die Verteilung enthält. Bevor Sie mit dem Kompilieren des Servers fortfahren, sollten Sie in das Unterverzeichnis wechseln.

Konfigurieren des Quellbaums ¶
Der nächste Schritt ist, den httpd-Quellbaum für Ihre spezifische Plattform und persönliche Anforderungen zu konfigurieren. Dies geschieht über das Skript configure, das im Wurzelverzeichnis der Verteilung enthalten ist. (Entwickler, die eine unveröffentlichte Version des httpd-Quellcodes heruntergeladen haben, müssen autoconf und libtool installiert haben und müssen buildconf ausführen, bevor sie mit den nächsten Schritten fortfahren. Das ist nicht erforderlich für offizielle Veröffentlichungen.) Um den Quellbaum mit allen Standardoptionen zu konfigurieren, geben Sie ./configure ein.

Schritte. Dies ist nicht notwendig für offizielle Veröffentlichungen.) Um die Quellbaumkonfiguration mit allen Standardoptionen zu verwenden, tippe ./configure. Um die Standardoptionen zu ändern, akzeptiert configure eine Vielzahl von Variablen und Befehlszeilenoptionen. Die wichtigste Option ist die Standort --prefix, an dem httpd später installiert wird, da httpd für diesen Standort korrekt konfiguriert werden muss. Weitere fein abgestimmte Kontrolle über die Position von Dateien ist möglich, indem Sie zusätzliche configure-Optionen verwenden. Außerdem können Sie hier entscheiden, welche Funktionalitäten in httpd enthalten sein sollen, indem Sie Module aktivieren und deaktivieren. httpd kommt mit einer weiten Palette von Modulen standardmäßig mit eingeschlossen. Sie werden als dynamische Objekte (DSOs) kompiliert, die während der Laufzeit geladen oder gelöscht werden können. Sie können auch entscheiden, Module statisch zu kompilieren, indem Sie die Option --enable-module=static verwenden. Zusätzliche Module aktivieren Sie mithilfe der Option --enable-module, wobei Module der Name des Moduls mit dem mod_ Streifen entfernt und jedem Unterstrich durch einen Bindestrich ersetzt wird. Analog können Sie Module deaktivieren, indem Sie die Option --disable-module verwenden. Achtung, wenn Sie diese Optionen verwenden, müssen Sie vorsichtig sein, da configure Sie nicht warnen kann, wenn das Modul, das Sie angeben, nicht existiert; es ignoriert die Option. Zusätzlich ist es manchmal erforderlich, dem configure-Skript zusätzliche Informationen über die Position Ihres Compilers, Bibliotheken oder Headerdateien zu geben. Dies geschieht indem Sie entweder Umgebungsvariablen oder Befehlszeilenoptionen an configure übergeben.

(Technische Terme, Codeblöcke, Befehle, Dateipfade und URLs werden wie folgt übertragen:

./configure
--prefix
--enable-module
--enable-module=static
--disable-module)

Ihr Compiler, Bibliotheken oder Header-Dateien. Dies wird durch Übergeben von entweder Umgebungsvariablen oder Befehlszeilenoptionen an configure ausgeführt. Weitere Informationen finden Sie auf der configure-Manual-Seite. Oder führen Sie configure mit dem --help-Option aus. Um einen kurzen Eindruck von den Möglichkeiten zu bekommen, hier ein typisches Beispiel, das httpd für die Installationsmappe /sw/pkg/apache mit einem bestimmten Compiler und Flags sowie den zwei zusätzlichen Modulen mod_ldap und mod_lua kompiliert:

CC="pgcc" CFLAGS="-O2"
./configure --prefix=/sw/pkg/apache
--enable-ldap=shared
--enable-lua=shared

Wenn configure ausgeführt wird, wird es mehrere Minuten dauern, um auf Ihrem System nach Verfügbarkeit von Funktionen zu prüfen und Makefiles zu erstellen, die später verwendet werden, um den Server zu kompilieren. Weitere Informationen zu allen verschiedenen configure-Optionen finden Sie auf der configure-Manual-Seite.

Build ¶ Nun können Sie die verschiedenen Teile, die das httpd-Paket bilden, indem Sie folgendes ausführen:

Bitte seien Sie hier geduldig, da eine Basiskonfiguration mehrere Minuten zum Kompilieren benötigt und die Zeit stark von Ihrer Hardware und der Anzahl der aktivierten Modulen abhängt.

Dieser Schritt wird normalerweise Administratorrechte erfordern, da PREFIX meistens ein Verzeichnis mit beschränkten Schreibrechten ist. Wenn Sie aktualisieren, wird die Installation Ihre Konfigurationsdateien und Dokumente nicht überschreiben.

Anpassen ¶ Nun können Sie Ihren Apache HTTP Server individuell anpassen, indem Sie die Konfigurationsdateien in PREFIX/conf/ bearbeiten. $ vi PREFIX/conf/httpd.conf Haben Sie bitte einen Blick auf die httpd-Dokumentation in PREFIX/docs/manual/ oder konsultieren Sie https://httpd.apache.org/docs/2.4/ für die aktuellste Version dieser Dokumentation und einen umfassenden Überblick über verfügbare Konfigurationsdirektiven. Test ¶ Jetzt können Sie Ihren Apache HTTP Server starten, indem Sie sofort folgen lassen: $ PREFIX/bin/apachectl -k start Sie sollten dann Ihre erste Datei über die URL http://localhost/ abrufen können. Die Seite, die Sie sehen, befindet sich unter dem DocumentRoot, der normalerweise PREFIX/htdocs/ ist. Danach starten Sie den Server wieder, indem Sie folgen lassen: $ PREFIX/bin/apachectl -k stop

Aktualisieren ¶ Der erste Schritt beim Aktualisieren ist, die Release-Ankündigung und das Datei CHANGES in der Quellverteilung zu lesen, um eventuelle Änderungen zu finden, die Ihre Seite betreffen können. Wenn Sie zwischen Hauptversionen wechseln (zum Beispiel von 2.4 auf 2.6), sind es wahrscheinlich große Unterschiede bei der Compile-Zeit und der Laufzeitkonfiguration, die manuelle Anpassungen erfordern. Alle Module müssen auch aktualisiert werden, um Änderungen in der Modul-API zu berücksichtigen. Aktualisieren Sie von einer kleinen Version auf die nächste (zum Beispiel von 2.4.66 auf 2.4.67) ist einfacher.

Im Modul API wird der Aufstieg von einer kleinen Version auf die nächste (z.B. von 2.4.66 auf 2.4.67) leichter durchgeführt. Das make install-Prozess wird keine Ihre vorhandenen Dokumente, Logdateien oder Konfigurationsdateien überschreiben. Zusätzlich versuchen die Entwickler, unvereinbare Änderungen in den configure-Optionen, der Laufzeitkonfiguration oder dem Modul API zwischen den kleinen Versionen zu vermeiden. In den meisten Fällen solltest du eine identische configure-Befehlszeile, eine identische Konfigurationsdatei und alle deine Module weiterhin funktionieren. Um zwischen den kleinen Versionen aufzusteigen, startest du zunächst mit der Suche nach der Datei config.nice im Build-Verzeichnis deines installierten Servers oder am Wurzelverzeichnis des alten Installationsbaums. Diese enthält die genaue configure-Befehlszeile, die du zum Konfigurieren des Quellbaums verwendest. Dann um von einer Version auf die nächste zu wechseln, benötigst du nur die Datei config.nice in das Quellverzeichnis der neuen Version zu kopieren, sie zu bearbeiten, um gewünschte Änderungen vorzunehmen, und dann folgende Befehle auszuführen:

$ ./config.nice
$ make
$ make install
$ PREFIX/bin/apachectl -k graceful-stop
$ PREFIX/bin/apachectl -k start

Du solltest immer eine neue Version in deiner Umgebung testen, bevor du sie in die Produktion bringst. Zum Beispiel kannst du die neue Version neben der alten installieren und ausführen, indem du ein anderes --prefix und ein anderes Port (durch Anpassung des Listen-Direktivs) verwendest, um auf eventuelle Unvereinbarkeiten zu testen, bevor du den finalen Aufstieg durchführst.

Einleitung ¶
Der Apache HTTP-Server bietet eine Reihe von Caching-Funktionen, die zum Verbessern der Leistung des Servers in verschiedenen Weisen konzipiert sind.
Drei-Zustands-RFC2616 HTTP-Caching
mod_cache und seine Provider-Module mod_cache_disk bieten intelligente, HTTP-bewusste Caching. Das Inhalt selbst wird im Cache gespeichert, und mod_cache versucht, alle der HTTP-Header und Optionen zu beachten, die die Cachierbarkeit des Inhalts in RFC 2616 beschreiben. mod_cache ist für einfache und komplexe Caching-Konfigurationen gedacht, wo Sie mit proxiedem Inhalt, dynamischem lokalen Inhalt oder einer Notwendigkeit, den Zugriff auf lokale Dateien auf einem möglicherweise langsamen Datenträger zu beschleunigen, zu tun haben.
Zwei-Zustands-Schlüssel/Wert-Shared-Object-Caching
Die shared object cache API (socache) und ihre Provider-Module bieten ein serverweites Schlüssel/Wert-basiertes shared object cache. Diese Module sind für den Cache von niedrigstes Niveau-Daten wie SSL-Sessions und Authentifizierungskredentiale konzipiert.

Backends ermöglichen es, die Daten serverweit in geteilter Speicher zu speichern, oder datenzentrumweit in einem Cache wie memcache oder distcache. Ein spezialisiertes Dateicaching mod_file_cache bietet die Möglichkeit, Dateien in der Speicherstartphase vorzuladen, und kann Zugriffszeiten verbessern und Dateihandles für häufig zugeschriebene Dateien sparen, da es keinen Bedarf gibt, auf jeden Anfrage zum Lesen auf dem Datenträger zu gehen. CacheDirLength 1

In-Memory-Caching

Das Direktservieren aus dem Systemspeicher ist universell die schnellste Methode zum Servieren von Inhalten. Lesen von Dateien über einen Datenträgercontroller oder, noch schlimmer, über ein ferngesteuertes Netzwerk ist um Größenordnungen langsamer.

Speicherung von Inhalt. Lesen Sie Dateien von einem Datenträgercontroller oder, noch schlimmer, von einer entfernten Netzwerkquelle ist um Größenordnungen langsamer. Datenträgercontroller sind meistens mit physikalischen Prozessen verbunden, und das Netzwerkzugriff ist durch Ihre verfügbare Bandbreite begrenzt. Andererseits kann Zugriff auf Speicher aber nur in Nanosekunden erfolgen. Systemspeicher ist jedoch nicht billig, und es ist wichtig, dass er effizient verwendet wird. Durch Speicherung von Dateien in der Speicherleistung verbessern Sie den Speicherverbrauch. Wir werden sehen, dass dies bei der Betriebssystemspeicherung nicht so großes Problem ist, aber bei der Verwendung von httpd's eigenem Speicher-Cache ist es wichtig, sicherzustellen, dass Sie nicht zu viel Speicher an einen Cache zuweisen. Andernfalls wird das System gezwungen, Speicher auszutauschen, was die Leistung wahrscheinlich verringern wird. Betriebssystem-Speicherung Fast alle modernen Betriebssysteme speichern Dateidaten in der Speicherleistung, die direkt vom Kernel verwaltet wird. Dies ist eine mächtige Funktion, und im Allgemeinen funktionieren Betriebssysteme gut. Beispielsweise auf Linux: Sehen Sie sich die Zeit an, die es für die erste Lesung einer Datei und die zweite Lesung benötigt; colm@coroebus:~$ time cat testfile > /dev/null real 0m0.065s user 0m0.000s sys 0m0.001s colm@coroebus:~$ time cat testfile > /dev/null real 0m0.003s user 0m0.003s sys 0m0.000s Auch für diese kleine Datei gibt es einen großen Unterschied in der Zeit, die benötigt wird, um die Datei zu lesen.

Für dies kleine Datei gibt es einen großen Unterschied in der Zeit, die zur Lesung der Datei benötigt wird. Das liegt daran, dass der Kernel die Dateiinhalte in der Speicher-Cache-Bereich gespeichert hat. Durch sicherzustellen, dass auf Ihrem System genügend "spare" Speicher vorhanden ist, können Sie sicherstellen, dass immer mehr Dateiinhalte in diesem Cache gespeichert werden. Dies kann eine sehr effiziente Art des Speicher-Cachings sein, und es bedarf keiner zusätzlichen Konfiguration von httpd. Zusätzlich weiß das Betriebssystem, wenn Dateien gelöscht oder geändert werden, automatisch Dateiinhalte aus dem Cache zu entfernen, wenn es notwendig ist. Dies ist ein großer Vorteil gegenüber dem in-Memory-Caching von httpd, das keine Möglichkeit hat, zu erkennen, wenn eine Datei geändert wurde. Obwohl die Leistung und die Vorteile des automatischen Betriebssystem-Cachings groß sind, gibt es einige Umstände, in denen das in-Memory-Caching besser durch httpd durchgeführt werden kann. Mod_file_cache bietet die MMapFile-Anweisung, die es Ihnen ermöglicht, httpd, um eine statische Datei in der Startzeit in die Speicher (mit Hilfe des mmap-Systemaufrufs) zu kopieren. httpd wird die in-Memory-Inhalte für alle anschließenden Zugriffe auf diese Datei verwenden.

Denial of Service / Cachebusting
Das Vary-Mechanismus erlaubt es, mehrere Varianten der gleichen URL nebeneinander im Cache zu speichern. Je nach Header-Werten, die der Client bereitstellt, wählt der Cache die richtige Variante aus, um sie dem Client zurückzugeben. Dieses Mechanismus kann ein Problem werden, wenn versucht wird, auf einem Header zu variieren, der unter normalen Bedingungen eine breite Palette möglicher Werte aufweist, beispielsweise der User-Agent-Header. Je nach der Popularität der jeweiligen Webseite können durch diesen Vorgang tausende oder Millionen von identischen Cache-Einträgen für die gleiche URL erstellt werden, die andere Einträge im Cache verdrängen.

In anderen Fällen kann es notwendig sein, die URL eines bestimmten Ressourcen auf jeden Anfrage zu ändern, meist indem man einen "Cachebuster"-String zur URL hinzufügt. Wenn dieses Inhalt als zachlich von einer Server erklärt wird, kann dies zu einer Verdrängung legitimer Einträge im Cache führen. Während mod_cache eine CacheIgnoreURLSessionIdentifiers-Direktive bereitstellt, sollte diese Direktive mit Vorsicht verwendet werden, um sicherzustellen, dass Downstream-Proxy- oder Browser-Caches nicht dem gleichen Denial of Service-Problem ausgesetzt sind.

Was ist IP-basierter Virtual Hosting?
¶
IP-basierter Virtual Hosting ist eine Methode, um unterschiedliche Direktiven anhand der IP-Adresse und des empfangenen Ports anzuwenden. Am häufigsten wird dies verwendet, um verschiedene Websites auf verschiedenen Ports oder Schnittstellen bereitzustellen. In vielen Fällen sind name-basierte Virtual Hosts bequemer, weil sie es erlauben, viele Virtual Hosts auf einem einzigen Adresse/Port zu teilen. Siehe Name-basierte vs. IP-basierte Virtual Hosts, um Ihre Entscheidung zu unterstützen.
Systemanforderungen
¶
Da der Begriff IP-basierter angibt, muss der Server eine andere IP-Adresse/Port-Kombination für jeden IP-basierten Virtual Host haben. Dies kann erreicht werden, indem die Maschine mehrere physische Netzwerkverbindungen hat, oder indem virtuelle Schnittstellen verwendet werden, die von den meisten modernen Betriebssystemen unterstützt werden (siehe Betriebssystemdokumentation für Details, diese werden häufig "ip Aliases" genannt, und das "ifconfig"-Befehl ist das meist verwendete Kommando, um sie einzurichten). In der Terminologie des Apache HTTP Server ist auch die Verwendung einer einzigen IP-Adresse, aber mehrerer TCP-Ports, IP-basierter Virtual Hosting.
Wie konfiguriert man Apache?
Es gibt zwei Möglichkeiten, Apache für mehrere Hosts zu konfigurieren.

In diesem Beispiel wird die Konfiguration für eine einzelne IP-Adresse und mehrere Ports gezeigt.

  1. Erstellen Sie eine neue Datei für jeden Virtual Host in der Apache-Konfigurationsordnung (z. B. /etc/httpd/conf.d/).
  1. Fügen Sie in jeder Datei die entsprechenden Konfigurationseinstellungen für den Virtual Host ein.
  1. Aktivieren Sie die Konfiguration für den Virtual Host, indem Sie in der Datei /etc/httpd/conf/httpd.conf die entsprechende Zeile hinzufügen:

IncludeOptional conf.d/*.conf
  1. Starten Sie den Apache-Dienst neu, um die Änderungen zu übernehmen:

systemctl restart httpd
  1. Überprüfen Sie die Konfiguration mit dem Befehl:

httpd -t
  1. Falls es Fehler gibt, korrigieren Sie sie und starten Sie den Apache-Dienst erneut.

IP-basiertes virtuelles Hosting. Wie wird Apache einrichten? ¶ Es gibt zwei Möglichkeiten, Apache für mehrere Hosts zu konfigurieren. Entweder durch den Start eines separaten httpd-Dämonens für jeden Hostnamen, oder durch den Start eines einzigen Dämonens, der alle virtuellen Hosts unterstützt. Verwende mehrere Dämonens, wenn: Es gibt Sicherheits-Partitionierungsprobleme, wie z.B. die Firma1 möchte, dass niemand aus der Firma2 ihre Daten lesen kann, außer über das Web. In diesem Fall benötigen Sie zwei Dämonens, die jeweils mit anderen User, Group, Listen und ServerRoot-Einstellungen gestartet werden. Sie können die Speicher- und Datei-Deskriptor-Anforderungen des Zuhörens zu jedem IP-Alias auf dem Rechner erfüllen. Es ist nur möglich, auf die "wildcard"-Adresse oder auf spezifische Adressen zu hören. Also, wenn Sie eine Notwendigkeit haben, auf eine spezifische Adresse zu hören, müssen Sie auf alle spezifischen Adressen hören. (Although one httpd could listen to N-1 of the addresses, and another could listen to the remaining address.) Verwende einen einzigen Dämonen, wenn: Die Sharing des httpd-Konfigurations zwischen virtuellen Hosts akzeptabel ist. Die Maschine verarbeitet eine große Anzahl von Anfragen, und so kann die Leistungsverlust durch den Start von separaten Dämonens bedeutend sein. Einrichtung mehrerer Dämonens ¶ Erstellt eine separate httpd-Installation für jeden virtuellen Host. Für jede Installation verwendet Sie die Listen-Anweisung in der Konfigurationsdatei, um auszuwählen, welche IP-Adresse (oder virtueller Host) der Dämon dient. z.B. Listen 192.0.2.

Hören-Direktive in der Konfigurationsdatei, um festzulegen, welche IP-Adresse (oder virtuelle Domäne) der Dämon-Dienst bereitstellt. Beispiel: Listen 192.0.2.100:80 Es wird empfohlen, eine IP-Adresse statt eines Hostnamens zu verwenden (siehe DNS-Kaviat). Für den Fall einer einzelnen Daemon-Installation mit virtuellen Domänen ¶ In diesem Fall wird eine einzige httpd daemon die Anfragen für den Hauptserver und alle virtuellen Domänen bearbeiten. Die VirtualHost-Direktive in der Konfigurationsdatei wird verwendet, um die Werte von ServerAdmin, ServerName, DocumentRoot, ErrorLog und TransferLog oder CustomLog-Konfigurationsdirektiven für jede virtuelle Domäne unterschiedlich zu setzen. Beispiel:

&lt;VirtualHost 172.20.30.40:80&gt;
 ServerAdmin webmaster@www1.example.com
 DocumentRoot "/www/vhosts/www1"
 ServerName www1.example.com
 ErrorLog "/www/logs/www1/error_log"
 CustomLog "/www/logs/www1/access_log" combined
&lt;/VirtualHost&gt;
&lt;VirtualHost 172.20.30.50:80&gt;
 ServerAdmin webmaster@www2.example.org
 DocumentRoot "/www/vhosts/www2"
 ServerName www2.example.org
 ErrorLog "/www/logs/www2/error_log"
 CustomLog "/www/logs/www2/access_log" combined
&lt;/VirtualHost&gt;

Es wird empfohlen, eine IP-Adresse statt eines Hostnamens in der <VirtualHost>-Direktive zu verwenden (siehe DNS-Kaviat). Spezifische IP-Adressen oder Ports haben Vorrang über ihre Wildcard-Äquivalente, und jede virtuelle Domäne, die passt, hat Vorrang über die Basiskonfiguration des Servers.

VirtualHost-Direktiven haben Vorrang gegenüber ihren Wildcard-Entsprechungen, und jede VirtualHost, die passt, hat Vorrang über die Basiskonfiguration des Servers. Fast jeder Konfigurationsbefehl kann in der VirtualHost-Direktive platziert werden, mit Ausnahme von Befehlen, die die Prozesserstellung steuern und einigen anderen Befehlen. Um herauszufinden, ob ein Befehl in der VirtualHost-Direktive verwendet werden kann, prüfe den Kontext mithilfe des Befehlindex. SuexecUserGroup kann innerhalb einer VirtualHost-Direktive verwendet werden, wenn der suEXEC-Wrapper verwendet wird. SICHERHEIT: Beachte, dass es bei der Angabe der Verzeichnispfade für die Protokolldateien einige Sicherheitsrisiken gibt, die vorliegen, wenn jemand anders als der Benutzer, der Apache startet, Schreibzugriff auf das Verzeichnis hat, in dem sie geschrieben werden. Weitere Informationen findest du im Sicherheits-Tipps-Dokument.

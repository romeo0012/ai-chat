Ein "Handler" ist eine interne Apache-Darstellung der zu durchführenden Aktion, wenn ein Datei aufgerufen wird. Allgemein haben Dateien implizite Handler, basierend auf dem Dateityp. Normalerweise werden alle Dateien einfach vom Server bereitgestellt, aber bestimmte Dateitypen werden separat "gehandelt". Handler können auch explizit konfiguriert werden, basierend entweder auf Dateinamen Erweiterungen oder auf Ort, ohne Bezug zum Dateityp. Dies ist vorteilhaft sowohl weil es eine elegantere Lösung ist, als auch weil es auch ermöglicht, einer Datei sowohl einen Typ als auch einen Handler zuzuordnen. (Siehe auch Dateien mit Mehreren Erweiterungen.) Handler können entweder in den Server integriert oder in einem Modul enthalten sein, oder sie können mit der Action-Direktive hinzugefügt werden. Die eingebauten Handler in der Standardverteilung sind wie folgt:

default-handler: Die Datei wird mithilfe der default_handler()-Funktion gesendet. Dies ist der Handler, der standardmäßig verwendet wird, um statisches Inhalt zu verarbeiten. (core)
send-as-is: Die Datei wird mit den HTTP-Headers wie sie sind gesendet. (mod_asis)
cgi-script: Die Datei wird als CGI-Skript behandelt. (mod_cgi)
imap-file: Als imagemap Regeldatei interpretieren. (mod_imagemap)
server-info: Die Serverkonfigurationsinformationen abrufen.

Die untenstehenden Beispiele zeigen, wie Sie Handler explizit konfigurieren können:

AddHandler cgi-script .cgi
AddHandler imap-file .map

In diesem Beispiel wird jede Datei mit der Erweiterung ".cgi" als CGI-Skript behandelt und jede Datei mit der Erweiterung ".map" als imagemap Regeldatei interpretiert.

&lt;Location /mydir&gt;
SetHandler server-info
&lt;/Location&gt;

In diesem Beispiel wird die Datei in der Ordnerstruktur "/mydir" mit dem Handler "server-info" behandelt.

Datei als CGI-Skript. (mod_cgi) imap-file: Als imagemap Regeldatei parsen. (mod_imagemap) server-info: Die Konfigurationsinformationen des Servers abrufen. (mod_info) server-status: Den Statusbericht des Servers abrufen. (mod_status) type-map: Als Typ-Map-Datei für Inhaltsverhandlung parsen. (mod_negotiation)

Beispiele ¶
Veränderung von statischem Inhalt mittels einer CGI-Skript
Die folgenden Direktiven lösen Anfragen nach Dateien mit der html-Erweiterung aus, indem sie das footer.pl-CGI-Skript starten.
Action add-footer /cgi-bin/footer.pl
AddHandler add-footer .html

Dann ist das CGI-Skript verantwortlich für die Übermittlung des ursprünglich angeforderten Dokuments (dargestellt durch die Umgebungsvariable PATH_TRANSLATED) und für die gewünschten Änderungen oder Zusätze.
Dateien mit HTTP-Headers
Die folgenden Direktiven aktivieren den send-as-is-Handler, der für Dateien verwendet wird, die ihre eigenen HTTP-Headers enthalten. Alle Dateien in dem Verzeichnis /web/htdocs/asis/ werden von dem send-as-is-Handler verarbeitet, unabhängig von ihren Dateinamenserweiterungen.
<Directory "/web/htdocs/asis">
SetHandler send-as-is
</Directory>

Programmierer-Hinweis ¶
Um die Handler-Funktionen zu implementieren, wurde eine Erweiterung hinzugefügt, die Sie möglicherweise nutzen möchten. Speziell wurde ein neues Feld hinzugefügt zur request_rec-Struktur: char *handler

Wenn Sie Ihre Modul engagieren möchten, müssen Sie lediglich r->handler auf den Namen des Handlers zu einer beliebigen Zeit vor der invoke_handler-Stufe der Anfrage festlegen.
Handlers werden wie vorher implementiert, allerdings wird der Handlername statt des Inhalts-Typs verwendet. Während es nicht notwendig ist, folgt die Benennungskonvention für Handler dem Muster eines Wortes, getrennt durch Bindestrich, ohne Schrägstriche, um den Namenraum der Medientypen nicht zu verwirren.

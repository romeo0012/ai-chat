Vorwärts-Proxys und Rückwärts-Proxys/Gateways ¶

Der Apache HTTP Server kann sowohl in einem vorwärts als auch in einem Rückwärts-Proxy (auch bekannt als Gateway) konfiguriert werden.

Proxys/Gateways ¶ Der Apache HTTP Server kann in beiden einem Vorwärts- und Rückwärtsproxy (auch bekannt als Gateway) konfiguriert werden. Ein gewöhnlicher Vorwärtsproxy ist ein Zwischenserver, der sich zwischen dem Client und dem Ursprungsserver befindet. Um Inhalte vom Ursprungsserver zu erhalten, sendet der Client eine Anfrage an den Proxy, bei der der Ursprungsserver als Ziel angegeben wird. Der Proxy sendet dann die Anfrage an den Ursprungsserver und gibt das Inhalt an den Client zurück. Der Client muss speziell konfiguriert werden, um den Vorwärtsproxy zur Verwendung bei anderen Seiten zu nutzen. Ein typischer Einsatz eines Vorwärtsproxys ist es, Internetzugang zu internen Clients bereitzustellen, die sonst durch ein Firewall-System eingeschränkt sind. Der Vorwärtsproxy kann auch Caching (wie es durch mod_cache bereitgestellt wird) verwenden, um den Netzverkehr zu reduzieren. Der Vorwärtsproxy wird über die ProxyRequests-Direktive aktiviert. Da Vorwärtsproxys Clients erlauben, über Ihre Server beliebige Seiten zu erreichen und ihre wahre Herkunft zu verbergen, ist es essentiell, dass Sie Ihren Server sichern, damit nur autorisierte Clients Zugang zum Proxy haben, bevor Sie einen Vorwärtsproxy aktivieren. Ein Rückwärtsproxy (oder Gateway), im Gegensatz dazu, erscheint dem Client wie ein gewöhnlicher Webserver. Keine spezielle Konfiguration auf dem Client ist notwendig. Der Client macht gewöhnliche Anfragen nach Inhalt im Namespace des Rückwärtsproxys. Der Rückwärtsproxy entscheidet dann, an welcher Stelle solche Anfragen gesendet werden sollen und gibt das Inhalt wie es selbst der Ursprung wäre zurück.

Umkehrproxys entscheiden, an welcher Stelle die Anfragen weitergeleitet werden und die Inhalte wie selbst der Ursprung zurückgeben. Ein typischer Einsatz eines Umkehrproxys ist es, Internet-Nutzer Zugriff auf einen Server zu ermöglichen, der hinter einem Firewall liegt. Umkehrproxys können auch verwendet werden, um die Last auf mehrere Back-End-Server zu verteilen oder einen langsamen Back-End-Server zu cachend. Zusätzlich können Umkehrproxys einfach verwendet werden, um mehrere Server in das gleiche URL-Raum zu bringen. Ein Umkehrproxy wird über die ProxyPass-Direktive oder das [P]-Flag zur RewriteRule-Direktive aktiviert. Es ist nicht notwendig, ProxyRequests zu aktivieren, um einen Umkehrproxy zu konfigurieren. ProxyVia Direktiv ¶ Beschreibung: Informationen, die in dem Via HTTP-Antwortkopf für proxied Requests bereitgestellt werden
Syntax: ProxyVia On|Off|Full|Block
Standard: ProxyVia Off
Kontext: server config, virtual host
Status: Erweiterung Modul: mod_proxy
Diese Direktive steuert die Verwendung des Via: HTTP-Kopfers durch den Proxy. Ihre vorgesehene Verwendung ist, den Fluss von proxy Requests entlang einer Kette von Proxy-Servern zu kontrollieren. Siehe RFC 2616 (HTTP/1.1), Abschnitt 14.45 für eine Erklärung von Via: Kopfzeile-Zeilen. Wenn auf Off gesetzt ist, was der Standard ist, wird kein spezielles Verhalten durchgeführt. Wenn eine Anforderung oder Antwort einen Via: Kopf enthält, wird er unverändert durchgelassen. Wenn auf An gesetzt ist, wird jede Anforderung und Antwort eine Via: Kopfzeile-Zeile hinzugefügt für den aktuellen Host. Wenn auf Full gesetzt ist, werden jede generierte Via: Kopfzeile-Zeile zusätzlich die Apache httpd Serverversion als Via: Kommentarfeld angezeigt.

Wenn auf Block gesetzt ist, wird jede proxy Anforderung alle ihre Via: Kopfzeile-Zeilen entfernt. Keine neue Via: Kopfzeile wird erstellt.

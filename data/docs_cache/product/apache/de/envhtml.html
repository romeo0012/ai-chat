Es gibt zwei Arten von Umgebungsvariablen, die das Apache HTTP-Server beeinflussen. Zunächst gibt es die Umgebungsvariablen, die vom unterliegenden Betriebssystem gesteuert werden. Diese werden vor dem Serverstart gesetzt und können in Konfigurationsdateien in Expansionen verwendet werden. Sie können optional an CGI-Skripte und SSI über den PassEnv-Befehl übergeben werden. Zweitens bietet der Apache HTTP-Server eine Möglichkeit, Informationen in benannten Variablen zu speichern, die auch als Umgebungsvariablen bezeichnet werden. Diese Information kann verwendet werden, um verschiedene Operationen wie das Protokollieren oder die Zugriffssteuerung zu kontrollieren. Die Variablen werden auch als Mechanismus verwendet, um mit externen Programmen wie CGI-Skripten zu kommunizieren. Dieses Dokument diskutiert verschiedene Möglichkeiten, diese Variablen zu manipulieren und zu verwenden. Obwohl diese Variablen als Umgebungsvariablen bezeichnet werden, sind sie nicht die gleichen Umgebungsvariablen, die vom unterliegenden Betriebssystem gesteuert werden. Stattdessen werden diese Variablen in einer internen httpd-Struktur gespeichert und manipuliert. Sie werden nur tatsächliche Betriebssystem-Umgebungsvariablen, wenn sie an CGI-Skripte und Server-Seiteneinschlüsse (SSI) bereitgestellt werden. Wenn Sie die Betriebssystemumgebung unter derer der Server selbst läuft manipulieren möchten, müssen Sie die standardmäßigen Umgebungsummanipulationsmechanismen Ihrer Betriebssystem-Shell verwenden.

Unter dem Betriebssystem, unter dem der Server selbst läuft, müssen Sie die standardmäßigen Umgebungsvariablenmanipulationsmechanismen Ihrer Betriebssystem-Shell verwenden. Um Umgebungsvariablen zu setzen, verwenden Sie die unbedingte SetEnv-Direktive in Apache. Variablen können auch über die PassEnv-Direktive von der Umgebung des Shells, aus dem der Server gestartet wurde, übernommen werden.

Für zusätzliche Flexibilität bieten die Direktiven von mod_setenvif die Möglichkeit, Umgebungsvariablen auf Basis von Eigenschaften bestimmter Anfragen auf Anfrageebene zu setzen. Beispielsweise könnte eine Variable nur dann gesetzt werden, wenn ein bestimmter Browser (User-Agent) eine Anfrage stellt, oder wenn ein bestimmter Referer-Header gefunden wird. Weitere Flexibilität ist über die mod_rewrite-Direktive RewriteRule verfügbar, die die [E=...]-Option verwendet, um Umgebungsvariablen zu setzen.

Schließlich setzt mod_unique_id die Umgebungsvariable UNIQUE_ID für jede Anfrage auf einen Wert, der unter sehr spezifischen Bedingungen eindeutig ist.

EINIQUE_ID für jede Anfrage an einen Wert, der unter sehr spezifischen Bedingungen für alle Anfragen eindeutig ist. Standard-CGI-Variablen

Zugriffssteuerung
Der Zugriff auf den Server kann anhand von Umgebungsvariablen gesteuert werden, indem die Direktiven Require env und Require not env verwendet werden. In Kombination mit SetEnvIf ermöglicht dies eine flexible Steuerung des Zugriffs auf den Server anhand von Merkmalen des Clients. Beispielsweise können Sie diese Direktiven verwenden, um Zugriff auf eine bestimmte Browser-Software (User-Agent) zu verweigern. Für komplexere Bedingungen bietet Require expr eine Alternative, die Umgebungsvariablen mithilfe der reqenv-Funktion und anderen Anfrageeigenschaften auswerten kann.

REDIRECT_ Variablen ¶

Wenn ein internes Leitungswechsel stattfindet - unabhängig von einem ErrorDocument, mod_rewrite, FallbackResource, oder irgendeinem anderen internen Leitungswechselmechanismus - werden die Umgebungsvariablen aus der Originalanfrage dem Leitungswechselziel mit einem REDIRECT_-Präfix zur Verfügung gestellt. Zwei zusätzliche Variablen werden immer gesetzt:

REDIRECT_URL

Der URL-Pfad der Originalanfrage vor dem internen Leitungswechsel. Dies wird vom Kernserver, nicht von irgendeinem speziellen Modul, gesetzt.

REDIRECT_STATUS

Der HTTP-Statuscode, der den Leitungswechsel ausgelöst hat. Für Fehlerdokumente ist dies der Fehlerstatus (z.B., 404).

Modul. REDIRECT_STATUS Der HTTP-Statuscode, der die Umleitung ausgelöst hat. Für Fehlerdokumente ist dies der Fehlerstatus (z.B., 404). Für interne Umleitungen von mod_rewrite oder FallbackResource ist dies meistens 200. Beispielhaft würde, wenn REQUEST_URI auf /original/pfad lautet und eine interne Umleitung die Anfrage auf /handler.php sendet, die Umleitungsziel die Variablen REDIRECT_URL=/original/pfad und REQUEST_URI=/handler.php sehen. Diese Variablen sind für CGI-Skripte, SSI-Seiten und in Ausdrücken verfügbar.

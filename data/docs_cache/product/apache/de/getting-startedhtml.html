Clients, Servers und URLs ¶
Adressen im Web werden mit URLs - Uniform Resource Locators - angegeben, die ein Protokoll (z.B. http), einen Servernamen (z.B. www.apache.org), einen URL-Pfad (z.B. /docs/current/getting-started.html) und möglicherweise eine Abfragezeichenfolge (z.B. ?arg=value) enthalten, die zusätzliche Argumente an den Server übermittelt. Ein Client (z.B. ein Webbrowser) verbindet sich mit einem Server (z.B. Ihrer Apache HTTP-Server), mit dem angegebenen Protokoll, und stellt einen Antrag auf eine Ressource mithilfe des URL-Pfads. Der URL-Pfad kann beliebig viele Dinge auf dem Server repräsentieren. Er kann ein Dateiobjekt (z.B. getting-started.html) sein, ein Handler (z.B. server-status) oder irgendeine Art von Programmdatei (z.B. index.php). Wir diskutieren dies weiter unten im Abschnitt Webseiteninhalt. Der Server sendet eine Antwort, die aus einem Statuscode und, optional, einer Antwortkörper besteht. Der Statuscode gibt an, ob der Antrag erfolgreich war, und, wenn nicht, welche Art von Fehlerbedingung vorlag. Dies informiert den Client, was er mit der Antwort tun soll. Sie können sich in der HTTP-Server-Wiki über die möglichen Antwortcodes informieren.

Details zur Transaktion und jeden Fehlerzustand werden in Logdateien protokolliert. Dies wird in größerem Umfang unten im Abschnitt Logdateien und Fehlerbehebung erläutert. Hostnamen und DNS ¶
Um auf einen Server zuzugreifen, muss der Client zuerst den Servernamen in eine IP-Adresse umwandeln - die Stelle im Internet, an der der Server residiert. Somit muss Ihr Webserver, um erreichbar zu sein, den Servernamen in DNS sein. Wenn Sie nicht wissen, wie dies geschieht, müssen Sie Ihren Netzwerkadministrator oder Ihren Internetdienstleister kontaktieren, um dies für Sie durchzuführen. Mehrere Hostnamen können auf die gleiche IP-Adresse zeigen, und mehrere IP-Adressen können an den gleichen physischen Server angehängt werden. Somit können Sie mehr als eine Webseite auf dem gleichen physischen Server betreiben, indem Sie die Funktion Virtual Hosts verwenden. Wenn Sie einen Server testen, der nicht Internetzugänglich ist, können Sie Hostnamen in Ihrer hosts-Datei eintragen, um lokale Auflösung durchzuführen. Beispielsweise möchten Sie möglicherweise eine Eintragung in Ihrer hosts-Datei erstellen, um eine Anfrage nach www.beispiel.com auf Ihr lokales System zu leiten, um Testzwecken. Diese Eintragung würde so aussehen: 127.0.0.1 www.beispiel.com Ein hosts-Datei wird wahrscheinlich an /etc/hosts oder C:\Windows\system32\drivers\etc\hosts befinden. Konfigurationsdateien und Direktiven ¶ Der Apache HTTP Server wird über einfache Textdateien konfiguriert. Diese Dateien können sich in einer Vielzahl von Orten befinden, je nachdem, wie genau Sie den Server installiert haben. Mögliche Standorte für diese Dateien können im httpd Wiki aufgeführt werden. Wenn Sie httpd von Quelltext installiert haben, befindet sich die Standard-Standort der Konfigurationsdateien in /usr/local/apache2/conf. Die Standard-Konfigurationsdatei heißt meist httpd.conf. Dies kann auch in anderen Verteilungen des Servers variieren. Die Konfiguration wird häufig in mehrere kleinere Dateien aufgeteilt, um die Verwaltung einfacher zu machen. Diese Dateien werden über den Include-Direktiv geladen. Die Namen oder Standorte dieser Unter-Dateien sind nicht magisch und können sich von einer Installation zur anderen stark unterscheiden. Organisieren und unterteilen Sie diese Dateien nach Ihrem Verständnis. Wenn die Datei-Organisation, die Sie standardmäßig haben, nicht für Sie verständlich ist, fühlen Sie sich frei, sie umzustrukturieren. Die Serverkonfiguration erfolgt durch Einfügen von Konfigurations-Direktiven in diese Konfigurationsdateien. Eine Direktive ist ein Schlüsselwort gefolgt von einem oder mehreren Argumenten, die ihr Wert setzen. Die Frage "Wo soll ich diese Direktive einfügen?" wird allgemein beantwortet, indem man sich fragt, an welcher Stelle eine Direktive wirksam sein soll.

"Wo soll ich diesen Direktiv eingeben?" wird allgemein beantwortet, indem man sich fragt, wo man eine Direktive wirksam machen möchte. Wenn es sich um eine globale Einstellung handelt, sollte sie in der Konfigurationsdatei außerhalb von jedem <Directory>, <Location>, <VirtualHost>, oder anderen Abschnitt stehen. Wenn sie nur für ein bestimmtes Verzeichnis gelten soll, dann sollte sie innerhalb eines <Directory>-Abschnitts stehen, der auf dieses Verzeichnis verweist, und so weiter. Weitere Informationen zu diesen Abschnitten finden Sie im Dokument "Konfigurationsabschnitte". Hinzu kommen zu den Hauptkonfigurationsdateien bestimmte Direktiven, die in .htaccess-Dateien in den Inhaltsverzeichnissen stehen können. .htaccess-Dateien sind hauptsächlich für Menschen, die keinen Zugriff auf die Hauptserverkonfigurationsdatei(n) haben. Weitere Informationen zu .htaccess-Dateien finden Sie im Artikel .htaccess-Dateien. Webseiteninhalt ¶ Webseiteninhalt kann sich in vielen verschiedenen Formen manifestieren, kann aber grob in statisches und dynamisches Inhalt unterteilt werden. Statisches Inhalt sind Dinge wie HTML-Dateien, Bilddateien, CSS-Dateien und andere Dateien, die im Dateisystem liegen. Die Direktive DocumentRoot gibt an, wo in Ihrem Dateisystem diese Dateien platziert werden sollen. Diese Direktive wird entweder global oder pro Virtual Host festgelegt. Schauen Sie in Ihren Konfigurationsdateien, um festzustellen, wie dies für Ihren Server gesetzt ist. Typischerweise wird ein Dokument namens index.html serviert, wenn ein Verzeichnis angefordert wird, ohne dass ein Dateiname angegeben wird. Beispiel: Wenn DocumentRoot auf /var/www/html festgelegt ist und eine Anfrage für http://www.beispiel.de gemacht wird, wird index.html serviert.

Ein Dateiname wird angegeben. Beispielhaft wird angenommen, dass DocumentRoot auf /var/www/html festgelegt ist und eine Anfrage für http://www.beispiel.com/arbeit/ gemacht wird. Dann wird dem Client das Datei /var/www/html/arbeit/index.html zur Verfügung gestellt. Dynamische Inhalte sind alles, was bei der Anfragezeit erstellt wird und von einer Anfrage zu einer anderen wechseln kann. Es gibt zahlreiche Möglichkeiten, wie dynamische Inhalte erstellt werden können. Viele Handler stehen zur Verfügung, um Inhalte zu generieren. CGI-Programme können geschrieben werden, um Inhalte für Ihre Seite zu erzeugen. Drittanbieter-Module wie mod_php können verwendet werden, um Code zu schreiben, der eine Vielzahl von Dingen tut. Viele Drittanbieter-Anwendungen, die mit einer Vielzahl von Sprachen und Werkzeugen geschrieben wurden, sind für den Download und die Installation auf Ihrer Apache HTTP Server verfügbar. Die Unterstützung dieser Drittanbieter-Dinge liegt außerhalb des Bereichs dieser Dokumentation, und Sie sollten ihre Dokumentation oder andere Unterstützungsforen zur Beantwortung Ihrer Fragen über sie finden.

Log Files und Fehlerbehebung ¶ Als Administrator des Apache HTTP Server ist die wertvollste Ressource Ihre Logfiles, insbesondere der Fehlerlog. Jede Problemlösung ohne Fehlerlog ist wie Fahren mit geschlossenen Augen. Der Speicherort der Fehlerlog wird durch die ErrorLog-Direktive definiert, die global oder pro virtueller Host festgelegt werden kann. Einträge in der Fehlerlog erzählen Ihnen, was schiefgegangen ist, und wann. Sie erzählen oft auch, wie Sie es reparieren können.

Einleitung ¶ Apache HTTP Server ist ein freies und offenes Webserver-Programm, das von der Apache Software Foundation entwickelt wird. Es ist der am häufigsten verwendete Webserver auf der Welt und wird von vielen großen Unternehmen und Organisationen verwendet. Apache HTTP Server ist einfach zu installieren und konfigurieren, und es gibt eine große Community von Entwicklern, die es unterstützen.

Installation ¶ Apache HTTP Server kann auf verschiedenen Plattformen installiert werden, darunter Linux, macOS und Windows. Die Installation ist je nach Plattform unterschiedlich, aber es gibt zahlreiche Tutorials und Dokumentationen, die Sie durch die Installation führen.

Konfiguration ¶ Apache HTTP Server kann durch die Bearbeitung von Konfigurationsdateien konfiguriert werden. Die Hauptkonfigurationsdatei ist httpd.conf, die in der Standardinstallation in /etc/httpd/conf/ oder /etc/apache2/ auf Linux-basierten Systemen und in /Applications/MAMP/conf/apache2/ auf macOS liegt. In dieser Datei können Sie die Konfiguration des Servers, der Modulaktivierung und die Virtual Hosts festlegen.

Benutzerrechte ¶ Apache HTTP Server läuft als Benutzer apache oder www-data, je nach Plattform. Es ist wichtig, dass der Benutzer, unter dem Apache HTTP Server läuft, die notwendigen Rechte hat, um die Dateien und Verzeichnisse zu lesen, die er benötigt.

Dateien und Verzeichnisse ¶ Apache HTTP Server dient als Server für Webseiten, und es ist wichtig, dass die Dateien und Verzeichnisse korrekt konfiguriert sind. Die Standardverzeichnis für Webseiten ist /var/www/html auf Linux-basierten Systemen und /Applications/MAMP/htdocs auf macOS.

Modulaktivierung ¶ Apache HTTP Server unterstützt eine Vielzahl von Modulen, die verschiedene Funktionen bieten. Um ein Modul zu aktivieren, müssen Sie es in der Konfigurationsdatei httpd.conf aktivieren und das Modul starten.

Virtual Hosts ¶ Virtual Hosts ermöglichen es Ihnen, mehrere Webseiten auf einem Server zu hosten. Sie können Virtual Hosts in der Konfigurationsdatei httpd.conf festlegen.

Log Files und Troubleshooting ¶ Als Administrator des Apache HTTP Server ist die wertvollste Ressource Ihre Logfiles, insbesondere der Fehlerlog. Troubleshooting any problem without the error log is like driving with your eyes closed. The location of the error log is defined by the ErrorLog directive, which may be set globally, or per virtual host. Entries in the error log tell you what went wrong, and when. They often also tell you how to fix it.

Im Fehlerprotokoll erzählt Ihnen, was schief gelaufen ist, und wann. Sie erzählen oft auch, wie Sie das beheben können. Jede Fehlerprotokoll-Nachricht enthält einen Fehlercode, den Sie online suchen können, um noch detailliertere Beschreibungen zur Behandlung des Problems zu erhalten. Sie können auch Ihr Fehlerprotokoll so konfigurieren, dass es eine Log-ID enthält, die Sie dann mit einer Zugriffsprotokoll-Eintragskorrelation verknüpfen können, um festzustellen, was die Anfrage war, die den Fehlerzustand auslöste.

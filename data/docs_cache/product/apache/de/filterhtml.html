Filter als HTTP-Dienst bereitstellen ¶
Filters können verwendet werden, um Inhalte zu verarbeiten, die vom Client stammen, zusätzlich zu Inhalten, die auf dem Server mithilfe des mod_reflector-Moduls verarbeitet werden. mod_reflector akzeptiert POST-Anfragen von Clients und reflektiert den Inhalt der Anfragekörper, der innerhalb der POST-Anfrage empfangen wurde, im Antworten, während die Ausgabefilterstapel auf dem Weg zurück zum Client durchlaufen. Diese Technik kann als Alternative zu einem laufenden Webdienst innerhalb eines Anwendungsserverstacks verwendet werden, wo ein Ausgabefilter die erforderliche Transformation auf dem Anfragekörper vornimmt. Beispielhaft könnte das mod_deflate-Modul verwendet werden, um einen allgemeinen Kompressionsdienst bereitzustellen, oder ein Bildtransformationfilter könnte in ein Bildtransformationdienst umgewandelt werden.

Verwendung von Filtern ¶
Es gibt zwei Arten der Filterung: Einfache und dynamische. Allgemein sollte man entweder eine oder die andere verwenden; die Mischung kann unerwartete Folgen haben (obwohl einfache Eingabefilterung frei mit einfacher oder dynamischer Ausgabefilterung gemischt werden kann).

Sie können unerwartete Folgen haben (obwohl einfache Eingabefilterung frei mit einfacher oder dynamischer Ausgabefilterung kombiniert werden kann). Die Einfache Methode ist die einzige Methode, um Eingabefilter einzurichten, und genügt für Ausgabefilter, bei denen Sie eine statische Filterkette benötigen. Relevante Direktiven sind SetInputFilter, SetOutputFilter, AddInputFilter, AddOutputFilter, RemoveInputFilter und RemoveOutputFilter. Die dynamische Methode ermöglicht sowohl statische als auch flexibel, dynamische Konfiguration von Ausgabefiltern, wie es auf der Seite mod_filter diskutiert wird. Relevante Direktiven sind FilterChain, FilterDeclare und FilterProvider. Eine weitere Direktive AddOutputFilterByType wird noch unterstützt, aber veraltet. Verwenden Sie stattdessen die dynamische Konfiguration.

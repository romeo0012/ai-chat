Grundlegende Konfigurationsbeispiel ¶
Ihre SSL-Konfiguration muss mindestens die folgenden Direktiven enthalten.

LoadModule ssl_module modules/mod_ssl.so
Listen 443
<VirtualHost *:443>
ServerName www.example.com
SSLEngine on
SSLCertificateFile "/path/to/www.example.com.cert"
SSLCertificateKeyFile "/path/to/www.example.com.key"
</VirtualHost>

OCSP Stapling ¶
Die Online Certificate Status Protocol (OCSP) ist ein Mechanismus, um festzustellen, ob ein Serverzertifikat entzogen wurde, und OCSP Stapling ist eine spezielle Form dieses, in der der Server, wie z.B. httpd und mod_ssl, aktuelle OCSP-Antworten für seine Zertifikate wahrt und sie an die kommunizierenden Clients sendet. Meistens enthalten Zertifikate die Adresse eines OCSP-Responders, der von der ausstellenden Zertifizierungsstelle (CA) unterhalten wird, und mod_ssl kann mit diesem Responder kommunizieren, um eine signierte Antwort zu erhalten, die an die mit dem Server kommunizierenden Clients gesendet werden kann.

Sie können mit diesem Responder kommunizieren, um eine signierte Antwort zu erhalten, die an die Clients gesendet werden kann, die mit dem Server kommunizieren. Da der Client das Zertifikat-Entzerrungsstatus vom Server erhalten kann, ohne dass ein zusätzlicher Verbindungsweg vom Client zur Zertifikatbehörde erforderlich ist, ist OCSP-Stapling die bevorzugte Methode, um den Entzerrungsstatus zu erhalten. Weitere Vorteile der Eliminierung der Kommunikation zwischen Client und Zertifikatbehörde sind, dass das Browsing-Verhalten des Clients dem Zertifikatbehörde nicht zugänglich ist und der Status sicherer ist, indem er nicht auf möglicherweise stark belastete Zertifikatbehörde-Server angewiesen ist. Da die vom Server erhaltene Antwort für alle Clients, die während der Gültigkeitsdauer des Antworten dieselbe Zertifikat nutzen, wiederverwendbar ist, ist die Belastung für den Server gering. Sobald die allgemeine SSL-Unterstützung richtig konfiguriert ist, erfordert die Aktivierung von OCSP-Stapling nur sehr geringfügige Änderungen an der httpd-Konfiguration – die Hinzufügung dieser zwei Direktiven: SSLUseStapling On SSLStaplingCache "shmcb:logs/ssl_stapling(32768)". Diese Direktiven werden im globalen Bereich (d.h. nicht innerhalb einer virtuellen Hostdefinition) platziert (z.B. in conf/extra/httpd-ssl.conf für normale offene Open-Source-Builds von httpd, /etc/apache2/mods-enabled/ssl.conf für die Ubuntu- oder Debian-gebundelte httpd usw.). $ openssl s_client -connect www.example.com:443 -status -servername www.example.com ... Wenn mehr als einige SSL-Zertifikate für den Server verwendet werden, werden OCSP-Antworten in der SSL-Stapling-Cache gespeichert.

Mehr als einige SSL-Zertifikate werden für den Server verwendet. Die Antworten auf OCSP (Online Certificate Status Protocol) werden in dem SSL-Stapling-Cache gespeichert. Normale Antworten haben eine Größe von einigen hundert bis einigen tausend Bytes, mod_ssl unterstützt OCSP-Antworten bis zu etwa 10K Bytes. Bei mehr als einigen Zertifikaten kann die Größe des Stapling-Cache (32768 Bytes im oben genannten Beispiel) erhöht werden. Bei Fehlern beim Speichern einer Antwort wird der Fehler mit dem Log-Eintrag AH01929 protokolliert. Wenn das Zertifikat keinen OCSP-Antwortserver angibt oder ein anderes Adresse benötigt, beachten Sie die SSLStaplingForceURL-Direktive. Sie können überprüfen, ob ein Serverzertifikat einen OCSP-Antwortserver angibt, indem Sie das openssl-Befehlszeilenprogramm wie folgt verwenden:

$ openssl x509 -in ./www.beispiel.com.crt -text | grep 'OCSP.*http'

Wenn die OCSP-URI angegeben ist und der Webserver direkt mit ihr kommunizieren kann, ohne einen Proxy zu verwenden, ist keine Konfiguration erforderlich. Achten Sie darauf, dass Firewall-Regeln, die die ausgehenden Verbindungen vom Webserver kontrollieren, eventuell angepasst werden müssen. Wenn keine OCSP-URI angegeben ist, wenden Sie sich an Ihre Zertifikat-Autorität, um festzustellen, ob eine verfügbar ist; falls ja, konfigurieren Sie sie mit SSLStaplingForceURL in dem virtuellen Host, der das Zertifikat verwendet. Wenn mehrere SSL-aktivierte virtuelle Hosts konfiguriert sind und OCSP-Stapling für einige deaktiviert werden soll, fügen Sie SSLUseStapling Off den virtuellen Hosts hinzu, für die OCSP-Stapling deaktiviert werden soll.

Würde die Verknüpfung für bestimmte Add SSLUseStapling Off müssen Sie den virtuellen Hosts für die OCSP-Verknüpfung deaktivieren, für die diese deaktiviert werden soll. Wenn der OCSP-Antwortgeber langsam oder unzuverlässig ist, stehen mehrere Direktiven zur Verfügung, um Timeouts und Fehler zu behandeln. Siehe die Dokumentation für die Direktiven SSLStaplingFakeTryLater, SSLStaplingResponderTimeout und SSLStaplingReturnResponderErrors. Wenn mod_ssl Fehler AH02217 AH02217: ssl_stapling_init_cert: Kein Ausstellerzertifikat abrufen! auftritt, um OCSP-Verknüpfung zu unterstützen, wenn eine bestimmte Serverzertifikat verwendet wird, muss die Zertifikatkette für dieses Zertifikat konfiguriert werden. Wenn dieses bei der Aktivierung von SSL nicht konfiguriert wurde, wird Fehler AH02217 ausgelöst, wenn Verknüpfung aktiviert wird, und für Kunden, die das Zertifikat verwenden, wird keine OCSP-Antwort bereitgestellt. Siehe SSLCertificateChainFile und SSLCertificateFile für Anweisungen zur Konfiguration der Zertifikatkette. Die OCSP-Verknüpfung anpassen für die Produktion Die standardmäßigen OCSP-Verknüpfungseinstellungen sind konservativ und können zu einer unzureichenden Anzahl von Abfragen an OCSP-Antwortgebern, Timeouts oder zu langer Speicherung von Fehlerantworten führen. Die folgenden Einstellungen sind für die Produktion empfohlen: # OCSP-Antwortgeberfehler nicht den Clients zugänglich machen: SSLStaplingReturnResponderErrors off # OCSP-Antwortgeber Timeout von Standardwert 10s reduzieren: SSLStaplingResponderTimeout 4 # Gültige OCSP-Antworten für 48 Stunden speichern (Standard: 1 Stunde).

OCSP Antwortverzögerung von der Standardzeit von 10s: SSLStaplingResponderTimeout 4 # Cache gültige OCSP-Antworten für 48 Stunden (Standard: 1 Stunde). # Dadurch wird die Belastung von OCSP-Antwortern reduziert und transiente Fehler vermieden, die durch häufige Abfragen verursacht werden: SSLStaplingStandardCacheTimeout 172800 # Wiederholen Sie erfolglose OCSP-Abfragen nach 60 Sekunden statt der # Standardzeit von 600s: SSLStaplingErrorCacheTimeout 60

Diese Einstellungen beheben häufig auftretende Probleme, bei denen die Standard-OCSP-Stapling die Fehler unter Last erzeugt — insbesondere, wenn OCSP-Antwortschreiber langsam oder unzuverlässig sind. Wie kann ich Clients verpflichten, ihre Zertifikate für die Authentifizierung zu verwenden? Wenn Sie alle Benutzer kennen (z.B. wie oft der Fall ist auf einer corporate Intranet), können Sie die einfache Zertifikat-Authentifizierung erzwingen.

Ihre gesamte Nutzer (z.B. wie oft der Fall auf einer internen Intranet-Plattform ist), können Sie eine einfache Zertifikatsauthentifizierung erzwingen. Dazu müssen Sie lediglich Clientzertifikate erstellen, die von Ihrer eigenen CA-Zertifikatdatei (ca.crt) signiert wurden, und anschließend die Clients gegen dieses Zertifikat überprüfen. # Es wird ein Clientzertifikat erfordert, das direkt # von unserer CA-Zertifikatdatei in ca.crt signiert sein muss SSLVerifyClient require SSLVerifyDepth 1 SSLCACertificateFile "conf/ssl.crt/ca.crt"

Wie kann ich Clients veranlassen, für eine bestimmte URL (URL) mit Zertifikaten zu authentifizieren, aber dennoch beliebigen Clients den Zugang zum Rest des Servers erlauben? Um Clients zu veranlassen, für eine bestimmte URL mit Zertifikaten zu authentifizieren, können Sie die per-Directory-Konfigurationseigenschaften von mod_ssl verwenden: SSLVerifyClient none SSLCACertificateFile "conf/ssl.crt/ca.crt" <Location "/secure/area"> SSLVerifyClient require SSLVerifyDepth 1 </Location>

Wie kann ich nur Clients zugreifen lassen, die Zertifikate besitzen, um eine bestimmte URL zu erreichen, aber dennoch alle Clients auf den Rest des Servers zugreifen lassen? Die Schlüssel zu diesem sind, dass Sie überprüfen, ob ein Teil des Clientzertifikats mit dem erwarteten Übereinstimmt. Normalerweise überprüfen Sie hierbei den gesamten oder einen Teil des Distinguished Name (DN), um zu sehen, ob es eine bekannte Zeichenkette enthält. Es gibt zwei Möglichkeiten, dies zu tun, entweder mit der Verwendung von mod_auth_basic oder SSLRequire. Die Methode von mod_auth_basic wird normalerweise erforderlich, wenn die Zertifikate vollkommen beliebig sind, oder wenn ihre DNs keine gemeinsamen Felder (normalerweise die Organisation usw.) haben.

Allgemein erforderlich ist dies, wenn die Zertifikate vollkommen zufällig sind, oder wenn ihre DNs keine gemeinsamen Felder aufweisen (meistens die Organisation usw.). In diesem Fall sollte ein Passwort-Datenbank-Verzeichnis eingerichtet werden, das alle zugelassenen Clients enthält, wie folgt:

SSLVerifyClient none
SSLCACertificateFile "conf/ssl.crt/ca.crt"
SSLCACertificatePath "conf/ssl.crt"
<Directory "/usr/local/apache2/htdocs/secure/area">
SSLVerifyClient require
SSLVerifyDepth 5
SSLOptions +FakeBasicAuth
SSLRequireSSL
AuthName "Schlangenöl-Authentifizierung"
AuthType Basic
AuthBasicProvider file
AuthUserFile "/usr/local/apache2/conf/httpd.passwd"
Require valid-user
</Directory>

In diesem Beispiel wird das DES verschlüsselte Passwort "password" verwendet. Weitere Informationen finden Sie in den SSLOptions-Dokumentationen.

httpd.passwd/Ländercode=DE/Ort=München/Organisation=Schlangenöl, Ltd./Organisationsabteilung=Personal/Name=Foo:xxj31ZMTZzkVA
/Ländercode=US/Ort=S.F./Organisation=Schlangenöl, Ltd./Organisationsabteilung=CA/Name=Bar:xxj31ZMTZzkVA
/Ländercode=US/Ort=L.A./Organisation=Schlangenöl, Ltd./Organisationsabteilung=Dev/Name=Quux:xxj31ZMTZzkVA

Wenn alle Clients einer gemeinsamen Hierarchie angehören, die in der DN codiert ist, können sie leichter mithilfe von SSLRequire angepasst werden, wie folgt:

SSLVerifyClient none
SSLCACertificateFile "conf/ssl.crt/ca.crt"
SSLCACertificatePath "conf/ssl.crt"
<Directory "/usr/local/apache2/htdocs/secure/area">
SSLVerifyClient require
SSLVerifyDepth 5
SSLOptions +FakeBasicAuth
SSLRequireSSL
SSLRequire %{SSL_CLIENT_S_DN_O} eq "Schlangenöl, Ltd."
</Directory>

Deine SSL-Zertifikatdatei ist "conf/ssl.crt/ca.crt".
Dein Pfad für SSL-Zertifikate ist "conf/ssl.crt".

<Directory "/usr/local/apache2/htdocs/sicher/bereich">
SSL-Zertifikat-Client wird erfordert und SSL-Tiefe beträgt 5.
SSL-Optionen: +FakeBasicAuth SSLRequireSSL SSLRequire %{SSL_CLIENT_S_DN_O} gleich "Snake Oil, Ltd." und %{SSL_CLIENT_S_DN_OU} in {"Personal", "CA", "Dev"}

Logging ¶ mod_ssl kann sehr detaillierte Fehlerprotokollierungsinformationen in das Fehlerprotokoll schreiben, wenn sein LogLevel auf höhere Spurenstufen festgelegt ist. Andererseits kann auf einem sehr belasteten Server der Level info bereits zu viel sein. Erinnern Sie sich, dass Sie das LogLevel pro Modul individuell konfigurieren können, um Ihren Anforderungen entsprechend zu passen.

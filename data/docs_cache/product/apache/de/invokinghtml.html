Wie Apache gestartet wird ¶

Wenn im Konfigurationsfile der Listen-Wert der Standardwert von 80 (oder irgendein anderer Port unter 1024) ist, ist es erforderlich, Root-Rechte zu haben, um Apache zu starten, damit er sich an diesem privilegierten Port binden kann. Nachdem der Server gestartet und einige vorläufige Aktivitäten wie das Öffnen seiner Log-Dateien durchgeführt hat, wird er mehrere Child-Prozesse starten, die die Arbeit ausführen, Anfragen von Clients zu hören und zu beantworten. Das Haupt-httpd-Prozess läuft weiterhin als root-Benutzer, aber die Child-Prozesse laufen als weniger privilegierter Benutzer. Dies wird durch die ausgewählte Multi-Processing Module kontrolliert. Die empfohlene Methode, das httpd-Executable aufzurufen, ist, das apachectl-Steuerscript zu verwenden. Dieses Script setzt bestimmte Umgebungsvariablen, die für httpd korrekt funktionieren müssen unter bestimmten Betriebssystemen, und dann ruft es das httpd-Binary auf. apachectl überträgt alle Befehlszeilenargumente, sodass auch httpd-Optionen mit apachectl verwendet werden können.

httpd-Binär. Mit apachectl werden beliebige Befehlszeilenargumente übergeben, sodass auch Apache-Optionen mit apachectl verwendet werden können. Sie können auch direkt das apachectl-Skript bearbeiten, indem Sie die HTTPD-Variable nahe oben ändern, um den richtigen Speicherort des httpd-Binärs und beliebige stets vorhandene Befehlszeilenargumente anzugeben. Das erste, was httpd tut, wenn es aufgerufen wird, ist, den Konfigurationsdatei httpd.conf zu lokalisieren und zu lesen. Der Speicherort dieser Datei wird bei der Kompilierung festgelegt, aber es ist möglich, seinen Speicherort während der Ausführung mit dem -f-Option der Befehlszeile anzugeben, wie z.B. /usr/local/apache2/bin/apachectl -f /usr/local/apache2/conf/httpd.conf Wenn alles gut geht während der Startphase, wird der Server sich von der Konsole lösen und der Befehlssatz kehrt fast sofort zurück. Dies zeigt an, dass der Server lauffähig ist. Sie können dann Ihren Browser verwenden, um auf den Server zu verbinden und die Testseite in dem DocumentRoot-Verzeichnis anzusehen. Fehler bei der Startphase ¶ Wenn Apache während der Startphase einen tödlichen Fehler erleidet, schreibt er eine Beschreibung des Problems entweder auf die Konsole oder in den ErrorLog vor dem Beenden. Eine der häufigsten Fehlermeldungen lautet "Unfähig, an Port ... zu binden ...". Diese Meldung wird normalerweise durch folgende Ursachen verursacht:

  • Versuchen, den Server auf einem privilegierten Port zu starten, wenn nicht als root-Benutzer angemeldet ist; oder
  • Versuchen, den Server zu starten, wenn bereits eine Instanz von Apache oder einer anderen Web-Server auf demselben Port gebunden ist.

Der Server, wenn es bereits eine weitere Instanz von Apache oder einem anderen Webserver gibt, der auf demselben Port gebunden ist. Für weitere Problembehebungshinweise konsultieren Sie bitte die Apache FAQ. Starten beim Booten ¶ Wenn Sie Ihren Server nach einem Systemneustart fortführen möchten, sollten Sie einen Aufruf von apachectl in Ihre Systemstartdateien (typischerweise rc.local oder eine Datei in einem rc.N-Verzeichnis) hinzufügen. Dadurch wird Apache als root gestartet. Bevor Sie dies tun, sollten Sie sicherstellen, dass Ihr Server für Sicherheit und Zugriffsbeschränkungen korrekt konfiguriert ist. Der apachectl-Skript ist so entworfen, dass es sich wie ein standardisierter SysV-Init-Skript verhält; es kann die Argumente start, restart und stop empfangen und sie in die entsprechenden Signale an httpd übersetzen. Somit können Sie oft einfach apachectl in das passende Init-Verzeichnis verlinken. Allerdings sollten Sie die genauen Anforderungen Ihres Systems überprüfen.

Core Enhancements ¶
Laufzeitladenbare MPMs
Es können jetzt mehrere MPMs als laufzeitladenbare Module bei der Kompilierung erstellt werden. Die gewünschte MPM kann bei Laufzeit über die LoadModule-Direktive konfiguriert werden.
Event MPM
Das Event MPM ist nicht mehr experimentell, sondern wird jetzt vollständig unterstützt.
Besseres Unterstützung für asynchrones Lesen/Schreiben für unterstützende MPMs und Plattformen.
Per-Modul- und per-Verzeichnis-LogLevel-Konfiguration
Der LogLevel kann jetzt pro Modul und pro Verzeichnis konfiguriert werden. Neue Stufen trace1 bis trace8 wurden hinzugefügt, die über der Debug-Stufe liegen.
Per-Anfrage-Konfigurationsektionen <If>, <ElseIf>, und <Else> können verwendet werden, um die Konfiguration anhand von per-Anfrage-Kriterien zu setzen.
Allgemein nutzbarer Ausdrucksparser
Ein neuer Ausdrucksparser erlaubt es, komplexe Bedingungen in Direktiven wie SetEnvIfExpr, RewriteCond, Header, <If>, und anderen zu spezifizieren.
KeepAliveTimeout in Millisekunden
Es ist jetzt möglich, KeepAliveTimeout in Millisekunden anzugeben.

Richtlinien wie SetEnvIfExpr, RewriteCond, Header, <If>, und andere. Es ist nun möglich, KeepAliveTimeout in Millisekunden zu spezifizieren. NameVirtualHost-Richtlinie
Diese Richtlinie wird nicht mehr benötigt und ist jetzt veraltet.
Überschreiben der Konfiguration
Mit der neuen AllowOverrideList-Richtlinie können mehr fein abgestimmte Steuerungsmöglichkeiten erzielt werden, welche Richtlinien in .htaccess-Dateien erlaubt sind. Konfigurationsdateivariablen
Es ist nun möglich, Variablen in der Konfiguration zu definieren, was eine klarere Darstellung ermöglicht, wenn dasselbe Wert an vielen Stellen in der Konfiguration verwendet wird.
Reduzierte Speicherverbrauch
Trotz vieler neuer Funktionen verbraucht 2.4.x im Vergleich zu 2.2.x weniger Speicher.

Module-Verbesserungen ¶
mod_ssl
mod_ssl kann nun konfiguriert werden, um einen OCSP-Server zu verwenden, um den Validierungsstatus eines Clientzertifikats zu überprüfen. Der Standard-Antwortserver ist konfigurierbar, ebenso wie die Entscheidung, ob der Antwortserver im Clientzertifikat selbst angegebenen zu bevorzugen.
mod_ssl unterstützt nun auch OCSP-Stapling, bei dem der Server proaktiv einen OCSP-Verifikationsschritt für sein Zertifikat erstellt und diesem während der Handshake an den Client übermittelt.

(Die technischen Terme, Codeblöcke, Befehle, Dateipfade und URLs wurden unverändert übernommen.)

Hier wird der Server vorgreifend eine OCSP-Validierung seines Zertifikats aktiv erlangen und übermittelt diese dem Client während der Verbindungsaufnahme. mod_ssl kann nun konfiguriert werden, um SSL-Sessiondaten zwischen Servern über memcached zu teilen. Neben RSA und DSA werden jetzt auch EC-Schlüssel unterstützt. Unterstützung für TLS-SRP (ab 2.4.4 und später). mod_proxy Der ProxyPass-Direktiv kann jetzt optimale Konfiguration innerhalb eines Location- oder LocationMatch-Blocks erhalten und bietet einen signifikanten Leistungsvorteil gegenüber der traditionellen zwei-parameter-Syntax, wenn er in großer Zahl vorhanden ist. Die Quelladresse, die für Proxy-Anfragen verwendet wird, kann nun konfiguriert werden. Unterstützung für Unix-Domain-Sockets zum Backend (ab 2.4.7 und später). mod_proxy_balancer Es werden zusätzliche Laufzeitkonfigurationsänderungen für BalancerMembers über balancer-manager unterstützt. Weitere BalancerMembers können dynamisch über balancer-manager hinzugefügt werden. Laufzeitkonfiguration eines Teilmengens von Balancer-Parametern BalancerMembers können nun auf 'Drain' gesetzt werden, so dass sie nur auf bestehende sticky Sessions reagieren und damit sanft abgeschaltet werden können. Balancer-Einstellungen können persistente sein, also nach Neustarts. mod_cache Der mod_cache CACHE-Filter kann optional an einer gegebenen Stelle in der Filterkette eingefügt werden, um feine Kontrolle über den Cache zu erlangen. mod_cache kann nun HEAD-Anfragen cachend speichern. Sofern möglich, können mod_cache-Direktiven nun pro Verzeichnis gesetzt werden, statt pro Server. Der Basis-URL der in Cache gespeicherten URLs kann nun angepasst werden, so dass eine Gruppe von Caches die gleiche Endpunkt-URL-Präfix teilen kann.

Um eine Einstellung pro Verzeichnis, anstatt pro Server zu haben, kann mod_cache nun konfiguriert werden. Der Basis-URL der von mod_cache gecacheten URLs kann benutzerdefiniert werden, sodass eine Gruppe von Caches den gleichen Endpunkt-URL-Präfix teilen können. mod_cache ist nun in der Lage, alte gecachete Daten anzeigen, wenn ein Backend nicht verfügbar ist (Fehler 5xx). mod_cache kann nun HIT/MISS/REVALIDATE in einen X-Cache-Header einfügen. mod_include unterstützt nun das 'onerror'-Attribut innerhalb eines 'include'-Elements, sodass ein Fehlerdokument anstelle des Standardfehlertexts angezeigt werden kann, wenn ein Fehler auftritt. mod_cgi, mod_include, mod_isapi, ... Die Übersetzung von Headern in Umgebungsvariablen ist strenger geworden, um einige mögliche Cross-Site-Scripting-Angriffe durch Header-Injektion zu verhindern. Header-Namen, die ungültige Zeichen (inklusive Unterstriche) enthalten, werden nicht mehr in Umgebungsvariablen umgewandelt. Apache-Umgebungsvariablen bieten einige Hinweise, wie man mit gebrochenen Legacy-Clients umgehen muss, die solche Headern erfordern. (Dies betrifft alle Module, die diese Umgebungsvariablen verwenden.) mod_authz_core Autorisierungslogik-Container Erweiterte Autorisierungslogik kann nun mithilfe des Require-Directives und den entsprechenden Container-Directives, wie z.B. <RequireAll>, angegeben werden. mod_rewrite mod_rewrite erweitert [QSD] (Query String Discard) und [END] als Flagge für RewriteRule, um häufig auftretende Umleitungsszenarien zu vereinfachen. Es ermöglicht die Verwendung komplexer boolescher Ausdrücke in RewriteCond. Es erlaubt die Verwendung von SQL-Abfragen als RewriteMap-Funktionen.

(Diese Änderungen betreffen alle Module, die diese Funktionalitäten verwenden.)

Dokumentation ¶ mod_rewrite Die mod_rewrite-Dokumentation wurde neu geordnet und fast vollständig neu geschrieben, mit dem Fokus auf Beispiele und häufiger Verwendung, sowie auf dem zeigen, wann andere Lösungen besser geeignet sind. Die Rewrite Guide ist jetzt eine top-level-Sektion mit viel mehr Detail und besserer Organisation. mod_ssl Die mod_ssl-Dokumentation wurde stark verbessert, mit mehr Beispielen auf dem Einstiegsebene, zusätzlich zur vorherigen Fokussierung auf technische Details. Caching Guide Das Caching Guide wurde neu geschrieben, um die RFC2616 HTTP/1.1-Caching-Funktionen, die von mod_cache bereitgestellt werden, richtig von der allgemeinen key/value-Caching, die über den socache-Schnittstelle bereitgestellt wird, zu unterscheiden, sowie um spezialisierte Caching-Mechanismen wie mod_file_cache zu behandeln. Module Developer Changes ¶ Check Configuration Hook Hinzugefügt Ein neuer Hook, check_config, wurde hinzugefügt, der zwischen den Hooks pre_config und open_logs läuft. Er läuft auch vor dem test_config-Hook, wenn die -t-Option an httpd übergeben wird. Der check_config-Hook ermöglicht Modulen, abhängige Konfigurationsdirektivwerte zu überprüfen und sie anzupassen, bevor die Meldungen noch an die Konsole geschrieben werden. Der Benutzer kann damit vor Miskonfiguration-Problemen vor dem Core-Funktion open_logs-Hook die Konsole-Ausgabe in das Fehlerprotokoll umleiten.

Meldungen können noch in die Konsole protokolliert werden. Dadurch kann der Benutzer auf Konfigurationsfehler vor dem Kern-Funktion open_logs hook auf die Fehlerprotokollierung der Konsole hingewiesen werden. Expression Parser Hinzugefügt
Wir verfügen jetzt über einen allgemein nutzbaren Ausdrucks-Parser, dessen API in ap_expr.h ausgeliefert wird. Dieser basiert auf dem Ausdrucks-Parser, der zuvor in mod_ssl implementiert wurde.
Autorisierungslogik-Container
Autorisierungsmodule registrieren sich jetzt als Anbieter, über ap_register_auth_provider(), um fortgeschrittenes Autorisierungslogik zu unterstützen, wie z.B. <RequireAll>.
Small-Object-Caching-Schnittstelle
Der ap_socache.h-Header stellt eine providerbasierte Schnittstelle für das Cachen kleiner Datenobjekte bereit, basierend auf der vorherigen Implementierung des mod_ssl-Sessioncaches. Derzeit werden Anbieter mit einem shared-memory-cyclic buffer, diskbasierten dbm-Dateien und einem memcache-verteilten Cache unterstützt. Status-Hook hinzugefügt
Das mod_cache-Modul enthält nun einen neuen cache_status-Hook, der aufgerufen wird, wenn die Cachingentscheidung bekannt wird. Eine Standardimplementierung ist bereit, die eine optionalen X-Cache und X-Cache-Detail-Header zur Antwort hinzufügt. Die Entwicklerdokumentation enthält eine ausführliche Liste der API-Änderungen.

Dieses Dokument beschreibt, was ein Mehrprozessor-Modul ist und wie sie vom Apache HTTP-Server verwendet werden.
Einleitung
Der Apache HTTP-Server ist ein mächtiger und flexibler Webserver, der auf einem sehr breiten Spektrum von Plattformen in einer Reihe von verschiedenen Umgebungen arbeiten kann.
Different Plattformen und verschiedene Umgebungen erfordern oft andere Funktionen oder haben unterschiedliche Wege, um die gleiche Funktion am effizientesten zu implementieren.
Apache httpd hat immer eine breite Palette von Umgebungen durch seine modulare Konstruktion unterstützt.
Diese Konstruktion erlaubt dem Webmaster, die Features des Servers auszuwählen, indem er entscheidet, welche Module zu laden, entweder bei der Kompilierung oder beim Laufen.
Apache HTTP Server 2.0 erweitert diese modulare Konstruktion auf die grundlegendsten Funktionen eines Webservers.

Der Server bietet zwei wichtige Vorteile: Apache httpd kann eine breite Palette an Betriebssystemen sauberer und effizienter unterstützen. Im Besonderen ist die Windows-Version des Servers nun viel effizienter, da mpm_winnt native Netzwerkfunktionen anstelle der POSIX-Schicht von Apache httpd 1.3 verwenden kann. Dieser Vorteil erstreckt sich auch auf andere Betriebssysteme, die spezialisierte MPMs implementieren. Der Server kann sich besser an die Bedürfnisse der jeweiligen Website anpassen. Beispielsweise können Websites, die eine große Skalierbarkeit benötigen, entscheiden, einen threadbasierten MPM wie worker oder event zu verwenden, während Websites, die Stabilität oder Kompatibilität mit älterem Software benötigen, einen prefork MPM verwenden können. Auf Benutzerebene erscheinen MPMs ähnlich anderen Apache httpd-Modulen. Der Hauptunterschied besteht darin, dass nur ein und dieselbe MPM in den Server geladen werden kann. Die Liste der verfügbaren MPMs findet sich auf der Modul-Index-Seite.

Die Entscheidung, welcher MPM installiert ist, basiert auf zwei Fragen: 1. Unterstützt das System Threads? 2. Unterstützt das System thread-sicheres Polling (speziell die Funktionen kqueue und epoll)? Wenn die Antwort auf beide Fragen 'ja' lautet, ist der Standard-MPM event. Wenn die Antwort auf #1 'ja' lautet, aber die Antwort auf #2 'nein', ist der Standard der worker. Wenn die Antwort auf beide Fragen 'nein' lautet, ist der Standard-MPM prefork. In praktischen Begriffen bedeutet dies, dass der Standard fast immer event sein wird, da alle modernen Betriebssysteme diese beiden Funktionen unterstützen.

MPMs als statische Module bauen ¶
MPMs können als statische Module auf allen Plattformen gebaut werden. Eine einzelne MPM wird zur Buildzeit gewählt und in den Server eingebunden. Um den Server umzubauen, um die MPM zu ändern, muss der Server neu gebaut werden. Um den Standard-MPM-Wahl zu überprüfen, verwenden Sie die --with-mpm=NAME-Option des configure-Skripts. NAME ist der Name des gewünschten MPM. Nachdem der Server gebaut wurde, kann man durch Verwenden von ./httpd -l bestimmen, welcher MPM gewählt wurde. Dieser Befehl listet alle Module auf, die in den Server eingebunden wurden, einschließlich des MPM.

MPMs als DSO-Module bauen ¶
Auf Unix- und ähnlichen Plattformen können MPMs als DSO-Module gebaut und dynamisch in den Server geladen werden, wie andere DSO-Module. Das Bauen von MPMs als DSO-Module ermöglicht es, den MPM zu ändern, indem man die LoadModule-Direktive für den MPM statt durch Neubau des Servers aktualisiert. LoadModule mpm_event_module modules/mod_mpm_event.

Um durch Aktualisierung der LoadModule-Anweisung für das MPM anstatt durch Neubau des Servers zu ändern. LadeModul mpm_event_module modules/mod_mpm_event.so
Versuchen Sie, mehr als ein MPM zu laden, wird zu einem Startfehler mit dem folgenden Fehler führen. AH00534: httpd: Konfigurationsfehler: Mehr als ein MPM geladen. Diese Funktion wird über das --enable-mpms-shared-Option der configure-Skript-Anweisung aktiviert. Mit Argument all werden alle möglichen MPMs für die Plattform installiert. Andernfalls können Sie eine Liste von MPMs als Argument angeben. Das Standard-MPM, entweder automatisch ausgewählt oder mit der --with-mpm-Option der configure-Skript-Anweisung angegeben, wird in der generierten Server-Konfigurationsdatei geladen. Bearbeiten Sie die LoadModule-Anweisung, um ein anderes MPM auszuwählen.

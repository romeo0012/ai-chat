Řešení problémů s klastery
Řešení běžných problémů s klastery. Tento dokument se týká řešení problémů s klastery; předpokládáme, že jste již vyřadili aplikaci jako možnou příčinu problému, který se vám přítulil. Pro tipy k řešení problémů s aplikací můžete navštívit průvodce řešením problémů s aplikací. Můžete také navštívit přehled řešení problémů pro více informací.
Řešení problémů s kubectl
Pro řešení problémů s kubectl se přečtěte Troubleshooting kubectl.
Zobrazení klasteru
Nejprve je třeba zkontrolovat, zda jsou všechny vaše uzly registrovány správně. Spusťte následující příkaz: 

kubectl get nodes

A poté ověřte, že všechny uzly, které očekáváte, jsou zobrazeny a že jsou všechny v připraveném stavu.
Chcete-li získat podrobné informace o celkové zdravotní stavu vašeho klasteru, můžete spustit: 
kubectl cluster-info dump

Příklad: řešení problému s nedostupným/nefunkčním uzlem
Při řešení může být užitečné zkontrolovat stav uzlu - například, protože jste si všimli neobvyklého chování Pod, který běží na uzlu, nebo abyste se dověděli, proč Pod nebude rozvrhnout se na uzle. Stejně jako s Pods můžete použít kubectl describe node a kubectl get node -o yaml k získání podrobné informace o uzlech. Například zde je to, co zobrazíte, pokud je uzel nedostupný (odpojen z sítě, nebo kubelet umírá a nereaguje na restart, atd.). Pozorujte události, které ukazují, že uzel není připravený, a také pozorujte, že pody již neběží (odstraňují se po pěti minutách stavu NotReady).

Všimněte si, že všechny události ukazují, že uzel není připravený, a také zkontrolujte, že pody již neběží (odstraňují se po pěti minutách stavu NotReady).

Prohlížení logů
Pro získání dalších informací o clusteru je třeba se přihlásit k odpovídajícím strojům. Níže jsou umístěny lokace relevantních logovacích souborů. Na systémech s systemd můžete místo toho použít journalctl.

Uzel správy API: /var/log/kube-apiserver.log - API Server, odpovědný za poskytování API
Uzel plánovače: /var/log/kube-scheduler.log - Plánovač, odpovědný za vytváření rozhodnutí o nasazení
Uzel řídícího programu: /var/log/kube-controller-manager.log - komponenta, která spouští většinu vlastních kontrolérů Kubernetes, s výjimkou plánování (plánovač kube-scheduler se stará o plánování).
Uzel pracovníka: /var/log/kubelet.log - logy z kubeletu, odpovědný za spouštění kontejnerů na uzlu
Uzel proxy: /var/log/kube-proxy.log - logy z kube-proxy, který se stará o řízení provozu k endpointům služeb

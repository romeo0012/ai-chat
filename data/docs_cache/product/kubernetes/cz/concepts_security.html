Bezpečnostní koncepty pro zajištění bezpečnosti vašeho cloud-native workload. Tato část dokumentace Kubernetes má za cíl vám pomoci se naučit, jak spouštět workload bezpečněji, a o essenciálních aspektech zabezpečení Kubernetes clusteru. Kubernetes je založen na cloud-native architektuře, a využívá rady z CNCF o dobré praxi pro cloud native informační zabezpečení.

Pročtejte si Cloud Native Security a Kubernetes, abyste získali širší pojetí o tom, jak zabezpečit svůj cluster a aplikace, které na něm běží.

Mechanismy zabezpečení Kubernetes
Kubernetes obsahuje několik API a zabezpečovacích kontrol, a také způsoby definování politik, které mohou tvořit součást způsobu, jaké řídíte informační zabezpečení.

Ochrana řídícího panelu
Základní zabezpečovací mechanismus pro každý Kubernetes cluster je kontrola přístupu k Kubernetes API.

Kubernetes očekává, že budete konfigurovat a používat TLS k poskytnutí šifrování dat při přenosu v rámci řídícího panelu, a mezi řídícím panelem a jeho klienty. Můžete také povolit šifrování v klidu pro data uložená v Kubernetes řídícím panelu; to je oddělené od použití šifrování v klidu pro vlastní workloady, což by mohlo být také dobrá myšlenka.

Tajné informace
Tajné API poskytuje základní ochranu pro konfigurační hodnoty, které vyžadují konfidentialitu.

Ochrana workload
Použijte standardy pro zabezpečení podů, aby byly Pody a jejich kontejnery izolovány správně. Můžete také použít RuntimeClasses k definování vlastní izolace, pokud to potřebujete.

Obsahy a jejich kontejnery jsou vhodně izolovány. Můžete také použít RuntimeClasses k definování vlastní izolace, pokud to potřebujete. Polovky sítě umožňují vám ovládat sítový provoz mezi Obsahy, nebo mezi Obsahy a sítí mimo vaši cluster. Můžete nasadit zabezpečovací kontroly z širšího ekosystému, aby implementovaly prevencionální nebo detektivní kontroly kolem Obsahů, jejich kontejnerů a obrázků, která v nich běží.

Admisní kontrola
Admisní kontrolé jsou pluginy, které zasahují do požadavků na API Kubernetes a mohou ověřovat nebo upravovat požadavky podle určitých polí v požadavku. Myšlenkovitě navrhování těchto kontrol pomáhá vyhnout se nežádoucím narušením, když se API Kubernetes mění při aktualizacích verzí. Pro úvahy ohledně navrhování, přečtěte si Admission Webhook Good Practices.

Auditing
Kubernetes auditing poskytuje zabezpečení relevantní, chronologický seznam záznamů, který dokumentuje sekvenci akcí v clusteru. Cluster audituje aktivity vytvořené uživateli, aplikacemi, které používají API Kubernetes, a samotným control plane.

Politiky

Můžete definovat zabezpečení politiky pomocí mechanismů Kubernetes-native, jako je NetworkPolicy (deklarativní kontrola filtrování sítových balíčků) nebo ValidatingAdmissionPolicy (deklarativní omezení, co může někdo udělat pomocí rozhraní API Kubernetes).

Nicméně můžete také spoléhat na implementacích politik z širšího ekosystému kolem Kubernetes. Kubernetes poskytuje rozšířitelná mechanismy, aby tyto projekty ekosystému mohly implementovat vlastní kontroly politik na kontrolu zdrojového kódu, schvalování obrázků kontejnerů, kontrolu přístupu k API, síti a dalších.

Další informace o mechanismech politik a Kubernetes, přečtěte si v Policích.

V robotice a automatizaci je kontrolní smyčka nekonečný smyček, který reguluje stav systému. Níže je jeden příklad kontrolní smyčky: termostat v místnosti. Když nastavíte teplotu, to je oznámení termostatu o vašem požadovaném stavu. Skutečná teplota v místnosti je aktuální stav. Termostat se snaží přiblížit aktuálnímu stavu k požadovanému stavu, tím, že zapne nebo vypne zařízení. V Kubernetesu jsou kontrolní smyčky kontrolní smyčky, které sledují stav vašeho clusteru a poté provedou nebo požadují změny, kde je to potřeba. Každý kontrolér se snaží přiblížit aktuálnímu stavu clusteru k požadovanému stavu.

Vzorový vzor Vzorový vzor je vzor, který sleduje alespoň jeden typ prostředku Kubernetes. Tyto objekty mají pole spec, které představuje požadovaný stav. Kontroléři pro tento prostředek jsou odpovědní za to, aby aktuální stav přiblížil tento požadovaný stav. Kontrolér může provést akci sám; v Kubernetesu je to však běžnější, že kontrolér odešle zprávu na server API, která má užitečné vedlejší účinky. Viz příklady níže. Ovládání prostřednictvím serveru API

Kontrolér úloh je příkladem vbudovaného kontroléru Kubernetes. Vbudované kontroléry spravují stav prostřednictvím interakce s serverem API clusteru. Úloha je prostředek Kubernetes, který spouští Pod, nebo možná několik Podů, aby provedl úkol a poté zastavil. (Jakmile je rozdělen, objekty Pod se stávají součástí požadovaného stavu pro kubelet).

Příklady

apiVersion: batch/v1
kind: Job
metadata:
  name: hello
spec:
  template:
    spec:
      containers:
      - name: hello
        image: busybox
        args:
        - /bin/sh
        - -c
        - echo Hello from Kubernetes
      restartPolicy: OnFailure

V tomto příkladu je definována úloha, která spustí Pod s obrázkem busybox a vytiskne "Hello from Kubernetes". Pokud se však kontrolér úloh rozhodne, že aktuální stav clusteru není v souladu s požadovaným stavem, odešle zprávu na server API, která způsobí, že se úloha spustí.

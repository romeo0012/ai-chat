Dokumentace funkce pro vydání
Každá hlavní verze Kubernetes přináší nové funkce, které potřebují dokumentaci. Nové vydání také přináší aktualizace pro existující funkce a dokumentaci (například aktualizaci funkce z alfa na beta). Obecně je SIG odpovědný za funkci, která vytváří pull request s návrhem dokumentace funkce do vhodné větvě repozitáře kubernetes/website. Poté někdo z týmu SIG Docs poskytne editoriální zpětnou vazbu nebo upraví návrh dokumentace přímo. Tato část se týká konvencí větvování a procesu, který se používá během vydání oběma skupinami. Chcete-li se dozvědět, jak oznámit funkce na blogu, přečtěte si komunikace po vydání. Pro přispěvatele dokumentace Obecně přispěvatelé dokumentace nevytvářejí obsah z nulové míry pro vydání. Místo toho spolupracují se SIG vytvářícím novou funkci, aby upravili návrh dokumentace a připravili ho na vydání. Po vybrání funkce k dokumentaci nebo podpoře septěte v kanále Slack #sig-docs, v týdenním setkání SIG Docs nebo přímo na pull requestu vytvořeném SIG funkce. Pokud jste dostali zelený světlo, můžete upravit do pull requestu pomocí jedné z technik popsaných v Commit into another person's PR. Zjistit o budoucích funkcích Chcete-li zjistit o budoucích funkcích, účastníte se týdenního setkání SIG Vydání (viz stránku s komunitou pro příští setkání) a monitorujte dokumentaci vydání specifickou pro Kubernetes v repozitáři kubernetes/sig-release.

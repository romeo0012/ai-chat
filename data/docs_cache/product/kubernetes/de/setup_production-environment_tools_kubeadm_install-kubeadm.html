Es ist sehr wahrscheinlich, dass Hardware-Geräte eindeutige Adressen haben, obwohl einige virtuelle Maschinen identische Werte haben. Kubernetes verwendet diese Werte, um die Knoten im Cluster eindeutig zu identifizieren. Wenn diese Werte nicht für jeden Knoten eindeutig sind, kann die Installationsprozess scheitern.

Überprüfen Sie die Netzwerk-Anschlüsse

Wenn Sie mehr als einen Netzwerk-Anschluss haben und Ihre Kubernetes-Komponenten über den Standardroute nicht erreichbar sind, empfehlen wir Ihnen, IP-Routen hinzuzufügen, damit die Adressen des Kubernetes-Clusters über den passenden Anschluss gingen.

Überprüfen Sie erforderliche Ports

Diese erforderlichen Ports müssen offen sein, damit Kubernetes-Komponenten miteinander kommunizieren können. Sie können Werkzeuge wie netcat verwenden, um zu überprüfen, ob ein Port offen ist. Beispiel:
nc 127.0.0.1 6443 -zv -w 2

Der Pod-Netzwerk-Plugin, das Sie verwenden, kann auch bestimmte Ports offen halten müssen.

Um einen Port zu überprüfen, ob er offen ist, kann man wie folgt mit netcat vorgehen. Beispiel:

Der Pod-Netzwerk-Plugin, das Sie verwenden, kann auch bestimmte Ports benötigen, um zu funktionieren. Da dies je nach Pod-Netzwerk-Plugin unterschiedlich ist, bitte siehe die Dokumentation zu den Plugins, um herauszufinden, welche Port(s) dies sind.

Um die Konfiguration zu tauschen
Die Standardverhalten des kubelet ist, wenn Swap-Speicher auf einem Knoten erkannt wird, dass es fehlschlägt, um zu starten. Das bedeutet also, dass Swap entweder ausgeschaltet oder vom kubelet toleriert werden muss.
Um Swap zu tolerieren, fügt man failSwapOn: false in die kubelet-Konfiguration ein oder als Befehlszeilenargument. Hinweis: selbst wenn failSwapOn: false bereitgestellt wird, haben Arbeitslasten keinen Zugriff auf Swap-Speicher standardmäßig. Dies kann durch die Einstellung einer swapBehavior geändert werden, wiederum in der kubelet-Konfigurationsdatei. Um Swap zu nutzen, setzt man eine swapBehavior, die anders ist als die Standard-Einstellung NoSwap. Weitere Details finden Sie unter Swap-Speicherverwaltung.
Um Swap auszuschalten, kann sudo swapoff -a verwendet werden, um das Schalten von Swap vorübergehend auszuschalten. Um diese Änderung persistenzhaft bei Neustart zu halten, muss Swap in Konfigurationsdateien wie /etc/fstab, systemd.swap, abhängig von der Konfiguration Ihres Systems, deaktiviert werden.

Installation eines Container-Laufzeitsystems
Um Container in Pods auszuführen, verwendet Kubernetes ein Container-Laufzeitsystem.
Voreingestellt wird Kubernetes mit dem Container Runtime Interface (CRI) umgehen, um mit Ihrem gewünschten Container-Laufzeitsystem zu kommunizieren.
Wenn Sie kein Laufzeitsystem angeben, versucht kubeadm automatisch, ein installiertes Laufzeitsystem durch Scannen einer Liste von bekannten Endpunkten zu erkennen.

spezifiziere eine Laufzeit, kubeadm versucht automatisch einen installierten Container-Laufzeitumgebung durch Suche an einer Liste von bekannten Endpunkten zu erkennen. Wenn mehrere oder keine Container-Laufzeitumgebungen erkannt werden, wird von kubeadm ein Fehler geworfen und es wird gefordert, die gewünschte zu spezifizieren. Weitere Informationen finden Sie unter Container-Laufzeitumgebungen.

Hinweis: Docker Engine implementiert nicht die CRI, die eine Anforderung für eine Container-Laufzeitumgebung ist, um mit Kubernetes zu funktionieren. Daher muss das zusätzliche Service cri-dockerd installiert werden. cri-dockerd ist ein Projekt auf Basis der alten integrierten Unterstützung von Docker Engine, die aus dem kubelet in der Version 1.24 entfernt wurde.

kubeadm wird Ihnen nicht helfen, kubelet oder kubectl zu installieren oder zu verwalten, sodass Sie sicherstellen müssen, dass sie der Version des Kubernetes-Control-Planes entsprechen, den Sie kubeadm installieren möchten. Wenn Sie dies nicht tun, besteht die Gefahr eines Version-Verschwimmens, das zu unerwarteten, fehlerhaften Verhalten führen kann. Allerdings wird ein geringer Version-Verschwimmung zwischen kubelet und dem Control-Plane unterstützt, aber die kubelet-Version darf nie die API-Server-Version überschreiten. Beispielhaft ist das kubelet, das 1.7.0 läuft, vollkommen kompatibel mit einem 1.8.0 API-Server, aber nicht umgekehrt.

Aktualisieren Sie den apt-Paket-Index und installieren Sie die benötigten Pakete, um die Kubernetes-apt-Repository-Verwendung zu ermöglichen:

Laden Sie die öffentliche Signatur-Schlüsseldatei für die Kubernetes-Paket-Repositories herunter. Der gleiche Signatur-Schlüssel wird für alle Repositories verwendet, sodass Sie den Version-Teil in der URL verneinen können:

# Wenn das Verzeichnis /etc/apt/keyrings nicht existiert, sollte es vor der curl-Befehlausführung erstellt werden, lesen Sie bitte den Hinweis unten. #

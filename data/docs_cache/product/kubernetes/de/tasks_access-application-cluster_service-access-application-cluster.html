Use a Service to Access an Application in a Cluster

← Chat

Verwenden Sie einen Dienst, um eine Anwendung in einem Cluster zu erreichen
Diese Seite zeigt, wie Sie ein Kubernetes-Dienstobjekt erstellen, das externen Clients zur Verfügung steht, um eine Anwendung in einem Cluster zu erreichen. Der Dienst bietet Lastenausgleich für eine Anwendung, die zwei laufende Instanzen hat.

Vor dem Start
Sie benötigen einen Kubernetes-Cluster, und das kubectl-Befehlszeilentool muss konfiguriert sein, um mit Ihrem Cluster zu kommunizieren. Empfohlen wird, dieses Tutorial auf einem Cluster mit mindestens zwei Knoten auszuführen, die nicht als Control-Plane-Hosts fungieren. Wenn Sie keinen Cluster haben, können Sie einen mit minikube erstellen oder können Sie einen von diesen Kubernetes-Playgrounds verwenden:
iximiuz Labs
Killercoda
KodeKloud

Ziele

  • Zwei Instanzen einer Hallo-Welt-Anwendung ausführen.
  • Ein Dienstobjekt erstellen, das eine Node-Port exponiert.
  • Das Dienstobjekt zur Verfügung stellen, um die laufende Anwendung zu erreichen.

Erstellen Sie einen Dienst für eine Anwendung, die in zwei Pods läuft
Hier ist die Konfigurationsdatei für die Anwendung Deployment:

service/access/hello-application.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
name: hello-world
spec:
selector:
matchLabels:
run: load-balancer-example
replicas: 2
template:
metadata:
labels:
run: load-balancer-example
spec:
containers:
- name: hello-world
image: us-docker.pkg.dev/google-samples/containers/gke/hello-app:2.0
ports:
- containerPort: 8080
protocol: TCP

Starten Sie eine Hallo-Welt-Anwendung in Ihrem Cluster:

Erstellen Sie die Anwendung Deployment mit der oben angegebenen Datei:

kubectl apply -f https://k8s.

TCP Führen Sie in Ihrem Cluster eine Hello World-Anwendung aus: Erstellen Sie die Bereitstellung der Anwendung mithilfe des oben angegebenen Datei: 

kubectl apply -f https://k8s.io/examples/service/access/hello-application.yaml

Das vorherige Befehl erstellt eine Bereitstellung und ein assoziiertes ReplicaSet. Das ReplicaSet hat zwei Pods, die jeweils die Hello World-Anwendung ausführen.

Anzeigen Sie Informationen zur Bereitstellung: 

kubectl get deployments hello-world
kubectl describe deployments hello-world

Anzeigen Sie Informationen zu Ihren ReplicaSet-Objekten: 
kubectl get replicasets
kubectl describe replicasets

Erstellen Sie ein Service-Objekt, das die Bereitstellung ausblendet: 
kubectl expose deployment hello-world --type=NodePort --name=example-service

Anzeigen Sie Informationen zum Service: 
kubectl describe services example-service

Das Ausgabeergebnis ist ähnlich diesem:
Name: example-service
Namespace: default
Labels: run=load-balancer-example
Annotations: <none>
Selector: run=load-balancer-example
Type: NodePort
IP: 10.32.0.16
Port: <unset> 8080/TCP
TargetPort: 8080/TCP
NodePort: <unset> 31496/TCP
Endpoints: 10.200.1.4:8080,10.200.2.5:8080
Session Affinity: None
Events: <none>

Notieren Sie sich den NodePort-Wert für das Service. Beispielhaft ist der NodePort-Wert in dem vorherigen Ausgabeergebnis 31496.

Liste Sie die Pods auf, die die Hello World-Anwendung ausführen: 

kubectl get pods --selector="run=load-balancer-example" --output=wide

Das Ausgabeergebnis ist ähnlich diesem:
NAME READY STATUS ... IP NODE
hello-world-2895499144-bsbk5 1/1 Running ... 10.200.1.4

Notieren Sie sich die IP-Adresse der Pods, die die Hello World-Anwendung ausführen.

get Pods --selector="run=load-balancer-beispiel" --output=breit Die Ausgabe ähnelt diesem:
NAME READY STATUS ... IP NODE hello-world-2895499144-bsbk5 1/1 Laufend ... 10.200.1.4 worker1 hello-world-2895499144-m1pwt 1/1 Laufend ... 10.200.2.5 worker2

Holzen Sie sich die öffentliche IP-Adresse eines Ihrer Knoten, der ein Hello World Pod ausführt. Wie Sie diese Adresse erhalten, hängt von der Konfiguration Ihres Clusters ab. Zum Beispiel können Sie, wenn Sie Minikube verwenden, die Adresse Ihres Knotens durch Ausführen von kubectl cluster-info sehen. Wenn Sie Google Compute Engine Instanzen verwenden, können Sie die öffentlichen Adressen Ihrer Knoten mit dem Befehl gcloud compute instances list abrufen.

Auf Ihrem gewählten Knoten erstellen Sie eine Firewallregel, die TCP-Verkehr auf Ihrer Knotenport erlaubt. Zum Beispiel, wenn Ihre Dienstkonfiguration den Wert NodePort von 31568 hat, sollte Sie eine Firewallregel erstellen, die TCP-Verkehr auf Port 31568 erlaubt. Cloud-Anbieter bieten unterschiedliche Möglichkeiten, Firewallregeln zu konfigurieren.

Verwenden Sie die öffentliche IP-Adresse Ihres Knotens und den Knotenport, um die Hello World Anwendung aufzurufen:

curl http://<öffentliche-knoten-ip>:<knoten-port>

Wo <öffentliche-knoten-ip> die öffentliche IP-Adresse Ihres Knotens und <knoten-port> der NodePort-Wert für Ihren Dienst ist. Die Antwort auf eine erfolgreiche Anfrage ist ein Hallo-Meldung:

Hallo, Welt! Version: 2.0.0 Hostname: hello-world-cdd4458f4-m47c8

Alternativ zum Verwenden von kubectl expose können Sie eine Dienstkonfigurationsdatei verwenden, um einen Dienst zu erstellen.

Aufbereiten
Um den Service zu löschen, führen Sie den folgenden Befehl aus: 

kubectl delete services example-service

Um die Deployment, den ReplicaSet und die Pods, die das Hello World-Anwendungslaufen, zu löschen, führen Sie den folgenden Befehl aus: 
kubectl delete deployment hello-world

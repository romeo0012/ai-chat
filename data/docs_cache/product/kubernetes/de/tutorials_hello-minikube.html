Hallo Minikube
Diese Anleitung zeigt Ihnen, wie Sie eine Beispiel-App auf Kubernetes mit Minikube ausführen. Die Anleitung bietet ein Container-Bild, das NGINX verwendet, um alle Anfragen zurückzugeben.

Ziele

  • Eine Beispiel-Anwendung auf minikube bereitstellen.
  • Die App ausführen.
  • Anwendungslogfiles anzeigen.

Vor dem Start
Diese Anleitung setzt voraus, dass Sie bereits Minikube eingerichtet haben. Siehe Schritt 1 in minikube start für Installationsanweisungen.

Hinweis:
Führen Sie nur die Anweisungen in Schritt 1, Installation, aus. Der Rest wird auf dieser Seite abgedeckt.
Sie benötigen auch kubectl. Siehe Install tools für Installationsanweisungen.

Erstellen Sie ein minikube-Cluster
minikube start
Überprüfen Sie den Status des minikube-Clusters
Überprüfen Sie den Status des minikube-Clusters, um sicherzustellen, dass alle Komponenten in einem laufenden Zustand sind.
minikube status
Das Ausgabeergebnis der obenstehenden Befehl sollte zeigen, dass alle Komponenten Running oder Configured sind, wie im Beispielausgabe unten dargestellt:
minikube type: Control Plane host: Running kubelet: Running apiserver: Running kubeconfig: Configured

Öffnen Sie das Dashboard
Öffnen Sie das Kubernetes-Dashboard. Sie können dies in zwei verschiedenen Weisen tun:

  • Eine neue Browser-URL kopieren und einfügen
  • Eine neue Terminal-Fenster öffnen und führen Sie folgenden Befehl aus:

    Öffnen Sie eine neue Terminal-Fenster und lassen Sie dieses laufen.


    minikube dashboard

Notiz:
Der dashboard-Befehl aktiviert den dashboard-Add-on und öffnet den Proxy im Standard-Web-Browser. Sie können auf dem Dashboard Kubernetes-Ressourcen wie Deployment und Service erstellen.

Der Proxy im Standard-Web-Browser. Sie können Kubernetes-Ressourcen auf der Benutzeroberfläche wie Deployment und Service erstellen. Um herauszufinden, wie Sie den Browser direkt aus der Befehlszeile aufrufen vermeiden und eine URL für die Web-Benutzeroberfläche erhalten, siehe den "URL kopieren und einfügen"-Abschnitt.

Voreingestellt ist die Benutzeroberfläche nur über den internen Kubernetes-Virtuellen Netzwerk zu erreichen. Der Befehl der Benutzeroberfläche erstellt einen temporären Proxy, um die Benutzeroberfläche von außerhalb des Kubernetes-Virtuellen Netzwerks zugänglich zu machen. Um den Proxy zu stoppen, führen Sie Ctrl+C aus, um das Prozess zu beenden. Nachdem der Befehl beendet ist, bleibt die Benutzeroberfläche im Kubernetes-Cluster laufen. Sie können den Befehl der Benutzeroberfläche erneut ausführen, um einen anderen Proxy zu erstellen, um die Benutzeroberfläche zu erreichen.

Wenn Sie minikube nicht, um einen Web-Browser für Sie zu öffnen, führen Sie den Befehl des Dashboard-Unterbefehls mit dem --url-Flag aus. minikube gibt eine URL aus, die Sie in den von Ihnen bevorzugten Browser öffnen können.

Öffnen Sie ein neues Terminal und führen Sie aus:

# Starten Sie ein neues Terminal und lassen Sie es laufen.
minikube dashboard --url

Jetzt können Sie diese URL und zurückkehren zum Terminal, wo Sie minikube start ausgeführt haben.

Erstellen Sie eine Deployment

Ein Kubernetes-Pod ist eine Gruppe von einem oder mehreren Containern, die für die Verwaltung und Netzwerkzusammenarbeit zusammengefasst sind. Der Pod in diesem Tutorial hat nur ein Container. Ein Kubernetes-Deployment überprüft den Zustand Ihres Pods und startet den Pod-Container neu, wenn er beendet wird. Deployments sind die empfohlene Methode, um die Erstellung und Skalierung von Pods zu verwalten.

Kubernetes-Bereitstellung prüft auf den Zustand Ihrer Pod und startet den Pod-Container neu, wenn er beendet wird. Bereitstellungen sind die empfohlenen Methode, um die Erstellung und Skalierung von Pods zu verwalten. Verwenden Sie den Befehl kubectl create , um eine Bereitstellung zu erstellen, die einen Pod verwaltet. Der Pod läuft einen Container basierend auf der bereitgestellten Docker-Bilddatei.# Führen Sie ein Test-Container-Bild aus, das einen Webserver enthält

kubectl create deployment hello-node --image=registry.k8s.io/e2e-test-images/agnhost:2.53 -- /agnhost netexec --http-port=8080

Anzeigen der Bereitstellung: kubectl get deployments

Das Ausgabeverhalten ist ähnlich wie:
NAME READY UP-TO-DATE AVAILABLE AGE
hello-node 1/1 1 1 1m (Es kann einige Zeit dauern, bis der Pod verfügbar ist. Wenn Sie "0/1" sehen, versuchen Sie es in einigen Sekunden erneut.)

Anzeigen des Pods: kubectl get pods

Das Ausgabeverhalten ist ähnlich wie:
NAME READY STATUS RESTARTS AGE
hello-node-5f76cf6ccf-br9b5 1/1 Laufend 0 1m

Anzeigen von Clusterereignissen: kubectl get events

Anzeigen der kubectl-Konfiguration: kubectl config view

Anzeigen der Anwendungsprotokolle für ein Container in einem Pod (ersetzen Sie den Pod-Namen durch den, den Sie von kubectl get pods erhalten haben).

Erstelle eine Service
Voreingestellt ist das Pod nur über seine interne IP-Adresse innerhalb des Kubernetes-Clusters zugänglich. Um das Container hello-node außerhalb des virtuellen Kubernetes-Netzwerks zugänglich zu machen, muss das Pod als Kubernetes-Service ausgesetzt werden.
Warnung: Der Container agnhost hat ein /shell-Endpunkt, der für das Debuggen nützlich ist, aber gefährlich für die Öffentliche Internetseite ist. Bitte führe dieses nicht auf einer internetfacing- oder Produktions-Cluster aus.
Verwende das kubectl expose-Befehl, um das Pod der Öffentlichkeit zuzugänglich zu machen: 

kubectl expose deployment hello-node --type=LoadBalancer --port=8080

Das Flag --type=LoadBalancer deutet an, dass Sie Ihr Service außerhalb des Clusters aussetzen möchten.
Das Anwendungscode innerhalb des Test-Images listent nur auf TCP-Port 8080. Wenn Sie kubectl expose verwendet haben, um einen anderen Port auszusetzen, konnten Clients nicht auf diesen anderen Port verbinden.
Anzeigen Sie das Service, das Sie erstellt haben: 
kubectl get services

Das Ausgabe ist ähnlich wie:
NAME TYPE CLUSTER-IP EXTERNAL-IP PORT(S) AGE
hello-node LoadBalancer 10.108.144.78 <pending> 8080:30369/TCP 21s
kubernetes ClusterIP 10.96.0.1 <none> 443/TCP 23m
Auf Cloud-Anbietern, die Load Balancer unterstützen, wird eine externen IP-Adresse bereitgestellt, um das Service zu erreichen. Auf minikube macht der LoadBalancer-Typ das Service über den minikube service-Befehl zugänglich.

Führen Sie den folgenden Befehl aus: 

minikube service hello-node

Dies öffnet einen Browserfenster, das Ihre App serviert und die Antwort des Apps zeigt.
Aktivieren Sie Addons
Das minikube-Tool enthält eine Menge von integrierten Addons, die aktiviert, deaktiviert und in der lokalen Kubernetes-Umgebung geöffnet werden können.

Dieses Skript dient Ihrer App und zeigt die Antwort Ihrer App an. Aktivieren Sie Add-ons

Das Werkzeug minikube enthält eine Voreinstellung von Add-ons, die aktiviert, deaktiviert und in der lokalen Kubernetes-Umgebung geöffnet werden können. Liste die derzeit unterstützten Add-ons:

minikube addons list

Aktivieren Sie ein Add-on, z.B. metrics-server:

minikube addons enable metrics-server

Stoppe den Minikube Cluster:minikube stop

Optional: lösche die Minikube VM:# Optional minikube delete

Wenn Sie minikube erneut verwenden möchten, um mehr über Kubernetes zu lernen, müssen Sie es nicht löschen.

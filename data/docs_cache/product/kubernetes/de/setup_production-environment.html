Produktionsumgebung
Erstellen Sie eine produktionsqualitätsmäßige Kubernetes-Cluster
Ein produktionsqualitätsmäßiger Kubernetes-Cluster erfordert Planung und Vorbereitung. Wenn Ihr Kubernetes-Cluster kritische Workloads ausführen soll, muss er konfiguriert werden, um resilient zu sein. Diese Seite erklärt Schritte, die Sie ausführen können, um einen produktionsbereiten Cluster zu erstellen, oder einen bestehenden Cluster für die Produktion zu promoten. Wenn Sie bereits mit der Produktionsausstattung vertraut sind und die Links suchen möchten, können Sie auf Was ist nächstes springen.

Produktionsaspekte
Typischerweise hat eine produktionsqualitätsmäßige Kubernetes-Clusterumgebung mehr Anforderungen als eine persönliche Lern-, Entwicklungs- oder Testumgebung Kubernetes. Eine produktionsumgebliche Kubernetes-Clusterumgebung kann sicher über viele Benutzer zugreifen, konsistent verfügbar sein und die Ressourcen haben, sich an sich ändernde Anforderungen anzupassen.
Während Sie entscheiden, wo Sie Ihre produktionsqualitätsmäßige Kubernetes-Clusterumgebung wollen und wie viel Management Sie selbst übernehmen oder anderen überlassen möchten, sollten Sie sich fragen, wie Ihre Anforderungen an einen Kubernetes-Cluster durch die folgenden Fragen beeinflusst werden:

Verfügbarkeit: Ein einzelnes Kubernetes-Lernumgebung auf einem Rechner hat einen einzigen Punkt von Versagen. Die Schaffung einer hochverfügbaren Cluster bedeutet, sich mit folgenden Aspekten auseinanderzusetzen:
Trennen Sie die Steuerungsebene von den Arbeitsknoten.
Replizieren Sie die Steuerungsebene-Komponenten auf mehreren Knoten.
Balancieren Sie den Verkehr an den Cluster-API-Server.
Haben Sie genügend Arbeitsknoten verfügbar oder können sie schnell verfügbar werden, wie sich die Workloads ändern.

Wenn Sie jedoch erwarten, dass die Nachfrage über die Zeit wachsen oder sich dramatisch ändern kann, basierend auf Dingen wie der Jahreszeit oder speziellen Veranstaltungen, müssen Sie planen, wie Sie skalieren, um den zusätzlichen Druck von mehr Anfragen an die Steuerungsebene und Arbeiterknoten zu entlasten, oder um zu reduzieren, um unbenutzte Ressourcen zu sparen.Sicherheit und Zugriffsmangement: Sie haben vollständige Admin-Rechte auf Ihrer eigenen Kubernetes-Lernumgebung. Produktions-Cluster-Einrichtung
In einer qualitätsvollen Produktions-Kubernetes-Cluster verwaltet das Steuerungspaneel den Cluster über Dienste, die auf verschiedenen Computern in unterschiedlichen Weisen verteilt sein können. Jeder Arbeitsknoten jedoch repräsentiert eine einzelne Einheit, die konfiguriert ist, um Kubernetes-Pods auszuführen.

Trennen und sichern Sie den etcd-Dienst: Die etcd-Dienste können entweder auf den gleichen Maschinen wie andere Control-Plane-Dienste laufen oder auf separaten Maschinen, um zusätzliche Sicherheit und Verfügbarkeit zu gewährleisten. Mehrere Control-Plane-Systeme erstellen: Um hohe Verfügbarkeit zu gewährleisten, sollte der Control-Plane nicht auf einer einzigen Maschine beschränkt werden. Wenn die Control-Plane-Dienste von einem init-Dienst (z.B. systemd) gestartet werden, sollte jede Dienstinstanz auf mindestens drei Maschinen laufen. Wenn Control-Plane-Dienste als Pods in Kubernetes gestartet werden, wird sichergestellt, dass die angeforderten replizierten Dienstinstanzen immer verfügbar sind. Der Scheduler sollte fehlerverträglich sein, aber nicht hochverfügbar. Einige Bereitstellungswerkzeuge richten den Raft-Konsensus-Algorithmus ein, um die Wahl des Kubernetes-Dienstes durchzuführen. Wenn der Primärdienst ausfällt, wählt sich ein anderer Dienst und übernimmt die Aufgabe.

Produktionsbenutzerverwaltung
In der Produktion können Sie sich von einem Modell wechseln, bei dem Sie oder eine kleine Gruppe von Personen den Zugriff auf den Cluster haben, zu einem Modell, bei dem es möglicherweise Dutzende oder hundert von Personen sein könnten. In einer Lernumgebung oder Plattform-Prototyp können Sie möglicherweise eine einzige administrative Benutzerkonto für alles, was Sie tun, verwenden. In der Produktion möchten Sie mehr Konten mit unterschiedlichen Zugriffsrechten auf verschiedene Namespaces haben.

Die Aufnahme einer produktionsqualitätsmäßigen Clusterbedienung bedeutet, dass Sie entscheiden müssen, wie Sie selektiv anderen Benutzern den Zugriff erlauben.

Zugang zu verschiedenen Namespaces. Eine produktionsbereite Knoten-Cluster-Bereitstellung bedeutet, zu entscheiden, wie Sie selektiv anderen Benutzern den Zugang gewähren möchten. Insbesondere müssen Sie Strategien für die Identitätsprüfung derjenigen auswählen, die versuchen, Ihren Cluster zu erreichen (Authentifizierung) und entscheiden, ob sie die Berechtigung haben, was sie anfragen (Autorisierung):

Authentifizierung: Der apiserver kann Benutzer authentifizieren, indem er Client-Zertifikate, Bearer-Tokens, einen authentifizierenden Proxy oder HTTP Basic Auth verwendet. Sie können die Authentifizierungsmethoden, die Sie verwenden möchten, auswählen. Mithilfe von Plugins kann der apiserver Ihre Organisationseigenen Authentifizierungsmethoden, wie z.B. LDAP oder Kerberos, nutzen. Siehe Authentifizierung für eine Beschreibung dieser verschiedenen Methoden, um Kubernetes-Benutzer zu authentifizieren.

Autorisierung: Wenn Sie Ihre regelmäßigen Benutzer autorisieren wollen, werden Sie wahrscheinlich zwischen RBAC und ABAC-Autorisierung wählen. Siehe Autorisierung-Übersicht, um verschiedene Möglichkeiten für die Autorisierung von Benutzerkonten (einschließlich des Zugriffs auf Service-Accounts auf Ihren Cluster) zu überprüfen:

Rollenbasierte Zugriffssteuerung (RBAC): Erlaubt es Ihnen, Zugriff auf Ihren Cluster durch die Zuweisung spezifischer Berechtigungen an authentifizierte Benutzer zu gewähren. Berechtigungen können für einen bestimmten Namespace (Rolle) oder für den gesamten Cluster (Clusterrolle) zugewiesen werden. Dann können diese Berechtigungen mithilfe von RoleBindings und ClusterRoleBindings an bestimmte Benutzer angehängt werden.

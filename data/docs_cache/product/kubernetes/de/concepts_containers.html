Containers

← Chat

ContainerTechnologie zur Verpackung einer Anwendung zusammen mit ihren Laufzeitabhängigkeiten. Auf dieser Seite wird diskutiert, was Containers und Container-Images sind, sowie ihre Verwendung in Operationen und Lösungsentwicklung.

Das Wort Container ist ein überladenes Wort. Jede Verwendung des Wortes prüfen, ob Ihre Zielgruppe dieselbe Definition verwendet.

Jeder Container, den Sie ausführen, ist wiederholbar; die Standardisierung durch die Einbeziehung von Abhängigkeiten bedeutet, dass Sie dasselbe Verhalten überall, wo Sie es ausführen, erhalten.

Containers koppeln Anwendungen von der unterliegenden Host-Infrastruktur ab. Dadurch wird die Bereitstellung leichter in verschiedenen Cloud- oder OS-Umgebungen.

Jeder Knoten in einem Kubernetes-Cluster führt die Containers aus, die die Pods auf diesem Knoten zugewiesen sind. Containers in einem Pod sind ko-lokalisiert und ko-geschaltet, um auf demselben Knoten zu laufen.

Container-Images
Ein Container-Image ist ein bereitgestelltes Softwarepaket, das alles enthält, was für die Ausführung einer Anwendung benötigt wird: das Code und jedes benötigte Laufzeitumfeld, Anwendungs- und Systembibliotheken, sowie Standardwerte für alle notwendigen Einstellungen.

Containers sollten stateless und unveränderlich sein: Sie sollten keine Änderungen an einem laufenden Container vornehmen, der bereits ausgeführt wird. Wenn Sie eine containerisierte Anwendung ändern möchten, ist das korrekte Verfahren, ein neues Bild zu erstellen, das die Änderung enthält, dann den Container neu zu erstellen, um von dem aktualisierten Bild auszufahren.

Container-Laufzeiten
Ein grundlegender Bestandteil, der Kubernetes dazu ermöglicht, Containers effektiv auszuführen.

Dann erstellt Sie erneut den Container, um von der aktualisierten Bildversion zu starten. Container-Laufzeiten
Ein grundlegender Bestandteil, der Kubernetes dazu ermöglicht, Containers effektiv zu betreiben. Es ist für die Verwaltung der Ausführung und des Lebenszyklus von Containern innerhalb des Kubernetes-Umfelds zuständig.

Kubernetes unterstützt Container-Laufzeiten wie containerd, CRI-O und jede andere Implementierung des Kubernetes-CRI (Container-Laufzeit-Schnittstelle).
Gewöhnlich können Sie Ihrem Cluster erlauben, den Standard-Container-Laufzeit-Typ für einen Pod auszuwählen. Wenn Sie mehr als einen Container-Laufzeit-Typ in Ihrem Cluster verwenden möchten, können Sie dem Pod den RuntimeClass zuweisen, um sicherzustellen, dass Kubernetes die Containers mit einem bestimmten Container-Laufzeit-Typ ausführt.

Sie können auch RuntimeClass verwenden, um verschiedene Pods mit demselben Container-Laufzeit-Typ, aber mit unterschiedlichen Einstellungen, auszuführen.

Dokumentation einer Funktion für eine Veröffentlichung

Jede große Kubernetes-Veröffentlichung führt neue Funktionen ein, die dokumentiert werden müssen. Neue Veröffentlichungen bringen auch Aktualisierungen für bestehende Funktionen und Dokumentation mit sich (zum Beispiel die Aufwertung einer Funktion von Alpha auf Beta). Im Allgemeinen übernimmt das SIG, das für eine Funktion verantwortlich ist, eine Entwurfsdokumentation der Funktion als Pull-Request an den passenden Entwicklungszweig des Repositorys kubernetes/website und jemand aus dem SIG Docs-Team gibt editoriales Feedback oder bearbeitet den Entwurf direkt. Diese Sektion behandelt die Branching-Konventionen und den Prozess, der während einer Veröffentlichung von beiden Gruppen verwendet wird. Um über Nachrichten auf dem Blog zu erfahren, lese bitte post-release-Kommunikationen. Für Beiträger zur Dokumentation Allgemein arbeiten Beiträger zur Dokumentation nicht von vorn an für eine Veröffentlichung. Stattdessen arbeiten sie mit dem SIG, das eine neue Funktion erstellt, um den Entwurf der Dokumentation zu verbessern und ihn für die Veröffentlichung fertigzustellen. Nachdem Sie eine Funktion ausgewählt haben, um zu dokumentieren oder zu unterstützen, fragen Sie nach ihm im #sig-docs Slack-Kanal, in einer wöchentlichen SIG Docs-Treffen oder direkt auf dem PR des Feature-SIG. Wenn Sie zugelassen werden, können Sie in den PR eintragen, indem Sie eine der Techniken beschrieben in Commit into another person's PR verwenden. Um über kommende Funktionen zu erfahren, nehmen Sie an der wöchentlichen SIG Release-Treffen (siehe die Community-Seite für Termine der nächsten Treffen) und beobachten Sie die release-spezifische Dokumentation in dem Repository kubernetes/sig-release.

KV secrets engine

← Chat

Tajemství KV sekvenční řadič je obecný klíč-hodnotový úložiště, používané k uložení libovolných tajemství do konfigurovaného fyzického úložiště pro Vault. Tento řadič může běžet v jednom z dvou režimů; uložit jedinou hodnotu pro klíč, nebo uložit určitý počet verzí pro každý klíč a udržet záznam o nich.

Verze KV 1
Při běhu neverzovaného řadiče KV se ukládá poslední napsaná hodnota pro klíč. Každá aktualizace přepsá hodnotu původní a není možné ji obnovit. Výhody neverzovaného KV jsou redukovaný rozsah úložiště pro kažodý klíč, protože žádné další metadata nebo historie se nekladou. Dále poskytuje lepší výkon během běhu, protože požadavky vyžadují méně volání k úložišti a žádné zámky. Další informace naleznete v Dokumentech KV verze 1.

Verze KV 2
Při běhu verze 2 řadiče KV může klíč udržet konfigurovatelný počet verzí. Výchozí hodnota je 10 verzí. Starší verze metadata a dat mohou být získány. Dále poskytuje operace kontrola a nastavení, aby se zabránilo nechtěnému přepsání dat. Když je verze smazána, podkladová data nejsou odstraněna, nýbrž označena jako smazána. Smazané verze mohou být znovuobnoveny. Chcete-li trvale odstranit datovou verzi, použijte příkaz vault kv destroy nebo API koncovou bod s verbem DELETE. Můžete odstranit všechny verze a metadata pro klíč odstraněním metadat pomocí příkazu vault kv metadata delete nebo API koncového bodu s verbem DELETE.

API koncový bod. Můžete odstranit všechny verze a metadata pro klíč odstraněním metadat pomocí příkazu vault kv metadata delete nebo koncového bodu API s verbem DELETE. Můžete omezit, kdo má oprávnění k odstranění, obnovení nebo úplnému odstranění dat pomocí politik Vault. Další informace naleznete v Dokumentaci KV verze 2.

Nezávisle na jeho verzi používáte příkaz vault kv k interakci s KV enginem tajných klíčů. Nicméně koncové body API jsou jiné. Musíte se se svými rozdíly seznámit, abyste mohli napsat politiky podle svých záměrů. Následující tabulka uvádí příkazy vault kv a jejich odpovídající koncové body API, pokud je KV engine tajných klíčů povolený v secret/.

Příkaz | KV v1 koncový bod | KV v2 koncový bod
--- | --- | ---
vault kv get | secret/<key_path> | secret/data/<key_path>
vault kv put | secret/<key_path> | secret/data/<key_path>
vault kv list | secret/<key_path> | secret/metadata/<key_path>
vault kv delete | secret/<key_path> | secret/data/<key_path>

Dále nabízí KV v2 příkazy k řízení verzování tajných klíčů.

Příkaz | KV v2 koncový bod
--- | ---
vault kv patch | vault kv patch secret/data/<key_path>
vault kv rollback | vault kv rollback secret/data/<key_path>
vault kv undelete | vault kv undelete secret/undelete/<key_path>
vault kv destroy | vault kv destroy secret/destroy/<key_path>
vault kv metadata | vault kv metadata secret/metadata/<key_path>

Chcete-li snížit zmatek, příkaz CLI vydá cestu k tajnému klíči, když pracujete s KV v2.

Příklad: 

$ vault kv put secret/web-app api-token="WEOIRJ13895130WENJWEFN"
=== Secret Path ===
secret/data/web-app
======= Metadata =======
Key Value --- -----
created_time 2024-07-02T00:34:58.074825Z
custom_metadata &lt;nil&gt;
deletion_time n/a
destroyed false
version 1

Můžete použít -mount flag, pokud omítání /data/ v příkazu CLI způsobuje zmatek. 
$ vault kv put -mount=secret web-app api-token="WEOIRJ13895130WENJWEFN"

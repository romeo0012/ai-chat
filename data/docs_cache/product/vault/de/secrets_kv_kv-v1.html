KV-Geheimnis-Engine - Version 1

Der KV-Geheimnis-Engine wird verwendet, um beliebige Geheimnisse innerhalb des von Vault konfigurierten physischen Speichers zu speichern. Schreiben auf einen Schlüssel im kv-Back-End ersetzt den alten Wert; Unterfelder werden nicht zusammengefügt. Schlüsselnamen müssen immer Zeichenfolgen sein. Wenn Sie direkt über die Befehlszeile nicht-Zeichenfolgenwerte schreiben, werden diese in Zeichenfolgen umgewandelt. Sie können jedoch nicht-Zeichenfolgenwerte erhalten, indem Sie den Schlüssel/Wert-Paaren Vault von einem JSON-Datei oder über die HTTP-API schreiben. Dieser Geheimnis-Engine beachtet die Unterscheidung zwischen der Erstellung und der Aktualisierung-Fähigkeiten innerhalb von ACL-Politiken. Hinweis: Pfade und Schlüsselnamen werden nicht verschlüsselt oder verschlüsselt; nur die Werte, die auf den Schlüsseln gesetzt werden, werden. Sie sollten nicht empfindliche Informationen als Teil eines Geheimnisses-Pfads speichern.

Einrichtung
Um eine Version 1 KV-Speicher-Instanz zu aktivieren:
$ vault secrets enable -version=1 kv

Nutzung
Nachdem der Geheimnis-Engine konfiguriert ist und ein Benutzer/Maschine einen Vault-Token mit den entsprechenden Berechtigungen hat, kann es Credentials generieren. Der KV-Geheimnis-Engine erlaubt es, Schlüssel mit beliebigen Werten zu schreiben. Schreibe beliebige Daten:
$ vault kv put kv/mein-geheimnis mein-wert=s3cr3t
Erfolg! Daten geschrieben: kv/mein-geheimnis
Lesen beliebige Daten:
$ vault kv get kv/mein-geheimnis
Schlüssel | Wert
-------- | -----
mein-wert s3cr3t

Liste die Schlüssel:
$ vault kv list kv/
Schlüssel


mein-geheimnis

Lösche einen Schlüssel:
$ vault kv delete kv/mein-geheimnis
Erfolg! Daten gelöscht (wenn sie existierten) an: kv/mein-geheimnis

Sie können auch Vaults Passwort-Politik-Funktion verwenden, um beliebige Werte zu generieren.

---- mein-geheimnis Lösche eine Schüssel: $ vault kv delete kv/mein-geheimnis Erfolg! Daten gelöscht (wenn sie existierten) an: kv/mein-geheimnis Sie können auch die Passwortpolitik-Funktion von Vault verwenden, um beliebige Werte zu generieren. Schreiben Sie eine Passwortpolitik: $ vault write sys/Policies/Passwörter/Beispiel policy=-<<EOF length=20 rule "charset" { charset = "abcdefghij0123456789" min-chars = 1 } rule "charset" { charset = "!@#$%^&*STUVWXYZ" min-chars = 1 } EOF Schreiben Sie Daten mithilfe der Beispielpolitik: $ vault kv put kv/mein-erzeugtes-geheimnis \ Passwort=$(vault read -field Passwort sys/Policies/Passwörter/Beispiel/generate) Lesen Sie das erzeugte Daten: $ vault kv get kv/mein-erzeugtes-geheimnis ====== Daten ====== Schlüssel Wert --- ----- Passwort ^dajd609Xf8Zhac$dW24 TTLs Im Gegensatz zu anderen Secrets-Engines erzwingt der KV-Secrets-Engine keine TTLs für die Ablaufzeit. Stattdessen ist der lease_duration ein Hinweis auf wie oft die Konsumenten sich zurückchecken sollen, um nach einem neuen Wert zu suchen. Wenn Sie eine Schüssel von ttl bereitgestellt haben, wird der KV-Secrets-Engine diese Werte als lease_duration verwenden: $ vault kv put kv/mein-geheimnis ttl=30m my-value=s3cr3t Erfolg! Daten geschrieben zu: kv/mein-geheimnis Auch mit einem ttl festgelegt, entfernt der Secrets-Engine die Daten nicht automatisch. Der ttl-Schlüssel ist lediglich beratend. Wenn Sie einen Wert mit einem ttl lesen, werden beide der ttl-Schlüssel und der Refresh-Intervallwert angezeigt: $ vault kv get kv/mein-geheimnis Schlüssel Wert --- ----- my-value s3cr3t ttl 30m API Der KV-Secrets-Engine verfügt über eine vollständige HTTP-API.

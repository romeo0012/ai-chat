KV-Sekretsspeicher Der KV-Sekretsspeicher ist ein allgemeiner Schlüssel-Wert-Speicher, der beliebige Geheimnisse innerhalb der von Vault konfigurierten physischen Speicherlager speichert. Der Sekretsspeicher kann in einem von zwei Modi laufen; ein einzelnes Wert für eine Schlüssel speichern, oder eine Anzahl von Versionen für jede Schlüssel speichern und deren Verlauf aufzeichnen.

KV-Version 1
Wenn man den KV-Sekretsspeicher nicht versioniert betreibt, speichert er den zuletzt geschriebenen Wert für eine Schlüssel. Jede Aktualisierung wird den ursprünglichen Wert überschreiben und ist nicht mehr wiederherstellbar. Die Vorteile des nicht versionierten KV sind ein reduzierter Speicherplatz für jede Schlüssel, da keine zusätzliche Metadaten oder Geschichte gespeichert wird. Zusätzlich bietet es besseres Laufzeitverhalten, weil die Anfragen weniger Speicheraufrufe und kein Sperren erfordern. Weitere Informationen finden Sie in den KV-Version 1-Dokumentationen.

KV-Version 2
Wenn man v2 des KV-Sekretsspeichers betreibt, kann eine Schlüssel eine konfigurierbare Anzahl von Versionen behalten. Der Standardwert ist 10 Versionen. Die Metadaten und Daten der älteren Versionen können abgerufen werden. Zusätzlich bietet es Check-und-Set-Operationen, um unbeabsichtigte Datenüberschreibungen zu verhindern. Wenn eine Version gelöscht wird, wird das unterliegende Daten nicht entfernt, sondern es wird als gelöscht markiert. Gelöschte Versionen können wiederhergestellt werden. Um die Daten einer Version dauerhaft zu löschen, verwenden Sie den Befehl vault kv destroy oder die API-Endpunkt. Um alle Versionen und Metadaten für eine Schlüssel zu löschen, löscht man die Metadaten mithilfe des Befehls vault kv metadata delete oder der API-Endpunkt mit DELETE-Verb.

API-Endpunkt. Sie können alle Versionen und Metadaten für eine Schlüssel-Taste durch Löschen der Metadaten mit dem Befehl vault kv metadata delete oder der API-Endpunkt mit DELETE-Verb löschen. Sie können die Berechtigungen für den Soft-Lösch, Wiederherstellen oder vollständige Entfernung von Daten durch Vault-Politiken beschränken. Weitere Informationen finden Sie in den Dokumenten zu KV-Version 2. Versionvergleich

Unabhängig von ihrer Version interagieren Sie mit KV-Geheimnis-Engine über den Befehl vault kv. Allerdings sind die API-Endpunkte unterschiedlich. Um Verwirrung zu vermeiden, müssen Sie diese Unterschiede bei der Schreibung von Politiken beachten. Die folgende Tabelle listet die Sub-Befehle von vault kv und ihre entsprechenden API-Endpunkte auf, wenn die KV-Geheimnis-Engine an secret/ aktiviert ist. Befehl KV v1-Endpunkt KV v2-Endpunkt

vault kv get secret/<key_path> secret/data/<key_path>

vault kv put secret/<key_path> secret/data/<key_path>

vault kv list secret/<key_path> secret/metadata/<key_path>

vault kv delete secret/<key_path> secret/data/<key_path>

Zusätzlich verfügt KV v2 über Sub-Befehle, um die Versionsverwaltung von Geheimnissen zu verwalten. Befehl KV v2-Endpunkt

vault kv patch vault kv rollback vault kv undelete vault kv destroy vault kv metadata

secret/metadata/<key_path>

Um Verwirrung zu vermeiden, gibt der Befehl vault kv beim Arbeiten mit KV v2 den Geheimnispfad aus.

Beispiel:

$ vault kv put secret/web-app api-token="WEOIRJ13895130WENJWEFN"
=== Secret Path ===
secret/data/web-app
======= Metadata =======
Key Value --- -----
created_time 2024-07-02T00:34:58.074825Z
custom_metadata &lt;nil&gt;
deletion_time n/a
destroyed false
version 1

Sie können das Flag -mount verwenden, wenn das Omitten von /data/ im Befehl verwirrend ist.

$ vault kv put -mount=secret web-app api-token="WEOIRJ13895130WENJWEFN"

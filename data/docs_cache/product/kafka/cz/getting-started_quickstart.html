Rychlý start, krok 1: Stáhněte si nejnovější verzi Kafka a extrahujte ji: $ tar -xzf kafka_2.13-4.3.1.tgz $ cd kafka_2.13-4.3.1

Krok 2: Spusťte prostředí Kafka
POMĚŘÁNÍ: Vaše lokální prostředí musí mít Java 17+ nainstalované. Kafka můžete spustit pomocí lokálních skriptů a stažených souborů nebo dockerového obrázku. Pomocí stažených souborů Vytvořte UUID clusteru $ KAFKA_CLUSTER_ID="$(bin/kafka-storage.sh random-uuid)" Formátujte adresáře protokolů $ bin/kafka-storage.sh format --standalone -t $KAFKA_CLUSTER_ID -c config/server.properties Spusťte server Kafka $ bin/kafka-server-start.sh config/server.properties Po úspěšném spuštění serveru Kafka máte běžící a připravenou k použití základní prostředí Kafka.

Pomocí JVM základní Apache Kafka Docker Image Získáte Docker obrázek: $ docker pull apache/kafka:4.3.1 Spusťte Dockerový kontejner Kafka: $ docker run -p 9092:9092 apache/kafka:4.3.1

Pomocí GraalVM základní Apache Kafka Docker Image Získáte Docker obrázek: $ docker pull apache/kafka-native:4.3.1 Spusťte Dockerový kontejner Kafka: $ docker run -p 9092:9092 apache/kafka-native:4.3.1

Krok 3: Vytvořte téma pro ukládání vašich událostí
Kafka je distribuovaná platforma pro streamování událostí, která vám umožňuje číst, psát, ukládat a zpracovávat události (také známé jako záznamy nebo zprávy v dokumentaci) na mnoha počítačích. Příklady událostí jsou platby transakcí, aktualizace poloh mobilních telefonů, objednávky dopravy, měření z IoT zařízení nebo lékařského vybavení, a mnoho dalších.

Přenosy platby, aktualizace geolokace z mobilních telefonů, objednávky dopravy, měření senzorů z zařízení IoT nebo lékařského vybavení, a mnoho dalšího. Tyto události se organizují a ukládají do témat. Velmi zjednodušeně, téma je podobné složkou v systému souborů, a události jsou soubory v této složce. Proto než můžete napsat své první události, musíte vytvořit téma. Otevřete další session terminálu a spusťte: $ bin/kafka-topics.sh --create --topic quickstart-events --bootstrap-server localhost:9092 Všechny nástroje příkazového řádku Kafka mají další možnosti: spusťte kafka-topics.sh bez žádných argumentů k zobrazení informací o použití. Například může vám také zobrazit další informace, jako je počet dělení nového tématu: $ bin/kafka-topics.sh --describe --topic quickstart-events --bootstrap-server localhost:9092 Téma: quickstart-events TémaId: NPmZHyhbR9y00wMglMH2sg Počet dělení: 1 Faktor zastoupení: 1 Konfigurace: Téma: quickstart-events Dělení: 0 Vůdce: 0 Zastoupení: 0 ISR: 0 Krok 4: Zapište nějaké události do tématu Klient Kafka komunikuje s brokery Kafka přes sítě pro zapsání (nebo čtení) událostí. Po přijetí budou události uloženy v trvalém a vysokojakoostním způsobu, dokud potřebujete-i navždy. Spusťte klienta konzoly producenta, aby napsali několik událostí do vašeho tématu. Výchozí nastavení znamená, že každá řádek, který zadáte, bude vytvářet samostatnou událost v tématu. $ bin/kafka-console-producer.

console vyráběč produkuje klienta, aby napsal několik událostí do vašeho tématu. Výchozí nastavení znamená, že každý řádek, který zadáte, bude vytvářet samostatnou událost v tématu. $ bin/kafka-console-producer.sh --topic quickstart-events --bootstrap-server localhost:9092 >Toto je moje první událost >Toto je moje druhá událost Můžete zastavit produkční klienta stisknutím Ctrl-C kdykoliv. Krok 5: Čtení událostí Otevřete další terminálovou sezenku a spusťte konzolového klienta konzumátoru událostí, aby četl události, které jste právě vytvořili: $ bin/kafka-console-consumer.sh --topic quickstart-events --from-beginning --bootstrap-server localhost:9092 Toto je moje první událost Toto je moje druhá událost Můžete zastavit konzumátora klienta stisknutím Ctrl-C kdykoliv. Uveďte si svou kreativitu: například přesuňte se zpět do produkčního terminálu (krok předchozí) a napsat další události, a vidíte, jak se okamžitě zobrazí v konzumátorském terminálu. Protože události jsou trvalě uloženy v Kafka, mohou být čteny jakýkoliv počet a jakýkoliv počet konzumátorů. Můžete snadno ověřit to, otevřením ještě jedné terminálové sezenky a znovu spuštěním předchozího příkazu. Krok 6: Import/export vaše data jako proudy událostí pomocí Kafka Connect Pravděpodobně máte mnoho dat v existujících systémech jako relační databáze nebo tradiční systémy zpráv, spolu s mnoha aplikacemi, které již tyto systémy používají. Kafka Connect vám umožňuje nepřerušovaně importovat data z externích systémů do Kafka a naopak.

Užívám tyto systémy. Kafka Connect umožňuje vytvářet data z externích systémů do Kafka a naopak. Jedná se o rozšiřitelný nástroj, který spouští connectory, které implementují vlastní logiku pro interakci s externím systémem. Je tudíž velmi snadné integrovat existující systémy s Kafka. Pro usnadnění tohoto procesu jsou k dispozici stovky takových connectorů. V tomto rychlém startu ukážeme, jak spustit Kafka Connect s jednoduchými connectory, které importují data z souboru do Kafka tématu a exportují data z Kafka tématu do souboru. Nezapomeňte si nejprve přidat connect-file-4.3.1.jar do plugin.path vlastnosti v konfiguraci pracovníka Connect. Pro účely tohoto rychlého startu budeme používat relativní cestu a považovat connectory za jeden uber jar, který funguje, když rychlý startovací příkazy jsou spouštěny z adresáře instalace. Je však vhodné poznamenat, že pro produkční nasazení se vždy preferuje použití absolutních cest. Další informace o nastavení tohoto konfiguračního parametru naleznete v plugin.path. Editujte soubor config/connect-standalone.properties, přidejte nebo upravte vlastnost plugin.path konfiguračního parametru tak, aby odpovídala následujícímu a uložte soubor:

$ echo "plugin.path=libs/connect-file-4.3.1.jar" >> config/connect-standalone.properties

Pak zahájte vytvářením testovacích dat:

$ echo -e "foo bar" > test.txt

Nebo na Windows:

$ echo foo > test.txt
$ echo bar >> test.txt

Začněte vytvářením nějakých seed dat pro testování: $ echo -e "foo bar" > test.txt Nebo na Windows: $ echo foo > test.txt $ echo bar >> test.txt Následně spustíme dva connektory v režimu standalone, což znamená, že běží v jednom, lokálním, věnovaném procesu. Poskytneme tři konfigurační soubory jako parametry. První je vždy konfigurace pro proces Kafka Connect, obsahující společnou konfiguraci, jako je například seznam Kafka brokerů pro spojení a formát serializace dat. Zbylé konfigurační soubory každý specifikují connector k vytvoření. Tyto soubory zahrnují unikátní název connectoru, třídu connectoru k instancování a jakékoliv další konfigurace požadované connektorem. $ bin/connect-standalone.sh config/connect-standalone.properties config/connect-file-source.properties config/connect-file-sink.properties Tyto ukázkové konfigurační soubory, zahrnuté s Kafka, používají výchozí konfiguraci lokálního clusteru, který jste dříve spustili, a vytvoří dva connektory: první je zdrojový connector, který čte řádky z vstupního souboru a každý produkuje do Kafka tématu a druhý je sink connector, který čte zprávy z Kafka tématu a každou produkuje jako řádek v výstupním souboru. Během spouštění byste měli vidět řadu logovací zpráv, včetně několika, které ukazují, že connectory jsou vytvářeny. Po spuštění procesu Kafka Connect by měl začít zdrojový connector číst řádky z test.txt.

Následující text obsahuje několik záznamů protokolu, včetně několika, které naznačují, že se spojovače inicializují. Po spuštění procesu Kafka Connect by se měl začít source connector číst řádky z test.txt a produkovat je do tématu connect-test, a sink connector by měl začít číst záznamy z tématu connect-test a psát je do souboru test.sink.txt. Můžeme ověřit, zda data procházejí celou linkou, kontrolou obsahu výstupního souboru: $ more test.sink.txt foo bar Upozornění: Data se ukládají do Kafka tématu connect-test, takže můžeme také spustit konzolového spotřebovače, abychom data v tématu viděli (nebo použít vlastní spotřebovačový kód k zpracování): $ bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic connect-test --from-beginning {"schema":{"type":"string","optional":false},"payload":"foo"} {"schema":{"type":"string","optional":false},"payload":"bar"} ... Spojovače data dále zpracovávají, takže můžeme data do souboru přidat a sledovat, jak se přesouvá po celé linkě: $ echo "Další řádek" >> test.txt Byste měli vidět řádek ve výstupu konzolového spotřebovače a v souboru sink. Měli byste také vidět, jak se data pohybují po celé linkě. Krok 7: Zpracování vašich událostí s Kafka Streams
Po uložení vašich dat do Kafka jako událostí, můžete data zpracovávat pomocí Kafka Streams klientské knihovny pro Java/Scala. Umožňuje vám implementovat důležité reálné aplikace a mikroslužby, kde vstupní a/nebo výstupní data jsou uložena do Kafka témat.

Umožňuje vám implementovat kritické aplikace v reálném čase a mikroslužby, kde vstupní a/nebo výstupní data jsou uložena v tématech Kafka. Kafka Streams kombinuje jednoduchost psaní a nasazování standardních Java a Scala aplikací na straně klienta se závazky technologie serverového clusteru Kafka, aby se tyto aplikace staly velmi škálovatelnými, elastickými, odolnými vůči chybám a rozloženými. Knihovna podporuje zpracování právě jednou, operace se stavy a agregace, okna, spojování, zpracování na základě času události a mnoho dalšího. Chci Vám poskytnout první vkus, jak by se implementovala populární algoritmus WordCount:

KStream<String, String> textLines = builder.stream("quickstart-events");
KTable<String, Long> wordCounts = textLines
.flatMapValues(line -> Arrays.asList(line.toLowerCase().split(" ")))
.groupBy((keyIgnorované, slovo) -> slovo)
.count();
wordCounts.toStream().to("output-topic", Produced.with(Serdes.String(), Serdes.Long()));

Kafka Streams demo a průvodce vývojem aplikace ukazují, jak kódovat a spustit takovou aplikaci z počátku k konci. Krok 8: Ukončení prostředí Kafka
Nyní, když jste dosáhli konce rychlého startu, nechte si zrušit prostředí Kafka-nebo pokračujte v hře. Zastavte producenta a klienta konzumátoru stisknutím Ctrl-C, pokud to už neudělali. Zastavte broker Kafka stisknutím Ctrl-C.

Volně si můžete rozebrat prostředí Kafka – nebo pokračovat v hraní se zákulisím. Zastavte producenta a spotřebitele klientů stisknutím Ctrl-C, pokud to už neudělali. Zastavte Kafka brokerem stisknutím Ctrl-C. Pokud chcete také smazat jakékoliv data svého místního prostředí Kafka, včetně jakýchkoli událostí, které jste vytvořili během průběhu, spusťte následující příkaz: $ rm -rf /tmp/kafka-logs /tmp/kraft-combined-logs

Starten Sie mit Git
Git ist ein Versionverwaltungssystem, das Sie verwenden, um Änderungen an Ihrem Code zu verfolgen und mit anderen zusammenzuarbeiten. GitLab ist ein Web-basierter Git-Repository-Manager, der CI/CD und weitere Funktionen zur Unterstützung Ihres Softwareentwicklungslebenszyklus bereitstellt. Sie können die GitLab-Web-Schnittstelle für viele Git-Operationen verwenden, aber die Kenntnis von Git-Befehlen bietet Ihnen zusätzliche Flexibilität und Kontrolle. Ein Git-Repository ist eine Verzeichnis, das alle Dateien, Verzeichnisse und Versionenhistorie Ihres Projekts enthält. Es dient als zentraler Hub, an dem Git Änderungen an Ihrem Code verwaltet und verfolgt. Wenn Sie ein Git-Repository initialisieren oder ein vorhandenes kopieren, erstellt Git eine versteckte Verzeichnis, .git, innerhalb des Projektverzeichnisses. Das Verzeichnis enthält alle wichtigen Metadaten und Objekte, die Git verwendet, um Ihr Repository zu verwalten, einschließlich der vollständigen Geschichte aller Änderungen an den Dateien. Git verfolgt Änderungen auf Dateinebene, sodass Sie die Modifikationen an einzelnen Dateien über die Zeit verfolgen können. Weitere Informationen finden Sie unter Repositories. Um zusammenzuarbeiten, können Sie: Commit: Nachdem Sie in Ihrem Arbeitsverzeichnis Änderungen vorgenommen haben, committen Sie diese Änderungen in Ihre lokale Repository. Push: Pushen Sie Ihre Änderungen an einen entfernten Git-Repository, das auf GitLab gehostet wird. Dadurch sind Ihre Änderungen anderen Teammitgliedern verfügbar. Pull: Pullen Sie Änderungen von anderen her, die im entfernten Repository vorgenommen wurden, und sicherstellen Sie, dass Ihre lokale Repository mit den neuesten Änderungen aktualisiert ist. Zweige In Git können Sie Zweige verwenden, um verschiedene Funktionen, Fehlerbehebungen oder Experimente gleichzeitig ohne sich gegenseitig zu beeinflussen zu bearbeiten. Zweigung ermöglicht es, ein isoliertes Umgebung zu schaffen, in der Sie Änderungen machen und testen können, ohne die Standard-Zweig zu beeinflussen. In GitLab ist die Standard-Zweig meistens main genannt. Merge einen Zweig Nachdem eine Funktion fertiggestellt oder ein Fehler behoben ist, können Sie Ihren Zweig in die Standard-Zweig mergeen. Das können Sie in einem Merge-Antrag tun. Merging ist eine sichere Methode, um Änderungen von einer Zweig in eine andere zu bringen, ohne die Geschichte der Änderungen zu verlieren. Wenn es Konflikte zwischen den Zweigen gibt, z.B. wenn Sie die gleichen Zeilencode in beiden Zweigen modifiziert haben, flaggt GitLab diese als Merge-Konflikte. Diese müssen manuell gelöst werden, indem Sie das Code bearbeiten.

Beispielhaft würde GitLab Konflikte markieren, wenn Sie die gleichen Zeilen in beiden Zweigen ändern. Diese müssen manuell gelöst werden, indem Sie das Code-Reviewing und die Bearbeitung durchführen. Ein Zweig löschen Nach einer erfolgreichen Verschmelzung können Sie den Zweig löschen, wenn er nicht mehr benötigt wird. Das Löschen unnötiger Zweige hilft Ihrem Repository bei der Organisation und Verwaltung. Um sicherzustellen, dass keine Arbeit verloren geht, überprüfen Sie bitte, dass alle Änderungen in die Standard-Zweig integriert sind, bevor Sie den Zweig nach der letzten Verschmelzung löschen. Forks

Manche Organisationen, insbesondere solche, die mit open-source Projekten arbeiten, können unterschiedliche Workflows verwenden. Beispiel: Forks. Ein Fork ist eine persönliche Kopie des Repositorys, das in Ihrem eigenen Namespace existiert. Verwenden Sie diesen Workflow, wenn Sie an open-source Projekten mitwirken oder wenn Ihre Team eine zentralisierte Repository verwendet.

Installieren Sie Git

Um Git-Befehle und an GitLab-Projekte beizutragen, sollten Sie den Git-Client auf Ihrem Computer herunterladen und installieren. Der Installationsprozess variiert je nach Betriebssystem. Beispiel: Windows, MacOS oder Linux. Weitere Informationen zum Installieren von Git finden Sie unter install Git.

Git-Befehle

Um mit Git von der Befehlszeile aus zu interagieren, können Sie Git-Befehle verwenden:

git clone: Klone ein Repository auf Ihre lokale Maschine.
git branch: Liste, erstelle oder lösche Branchs in Ihrem lokalen Repository.
git checkout: Wechselt zwischen verschiedenen Branchs in Ihrem lokalen Repository.

git klonen: Klone eine Repository auf dein lokales System. git branch: Liste, erzeuge oder lösche Branchs in deiner lokalen Repository. git checkout: Wechsle zwischen verschiedenen Branchs in deiner lokalen Repository. git add: Stage Änderungen für Commit. git commit: Commit staged Änderungen in deine lokale Repository. git push: Pushe lokale Commits in die remote Repository. git pull: Holt Änderungen von der remote Repository und merge sie in deine lokale Branch. Wenn du mit remote Repositories arbeitest, solltest du SSH für sichere Kommunikation verwenden. GitLab nutzt das SSH-Protokoll, um sicher mit Git zu kommunizieren. Wenn du SSH-Schlüssel verwendest, um dich bei dem GitLab-Remoteserver anzumelden, musst du deinen Benutzernamen und Passwort nicht jedes Mal eingeben. Um SSH mit GitLab zu verwenden, musst du:
Ein SSH-Schlüsselpaar auf deinem lokalen System generieren.
Deinen SSH-Schlüssel in dein GitLab-Konto hinzufügen.
Deine SSH-Verbindung zu GitLab überprüfen.

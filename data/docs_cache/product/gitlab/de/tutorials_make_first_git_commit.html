Leitfaden: Deine erste Git-Commit erstellen
Dieser Leitfaden lehrt dich etwas über die Funktionsweise von Git. Er führt dich durch die Schritte der Erstellung deines eigenen Projekts, der Bearbeitung einer Datei und des Kommittierens von Änderungen in einem Git-Repository über die Befehlszeile. Wenn du fertig bist, hast du ein Projekt, auf dem du Git ausprobieren kannst. Vor dem Start Installiere Git auf deinem lokalen Rechner. Stelle sicher, dass du sichern können, auf eine Instanz von GitLab zuzugreifen. Wenn deine Organisation keine GitLab-Instanz hat, registriere dich bei GitLab.com. Erzeuge SSH-Schlüssel und füge sie GitLab hinzu. SSH-Schlüssel sind die Weise, wie du sicher kommunizierst zwischen deinem Computer und GitLab. Was ist Git? Bevor wir uns auf die Schritte begeben, gehen wir noch über einige Grundbegriffe von Git. Git ist ein Versionverwaltungssystem. Es wird verwendet, um Änderungen an Dateien zu verfolgen. Man speichert Dateien, wie Code oder Dokumente, in einem Git-Repository. Wenn du die Dateien bearbeiten möchtest, klonierst du das Repository auf dein Computer, machest die Änderungen und schiebst deine Änderungen zurück in das Repository. Eine Beispiel-Projekt erzeugen
Um zu beginnen, erzeuge eine Beispiel-Projekt in GitLab. In GitLab, oben rechts, wähle Create new ( plus ) und New project/repository aus. Für Project name, gib My sample project ein. Der Projekt slug wird automatisch generiert. Dieser Slug ist die URL, die du verwenden kannst, um das Projekt nach der Erstellung zuzugreifen. Stelle sicher, dass Initialize repository with a README ausgewählt ist. Wie du die anderen Felder ausfüllst, ist dir überlassen. Klicke auf Create project.

Das Repository klonen
Jetzt kannst du das Repository in deinem Projekt klonen. Klonen eines Repositorys bedeutet, dass du eine Kopie auf deinem Computer, oder wo du die Dateien speichern und bearbeiten möchtest, erstellst. Auf der Überblickseite deines Projekts, oben rechts, wähle Code, dann kopiere die URL für Clone with SSH. Öffne ein Terminal auf deinem Computer und gehe zum Verzeichnis, in dem du die Dateien klonen möchtest. Gib git clone ein und füge die URL ein: git clone git@gitlab.com:gitlab-example/my-sample-project.git Gehe zum Verzeichnis: cd my-sample-project

Mit dem Befehl git clone hast du die Standard-Branch des Repositorys kopiert.

URL: git clone git@gitlab.com:gitlab-example/my-sample-project.git
Gehe in das Verzeichnis: cd my-sample-project
Standardmäßig haben Sie das Repository über die Standard-Zweiglinie des Repositorys geklont. Normalerweise ist dies die Zweiglinie "main". Um sicherzugehen, erhalte den Namen der Standard-Zweiglinie: git branch
Der Zweig, auf dem du sichst, wird mit einem Sternchen markiert. Drücke Q auf deiner Tastatur, um zum Hauptterminalfenster zurückzukehren.
Erstelle jetzt eine Zweiglinie und mache Änderungen
Nun hast du eine Kopie des Repositorys, erstelle jetzt deine eigene Zweiglinie, damit du deine Änderungen unabhängig bearbeiten kannst. Erstelle eine neue Zweiglinie namens example-tutorial-branch. git checkout -b example-tutorial-branch
In einem Texteditor wie Visual Studio Code, Sublime, vi oder jedem anderen Editor öffne die Datei README.md und füge diesen Text ein: Hallo Welt! Ich nutze Git! Speichere die Datei. Git beobachtet geänderte Dateien. Um zu bestätigen, welche Dateien geändert wurden, erhalte den Status. git status
Du solltest Ausgabe ähnlich der folgenden erhalten:
Auf Zweig example-tutorial-branch
Geänderte Dateien, die nicht für den Commit bereitgestellt wurden: (Verwende "git add <Datei>..." um zu aktualisieren, was für den Commit bereitgestellt wird) (Verwende "git restore <Datei>..." um Änderungen im Arbeitsverzeichnis zu verwerfen) geändert: README.md
keine Änderungen hinzugefügt (Verwende "git add" und/oder "git commit -a")
Commit und push deine Änderungen
Du hast Änderungen an einer Datei in deinem Repository vorgenommen. Nun ist es Zeit, diese Änderungen zu dokumentieren, indem du deine ersten Commit vornimmt. Füge die Datei README.md in den Staging-Bereich. Der Staging-Bereich ist der Bereich, in dem du Dateien vor dem Commit platzierst. git add README.md

Die Änderungen durchführen Sie, indem Sie Ihren ersten Commit ausführen. Fügen Sie den Datei README.md in den Bereich vor dem Commit ein. Der Bereich vor dem Commit ist der Ort, an dem Sie Dateien platzieren, bevor Sie sie committen. git add README.md Bestätigen Sie, dass die Datei im Bereich vor dem Commit ist: git status Sie sollten eine Ausgabe ähnlich der folgenden erhalten, und der Dateiname sollte in grünem Text angezeigt werden. Auf Branch example-tutorial-branch Änderungen vor dem Committen: (Verwenden Sie "git restore --staged <Datei>..." um die Datei aus dem Bereich vor dem Commit zu entfernen) geändert: README.md

Jetzt den staging-bereich committen Sie, und fügen Sie eine Nachricht ein, die die Änderung beschreibt, die Sie vorgenommen haben. Stellen Sie sicher, dass Sie die Nachricht in doppelte Anführungszeichen (") einbinden. git commit -m "Ich habe Text in die README-Datei hinzugefügt" Die Änderung wurde in Ihrer Branch eingecheckt, aber Ihre Branch und ihre Commits sind noch nur auf Ihrem Computer verfügbar. Andere haben noch keinen Zugriff auf sie.

Ihr Branch in GitLab pushen: git push origin example-tutorial-branch Ihr Branch ist jetzt auf GitLab verfügbar und sichtbar für andere Benutzer in Ihrem Projekt.

Ihre Änderungen zusammenführen Sie jetzt.

Zum Standardbranch (main) wechseln Sie. git checkout main

Ihre Änderungen in den Standardbranch zusammenführen Sie. git merge example-tutorial-branch

Die Änderungen pushen Sie. git push

Für dieses Tutorial werden Sie Ihre Branch direkt dem Standardbranch Ihres Repositorys zusammenführen. In GitLab verwenden Sie normalerweise einen Merge Request, um Ihre Branch zusammenzuführen. Ihre Änderungen in GitLab anzeigen Sie

Gefällt Ihnen! Sie haben den README aktualisiert!

Die Standard-Zweig für Ihr Repository. In GitLab verwenden Sie üblicherweise einen Merge-Antrag, um Ihren Zweig zu vereinigen. Ihre Änderungen in GitLab anzeigen Sie bitte! Sie haben es geschafft! Sie haben die README.md-Datei in Ihrem Zweig aktualisiert und die Änderungen in die Hauptzweig eingefügt. Lassen Sie uns unsere Änderungen im UI bestätigen. Gehen Sie zu Ihrem Projekt. Scrollen Sie nach unten und betrachten Sie den Inhalt der README.md-Datei. Ihre Änderungen sollten sichtbar sein. Oben an der README.md-Datei betrachten Sie den Text in der Spalte Letzter Commit. Ihr Commit-Nachricht wird in dieser Spalte angezeigt: Nun können Sie wieder zur Befehlszeile zurückkehren und auf Ihre persönliche Zweig (git checkout example-tutorial-branch) wechseln. Sie können weiterhin Dateien aktualisieren oder neue erstellen. Geben Sie git status ein, um den Status Ihrer Änderungen anzuzeigen und mit Abandon zu commit. Verzagen Sie nicht, wenn Sie etwas verfäulen. Alles in Git kann rückgängig gemacht werden, und wenn Sie feststellen, dass Sie nicht wiederherstellen können, können Sie immer wieder einen neuen Zweig erstellen und neu beginnen. Gut gemacht.

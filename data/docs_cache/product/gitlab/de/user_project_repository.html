Ihr Repository ist ein Bestandteil Ihrer GitLab-Projekt. Sie speichern Ihr Code in Ihrem Repository und verfolgen Änderungen an ihm mit Versionenkontrolle. Jedes Repository ist Teil eines GitLab-Projekts und kann ohne GitLab-Projekt nicht existieren. Ihr Projekt bietet die Konfigurationsoptionen für Ihr Repository.

Eine Repository erstellen
Um eine Repository zu erstellen:
Erstellen Sie ein Projekt oder Forken Sie ein vorhandenes Projekt.

Dateien einer Repository hinzufügen
Sie können Dateien einer Repository hinzufügen:
Wenn Sie ein Projekt erstellen, oder
Nachdem Sie ein Projekt erstellt haben, mit den folgenden Optionen:
Web-Editor. Benutzeroberfläche (UI). Befehlszeile.

Eine Datei aus der UI hinzufügen
Um eine Datei oder eine Datei hochzuladen, die Sie aus der GitLab-UI hinzufügen:
Im oberen Menü wählen Sie Suche aus oder navigieren Sie zu und finden Sie Ihr Projekt. Gehen Sie zum Verzeichnis, in das Sie die Datei hochladen möchten. Rechts neben dem Verzeichnisnamen wählen Sie das Plus-Symbol ( plus ) aus > Datei hochladen. Wirfen Sie Ihre Datei hoch oder wählen Sie Datei hochladen aus. Geben Sie eine Commit-Nachricht ein. Optional. Um einen Merge-Antrag für Ihre Änderungen zu erstellen, geben Sie in Ziel-Zweig einen Zweig ein, der nicht Ihr Repositorys Standard-Zweig ist. Wählen Sie Datei hochladen aus. Verwenden Sie Commit-Änderungen in einem Repository
Sie können Ihre Änderungen an einem Zweig in einem Repository veröffentlichen. Wenn Sie die Befehlszeile verwenden, verwenden Sie git commit. Weitere Informationen zum Verwenden von Commits, um Kommunikation und Zusammenarbeit zu verbessern, Pipelines auszulösen oder zu überspringen und Änderungen rückgängig zu machen, finden Sie unter Commits.

Wenn Sie die Befehlszeile verwenden, verwenden Sie den Befehl git commit. Quellcode des Repository herunterladen
Um das Quellcode des Repositorys als komprimiertes Archiv herunterzuladen:

In der oberen Leiste wählen Sie "Suche" oder navigieren Sie zu und finden Sie Ihr Projekt. Über der Datei-Liste wählen Sie "Code" aus. Aus den Optionen wählen Sie die Dateien, die Sie herunterladen möchten:

Quellcode: Herunterladen Sie das Quellcode vom aktuellen Branch, den Sie momentan ansehen. Verfügbare Erweiterungen: zip, tar, tar.gz, und tar.bz2.
Verzeichnis: Herunterladen Sie ein bestimmtes Verzeichnis. Nur sichtbar, wenn Sie ein Unterverzeichnis ansehen. Verfügbare Erweiterungen: zip, tar, tar.gz, und tar.bz2.
Artifacts: Herunterladen Sie die Artifacts aus dem letzten CI/CD Job. Die Prüfsummen der erzeugten Archive können sich ändern, selbst wenn das Repository selbst nicht geändert wird. Beispiel: Dies passiert, wenn Git oder ein dritter-Partei-Library, das GitLab verwendet, geändert wird.

Repository an Git-Revision anzeigen
Um alle Dateien und Verzeichnisse eines bestimmten Git-Revisions anzuzeigen, z.B. einem Commit SHA, Branchnamen oder Tag:

In der oberen Leiste wählen Sie "Suche" oder navigieren Sie zu und finden Sie Ihr Projekt. An der oberen Leiste wählen Sie "Git revision" aus, um das Dropdown-Menü für die Git-Revision zu öffnen. Wählen Sie dann ein Git-Revision aus oder suchen Sie es.

Oberen Menü, wählen Sie Suche aus oder navigieren Sie zu Ihrem Projekt. Im Oberen Bereich wählen Sie aus, um die Auswahlliste für das Auswählen eines Git-Revisionspunkts zu öffnen. Wählen Sie ein Git-Revisionspunkt aus oder suchen Sie nach einem. Sie können auch Dateien an einer bestimmten Git-Revision auf der Seite mit den Kommentaren ansehen und durchsuchen. Die verwendeten Programmiersprachen im Repository erkennt GitLab automatisch. Diese Information wird auf der Übersichtsseite des Projekts angezeigt. Wenn neue Dateien hinzugefügt werden, kann es bis zu fünf Minuten dauern, bis die Information aktualisiert wird. Repository-Sprachen Es werden nicht alle Dateien erkannt und auf der Übersichtsseite des Projekts aufgelistet. Dokumentation, Lieferantencode und die meisten Markup-Sprachen werden ausgeschlossen. Um eine Liste der unterstützten Dateien und Sprachen anzusehen, siehe unterstützte Datenformate. Um dieses Verhalten zu ändern und zusätzliche Dateitypen in den Standardeinstellungen einbeziehen: In Ihrem Repository-Wurzelverzeichnis erstellen Sie eine Datei namens .gitattributes. Fügen Sie eine Zeile hinzu, die GitLab anweist, einen bestimmten Dateityp einzuschließen. Beispiel: Um .proto-Dateien zu aktivieren, fügen Sie folgendes hinzu: *.proto linguist-detectable=true Diese Funktion kann hohen CPU-Auslastung bedürfen. Wenn Sie ein Problem erleiden, siehe die Troubleshooting-Seite für hohen CPU-Auslastung. Git-Remot-URLs für Projekte unter dem Namespace werden auf die neue Remote-URL umgeleitet. Fehler: Xcode scheitert bei der Klonung des Repositorys. GitLab bietet eine Option, eine Liste von zugelassenen SSH-Schlüsseln zu beschränken. Wenn Ihr SSH-Schlüssel nicht auf der zugelassenen Liste ist, könnt Ihr möglicherweise ein Fehler wie Das Repository hat die bereitgestellten Anmeldeinformationen abgelehnt bekommen. Um dieses Problem zu beheben, erstellt Sie ein neues SSH-Schlüsselpaar, das den Anforderungen für unterstützte SSH-Schlüssel entspricht. Nachdem Sie einen unterstützten SSH-Schlüssel erstellt haben, versuchen Sie erneut das Repository zu klonen.

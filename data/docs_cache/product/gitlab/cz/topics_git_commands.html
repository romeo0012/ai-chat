Common Git commands

Častěji používané Git příkazy Git příkazy vám ušetří čas během celého vývojového workflow. Tato stránka obsahuje častěji používané příkazy pro běžné úlohy, jako jsou změny kódu, správu větví a prohlídku historie. Každá část příkazu poskytuje přesný syntax, praktické příklady a odkazy na další dokumentaci.

git add Použijte git add k přidání souborů do staging area. git add <file_path> Můžete rekurzivně stagingovat změny z aktuálního pracovního adresáře pomocí git add ., nebo stagingovat všechny změny v Git repozitáři pomocí git add --all. Další informace naleznete v části [Přidání souborů do větve].

git blame Použijte git blame k zobrazení, které uživatele změnily jaké části souboru. git blame <file_name> Můžete použít git blame -L <line_start>,<line_end> k kontrole konkrétního rozsahu řádků. Další informace naleznete v části [Git file blame].

Příklad
Chcete-li zjistit, která uživatel posledně upravila pátou řádek example.txt: 

$ git blame -L 5,5 example.txt
123abc (Zhang Wei 2021-07-04 12:23:04 +0000 5)

git bisect Použijte git bisect k využití binárního vyhledávání k nalezení commitu, který zavodil chybu. Začněte identifikací commitu, který je “zlé” (obsahuje chybu) a commitu, který je “dobré” (neobsahuje chybu). 

git bisect start
git bisect bad # Current version is bad
git bisect good v2.6.13-rc2 # v2.6.13-rc2 je známý jako dobrý

Poté git bisect vybere commit mezi těmito body a požaduje, abyste identifikovali, zda je commit “zlý” nebo “dobrý” pomocí git bisect good nebo git bisect bad. Opakujte tento proces, dokud nenaleznete commit.

Text v češtině:

Pomocí nástroje git bisect můžete mezi dvěma body a požadujete, abyste určili, zda je commit "dobrý" nebo "špatný" pomocí příkazů git bisect good nebo git bisect bad. Opakujte tento proces, až nebudete nalézt commit. Použijte příkaz git checkout, abyste se přesunuli na určitou větev. git checkout <větev_jméno> Chcete-li vytvořit novou větev a přesunout se na ni, použijte git checkout -b <větev_jméno>. Další informace naleznete v tématu Vytvoření Git větve pro své změny. Použijte příkaz git clone, abyste kopírovali existující Git repozitář. git clone <repozitář> Další informace naleznete v tématu Klonování Git repozitáře na vaši místní počítač. Použijte příkaz git commit, abyste spojili staged změny s repozitářem. git commit -m "<commit_message>" Pokud zpráva o commitu obsahuje prázdnou řádek, první řádek se stane názvem commitu, zatímco zbytek se stane tělem commitu. Použijte název commitu k krátkému shrnutí změny, a tělo commitu k poskytnutí dalších podrobností. Další informace naleznete v tématu Stage, commit, a push změny. Použijte příkaz git commit --amend, abyste upravili poslední commit. Použijte příkaz git diff, abyste zobrazili rozdíly mezi vašimi místními nezastavenými změnami a poslední verzí, kterou jste klonovali nebo stáhli. Můžete zobrazit rozdíl (nebo diff) mezi vašimi místními změnami a poslední verzí větve. Zobrazte rozdíl, abyste pochopili své místní změny před tím, než je spojíte s větve.

Rozdíl (nebo diff) mezi vašimi místními změnami a nejnovější verzí větvě. Zobrazte diff, abyste porozuměli svým místním změnám před tím, než je přiřadíte k větvě. Chcete-li porovnat své změny s konkrétní větví, spusťte: git diff <větev> Výstupu: Řádky s přidáním začínají plusem (+) a jsou zobrazeny v zelené. Řádky s odstraněním nebo změnami začínají minusem (-) a jsou zobrazeny v červené.

git init
Použijte git init k inicializaci adresáře, aby Git ho sledoval jako repozitář. git init Do adresáře je přidán soubor .git s konfiguračními a logovacími soubory. Neupravujte přímo soubor .git. Výchozí větev je nastavena na main. Můžete změnit název výchozí větvě pomocí git branch -m <větev_název>, nebo inicializovat pomocí git init -b <větev_název>.

git pull
Použijte git pull k získání všech změn provedených uživateli po poslední dobu, kdy jste klonovali nebo stahovali projekt. git pull <volitelný_zdroj> <větev_název>

git push
Použijte git push k aktualizaci odkazů na vzdálené odkazy. Další informace najdete v tématu stage, commit, a push změny.

git reflog
Použijte git reflog k zobrazení seznamu změn v Git odkazových logech. Výchozí nastavení zobrazuje seznam změn k HEAD. Další informace najdete v tématu zpětná vazba.

git remote add
Použijte git remote add k tomu, aby Git věděl, která vzdálená repozitář v GitLab je propojena s místní adresářem. git remote add <remote_name> <repository_url>

Při klonování repozitáře je výchozí zdrojová repozitář spojena s odkazem origin.

V GitLab je připojen k místní adresáři. Použijte následující příkaz k přidání nového remota: git remote add <remote_name> <repository_url>
Při klonování repozitáře je výchozí repozitář spojen s názvem remota origin. Další informace o konfiguraci dalších remotů naleznete v článku [forks](forks). Použijte příkaz git log k zobrazení seznamu commitů v pořadí chronologickém. Použijte příkaz git show k zobrazení informací o objektu v Gitu. Následující příklad ukazuje, jak zobrazit informace o commitu, který ukazuje HEAD: $ git show HEAD commit ab123c (HEAD -> main, origin/main, origin/HEAD)
Použijte příkaz git merge k spojení změn z jedné větvě s jinou. Další informace o alternativě k příkazu git merge naleznete v článku [rebase](rebase) k řešení konfliktů při spojování. Následující příklad ukazuje, jak aplikovat změny z větvě feature_branch do větvě target_branch: git checkout target_branch git merge feature_branch
Použijte příkaz git rebase k přepsání historie commitů větvě. git rebase <branch_name> Můžete použít příkaz git rebase k řešení konfliktů při přepsání historie commitů. Většinou chcete rebase proti výchozí větvi. Použijte příkaz git reset k zrušení commitu a vrácení se do dřívějšího stavu. Další informace naleznete v článku [undo changes](undo changes). Použijte příkaz git status k zobrazení stavu pracovní složky a staging area. Při přidání, změně nebo smazání souborů Git může zobrazit změny.

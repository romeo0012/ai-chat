Můžete zkompilovat své změny do větve v repozitáři. Když používáte rozhraní příkazového řádku, použijte příkaz git commit. Další informace o tom, jak používat commits k zlepšení komunikace a spolupráce, aktivovat nebo zrušit kanály, a zpětnou vazbu změn, naleznete v commitech.

Při použití příkazového řádku použijte příkaz git commit. Informace o použití commitů k zlepšení komunikace a spolupráce, spouštění nebo přeskočení pipelineů a zpětné vazby změn, naleznete v [těchto informacích](commits). Klonovat repozitář Můžete klonovat repozitář pomocí následujících možností:

Příkazový řádek:

  • Klonovat pomocí SSH: git clone git@gitlab.com:username/repo.git
  • Klonovat pomocí HTTPS: git clone https://gitlab.com/username/repo.git

GitLab UI:

  • Klonovat a otevřít v Apple Xcode: Klikněte na tlačítko Klon a pak na tlačítko Otevřít v Apple Xcode
  • Klonovat a otevřít v Visual Studio Code: Klikněte na tlačítko Klon a pak na tlačítko Otevřít v Visual Studio Code
  • Klonovat a otevřít v IntelliJ IDEA: Klikněte na tlačítko Klon a pak na tlačítko Otevřít v IntelliJ IDEA

Stáhnout zdrojový kód repozitáře Chcete-li stáhnout zdrojový kód repozitáře jako komprimovaný soubor:
V horní části obrazovky, vyberte Hledat nebo přejděte na a najděte svůj projekt. Nad seznamem souborů, vyberte Kód. Z výběru souborů, vyberte ty, které chcete stáhnout:

  • Zdrojový kód: Stáhněte si zdrojový kód z aktuální větvě, kterou zobrazíte. Dostupné formáty: zip, tar, tar.gz, a tar.bz2.
  • Adresář: Stáhněte si určitý adresář. Dostupné formáty: zip, tar, tar.gz, a tar.bz2. Tato možnost je viditelná pouze tehdy, když zobrazíte podadresář.
  • Artikuly: Stáhněte si artikuly z posledního CI/CD jobu. Kontrolní součty generovaných archivů mohou být změněny i tehdy, když samotný repozitář nezměnil. To může nastat, například pokud Git nebo třetí strana, kterou GitLab používá, změní.

Pokud se změní cesta k repozitáři, GitLab řeší přechod z staré lokace na novou pomocí přesměrování. Pokud přejmenujete uživatele, změníte cestu skupiny nebo přejmenujete repozitář: URL pro prostor názvů a vše, co pod ním leží, jako jsou projekty, jsou přesměrovány na nové URL. Gitové URL pro projekty pod prostorem názvů jsou přesměrovány na nové URL remota. Když provedete push nebo pull do repozitáře, který se přesunul, zobrazí se varovný zpráva k aktualizaci vašeho remota. Skripty automatizace nebo klienti Git pokračují po přejmenování. Přesměrování jsou k dispozici, dokud původní cesta není zabrána jiným uživatelem, skupinou nebo projektem. API přesměrování mohou potřebovat být následována explicitně. Po změně cesty musíte aktualizovat existující URL v následujících zdrojích: Zahrnutí výjimek, kromě zahrnutí:component, jinak selhávají pipelines s syntaxovou chybou.

Bezpečnostní konfigurace¶ mod_security¶ Můžete povolit mod_security na úrovni Web ADC, ale nám neporadíme to. Použití mod_security na úrovni ADC zpomalí dramaticky rozdělování dat. Místo toho byste měli nechat zadní LiteSpeed Web Servery zpracovávat těžkou zátěž, kterou způsobuje načítání, kontrola a filtrování pravidel mod_security. Pokud stále přejete povolit mod_security, můžete to udělat podle našich instrukcí pro LiteSpeed Web Server. Konfigurace proti DDoS Anti-DDoS ConfigServer nebo iptables¶ LiteSpeed ADC's funkce proti DDoS můžete použít k úpravě brány firewall pomocí ifconfig a ipset k blokování podezřelých IP adres. Tento průvodce vysvětluje, jak integrovat funkci proti DDoS ADC s ConfigServer Security & Firewall (csf), nebo iptables. Konfigurace LiteSpeed ADC¶ Přihlaste se do ADC WebAdmin Console na adrese https://SERVER_IP:7090. Navigujte do Konfigurace > Bezpečnost. Nastavte Enable Anti-DDoS Protection a Enable Firewall Modifications na Yes, aby bylo možné povolit ochranu proti DDoS. Konfigurace ConfigServer Security & Firewall¶ Pro csf vytvořte soubor /etc/csf/csfpost.sh a přidejte následující obsah:

#!/bin/bash
ipset create ls-anti-ddos hash:ip hashsize 4096
ipset create ls-quic-ports bitmap:port range 0-65535 -exist
iptables -I INPUT -m set --match-set ls-anti-ddos src -j DROP
iptables -I FORWARD -m set --match-set ls-anti-ddos src -j DROP
iptables -I INPUT -p udp -m set --match-set ls-quic-ports dst -j ACCEPT
Reload with the command csf -r.

Přepněte s pomocí příkazu csf -r.

WordPress Brute Force Attack Protection¶
Brute force je typ útoku proti webu, který se snaží získat přístup k webu tím, že opakovaně zkouší odhadnout uživatelské jméno a heslo. WordPress je nejpopulárnější CMS a proto je často cílem tohoto typu útoku. Nejčastějším cílem brute force útoku je stránka wp-login.php a xmlrpc.php. WordPress nemá žádnou vlastní ochranu proti tomuto, díky čemuž je nutné použít třetí stranu řešení. LiteSpeed Web ADC má vlastní systém ochrany proti brute force útoku na WordPress. Budou chráněny prostředí WordPress pro sdílené hostování před masovými brute force útoky, které mají potenciál zabít celé servery.

Překlad technických termínů:

  • ipset - nástroj pro správu sestav IP adres
  • hash:ip - typ sestavy IP adres
  • maxelem - maximální počet členů v sestavě
  • family inet - rodina IPv4
  • hashsize - velikost hash tabulky
  • ret - návratový kód
  • status - stav
  • WordPress - popularní systém pro správu obsahu webu
  • CMS - Content Management System
  • POST - metoda HTTP pro odesílání formulářů
  • LiteSpeed Web ADC - systém pro zrychlení a zabezpečení webu

Budou ochránit prostředí WordPress na sdíleném hostingu před masovými útoky brute force, které mají potenciál zničit celé servery. Jak funguje ochrana proti útokům brute force?¶ Rozkaz pro ochranu WordPress je: [Throttle, Deny, Drop, Disable ] Akce je volitelná a výchozí hodnotou je Disable. Počet povolených pokusů o přihlášení můžete nastavit jako hodnotu (0|1|5-1000) 0 zakáže ochranu WordPress. 1, když je použito virtuálním hostitelem, odkazuje se na nastavení používané serverem. 5-1000 povolí ochranu WordPress a také určí hodnotu pro přihlášení. (Hodnoty nižší než 5 budou zpracovávány jako 5, a hodnoty vyšší než 1000 budou zpracovávány jako 1000) Hodnota Počet povolených pokusů o přihlášení určuje maximální počet pokusů o přihlášení k wp-login.php a xmlrpc.php, které jsou povoleny za 5 minut před tím, než je blokován IP adresa. Tento počet povolených pokusů o přihlášení je řešen pomocí systému kvót, který funguje následovně: Quota začíná s nastavenou hodnotou Počet povolených pokusů o přihlášení. Každý POST pokus o přihlášení snižuje quota o 1. Když quota dosáhne poloviny hodnoty, bude IP adresa zpomalována. Pokud quota klesne na 0, provede se zvolená akce (drop, deny, nebo zpomalení). Za 5 minut bez dalších pokusů o POST se quota postupně zvětšuje zpět na nastavenou hodnotu Počet povolených pokusů o přihlášení. Restartování LSADC zresetuje quota zpět na nastavenou hodnotu. Příklad Předpokládejme, že Počet povolených pokusů o přihlášení je nastaven na 10.

LSADC bude resetovat quota na zadanou hodnotu. Příklad Předpokládejme, že je povolené počet přihlášení nastaveno na 10. Když je počet pokusů o přihlášení více než 5 v krátkém časovém intervalu, bude IP zpomalován. Když se quota dostane na 0, bude provedena zvolená akce (drop, deny, nebo throttle). Každých 30 sekund (5 minut rozdělených hodnotou = 30 sekund), pokud nejsou další POST pokusy, quota se zvýší o 1. Příklad Předpokládejme, že je hodnota nastavena na 300. Když je počet pokusů o přihlášení více než 150 v krátkém časovém intervalu, bude IP zpomalován. Když se quota dostane na 0, bude provedena zvolená akce (drop, deny, nebo throttle). Po 1 sekundě (5 minut rozdělených hodnotou = 1 sekunda) bez dalších POST pokusů, quota se zvýší o 1.

Povolte na úrovni serveru globálně¶ Přístupte konzolu WebAdmin prostřednictvím https://IP_VAŠEHO_SERVERU:7090 Navigujte k Nastavení > Server > Bezpečnost > ochrana reCAPTCHA Nastavte povolení reCAPTCHA na Ano. Toto je switch hlavní. Zapne funkci reCAPTCHA pro celý Web ADC. Může být přepsáno na úrovni virtuálního hostitele. Pro další možnosti přejete nad ikonu ? pro zobrazení podrobné informace o dané možnosti. Pro ukázací účely nastavíme Limite připojení a Limite SSL připojení na 1, a typ reCAPTCHA na Tlačítko. Můžete tyto hodnoty upravit podle potřeby. Uložte a restartujte Web ADC. Tato nastavení limitu připojení budou děděna všemi virtuálními hostiteli, pokud nebudou přepsána na úrovni virtuálního hostitele. Když návštěvník přistupuje k webu, musí projít ověřováním reCAPTCHA. Toto ověřování chrání server proti HTTP Flood a dalším útokům DDoS. Po úspěšném procházení ověřování reCAPTCHA je návštěvník dočasně zahrnut do seznamu bílého seznamu, pokud pokračuje v procházení webu. Tímto zlepšuje uživatelský zážitek.

Poznámka: V textu IP_VAŠEHO_SERVERU je nutné vložit IP svého serveru.

Návštěvník je dočasně zahrnut do seznamu bělohlávek, pokud pokračuje ve prohlížení webu. Tímto způsobem se zlepšuje uživatelský zážitek. Jakmile návštěvník zůstane nečinný více než 20 minut, opět je reCAPTCHA povolena pro návštěvníka v příštím požadavku. Můžete také povolit reCAPTCHA pro jednotlivou virtuální hostitelskou doménu, která je pod útokem, zatímco ostatní webové stránky zůstávají zakázány. Přepsat/Zakázat na úrovni virtuální hostitelské domény¶ Předpokládejme, že jste reCAPTCHA povolili na úrovni serveru globálně, můžete nastavení přepsat na úrovni virtuální hostitelské domény. Použijte Web ADC WebAdmin konzoli k přepsání reCAPTCHA pro VHost. Přejděte do Nastavení > Virtuální hostitelské domény > Bezpečnost > ochrana reCAPTCHA. Definujte akce CAPTCHA pomocí přepisovacích pravidel¶ Pokud chcete další definovat akci CAPTCHA jako zámek nebo drop, nebo chcete CAPTCHA vypnout, můžete použít jednu z následujících příkazů přepisovacích pravidel: [E=verifycaptcha] [E=verifycaptcha:deny] [E=verifycaptcha:drop] [E=verifycaptcha:off] [E=verifycaptcha] bude směrovat na CAPTCHA, dokud nebude ověřeno (pokud není nastaveno na off, což zkapacitní CAPTCHA). deny vrátí kód 403, a drop ukončí spojení, když je dosaženo Max Tries. Než je dosaženo Max Tries, klient bude směrován na výzvu k CAPTCHA. Příklad Přepisovací podmínka SOME-CONDITIONAL-CHECK Přepisovací pravidlo .* - [E=verifycaptcha] (SOME-CONDITIONAL-CHECK by bylo podezřelý UA, IP adresa, atd.) Poznámka Většinou přepisovací pravidla přepíšou výchozí chování serveru.

Bud bylo podezřelé UA, IP adresa atd. Poznámka: V většině případů přepisovací pravidla převyšují chování serveru výchozí. V případech, kdy je Citlivost spouštěčů vysoká, mohou návštěvníci být okamžitě odesláni na CAPTCHA předtím, než se dokážou přepisovací pravidla zpracovat. Zapnite ochranu CAPTCHA pro libovolnou URL¶ Můžete zapnout CAPTCHA pro určitou URL. Například můžete chránit oblast správy (/administrator/) pro všechny Joomla stránky na serveru. Příklad: V cPanelu vytvořte /etc/apache2/conf.d/userdata/joomlaprotection.conf s následujícím obsahem:

<IfModule LiteSpeed>
RewriteRule /administrator/ - [E=verifycaptcha:deny]
</IfModule>

Aplikujte to všem virtuálním hostům cPanelu a restartujte LiteSpeed: /usr/local/cpanel/scripts/rebuildhttpdconf service lsws restart

Přizpůsobte seznam dobrých robotů¶ Google roboty jsou považovány za dobré roboty, protože pomáhají indexovat vaši stránku. Nicméně nemohou svou práci správně provést bez přijetí správné stránky. Konfigurace Seznamu dobrých robotů může být použita k určení robotů, které potřebujete pro vaši stránku. Zde jsme Edge nakonfigurovali v textovém poli Seznamu dobrých robotů. Seznam dobrých robotů je citlivý na "obsahuje" a může se použít regex také. Po restartu prohlížečů obsahujících Edge v hlavičce uživatele bude přeskočit CAPTCHA: Konfigurace Povolených robotických zásahů může být použita k omezení počtu zásahů dobrého robota (včetně Googlebotu) na URL předtím, než je odeslán na CAPTCHA také.

Překlad textu z angličtiny na češtinu:

TEXT:
Dobrý bot (včetně Googlebotu) může poškodit URL před tím, než je přesměrován na CAPTCHA. To může být užitečné k tomu, aby se zabránilo špatným aktérům na to, aby se CAPTCHA unikli pomocí vlastního identifikátoru uživatele. Tip Google a Bing bots jsou automaticky zahrnuti do whitelistu. Budete muset přidat jakékoliv další bots, které chcete povolit.

Osobně upravit stránku CAPTCHA¶
Výchozí stránka CAPTCHA je generická. Pokud byste chtěli osobně upravit stránku, můžete to udělat vytvořením souboru na $SERVER_ROOT/lsrecaptcha/_recaptcha_custom.shtml. Potřebují se dvě skript tagy, a je silně doporučeno, aby se změnili pouze form a recaptchadiv, pokud víte, co děláte. Na stránce jsou tři echo, které se používají webovým serverem k upravování typu a klíčů CAPTCHA a určování jakékoliv dotazovací řetězce použité. Mimo tyto požadované atributy je vše upravitelné. Jako uvedeno dříve, ujistěte se, že máte zálohy výchozí stránky a vaší upravené stránky. Poznámka: pro použití LSWS konfigurovaného typu a klíčů je požadováno použití rozšíření .shtml.

Přidat hlavičky na stránku CAPTCHA¶
Můžete upravit hlavičky na stránce CAPTCHA. Chcete-li to udělat, přidejte statický kontext s URL /.lsrecap/, poté přidejte požadovanou odpovědní hlavičku pro tento kontext, například takto:

<IfModule LiteSpeed>
<Location "/.lsrecap/">
Header set Access-Control-Allow-Origin "*"
</Location>
</IfModule>

Tento kus kódu nelze přidat do .htaccess.

Kontext, podobně takto: <IfModule LiteSpeed> <Location "/.lsrecap/"> Header set Access-Control-Allow-Origin "*" </Location> </IfModule> Tento úsek nelze přidat do souboru .htaccess. Musí být buď přidán do Apache konfiguračního souboru, nebo prostřednictvím WebAdmin Konzole pro nativní virtuální host LSWS. Příklad
Chcete-li přidat hlavičku CORS k stránce s kapčou v prostředí WHM/cPanel:
Přidejte <Location "/.lsrecap/"> kontext do globálního souboru zahrnutí na adresu /etc/apache2/conf.d/userdata/lsrecaptcha.conf, aby se aplikovaly nastavení na všechny virtuální hosty
Přidejte <Location "/.lsrecap/"> kontext do souboru zahrnutí virtuálního hostite na adresu /etc/apache2/conf.d/userdata/ssl/2_4/$USER/example.com/lsrecaptcha.conf, aby se aplikovaly nastavení pouze pro virtuální hostite $USER
Použijte svůj vlastní klíč reCAPTCHA¶ Můžete použít svůj vlastní klíč reCAPTCHA a upravit konfiguraci podle svých potřeb z Google developer stránky reCAPTCHA. Tip Při přijímání vlastního klíče, registrujte se pro reCAPTCHA v2, nikoliv v3. Styl ověřování klienta je úplně určen na straně Google prostřednictvím jejich reCAPTCHA služby. Když budete mít možnost vybrat kontrolní políčko nebo neviditelný známek, můžete si vybrat ten, který si vyberete. Uvidíte-li však, že neviditelný typ může zobrazit obtížný křížik. Pro celoserverovou ochranu, která musí pokrývat mnoho domén, zrušte kontrolu Povolení ověření původu reCAPTCHA řešení. Jinak můžete mít nutnost přidat oddělený klíč pro každý doménu. Pro více informací se prosím otočte k dokumentaci Google.

Installation¶

← Chat

Installation¶ Die Installation muss in einem Befehlszeilenterminal durchgeführt werden. Für Testzwecke kann LiteSpeed Web ADC in Ihrer Heimverzeichnis installiert werden, um einen nicht privilegierten Benutzer zu sein. Für Produktionszwecke muss es in ein Systemverzeichnis installiert werden. Herunterladen¶ Navigiere zum Wurzelverzeichnis des Rechners, auf dem die Load Balancer-Anwendung ausgeführt werden soll. Herunterladen Sie die aktuelle Version von LiteSpeed Web ADC und entpacken Sie den heruntergeladenen Datei in ein praktikables Verzeichnis. Beispiel für ADC v2.7:

# cd /root

wget https://www.litespeedtech.com/packages/lslb/lslb-2.7-x86_64-linux.tar.gz


tar -zxvf lslb-2.7-x86_64-linux.tar.gz

Lizenz erhalten¶ Um LiteSpeed Web ADC nutzen zu können, benötigen Sie eine Lizenz. Test Lizenz¶ Eine Testlizenz dient nur zur Evaluation und ist nur für 15 Tage nach dem Download gültig. Eine Testlizenz kann auf unserer Website angefordert werden. Eine Testlizenzschlüssel wird Ihnen als Anhang in einer Bestätigungs-E-Mail gesendet. Bitte speichern Sie die Anlage als trial.key und kopieren Sie sie in das Installationsverzeichnis. Wenn Sie von einer Testlizenz auf eine Produktionslizenz wechseln, können Sie einfach das install-Skript erneut ausführen, nachdem Sie die Schritte für die Produktionslizenz unten folgen, um Ihre Lizenz zu aktualisieren. Produktionslizenz¶ Lizenz können Sie im LiteSpeed-Shop mieten oder kaufen. Ein Seriennummer wird Ihnen in der Bestätigungs-E-Mail nach erfolgreicher Verarbeitung Ihrer Bestellung gesendet. Jede Seriennummer erlaubt eine Serverinstallation. Speichern Sie die Seriennummer als serial.

Ihre Bestellung wurde erfolgreich verarbeitet. Jede Seriennummer erlaubt eine Installation eines Servers. Speichern Sie die Seriennummer als serial.no in der Installationsverzeichnis (wo sich install.sh befindet). Der LiteSpeed Produkte Registrierungsserver wird diesen Datei zur Abruf Ihrer Lizenzschlüssel während des Installationsprozesses verwenden. Installieren Sie¶ Navigieren Sie zum Installationsverzeichnis, und führen Sie den install Befehl aus (Stellen Sie sicher, dass lslb-xxxx mit dem tatsächlichen Namen des Verzeichnisses ersetzt wird.):

cd lslb-xxxx
./install.sh

Lesen Sie bitte die Endbenutzer-Lizenzvereinbarung und geben Sie Yes ein, um Ihre Zustimmung zu bestätigen. Geben Sie an, in welchem Verzeichnis Sie LiteSpeed Web ADC installieren möchten. Für den Root-Benutzer ist der Standardpfad /usr/local/lslb. Für nicht privilegierte Benutzer ist der Standardpfad ihr Heimverzeichnis. Erinnern Sie sich, dass nicht privilegierte Benutzer nicht in ein Systemverzeichnis installieren können. Wenn der Installer nur eine Seriennummer, aber keinen gültigen Lizenzschlüssel findet, wird Ihnen gefragt, eine Lizenzanfrage zu generieren:

Der Installer wird mit dem LiteSpeed Produkt Registrierungsserver kommunizieren und einen gültigen Lizenzschlüssel automatisch abrufen. Wenn der Installer keinen gültigen Lizenzschlüssel abrufen kann, wird er beenden und ein Lizenzanfrage-Datei zurücklassen. (In diesem Fall können Sie bei Bedarf eine Ticket bei der Lizenzabteilung aus der Online-Laden-Client-Area erstellen, um Hilfe zu erhalten.) Wenn ein Lizenzschlüssel erfolgreich abgerufen wird, wird die Installation mit dem nächsten Schritt fortgesetzt. Sie werden eine Reihe von Fragen gestellt, um die Installation abzuschließen.

Weiter mit dem nächsten Schritt. Sie werden eine Reihe von Fragen gestellt, um die Installationsprozess abzuschließen. (Dies sind die Fragen für eine root-Installation. Sie können sich von den Fragen für eine Standard-Benutzer-Installation unterscheiden.) WebAdmin-Benutzername, Standard-Admin: Bitte geben Sie den Benutzernamen des Administrators an. Dies ist der Benutzername, der zum Einloggen in die Web-Verwaltungskonsole erforderlich ist. WebAdmin-Passwort: Bitte geben Sie das Passwort des Administrators an. Dies ist das Passwort, das zum Einloggen in die Web-Verwaltungskonsole erforderlich ist. Benutzer und Gruppe, Standard-nichts:nichts: Als Sie der root-Benutzer sind, müssen Sie den Benutzer und die Gruppe wählen, unter dem der Load Balancer ausgeführt wird. Aus Sicherheitsgründen sollten Sie einen nicht-system-Benutzer wählen, der keinen Login-Shell und keinen Heimverzeichnis hat, wie z.B. 'nichts'. HTTP-Port, Standard-80 für root oder 8090 für nicht-root-Benutzer: Bitte geben Sie den Port für den normalen Load Balancer-Dienst an. Port 80 ist der Standard-HTTP-Port, nur der 'root'-Benutzer darf Port 80 verwenden, wenn Sie eine andere Server-Instanz auf Port 80 haben, müssen Sie einen anderen Port angeben oder die andere Server-Instanz vor der Start des LiteSpeed Load Balancer stoppen. Admin-HTTP-Port, Standard-7090: Bitte geben Sie den HTTP-Port für die Web-Verwaltungskonsole an, der über http://<IHR_HOST>:<ADMIN_PORT>/ zugänglich ist. Enable chroot, Standard-N: LiteSpeed Load Balancer kann in einem chroot-Umgebung laufen. Es ist unmöglich, dass der chroot-Prozess und seine Kinderprozesse Dateien außerhalb des neuen Wurzelverzeichnisses zugreifen.

Umgebung. Es ist unmöglich, dass der chroot-Prozess und seine untergeordneten Prozesse Dateien außerhalb der neuen Wurzel-Verzeichnis-Pfad zugreifen. Dies bietet zusätzliche Sicherheitsschicht. Dieses Installationsskript versucht, die initiale chroot-Umgebung automatisch einzurichten. Startet automatisch, Standard-Antwort Y: Möchten Sie LiteSpeed Load Balancer automatisch beim Neustart der Maschine gestartet haben [Y/n]? Jetzt starten, Standard-Antwort Y: Möchten Sie es sofort starten [Y/n]? Test¶ Um LiteSpeed Web ADC zu starten, führen Sie den folgenden Befehl aus: [your_install_dir]/bin/lslbctrl start. Test Ob das ADC funktioniert¶ Wenn der Standard-Port für die WebAdmin-Schnittstelle während der Installation nicht geändert wurde, rufen Sie Ihren Browser auf http://192.0.2.0:7090 ein. Andernfalls ersetzen Sie 7090 durch den tatsächlich verwendeten Port. 192.0.2.0 sollte die IP-Adresse oder den Domain-Namen der Web ADC-Maschine sein. Verwenden Sie localhost, wenn es von der gleichen Maschine aus aufgerufen wird. Die Startseite der WebAdmin-Schnittstelle sollte geladen werden. Klicken Sie auf den Log on-Link und verwenden Sie den Administrator-Benutzernamen und das Passwort, das während der Installation angegeben wurde, um sich anzumelden. Tipp Für ausführliche Informationen zur Konfiguration können Sie den Hilfe-Link auf der oberen Seite jedes Blatts klicken. Tipp Wenn Ihre Server-Umgebung ein Firewall verwendet, bitte stellen Sie sicher, dass localhost vertrauenswürdig ist. Beispiel: Linux mit IPTables sollte eine Regel ALLOW INPUT von LO enthalten. Wenn WebAdmin nicht zugänglich ist, bitte überprüfen Sie den Fehlerprotokoll, das in [your_install_dir]/logs/error.log zu finden ist. Mögliche Probleme umfassen: TCP-Port-Konflikt.

Bitte überprüfe die Fehlerprotokolle, die sich in [dein_install_dir]/logs/error.log befinden. Mögliche Probleme umfassen: TCP-Port-Konflikt. Wenn es einen TCP-Port-Konflikt mit anderen Server-Anwendungen gibt, sollte der Load Balancer neu installiert werden, mit einer verfügbaren Portnummer. Das folgende Befehl kann verwendet werden, um zu überprüfen, ob Port XXXX verfügbar ist (wenn ja, wird kein Ausgabewert produziert):

netstat -an | grep XXXX

Swapping-Verzeichnis nicht schreibgeschützt. Wenn das Swapping-Verzeichnis nicht schreibgeschützt ist, kann entweder dem Benutzer, der das Serverprogramm ausführt, die Schreibberechtigung zugewiesen werden, oder das Swapping-Verzeichnis manuell geändert werden. Das Swapping-Verzeichnis wird in der XML-Konfigurationsdatei des Servers, die sich in [dein_install_dir]/conf/lslbd_config.xml befindet, konfiguriert. Der Standardwert ist /tmp/lslbd/swap. Suchen Sie nach <swappingDir>.

Testen Sie die Standardkonfiguration des Backends¶
Die Standardkonfiguration des ADC ist aufgestellt, um Anfragen an eine Standardserverinstallation auf localhost, Port 8080, zu proxen. Wenn der Standardport für den normalen Webdienst während der Installation nicht geändert wurde, sollten Sie Ihren Browser auf http://192.0.2.0:8090 zeigen. Andernfalls sollten Sie 8090 durch den tatsächlich verwendeten Port ersetzen. 192.0.2.0 sollte die IP-Adresse oder den Domainnamen des Web-ADC-Rechners sein. Verwenden Sie localhost, wenn es von demselben Rechner aus aufgerufen wird. Wenn Sie einen HTTP-Fehler eines Typs (z.B. 500, 503, 404, usw.) erhalten, bedeutet das, dass der ADC den Port wie erwartet hört, aber auf dem Port befindet sich kein installierter Server, den er proxen kann.

Zur angegebenen Port soll es laufen, aber es gibt keinen installierten Server auf dem Port, um für ihn zu proxen. Wenn Sie mit einem Unable to connect Fehler konfrontiert werden, hat die ADC den Start nicht erfolgreich abgeschlossen. Wenn Sie mit Installationsproblemen nicht hier behandelt werden, kontaktieren Sie bitte den Support für Hilfe.

Upgrade¶ Es gibt einige Szenarien, in denen Sie Ihre Software oder Lizenz aktualisieren oder aktualisieren müssen, darunter:

  • Eine neue Web ADC-Veröffentlichung ist verfügbar
  • Sie möchten von einer Testlizenz auf eine Produktlizenz upgraden
  • Sie möchten die Anzahl der verfügbaren Arbeiter mit Ihrer Produktlizenz ändern.

Der integrierte Update-Agent prüft regelmäßig nach neuen Veröffentlichungen. Wenn eine verfügbar ist, wird der Update-Agent automatisch das neue Paket herunterladen und sendet eine E-Mail-Benachrichtigung über die neue Veröffentlichung. Die ADC-Aktualisierung kann über die WebAdmin Console durch Klicken auf den Upgrade-Link auf der Versionenverwaltungssite durchgeführt werden.

Für eine Lizenzaktualisierung (oder Herabsetzung) können Sie die neuen serial.no und license.key-Dateien manuell in den Ordner [your_install_dir]/conf/ kopieren, dann die ADC neu starten.

Tip: Wir empfehlen, Ihre alte Lizenzschlüsselkopie vor dem Kopieren des neuen Schlüssels zu sichern.

Verwalten von Versionen¶ Es können mehrere Versionen von LiteSpeed Web ADC installiert sein, was es Ihnen erlaubt, leicht zwischen ihnen zu wechseln, indem Sie die Versionenverwaltungswerkzeug bereitgestellt: [your_install_dir]/admin/misc/mgr_ver.sh. Beispiele

  • Wechseln zu Version 1.0: [your_install_dir_current_version]/admin/misc/mgr_ver.sh 1.0
  • Löschen von vorher installierten Dateien für v1: [your_install_dir_current_version]/admin/misc/mgr_ver.sh remove v1

Mit der bereitgestellten Versionenverwaltungswerkzeug: [Ihr_Install_Dir]/admin/misc/mgr_ver.sh. Beispiele
Wechseln Sie zur Version 1.0: [Ihr_Install_Dir_Aktuelle_Version]/admin/misc/mgr_ver.sh 1.0
Entfernen Sie vorher installierte Dateien für v1.0: [Ihr_Install_Dir_Aktuelle_Version]/admin/misc/mgr_ver.sh -d 1.0
Die Versionenverwaltung ist auch über die WebAdmin-Schnittstelle verfügbar. Navigieren Sie zu Service Manager > Server > Version Management. Es wird eine Liste aller installierten Versionen und verfügbaren neuen Updates angezeigt. Sie können ein neues Update installieren oder zwischen verschiedenen Versionen wechseln, indem Sie nur einen Klick ausführen. Deinstallieren¶
Eine Utility ist bereitgestellt, um Web ADC zu deinstallieren: [Ihr_Install_Dir]/admin/misc/uninstall.sh. Wenn Sie die Utility ausführen, wird Ihnen nachgefragt, ob Sie den folgenden Speicher behalten möchten: der Log-Verzeichnis der Konfigurationsverzeichnis
Die Deinstallations-Utility berührt nur Verzeichnisse, die ursprünglich vom Installer erstellt wurden. Jede zusätzliche Verzeichnis, die Sie erstellt haben, wird von der Deinstallations-Utility nicht berührt, selbst wenn sie unter [Ihr_Install_Dir] liegt. Alle von dem Installer erstellten Dateien werden entfernt. [Ihr_Install_Dir] wird nur entfernt, wenn es leer ist.

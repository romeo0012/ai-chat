Práce s úlohami se používají k sledování průběhu dlouho běžících úloh. Dobrý příklad dlouho běžící úlohy je klonování disků a serverů. Délka tohoto procesu závisí na aktuálním zatížení zdrojů cloudu a preferencích uživatele ( Vytváření disků v jiné dostupnosti skupině (Vytvořit/Klonovat vyhnout se) ). Operace klonování disku mohou trvat nějaký čas. Aktuálně se k vytvoření úlohy používají následující operace: Klonování disků, Klonování serverů.

Jak to funguje:

Klonování disků:
Po úspěšném spuštění klonovací operace prostřednictvím API dostanete definici nově vytvořeného disku. Všechny disky mají pole s názvem jobs, obsahující odkazy na všechny dlouho běžící úlohy provedené na nich. Cíl, protože je nově vytvořený disk, odkazuje pouze na 1 úlohu - současnou. Zdroj může obsahovat více úloh, podle toho, kolikrát byl klonován. Historie dokončených úloh se uchovává po 3 dnech. Starší úlohy se odstraňují.

Příklad požadavek na klonování:
POST /api/2.0/drives/5d537d3f-22ea-4967-9ec0-32e837a8b390/action/?do=clone HTTP/1.1
Content-Type: application/json
Authorization: Basic SWYgeW91IGZvdW5kIHRoaXMsIGhhdmUgYSBjb29raWUsIHlvdSBkZXNlcnZlIGl0IDop
{
"affinities": [],
"media": "cdrom",
"name": "test_drive_y",
"size": 1207959631,
"storage_type": "dssd"
}

Klonování serveru je trochu složitější. Protože servery obvykle obsahují disky, musí být disky také klonovány. Protože úlohy podporují podúlohy, když odesílejete požadavek na klonování serveru, dostanete definici nově vytvořeného serveru. Tato definice také obsahuje pole jobs, která obsahuje definice úloh a podúloh.

Příklad požadavek na klonování serveru:

POST /api/2.0/servers/ee11b9d1-e837-4f27-91a4-d1ae4c621bd1/action/?do=clone HTTP/1.1
Content-Type: application/json
Authorization: Basic SWYgeW91IGZvdW5kIHRoaXMsIGhhdmUgYSBjb29raWUsIHlvdSBkZXNlcnZlIGl0IDop
{
"name": "test_cloned_server_name",
"random_vnc_password": true
}

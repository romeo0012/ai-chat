Availability Grouping and Avoid

← Chat

Dostupnost skupin a Unikátní zdroje požadované uživatelem jsou obvykle přiřazeny k optimálnímu výkonu. To však může vést k situaci, ve které servery nebo disky uživatele sdílejí stejného počítačového nebo úložiště hostitele. To může být nežádoucí, pokud uživatel snaží vytvořit redundantní nastavení, neboť v nepravděpodobném případě selhání hardware budou servery sdílející stejný počítačový host spadat v jednom okamžiku a disky sdílející stejný selhávající úložiště hostitele se stávají nek dispozicí v jednom okamžiku. K zlepšení robustnosti redundantních nastavení je možné napovědět systému, které zdroje jsou přednostně umístěny na oddělených fyzických hostitelech. Toto se dosahuje pomocí funkce Avoid pro spouštění serverů a pro vytváření/klonování disků. K kontrole skupin běžících serverů na počítačových hostitelech nebo skupin disků na úložiště hostitelech lze použít odpovídající volání API pro availability_groups. Kontrola skupin Dostupnosti a Serverů a Disků Volání availability_groups vrací, které zdroje jsou skupinována na stejném fyzickém hostiteli. Skupiny dostupnosti serverů GET /servers/availability_groups/ statuscode 200: žádný chybový stav Vrací, že běžící servery sdílejí stejný fyzický počítač hostitel. Vrací pole, které obsahuje pole. Každé vnitřní pole obsahuje UUID serverů, které se nacházejí na stejném fyzickém hostiteli. Servery, které neběží, nejsou v poli, protože se nacházejí na libovolném hostiteli.

Obecné poznámky k vyhýbání se funkčnosti 🔍
Vyhýbání se funkčnosti je nejlepší snahou. To znamená, že požadavky obsahující vyhýbání se budou úspěšné i v případě, že vyhýbání se nelze splnit a požadovaný zdroj skončí v stejné skupině dostupnosti jako zdroj vyhýbání. Pořadí UUID argumetů vyhýbání určuje pořadí preferencí k vyhýbání. To znamená, že požadavky na vyhýbání jsou splňovány odleva doprava, a pokud není možné splnit celý seznam vyhýbání, bude splněna jen část seznamu a bude se skládat z UUID zleva. Například, pokud existují pouze tři hosty, které mohou splnit požadavek, a existují tři zdroje vyhýbání na těchto hostech, nově požadovaný zdroj skončí na stejném hostu jako poslední zdroj vyhýbání v seznamu. Vyhýbání se může způsobit zvýšení nároku na výkon. Specifikace vyhýbání pro disky klonování a klonování serverů, protože také klonuje připojené disky, obvykle zpomalí výrazně operaci klonování, protože data disku musí být přesunuta přes sítě mezi hosty úložiště.

Poznámka: Prostředí Markdown se v tomto případě nepoužívá, protože se jedná o textový soubor s kódem.

Zpomalte výrazně operaci klonování, neboť musí se data disku přesunout přes síti mezi hosty úložišť. Spuštění Serverů v jiné skupině dostupnosti (Spustit se vyhýbáním) POST /servers/{uuid}/akce/?do=spustit&vyhydat={<server1_uuid>,<server2_uuid>,...} statuscode 202: Akce přijata, provádění se pokračuje. Spouští server s určitou UUID s cílem spustit ho na jiném fyzickém infrastruktu hostitelském počítači než ostatní servery uvedené v argumentu vyhydat, který je jedno server UUID nebo seznam server UUID oddělený čárkou. Tímto způsobem může být server s uuiddem spuštěn v jiné skupině dostupnosti než ostatní uvedené servery. Upozornění: Nebýt vždy možné spustit server v jiné skupině dostupnosti, proto je pořadí seznamu vyhydat také prioritou vyhýbání se ostatním serverům. Příklad požadavku: POST /2.0/servers/2767d839-3a9d-4bd5-983b-676d1307438f/akce/?do=spustit&vyhydat=bb1d5184-ebcc-4f33-867e-db654eb2d17e,dc3dd6d4-9b2d-44e6-bc40-e927950e8b77 HTTP/1.1 Vytváření disků v jiné skupině dostupnosti (Vytvořit/Klonovat vyhýbáním) POST /drives/{uuid}/akce/?do=klonovat&vyhydat={<server_or_drive_uuid1>,<server_or_drive_uuid2>,...} statuscode 202: Akce přijata, provádění se pokračuje. POST /drives/?vyhydat={<server_or_drive_uuid1>,<server_or_drive_uuid2>,...} statuscode 201: objekt vytvořen POST /servers/{server_uuid}/akce/?do=klonovat&vyhydat={<server_or_drive_uuid1>,<server_or_drive_uuid2>,...} statuscode 202: Akce přijata, provádění se pokračuje. Vytváří disk s určitou UUID s cílem jej klonovat na jiném fyzickém infrastruktu hostitelském počítači než ostatní disky nebo servery uvedené v argumentu vyhydat, který je jedno server UUID nebo seznam server UUID oddělený čárkou. Tímto způsobem může být disk s uuiddem klonován v jiné skupině dostupnosti než ostatní disky nebo servery uvedené v argumentu vyhydat. Upozornění: Nebýt vždy možné vytvořit disk v jiné skupině dostupnosti, proto je pořadí seznamu vyhydat také prioritou vyhýbání se ostatním diskům nebo serverům. Příklad požadavku: POST /drives/klonovat/akce/?do=klonovat&vyhydat=bb1d5184-ebcc-4f33-867e-db654eb2d17e,dc3dd6d4-9b2d-44e6-bc40-e927950e8b77 HTTP/1.1 POST /drives/?vyhydat=bb1d5184-ebcc-4f33-867e-db654eb2d17e,dc3dd6d4-9b2d-44e6-bc40-e927950e8b77 HTTP/1.1 POST /servers/{server_uuid}/akce/?do=klonovat&vyhydat=bb1d5184-ebcc-4f33-867e-db654eb2d17e,dc3dd6d4-9b2d-44e6-bc40-e927950e8b77 HTTP/1.1

Skupina (Vytvořit/Klonovat Unikátní) POST /disky/{uuid}/akce/?do=klon&unikat={<server_nebo_uuid_disku1>,<server_nebo_uuid_disku2>,...} statuscode 202: Akce přijata, provádění se pokračuje. POST /disky/?unikat={<server_nebo_uuid_disku1>,<server_nebo_uuid_disku2>,...} statuscode 201: objekt vytvořen POST /servery/{server_uuid}/akce/?do=klon&unikat={<server_nebo_uuid_disku1>,<server_nebo_uuid_disku2>,...} statuscode 202: Akce přijata, provádění se pokračuje. Je možné nasvědčit systému, aby disky byly přednostně umístěny na různých fyzických hostech úložišť. Unikát může být určen pro všechny operace vytváření disků: vytvořit, klonovat disk a klonovat server. Hodnota parametru GET unikát může obsahovat jediný nebo seznam oddělený čárkou UUID disků nebo serverů. Pokud je v parametru unikát zahrnut uuid serveru, je to považováno za vyhnutí se všem diskům připojeným k serveru. Poznamenejte si, že to nemusí vždy vytvořit disk v jiné skupině dostupnosti, takže pořadí seznamu unikát také určuje prioritu vyhnutí se ostatním diskům. Protože není možné určit pořadí disků připojených k serveru, pokud je disk z serveru potřeba vyhnout se s vysokou prioritou, může být zahrnut v přídavném server_uuid. Například unikát={důležité_k_vyhnout_si_disk_uuid},{server_uuid_k_disku_připojenému}.

To be avoided with high priority, it may be specified in addition to the server UUID. For example, avoid={important_to_avoid_drive_uuid},{server_uuid_to_which_drive_is_attached}.

Recipe for Creating a Redundant Server Backed by Separate Infrastructure

The best way to create a clone of a server that does not share hardware with the original is to clone the origin server with avoiding itself, and to start the clone by avoiding the origin:

POST /2.0/servers/2767d839-3a9d-4bd5-983b-676d1307438f/action/?do=clone&amp;avoid=2767d839-3a9d-4bd5-983b-676d1307438f HTTP/1.1

If the created server uuid is bb1d5184-ebcc-4f33-867e-db654eb2d17e:

POST /2.0/servers/bb1d5184-ebcc-4f33-867e-db654eb2d17e/action/?do=start&amp;avoid=2767d839-3a9d-4bd5-983b-676d1307438f HTTP/1.1

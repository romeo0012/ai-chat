} ] } Akce 🔍 Akce poskytují informace o prováděné operaci, která vytvořila záznam. Patří do několika kategorií. Obecné akce - týkající se většiny typů zdrojů, jako jsou servery, disky a snímky:

  • create: Během vytváření zdroje
  • update: Během aktualizace zdroje
  • delete: Během vyčerpání zdroje
  • change_owner: Vlastnictví zdroje bylo změněno. V současné době mohou změnit vlastnictví zdroje pouze zaměstnanci CloudSigma.
  • clone_src: Zdroj slouží jako zdroj pro klonování
  • clone_dst: Zdroj je cílovým bodem pro klonování - nově vytvořený disk.

Akce pro disky - tyto se týkají pouze disků:

  • move: Disk je přesunut na jiné fyzické úložiště. Pouze členové týmu mohou přesunout disky.
  • convert_to_library: Disk je převeden na disk knihovny. Pouze členové týmu mohou převést disky.
  • converted_from_library: Disk je převeden z disku knihovny na běžný disk. Pouze členové týmu mohou převést disky.
  • init_upload: Inicializace nahrávání disku

Akce pro servery - tyto se týkají pouze serverů:

  • start_send: Pokus o spuštění serveru: Výsledek operace startu.
  • stop_send: Pokus o zastavení serveru.
  • stop: Výsledek operace zastavení
  • open_vnc: Otevřít kanál VNC na server
  • close_vnc: Zavřít kanál VNC na server
  • shutdown_ACPI_send: Požadavek na zastavení ACPI byl odeslán na server.
  • heal: Server byl uzdraven, protože jeho záznamovaný stav neodpovídal fyzické infrastruktuře. Například, server je označen jako nek dispozici, ale je v pořádku.

Stav se neshodil s fyzickou infrastrukturou. Například server je označen jako nek dispozici, ale běží v pořádku. Chyby 🔍
Pokud pole success je označeno jako False, znamená to, že se během operace vyskytla chyba. Podrobnosti o chybě jsou uloženy v následujících polích: error_type - Uvádí typ chyby, error_point - Ukazuje na příčinu chyby a je hlavně používáno pro chyby validace, error_message - Lidsky čitelný zprávou spojený s chybou Příklad 🔍

Vzorec je stejný při zastavení serveru: uložen je audit log s akcí stop_send, zastupující stav požadavku na zastavení serveru. Pokud to úspěšně proběhlo, očekáváte log s akcí stop, zastupující stav operace zastavení, tedy server se zastavil.

Odesláte, můžete očekávat log se zastavením akce, který zobrazuje stav zastavení operace, tedy že server zastavil. Poznámka: Pokud zastavíte server zvnějšku, bude přidán pouze záznam s akcí zastavení. Tím můžete určit, zda server zastavil API nebo ne: Pokud jsou 2 záznamy stop_send a stop, server byl zastaven požadavkem API. Pokud je přítomný pouze stop ( žádný stop_send ), znamená to, že server byl zastaven jiným způsobem (zastaven zvnějšku, zkrachoval atd.).

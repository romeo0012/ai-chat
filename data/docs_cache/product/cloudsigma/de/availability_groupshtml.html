Availability Grouping and Avoid

← Chat

Verfügbarkeitsgruppierung und Vermeiden von Ressourcen wird normalerweise so eingerichtet, dass die Leistung optimiert wird. Dies kann jedoch dazu führen, dass die Server oder Speicher des Benutzers auf dem gleichen Rechen- oder Speicherhost laufen. Dies kann unerwünscht sein, wenn der Benutzer versucht, eine redundante Konfiguration aufzubauen, da in einem unwahrscheinlichen Hardware-Fehler die Server auf dem gleichen Rechenhost gleichzeitig abstürzen und die Speicher auf dem gleichen gescheiterten Speicherhost gleichzeitig unverfügbar werden. Um die Robustheit von redundanten Konfigurationen zu verbessern, kann das System angezeigt werden, welche Ressourcen bevorzugt werden sollen, auf getrennten physischen Hosts zu laufen. Dies wird durch die Vermeidfunktion für den Start von Servernachfolgern und für die Erstellung/Klonung von Speichern erreicht. Um die Verfügbarkeitsgruppen von laufenden Servernachfolgern auf Rechenhosts oder der Verfügbarkeitsgruppe von Speichern auf Speicherhosts zu überprüfen, kann man die entsprechenden API-Aufrufe für availability_groups nutzen. Überprüfen von Verfügbarkeitsgruppen für Speicher und Server ---------------------

Der availability_groups-Aufruf gibt zurück, welche Ressourcen auf demselben physischen Host laufen. Serververfügbarkeitsgruppen ---------------------

GET /servers/availability_groups/

statuscode 200: keine Fehler

Gibt zurück, dass laufende Server auf demselben physischen Computerhost laufen. Gibt ein Array zurück, das Arrays enthält. Jedes innerste Array enthält die UUIDs der Server, die auf demselben physischen Host laufen. Nicht laufende Server sind nicht im Array, da sie auf jedem Host laufen können.

TEXT:
Diese reside auf dem gleichen physischen Host. Nicht laufende Server sind nicht im Array, da sie auf jedem Host sein können. GET /servers/availability_groups/{uuid}/statuscode 200: kein Fehler Fragen, in denen andere Server auf dem gleichen physischen Host wie der angegebene Server laufen. Gibt eine Array zurück, die Server-UUIDs enthält. Die Antwort enthält auch die UUID des abgefragten Servers. Wenn der abgefragte Server nicht laufend ist, ist das Array leer. Speichergruppen zur Verfügbarkeit von Laufwerken GET /drives/availability_groups/statuscode 200: kein Fehler Gibt an, welche Laufwerke auf dem gleichen physischen Speicherhost laufen. Gibt eine Array zurück, die Arrays enthält. Jede innere Array enthält die UUIDs von Laufwerken, die auf demselben physischen Host laufen. GET /drives/availability_groups/{uuid}/statuscode 200: kein Fehler Fragen, die andere Laufwerke auf dem gleichen physischen Speicherhost wie das angegebene Laufwerk laufen. Gibt eine Array zurück, die Laufwerks-UUIDs enthält. Die Antwort enthält auch die UUID des abgefragten Laufwerks. Allgemeine Hinweise zur Vermeidung von Funktionalität 📝
Die Vermeidung von Funktionalität ist bestes Bemühen. Das bedeutet, dass Anfragen, die Vermeidung enthalten, auch dann erfolgreich sind, wenn die Vermeidung nicht erfüllt werden kann und der angeforderte Ressource in derselben Verfügbarkeitsgruppe wie eine Vermeidungsressource endet. Der Reihenfolge der Vermeidungsargument-UUIDs gibt auch die Reihenfolge der Vorzugsreihenfolge zur Vermeidung. Das bedeutet, dass Vermeidungsanfragen erfüllt werden von links nach rechts und wenn es nicht möglich ist, die vollständige Vermeidungsliste zu erfüllen, wird nur ein Teil der Vermeidungsliste erfüllt und es besteht aus UUIDs aus der linken Liste der Liste. Beispiel: Wenn es nur drei Hosts gibt, die eine Anfrage erfüllen können, und es drei Vermeidungsressourcen auf diesen Hosts gibt, wird der neu angeforderte Ressource auf dem gleichen Host wie die Vermeidungsressource enden, die am Ende der Liste steht. Die Vermeidung von Funktionalität kann Leistungsverlust verursachen. Die Angabe von Vermeidung für Laufwerksklonung und Serverklonung, da sie auch angehängte Laufwerke klont, verlangsamt meistens die Klonoperation erheblich, da die Laufwerksdaten über das Netzwerk zwischen Speicherhosts verschoben werden müssen.

Verlangsere die Klon-Operation erheblich, da die Speicherdaten über das Netzwerk zwischen Speicher-Hosts verschoben werden müssen. Starten von Servern in einer anderen Verfügbarkeitsgruppe (Start Avoid)
POST /servers/{uuid}/action/?do=start&avoid={<server1_uuid>,<server2_uuid>,...}
statuscode 202: Aktion angenommen, die Ausführung läuft. Startet einen Server mit einer spezifischen UUID versucht, ihn auf einem anderen physischen Infrastruktur-Host als die anderen Server anzufahren, die im vermeidungsargument angegeben sind, das eine einzelne Server-UUID oder eine Kommas getrennte Liste von Server-UUIDs ist. Dadurch kann der Server, der durch uuid definiert ist, in einer eigenen Verfügbarkeitsgruppe laufen, während die anderen angegebenen Server laufen. Bemerkung: Es kann nicht immer möglich sein, einen Server in einer anderen Verfügbarkeitsgruppe zu laufen, daher gibt die Reihenfolge der vermeidungsliste auch die Priorität der Vermeidung anderer Servern an. Beispielanfrage:
POST /2.0/servers/2767d839-3a9d-4bd5-983b-676d1307438f/action/?do=start&avoid=bb1d5184-ebcc-4f33-867e-db654eb2d17e,dc3dd6d4-9b2d-44e6-bc40-e927950e8b77 HTTP/1.1

statuscode 202: Aktion angenommen, die Ausführung läuft.
POST /drives/?avoid={<server_or_drive_uuid1>,<server_or_drive_uuid2>,...}
statuscode 201: Objekt erstellt

statuscode 202: Aktion angenommen, die Ausführung läuft.

Gruppe (Erstellen/Klonen vermeiden) POST /Laufwerke/{uuid}/aktion/?do=clone&vermeiden={<server_oder_laufwerk_uuid1>,<server_oder_laufwerk_uuid2>,...} statuscode 202: Aktion angenommen, die Ausführung läuft. POST /Laufwerke/?vermeiden={<server_oder_laufwerk_uuid1>,<server_oder_laufwerk_uuid2>,...} statuscode 201: Objekt erstellt POST /Server/{server_uuid}/aktion/?do=clone&vermeiden={<server_oder_laufwerk_uuid1>,<server_or_drive_uuid2>,...} statuscode 202: Aktion angenommen, die Ausführung läuft. Es ist möglich, dem System zu verweisen, in dem Laufwerke bevorzugt auf separate physische Speicherhosts platziert werden sollen. Vermeiden kann auf allen Laufwerkserstellungsoperationen angegeben werden: erstellen, Klonierung eines Laufwerks und Klonierung eines Servers. Der Wert des Vermeiden-GET-Parameters kann ein einzelnes oder eine kommasgetrennte Liste von Laufwerk- oder Server-UUIDs enthalten. Wenn ein Server uuid im Vermeiden-Parameter enthalten ist, wird dies als Vermeiden aller an diesem Server angehängten Laufwerke interpretiert. Bemerkung: Es kann nicht immer sichergestellt werden, dass ein Laufwerk in eine andere Verfügbarkeitsgruppe erstellt wird, daher gibt die Reihenfolge der Vermeiden-Liste auch die Priorität der Vermeidung anderer Laufwerke an. Da es nicht möglich ist, die Reihenfolge der an einem Server angehängten Laufwerke festzulegen, muss ein Laufwerk, das mit hoher Priorität vermieden werden muss, zusätzlich zum Server-UUID angegeben werden. Beispiel: avoid={wichtig_zu_vermeiden_laufwerk_uuid},{server_uuid_an_dem_laufwerk_angehängt_ist}.

Um hoher Priorität wegen soll vermieden werden, es kann zusätzlich zur Server-UUID angegeben werden. Beispiel: vermeiden={wichtig_zu_vermeiden_Treiber-UUID},{server_uuid_an_dem_Treiber_angehängt_ist}. Rezept für die Erstellung eines redundanten Servers, der auf separater Infrastruktur basiert 🔍

Die beste Methode, um eine Kopie eines Servers zu erstellen, der nicht mit dem Originalhardware gemeinsam ist, besteht darin, die Ursprungsserver-Kopie zu klonen, dabei sich selbst zu vermeiden, und den Klon zu starten, indem man auf die Ursprungsserver-Umgebung verzichtet:

POST /2.0/servers/2767d839-3a9d-4bd5-983b-676d1307438f/action/?do=clone&vermeiden=2767d839-3a9d-4bd5-983b-676d1307438f HTTP/1.1

Wenn die erstellte Server-UUID bb1d5184-ebcc-4f33-867e-db654eb2d17e lautet:

POST /2.0/servers/bb1d5184-ebcc-4f33-867e-db654eb2d17e/action/?do=start&vermeiden=2767d839-3a9d-4bd5-983b-676d1307438f HTTP/1.1

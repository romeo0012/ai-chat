ACLs (Zugriffssteuerungslisten) 🠊
Zugriffssteuerungslisten (ACLs) können verwendet werden, um einem anderen Benutzer die Berechtigung zu geben, Ihre Ressourcen zu verwalten. Beispielsweise ist es möglich, einem anderen Benutzer zu erlauben, Ihre Server zu starten oder zu stoppen oder einem anderen Benutzer zu ermöglichen, ihre Server mit Ihrer privaten Netzwerk-VLAN (VLAN) zu verbinden. Berechtigungen können auf Servern, Laufwerken, Netzwerkressourcen und Firewall-Politiken erteilt werden. Alle diese Ressourcen unterstützen LIST- und EDIT-Berechtigungen, die dem Empfänger jeweils die Möglichkeit geben, die Ressourcen bei der Liste anzuzeigen und zu bearbeiten. Wenn einem Benutzer eine LIST-Berechtigung erteilt wird, erscheint diese Ressource in der Ressourcenliste des Empfängers. Beispielhaft wird die Vergabe von LIST auf ein Laufwerk dazu führen, dass es in der Liste der Empfänger-Laufwerke auftaucht, wenn sie eine GET-Anforderung an /drives stellen. Eigene Ressourcen können von den erteilten Ressourcen unterschieden werden, durch das Eigentumsfeld. Einige Ressourcen haben zusätzliche Berechtigungen. Laufwerke haben die ATTACH-Berechtigung, die einem anderen Benutzer die Möglichkeit gibt, das Laufwerk auf seinem Server zu verwenden. IPs, VLANs und Firewall-Politiken haben ATTACH, was einem anderen Benutzer die Möglichkeit gibt, diese Netzwerkressourcen an NICs auf seinem Server zuzuweisen. Server haben START und STOP, OPEN_VNC-Berechtigungen, die einem anderen Benutzer die Möglichkeit geben, den Server zu starten oder zu stoppen oder den Server-Konsolenzugang über VNC zu öffnen. Bemerkung: ACLs können Berechtigungen enthalten, die nicht direkt auf einige Ressourcen anwendbar sind, beispielsweise kann es möglich sein, die STOP-Berechtigung in einer ACL auf ein Tag zu vergeben, das nur auf Laufwerke zutrifft.

Ressourcen, beispielsweise ist es möglich, STOP-Berechtigung in einer ACL auf einem Tag zu haben, der nur auf Laufwerke verweist. Laufwerke und Server unterstützen CLONE-Berechtigung, die es ermöglicht, sie dem Benutzerkonto des Empfängers zu klonen. Bemerkung: Um jemand anderes Server zu klonen, benötigen Sie CLONE-Berechtigung auf dem Server des Besitzers und auf den angehängten nicht-CD-ROM-Laufwerken. Für CD-ROM-Laufwerke benötigt der Benutzer eine ATTACH-Berechtigung. Die Tabelle unten fasst die für jede Ressource gültigen Berechtigungen zusammen:

Ressource | Berechtigungen
--------- | --------------
Server | LIST, EDIT, CLONE, START, STOP, OPEN_VNC
Laufwerk | LIST, EDIT, CLONE, ATTACH
IP, VLAN, Firewall Policy | LIST, EDIT, ATTACH
ACLs werden auf Tags gewährt und gelten für alle von diesen Tags markierten Ressourcen. Eine ACL kann an mehrere Tags angehängt werden und gilt für die Menge aller von diesen Tagen markierten Ressourcen. Es ist auch möglich, mehrere ACLs auf einem Tag zu haben, in dem Fall sind die Berechtigungen der Ressourcen, die von diesen ACLs regelt, die Kombination aller ACL-Regeln. Jede ACL kann einen oder mehrere Benutzer empfängern haben. Jede ACL-Objekt hat eine Liste von Regeln, die angibt, welche Berechtigungen durch die ACL gewährt werden. Berechtigungen sind nicht übertragbar an Dritte, d.h. wenn Sie Berechtigung jemandem gewähren, können sie diese nicht einem dritten Benutzer gewähren. Nur Besitzer können Berechtigungen gewähren.

i.e. wenn Sie einer Person die Erlaubnis gewähren, kann diese diese nicht einem dritten Benutzer gewähren. Nur Eigentümer können Erlaubnisse gewähren. Berechtigungen auf Ressourcen, die an einen Server angehängt sind
Beim Aktualisieren eines anderen Benutzers Servers sollen die angehängten Ressourcen, wie z.B. Laufwerke, IPs, VLANs oder Firewall-Politiken, verfügbar sein. Das bedeutet, dass entweder die angehängte Ressource vom Server-Besitzer besitzt oder dem Besitzer die ATTACH-Berechtigung auf der angehängten Ressource erteilt wird. Zum Beispiel, wenn Benutzer A dem Benutzer B ein Server mit EDIT-Berechtigung teilt, und Benutzer B sein Laufwerk dem Server anhängen möchte, muss Benutzer B die ATTACH-Berechtigung auf dem Laufwerk gewähren, damit der Besitzer des Servers es starten kann. Versuchen Sie, ein Laufwerk anzuhängen, auf dem es keine Berechtigung für den Server-Besitzer gibt, wird zu einem Fehler führen.

Statuses der Abonnements:
aktiv: Ein Abonnement, das derzeit verwendet wird, entweder weil die aktuelle Zeit zwischen seinem Start- oder Enddatum liegt oder weil es sich um das Abonnement für verbrauchbare Ressourcen (Verkehr) handelt, das derzeit verwendet wird. inaktiv: Ein Abonnement, das derzeit nicht verwendet wird, entweder weil es noch nicht aktiv ist oder weil für verbrauchbare Ressourcen (Verkehr) ein anderes Abonnement verwendet wird. abgelaufen: Ein Abonnement, das abgelaufen ist oder das aufgebraucht ist.

Aufruf:
GET /abonnements/

Beschreibt den Abonnementsliste des Benutzers.
param status: filtert nur Abonnements in diesem Status. Kann ein von aktiv , inaktiv, abgelaufen, all, nichtabgelaufen sein. Standard ist all. param Ressource: eine Liste (kommas getrennt) von Ressourcen. Eine oder mehrere von: dssd, cpu, mem, tx, ip, vlan. statuscode 200: kein Fehler

Erweitert das Abonnement. Ein erweitertes Abonnement ist tatsächlich nur eine weitere Unterabskription, die auf das Original verlinkt ist.
Wenn in der Anfrage eine Periode oder ein Ende_zeit angegeben sind, werden sie verwendet. Wenn beide nicht angegeben sind, wird die Erstellungszeit des Abonnements verwendet. Ein Hinweis hierbei ist, dass ein Abonnement, das ursprünglich mit einem Ende_zeit erstellt wurde, genau diesen Zeitraum verwendet. Abonnements, die mit einer Periode erstellt wurden, werden erneut im Kontext des neuen start_zeit geparst. Ein Beispiel wäre ein Abonnement, das am 1. Februar erstellt wurde mit einer Periode von ‘1 Monat’, wird erweitert für 31 Tage, aber das, das am 1. März erstellt wurde, wird erweitert für 28 Tage. Wenn die angegebene Unterabskription tatsächlich erweitert wurde, wird sie durchsucht und die letzte Unterabskription in der Kette erweitert.

Extending the subscription:
POST /subscriptions/{id}/action/?do=extend
Status Codes: 200 OK – no error
Extends the subscription. An extended subscription is actually just another subscription that is linked to the original. If a period or an end_time are specified in the request, they are used. If neither are specified, the creation length of the subscription is used. A caveat to this is that a subscription created initially with an end_time, the exact interval is used. Subscriptions that are created with a period have the period parsed again in the context of the new start_time. An example would be a subscription created on the 1st of February with a period of ‘1 month’ will be extended for 31 days, but one that was created with an end date of 1st of March will be extended for 28 days. If the specified subscription has actually been extended, it traverses and extends the last subscription in the chain.

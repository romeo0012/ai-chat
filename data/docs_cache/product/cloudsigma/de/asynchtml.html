Asynchrone Server-Authentifizierung 📄
Um den asynchronen Server zu nutzen, muss zuerst über die API authentifiziert werden. Dadurch erhält man einen Cookie, der für 2 Minuten gültig ist und bei der Verbindung zum Server benutzt werden muss. statuscode 200: kein Fehler
Beispielanfrage: POST /2.0/accounts/action/?do=authenticate_asynchronous HTTP/1.1
Host: api.cloudsigma.com
Accept: application/json
Authorization: Basic dGVzdHVzZXJAY2xvdWRzaWdtYS5jb206dmJudmJu

Beispielantwort: HTTP/1.0 200 OK
Content-Type: application/json; charset=utf-8
Set-Cookie: async_auth=YTlhZmMwYTctOWYzNi00ZmUzLThlYmUtMGZiOGZlODE0ZmQx|1356012032|f785e3d8083c7666209e54477652de0d057f0791; expires=Thu, 20-Dec-2012 14:02:32 GMT; Max-Age=120; Path=/ {}

Mit diesem Cookie kann man sich dem Server bei /2.0/websocket verbinden.

Informationen 📄
Der Websocket-Server sendet Frames jedes Mal, wenn einer der folgenden Änderungen erfolgt: Abonnements, Fahrzeuge, Server/VMs, Netzwerk, Belastung, Profil, Aufgaben
Der Frame ist ein JSON-Objekt, das die folgenden Felder enthält:

  • resource_type: Ein Textfeld, das die Art des betroffenen Ressourcen beschreibt.

* resource_uri: Die URI des Ressourcen, die geändert wurde.
Das JSON-Objekt kann ein 'object'-Feld enthalten, das die vollständige Ressource enthält, die durch die Benachrichtigung referenziert wird, JSON-kodiert.

Hochladen oder Herunterladen von Laufwerksbildern 📁
Hochladen eines Laufwerksbilders 📁
POST https://direct.{loc}.cloudsigma.com/api/2.0/drives/upload/ 🌐
Ein Laufwerksbild kann über eine POST-Anfrage mit dem Bild hochgeladen werden, indem Sie auf /drive/upload/ gesendet werden. Bemerkung: Es gibt eine andere Domain-Endpunkt für die Uploads (direct.{loc}.cloudsigma.com). Derzeit werden nur raw-Laufwerksbilder unterstützt. Die Anfrage sollte den rauen Byte-Stream des Laufwerksbilds enthalten und den richtigen Inhaltstyp (Content-Type: application/octet-stream) in den Anfrageköpfen angeben. Die Laufwerkshochlade-API unterstützt nur die Basis-HTTP-Authentifizierung. Es ist sehr wichtig, dass Content-Length die korrekte Größe der zu sendenden Daten enthält, denn sie bestimmt die Größe des zu erstellenden Laufwerks. Bemerkung: Wenn das hochgeladene Bild kleiner als der Mindestgröße des Laufwerks (Überprüfen der Fähigkeiten) ist, wird es automatisch beim Upload-Abschluss auf die Größe des Laufwerks angepasst. Es ist möglich, den Dateinamen in dem Pfad anzugeben, also das Bild an den Pfad /drive/upload/file_name hochzuladen, aber der Dateiname wird ignoriert. Dies macht es leichter, Tools wie curl zu verwenden, die normalerweise an einen Pfad mit dem Namen der Datei hochladen. Die zurückgegebene Antwort enthält die UUID des erstellten Laufwerks. Hier ist ein Beispiel, wie ein Laufwerksbild hochgeladen werden kann, indem Sie curl verwenden:

curl --request POST --user email@example.com:password \
--header 'Content-Type: application/octet-stream' \
--upload-file /path/to/file \
https://direct.zrh.cloudsigma.com/api/2.0/drives/upload/

upload ein Drive-Bild mit curl: 

curl --request POST --user email@example.com:password \
--header 'Content-Type: application/octet-stream' \
--upload-file /path/to/file \
https://direct.zrh.cloudsigma.com/api/2.0/drives/upload/

Beachten Sie, dass die Angabe des Content-Type-Headers auch curl dazu veranlasst, den Inhalt der Anfrage nicht zu kodieren und sie als Octet-Stream zu lassen. Die Befehlsgabe gibt die UUID des hochgeladenen Bildes aus. Sie möchten möglicherweise die UUID in eine Datei schreiben, indem Sie am Ende des Befehls > uploaded_drive_uuid anhängen. Standardmäßig zeigt curl keine Upload-Fortschrittsanzeige an. Sie können die –verbose (-v) Option hinzufügen, wenn Sie curl auf der Befehlszeile verwenden, um die Fortschritts- und Übertragungsgeschwindigkeit des Uploads zu drucken.

Um ein Drive-Bild herunterzuladen:
GET https://direct.{loc}.cloudsigma.com/api/2.0/drives/{uuid}/download/

Um ein Drive-Bild herunterzuladen, sollte ein GET-Anforderung an /drives/{uuid}/download/ gestellt werden. Beachten Sie, dass es für den Bilder-Download einen anderen Domain-Endpunkt gibt: direct.{loc}.cloudsigma.com. Der Download-Client sollte HTTP-Leitungen korrekt behandeln. Das Ergebnis ist ein Content-Type: application/octet-stream-Datei. Der Dateiname wird in der Content-Disposition-Header auf die UUID des Bildes festgelegt. Hier ist ein Beispiel, wie ein Drive-Bild mit curl heruntergeladen werden kann: 

curl --location \
--remote-name --remote-header-name \
--user email@example.com:password \
https://direct.zrh.cloudsigma.com/api/2.0/drives/{uuid}/download/

Beispiel, wie man eine Laufwerksbilddatei mithilfe von curl herunterladen kann:

curl --location \
--remote-name --remote-header-name \
--user email@beispiel.de:passwort \
https://direct.zrh.cloudsigma.com/api/2.0/drives/ad64ded1-be81-454a-aa14-d7809cca93eb/download/

Die Option –location gibt curl an, um auf Umleitungen zu folgen. Der Client soll HTTP-Umleitungen folgen. Die obige Befehlslinie nutzt –remote-header-name, um die Bilddatei in eine Datei mit dem Namen wie in Content-Disposition zu speichern. Der Name in der Content-Disposition ist auf den Laufwerk-UUID festgelegt. Es ist möglich, mit der Option –output (-o) einen anderen Ausgabename/Pfad anzugeben. Achtung: –remote-header-name sollte immer mit –remote-name verwendet werden.

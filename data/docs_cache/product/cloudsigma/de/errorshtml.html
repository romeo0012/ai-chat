Fehler 🔍 Format 🔍
Wenn ein oder mehrere Fehler auftraten, werden sie dem Client in einem Objekt mit drei Feldern zurückgegeben: error_type: Der Typ des Fehlers, einer der folgenden: validation, notexist, backend, permission, database, concurrency, billing, payment error_message: Eine Beschreibung des Fehlers, der aufgetreten ist. error_point: Der Punkt, an dem der Fehler aufgetreten ist. Immer vorhanden, kann aber manchmal null sein.

Typen 🔍
Die Typen von Fehlern:

  • validation: Bei der Überprüfung der eingegebenen Daten ist ein Fehler aufgetreten. Wenn der Fehler auf ein bestimmtes Feld bezogen ist, wird der error_point gesetzt.
  • notexist: Das Objekt, das Sie versuchen zuzugreifen, existiert nicht.
  • backend: Es gab ein Problem beim Ausführen der Anfrage auf dem Backend. Bitte kontaktieren Sie die Support-Abteilung.
  • permission: Sie haben keine Berechtigung, die Operation auszuführen. Kann der error_point gesetzt werden.
  • database: Es gab ein Datenbank-Fehler.
  • concurrency: Es gab ein Konflikt durch zwei gleichzeitig konkurrierende Operationen (z.B. versuchen Sie, einen Server gleichzeitig zu starten und zu löschen). Die Operation soll erneut ausgeführt werden.
  • billing: Es gab ein Rechnungsproblem.
  • payment: Es gab ein Problem bei der Bearbeitung Ihrer Zahlung.

Beispiel 🔍
POST /subscriptions/

Beispielanfrage:
{
"amount": "1",
"from_time": "2012-03-28T14:10:15.948157",
"period": "2 weeks"
}

Beispielantwort:
[
{
"error_message": "Dieses Feld ist erforderlich",
"error_point": "resource",
"error_type": "validation"
}
]

Server-Netzwerk-Schnittstellen 🔍 Privat und Öffentliche Netzwerk-Schnittstellen 🔍 Es gibt drei Konfigurationen für jede einzelne Schnittstelle, die bestimmen, wie diese Schnittstelle verhält sich. Nicht alle Kombinationen der Konfiguration sind gültig:

vlan: Privates Netzwerk
ip_v4_conf: Öffentliches IP v4-Netzwerk, entweder statisch, DHCP oder manuell zugewiesen.
ip_v6_conf: Öffentliches IP v6-Netzwerk, entweder statisch, DHCP oder manuell zugewiesen.

Ergebnisse
vlan ip_v4_conf ip_v6_conf
True True True Fehler: Es kann auf einer Schnittstelle keine alle Konfigurationen zugewiesen werden
True True False Fehler: Es kann auf einer Schnittstelle beide private und öffentliche Konfigurationen nicht zugewiesen werden
True False True Fehler: Es kann auf einer Schnittstelle beide private und öffentliche Konfigurationen nicht zugewiesen werden
True False False Privates Netzwerk zugewiesen Fehler: Es kann auf einer Schnittstelle beide private und öffentliche Konfigurationen nicht zugewiesen werden
True False False Keine Konfiguration zugewiesen

Zuweisung von IPs für Öffentliche Schnittstellen 🔍 Die Zuweisung von IPs auf privaten Netzwerk-Schnittstellen ist der Benutzer vorbehalten. Für öffentliche Netzwerk-Schnittstellen ist es möglich, die Art der Zuweisung zu konfigurieren, indem man das “conf”-Attribut auf dem ip_v4_conf- oder ip_v6_conf-Objekt setzt:

"dhcp": Die Adresse wird vom System bei der Startzeit ausgewählt und über DHCP zugewiesen. Bei jedem Neustart kann das VM eine andere Adresse erhalten. Es ist ein Fehler, die IP-Adresse für “conf” zu setzen: “dhcp”. Es ist möglich, die derzeit zugewiesene dynamische IP-Adresse eines NICs vom Server-Runtime eines laufenden Servers abzurufen.
{ "ip_v4_conf": { "conf": "dhcp" } }

"static": Die Adresse wird vom Benutzer ausgewählt und festgelegt.

Notiz: Die oben genannten Konfigurationen gelten nur für Linux-Systeme. Für andere Systeme können die Konfigurationen unterschiedlich sein.

Ein laufender Server. { "ip_v4_konfiguration": { "konfiguration": "dhcp" } } “statisch”: Die Adresse wird vom Benutzer gewählt und angegeben. Sie wird der NIC über DHCP zugewiesen und bleibt zwischen Neustartungen unverändert. Das “ip”-Attribut ist vorgeschrieben und eine IP-Adresse kann von den von dem Benutzer besitzenden Adressen zugewiesen werden. { "ip_v4_konfiguration": { "konfiguration": "statisch", "ip": "94.26.101.182" } } “manuell”: Für die NIC wird keine Adresse angegeben, und der Benutzer muss die IP-Adresse innerhalb der VM angeben. Wenn diese Einstellung verwendet wird, ist der NIC die Nutzung aller IPs erlaubt, für die der Benutzer eine Abonnement hat. Diese “konfiguration” kann verwendet werden, um mehrere IPs der gleichen NIC zuzuweisen. { "ip_v4_konfiguration": { "konfiguration": "manuell" } }

Hinweis: Die Cloud-Firewall erlaubt keinen Datenverkehr zu/von IPs, die nicht dem VM gehört oder nicht zugewiesen sind. Die einzige Ausnahme ist für die “manuell” konfigurierte Konfiguration, bei der der VM jede IP zugewiesen werden kann, die dem Benutzer gehört (der Benutzer hat ein Abonnement für sie). MAC-Adressen
Neu erstellte NICs haben ihre MAC-Adresse zufällig generiert.

Hinweis: Alle Datenverkehr von einer MAC-Adresse, die nicht vom System zugewiesen wurde, wird von der Cloud-Firewall blockiert, sodass Benutzer keine Versuche unternehmen sollten, ihre MACs innerhalb ihrer VM zu ändern. Um eine NIC-Definition zu aktualisieren, muss die Definition ihr “mac”-Attribut gefüllt haben. Wenn in der “nics” Liste eine MAC-Adresse entfällt, wird die entsprechende NIC gelöscht.

Attribute gefüllt. Wenn auf der Liste "nics" ein MAC-Adresse verschwindet, wird die entsprechende NIC gelöscht. Wenn eine MAC-Adresse in der neuen Liste auftaucht, wird die entsprechende nic aktualisiert, und wenn keine MAC-Adresse auf einer NIC angegeben ist, wird eine neue NIC erstellt. Es ist ein Fehler, eine MAC-Adresse anzugeben, die nicht zuvor auf der Liste "nics" war. Die Reihenfolge der NICs im Attribut "nics" ist wichtig, weil sie auch die Reihenfolge ist, in der NICs dem VM präsentiert werden. Es ist möglich, die NICs zu rearrangieren, indem man ihre Reihenfolge in der "nics" Liste ändert.

NIC Modelle 📄
Das Attribut "model" gibt die Art des emulierten Netzwerkkarten an. Es wird empfohlen, virtio, sofern möglich (wenn virtio-Treiber für das VM-Betriebssystem verfügbar sind), zu verwenden.

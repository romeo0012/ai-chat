PHP-Session-Klustering Das hohe Verfügbarkeitsniveau Ihrer PHP-Anwendung kann durch die Implementierung von PHP-Session-Klustering in der Cloud erreicht werden. Um den Fallback der Anwendungsserver erfolgreich zu bearbeiten, richten wir eine Umgebung mit Memcached, mehreren Apache-Servern und einem NGINX-Load Balancer ein:

  1. Melden Sie sich bei Ihrem PaaS-Konto an.
  1. Klicken Sie auf den Schaltflächen "Umgebung erstellen".
  1. Wählen Sie im Fenster "Umgebungstopologie" zwei oder mehr Server aus (z.B. zwei Instanzen von Apache) und einen Memcached-Knoten aus. Geben Sie einen Namen für die Umgebung ein und klicken Sie auf "Erstellen". Der Memcached-Knoten wird als verteilter Speicher in der Umgebung mit mehreren Knoten verwendet. In unserem Fall dient er als Web-Session mit dem Sticky-Sessions auf mehreren Anwendungsservern laufend. Wenn ein Server ausfällt, werden die Sessions für den Backup auf dem Memcached-Knoten gespeichert. Die anderen Server können die Sessions aus dem Memcached holen und die Session starten.

Wie es funktioniert:
Bei jedem abgeschlossenen Session-Anforderung wird die Session auf den Memcached-Knoten gespeichert, um als Backup zu dienen. Diese Session bleibt auf dem ursprünglichen Anwendungsserver verfügbar und kann für die nächste Anforderung verwendet werden. Nach der zweiten Anforderung wird die Session in Memcached aktualisiert. Wenn der ursprüngliche Server ausfällt, wird die nächste Anforderung an einen anderen Anwendungsserver weitergeleitet. Der neu angeforderte Server fragt nach der Session, die er nicht kennt. Somit sucht dieser neue Server die benötigte Session im Memcached-Knoten.

Routed auf ein weiteres Anwendungsserver. Der neu angeforderte Server wird für die Session, die er nicht kennt, angefragt. Somit sucht dieser neue Server die benötigte Session im Memcached-Knoten nach. Diese wird gemäß dem angehängten ID an der SessionID bei der Sessionerstellung identifiziert. Dadurch kann der Server die Session aus dem Memcached-Knoten holen. Wenn der Server auf die Anfrage antwortet, aktualisiert er auch die Session im Memcached-Knoten. Dadurch entsteht kein Abbruch der App durch den Ausfall des ursprünglichen Servers - der Fallover wird erfolgreich abgearbeitet. Gleichzeitig verteilt der NGINX-Load Balancer den Verkehr über die Cluster enthaltenden HTTP-Ressourcen. Sie können die Lastverteilung auf der Plattform über verschiedene Lastverteilungswerkzeuge überprüfen.

  1. Navigiere in dein Umgebung im Dashboard und klicke auf den Config-Button für Apache.
  1. Öffne im neuen Fenster die Datei etc > php.ini.
  1. Füge die folgende Zeile zur Dynamic Extensions hinzu: 1 extension=memcached.so
  1. Führe die Änderungen im [Session] Block durch:

1. 2. session.save_handler = memcached
2. session.save_path = "< server >:11211"
Hinweis: <server> steht für die IP oder URL des Memcached-Knotens, die Sie durch Klicken des Info-Buttons für den Memcached-Knoten in Ihrer Umgebung finden können.
  1. Speichere die Änderungen und starten Sie den Apache-Knoten neu. Das ist alles!

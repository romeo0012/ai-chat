Kubernetes-Cluster-Zugriff Nach erfolgreicher Installation eines Clusters stehen mehrere Möglichkeiten zur Verfügung, um ihn zu verwalten: Kubernetes-Dashboard, kubectl-Client, Kubernetes-Dashboard

  1. Die nach der Installation erscheinende Popup bietet alle notwendigen Daten, um mit dem Kubernetes-Dashboard verbunden zu werden - Link und Zugriffstoken. Dieselben Informationen werden auch über die passende E-Mail-Benachrichtigung bereitgestellt.
  1. Folge dem Link, wähle die Option Token und füge den erforderlichen Wert ein. Tip: Es ist auch möglich, mithilfe des kubeconfig-Datei zu loggen, jedoch benötigen Sie die Installation von kubectl und die richtige Kontext-Einstellung (siehe untenstehende Abschnitt).
  1. Wenn Sie eine E-Mail mit dem Zugangstoken zum Kubernetes-Cluster verloren haben, können Sie diesen durch Ausführen der folgenden Befehl auf dem Master-Knoten (z.B. über Web SSH) anzeigen:

1. kubectl -n kube-system describe secret $(kubectl -n kube-system get secret | grep fulladmin | awk '{print $1}') | grep 'token:' | sed -e's/token:\| //g'

Jetzt können Sie das Kubernetes-Dashboard erneut zugreifen.

kubectl-Client
kubectl ist ein Befehlszeilentool, um einen Kubernetes-Cluster zu steuern. Die Plattform installiert es automatisch auf allen Master-Knoten während der Umgebungskreation. Sie können sofort mit Ihrem Cluster arbeiten, indem Sie sich über SSH auf den erforderlichen Knoten verbinden.

  1. Folgen Sie den Installationsschritten, um ein lokales kubectl zu verwenden.

Sie können Ihre Arbeit mit Ihrem Cluster sofort mit kubectl beginnen, indem Sie sich über SSH auf den erforderlichen Knoten verbinden.

  1. Folgen Sie den Installationsschritten, um lokal kubectl zu verwenden. Anschließend führen Sie den folgenden Befehl aus, um eine remote Verbindung herzustellen:

1 2 3 4 5 
kubectl config set-cluster jelastic --server={api-endpoint} &amp;&amp; \
kubectl config set-context jelastic --cluster=jelastic &amp;&amp; \
kubectl config set-credentials user --token={token} &amp;&amp; \
kubectl config set-context jelastic --user=user &amp;&amp; \
kubectl config use-context jelastic

Ersetzen Sie die Platzhalter {api-endpoint} und {token} durch die Remote-API-URL und den Zugriffstoken entsprechend. Tip: Wenn Sie den Remote-API nicht während der Installation aktiviert haben, kann er über den in-built Add-on aktiviert werden, der für die Master-Knoten im Plattform-Dashboard verfügbar ist.
  1. Sie können über den folgenden Befehl überprüfen, ob kubectl auf die Clusterzugriff hat:

1 
kubectl get pods

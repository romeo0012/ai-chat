Automatische Konfigurationen für PHP-Anwendungsserver
Die dynamische Ressourcenoptimierung ergänzt die Grundimplementierung, die von PHP-Servern bereitgestellt wird, um die maximale Effizienz zu erreichen. Im Wesentlichen passen die Plattform automatisch die passenden PHP-Konfigurationen an, um den neuen Bedingungen zu entsprechen, wenn die Menge der zugewiesenen RAM- und CPU-Ressourcen (Cloudlets) geändert wird. Falls jedoch erforderlich, können Sie die automatische Konfiguration deaktivieren und die Parameter manuell in der Konfigurationsdatei Ihres Servers bereitstellen.

Deaktivieren von automatischer Optimierung
Um Ihre eigenen Werte stattdessen als Ersatz für die automatisch konfigurierten Direktiven anzugeben, müssen Sie die automatische Optimierung deaktivieren. Andernfalls werden Ihre eigenen Änderungen während des Containerneustart/Update zurückgesetzt.

Konfigurierte Direktiven benötigen Sie, die automatische Optimierung auszuschalten. Andernfalls werden Ihre persönlichen Änderungen während des Neustart oder Updates des Containers zurückgesetzt. Tip: Sie können die Variablen PHP_MEMORY_LIMIT und PHP_MAX_EXECUTION_TIME verwenden, um den PHP-Speicherlimit und die maximale Ausführungszeit ohne die automatische Optimierung festzulegen. Smart Auto-Configuration Wenn Sie irgendwelche der automatisch konfigurierten Einstellungen manuell ändern möchten, müssen Sie die Umgebungsvariable JELASTIC_AUTOCONFIG auf false (deaktiviert) festlegen. Apache
PHPDynamic request handling in Apache PHP wird mit Hilfe des prefork Multi-Processing Modules (MPM) implementiert, das helfen kann, die vollständige Serverleistung zu entdecken. Die MPM-Direktiven sind in der Hauptkonfigurationsdatei von Apache, /etc/httpd/conf/httpd.conf, aufgelistet. Hier ist eine vollständige Liste der Parameter, die die Plattform für den prefork-Modul konfiguriert:

  • StartServers - setzt die Anzahl der Kind-Serverprozesse, die auf Startup erstellt werden.
  • MinSpareServers (MaxSpareServers) - definiert die minimale (maximale) Anzahl von Serverprozessen, die als Reserve gehalten werden.
  • ServerLimit - setzt den höchsten zulässigen Wert für den MaxRequestWorkers-Direktiv.
  • MaxRequestWorkers - konfiguriert den Limit für gleichzeitig zu bearbeitende Anfragen.
  • MaxConnectionsPerChild - definiert die Anzahl der Anfragen, die ein einzelner Kindprozess bearbeiten kann.

Basierend auf den verfügbaren Ressourcen (z.B., eine Anzahl dynamischer Cloudlets, die dem Apache PHP-Server reserviert wurden) und der Leistungsfähigkeit des CPUs, den Ihrer speziellen Hosting-Anbieter bereitstellt, wird die ServerLimit und MaxRequestWorkers-Parameter automatisch angepasst: MaxRequestWorkers = ServerLimit = min( {containerRam} / 30MiB, {coresCount} * 5 )
Durch diese Aussage sind beide Direktiven gleichgestellt mit dem niedrigeren Wert zwischen: dem an der Node zugeordneten Speicherplatz, geteilt durch 30 und der Anzahl der Physikserver-Kerne des Hosters, auf dem der Container platziert ist, multipliziert mit 5
In diesem Weg werden die Parameter dynamisch angepasst, basierend auf der Anzahl der zugeordneten Cloudlets, aber sie wachsen nicht über die Hardware-Grenzen hinaus. Hinweis: Wenn Sie Ihre eigenen Werte für diese Direktiven festlegen möchten, sind Sie darauf aufmerksam, dass falsche Werte Ihren Apache PHP-Server instabil machen können: Wenn ServerLimit viel höher ist als nötig, wird unbenutztes geteiltes Speicherplatz zugeordnet; während ein zu niedriger angegebener Wert das volles Serverleistungspotenzial nicht offenbart. MaxRequestWorkers soll groß genug sein, um so viele gleichzeitige Anfragen zu bearbeiten, wie Sie erwarten, und klein genug, um sicherzustellen, dass es genügend Speicherplatz gibt. Die Verarbeitung von PHP-Anforderungen im NGINX PHP Anwendungserver wird von FastCGI Process Manager (FPM) verwaltet, der über die Konfigurationsdatei /etc/php-fpm.conf konfiguriert werden kann. Er wird automatisch in die bevorzugten Listen des Container-Dateimanagers aufgenommen, um schnell zugreifen zu können: Der FPM arbeitet im ondemand-Modus (durch die pm-Direktive) standardmäßig. Er erzeugt neue Prozesse, wenn sie benötigt werden (also auf Anforderung) und entfernt inaktive Prozesse. Die einzigen zusätzlichen Parameter für diesen Modus sind:

  • pm.max_children - definiert die maximale Anzahl an Kindprozessen (gleich der Anzahl an verfügbaren CPU-Kernen für den Container, aber mindestens 2)
    Tip: Der genaue Wert hängt von der CPU-Leistung Ihres speziellen Hosting-Anbieters und der Anzahl der zugewiesenen Cloudlets für Ihren Container ab. Dadurch, dass die Cloudlet-Anzahl vergrößert wird, wächst automatisch auch der Wert von pm.max_children. Dieser Direktivwert kann explizit definiert werden, ohne die automatische Optimierung durch die entsprechende PHPFPM_MAX_CHILDREN-Variable auszuschalten.
  • pm.process_idle_timeout - setzt den Verzögerungswert, bevor ein inaktiver Prozess getötet wird (60 Sekunden)

Zusätzlich erzielt die PHP FPM-Listener durch die Verwendung der UNIX-Domain-Sockets statt der allgemeinen TCP-Sockets einen Leistungsgewinn. Diese Lösung ist besser geeignet für Kommunikation innerhalb desselben Hosts, da sie die Überprüfungen und Operationen (wie Routing) auslassen kann.

WildFly Anwendungserver

WildFly ist ein modernes, flexibles, leichtes und verwaltetes Anwendungs-Runtime, das in Java geschrieben ist und die neuesten Standards und Technologie der Java-Plattform Enterprise Edition (Java EE) Spezifikation umsetzt. WildFly ist vollständig kostenlos und open source und kann auf mehreren Plattformen ausgeführt werden. Zu den Hauptmerkmalen dieses Anwendungservers gehören: ein benutzerdefinierter Laufzeitumfang basierend auf den erweiterbaren Subsystems, die auf Anforderung integriert oder entfernt werden können; Unterstützung von Java EE8, um die neuesten Java-Enterprise-Standards in einer einfach zu nutzenden Rahmenwerk-Ansatz mit der Fähigkeit zu starten, jeden Dienst isoliert, schnell, leicht und optimiert für die maximale Leistung;

Um einen WildFly-Anwendungserver für ein Java-Projekt innerhalb der Plattform zu erstellen, folgen Sie den einfachen Schritten unten. Hinweis: Dieses Template nutzt ein modernes systemd-Initialisierungs-Daemon.

Erstellen Sie einen WildFly-Server

  1. Melden Sie sich bei Ihrem PaaS-Konto an und klicken Sie auf den New Environment-Button in der oberen linken Ecke der Dashboard.
  1. In dem umgebungstopologiewizard, das sich öffnet, navigieren Sie zum Java-Tab und wählen Sie WildFly (die 10-16 Versionen werden unterstützt) aus der Liste der verfügbaren Anwendungserver aus. Anschließend legen Sie die zugewiesenen Ressourcenbegrenzung mittels cloudlet-Schaltern fest, wählen Sie eine Region (wenn mehrere verfügbar sind) und bearbeiten Sie den Namen Ihrer Umgebung.

Der WildFly-Anwendungserver wird standardmäßig im „standalone“-Modus betrieben, sodass jede Instanz ein unabhängiger Prozess basierend auf der Konfigurationsdatei ist, die über die STANDALONE_MODE_CONFIG-Umgebungsvariable definiert wird. Es gibt vier zertifizierte Profile für den standalone-Modus: standalone.xml (Standard) - Konfigurationen für Java Enterprise Edition 8 Web mit den erforderlichen Technologien, standalone-full.xml - Konfigurationen für Java Enterprise Edition 8 Full mit allen EE 8-Technologien, standalone-ha.xml - Konfigurationen für Java Enterprise Edition 8 Web mit hoher Verfügbarkeit, standalone-full-ha.xml - Konfigurationen für Java Enterprise Edition 8 Full mit hoher Verfügbarkeit. Wenn Sie die HA-Konfigurationen verwenden (die letzten beiden Optionen), wird das jgroups-Protokoll für die Kommunikation zwischen Knoten verwendet. Es wird standardmäßig konfiguriert, um die Authentifizierung mit dem MD5-Token und asymmetrischer Verschlüsselung zu verwenden. Dadurch wird es verhindert, dass nicht autorisierte Knoten in einem Cluster beitreten können und nicht Mitglieder mit Clustermitgliedern kommunizieren können. Hinweis: Es wird empfohlen, den standardmäßigen auth_value-Parameter in Ihrer standalone HA-Konfigurationsdatei auf den Produktionsumgebungen zu ändern.

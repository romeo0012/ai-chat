Bereitstellungsführung
Das Plattform unterstützt mehrere Möglichkeiten der automatischen Bereitstellung von Anwendungen, sodass Sie die passende Option wählen können, die Ihre spezifischen Anforderungen erfüllt:

Dashboard - entspricht der Bereitstellung über ein Archiv (bzw. lokales Datei oder URL)
VCS - ermöglicht die Bereitstellung aus Ihrem VCS-Repository (z.B., Git, SVN, Bitbucket)
Hub Registry - erstellt ein benutzerdefiniertes Container-Image mit Ihrer Anwendung basierend auf dem Docker-Image, das in Ihrer öffentlichen oder privaten Registry gespeichert ist

Weitere Informationen zu den letzten beiden Optionen finden Sie bitte über die entsprechenden Links, während in dieser Führung die Bereitstellung über ein Archiv und ein VCS-Repository beschrieben werden. Sie können sie entweder aus dem Bereitstellungsmanger oder indem Sie über das Bereitstellungsprotokoll zeigen und auf das entsprechende Schaltflächen klicken. Die ersten beiden Symbole (Lokale Datei und URL) entsprechen der Bereitstellung über ein Archiv und das letzte (Git / SVN) - der Bereitstellung aus dem VCS-Repository. Wählen Sie die passende Option und klicken Sie darauf, um mit Ihrer Bereitstellungskonfiguration fortzufahren.

Hinweise: Die Bereitstellungstypen für Java-Anwendungssysteme werden mit Hilfe des Maven-Build-Knotens durchgeführt. Weitere Details finden Sie bitte im verlinkten Führungsdokument.
Die .NET-Bereitstellung für den Windows-basierten IIS-Anwendungssystem ist anders als die in dieser Führung beschriebene standardisierte Ablaufreihe.

Archiv-Bereitstellungskonfigurationen
Der Prozess ist extrem einfach und kann innerhalb von nur wenigen Sekunden gestartet werden, indem Sie zwei Hauptparameter festlegen (z.B.):

  • Archivdatei: Die Datei, die Sie bereitstellen möchten
  • Archivtyp: Der Typ des Archivs (z.B. zip, tar.gz)

Sie können die Bereitstellungskonfiguration über das Bereitstellungsmanger oder indem Sie auf das entsprechende Schaltflächen klicken.

Wenn notwendig, können Sie den bereits bereitgestellten VCS-Projekt anpassen, indem Sie den Edit-Button für die passende Bereitstellung klicken. In dem geöffneten Rahmen können Sie die gleichen Parameter bearbeiten, die oben für die Bereitstellung beschrieben wurden. Beispielhaft ist es möglich, eine Branch zu wechseln, Hooks hinzuzufügen, Updates automatisch bereitstellen zu lassen, etc. Hinweis: Wenn die Zugangsdaten zum Projekt-Repository geändert wurden, müssen Sie neue bereitstellen, um weiter mit diesem Projekt zu arbeiten. Zunächst bearbeiten Sie die Authentifizierung für das Repository im Bereitstellungsmanger. Danach müssen Sie alle bereits vorhandenen Projekte aus diesem Repository bearbeiten. Ist die Bereitstellung über Archiv unterstützt für alle Programmiersprachen?
Ja, Sie können Ihre Anwendung über Archiv bereitstellen für alle unterstützten Programmiersprachen auf der Plattform (z.B., Java, PHP, Ruby, Python, Node.js, .NET, Go). Welche Archivformate sind für die Bereitstellung über Archiv unterstützt?

Unterstützt für Archiv-Bereitstellung? Die Plattform unterstützt die folgenden Archivformate für Bereitstellung über Archiv: .zip, .tar.gz, .tar.bz2, .tar, .war, .jar. Ist die Bereitstellung aus VCS für alle Programmiersprachen unterstützt?
Ja, Sie können Ihre Anwendung aus VCS bereitstellen für alle unterstützten Programmiersprachen auf der Plattform (z.B. Java, PHP, Ruby, Python, Node.js, .NET, Go). Welche Bereitstellungsmethode sollte ich wählen?
Die Wahl der Bereitstellungsmethode hängt von Ihren spezifischen Bedürfnissen ab: Wenn Sie eine bereite Anwendung in einem Archivdateiformat haben, verwenden Sie Bereitstellung über Archiv (entweder von lokaler Datei oder URL). Wenn Ihre Anwendungscode in einem Versionenkontrollsystem (z.B. Git oder SVN) gespeichert ist und Sie leicht Versionen und Updates verwalten möchten, verwenden Sie Bereitstellung aus VCS. Kann ich Bereitstellungen automatisieren?
Ja, die Plattform unterstützt die Automatisierung von Bereitstellungen. Sie können automatische Bereitstellungen für Ihre VCS-Projekte einrichten, indem Sie die Option "Check und automatisch Bereitstellen von Updates" in den Bereitstellungskonfigurationen aktivieren. Dadurch kann die Plattform periodisch nach Änderungen im Repository suchen und automatisch Updates bereitstellen, wenn Änderungen erkannt werden. Wie kann ich Downtime während Bereitstellungen vermeiden?
Um Downtime während Bereitstellungen zu minimieren oder zu vermeiden, können Sie die folgenden Optionen verwenden: Für Bereitstellungen in skalierte Server verwenden Sie die Option "Sequentielle Bereitstellung mit Verzögerung" in den "Bereitstellungsfolge"-Einstellungen.

Die folgenden Optionen: Für Bereitstellungen in skalierte Server verwenden Sie die Option "Sequentielle Bereitstellung mit Verzögerung" in den "Bereitstellungsfolge"-Einstellungen. Diese führt die Bereitstellung auf Servern einzeln mit einem festgelegten Verzögerungswert zwischen den Operationen durch, was sicherstellen soll, dass die Anwendung aufrecht bleibt. Für PHP-Server aktivieren Sie die Option "Enable zero-downtime deployment" um den Bereitstellungsfluss anzupassen, um Downtime zu vermeiden.

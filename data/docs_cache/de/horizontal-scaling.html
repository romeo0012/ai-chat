Horizontale Skalierung innerhalb der Cloud: Mehrere Knoten Mit der Plattform wird die Hosting Ihrer Anwendungen wirklich flexibel. Neben der automatischen vertikalen Skalierung ermöglicht die Plattform Ihnen auch, die Anzahl der Server in Ihrer Umgebung manuell oder automatisch erhöhen/verringern zu können. Das Prozess der manuellen Skalierung ist ziemlich einfach - öffnen Sie das Umgebungstopologie-Assistenten und verwenden Sie die passenden “+” und “-” Tasten oder geben Sie die erforderliche Anzahl in der zentralen Anzeige ein. Außerdem können Sie den Schieberegler verwenden, der automatisch erscheint, wenn Sie eine Änderung vornehmen. Tipps: Sie können die horizontale Skalierung basierend auf dem einkommenden Lastverlauf automatisieren, indem Sie die Hilfsmittel von steuerbaren Triggern nutzen. Sie können auch den initialen (Master) Knoten der Schicht als Ihrer Speicherserver für den Datenausgleich innerhalb der ganzen Schicht verwenden, falls Sie Skalierung einfahren (d.h. die Anzahl der Knoten verringern), der letzte Container, der der Schicht hinzugefügt wurde, ist der erste, der entfernt wird (außer er explizit ausgewählt wird) Danach können Sie die erforderliche Skalierungsmethode aus der passenden Dropdown-Liste auswählen. Außerdem empfehlen wir Ihnen für zusätzliche Details auf die horizontale Skalierung spezifischen Abschnitt unten zu beziehen.

Der bevorzugte Skalierungsmodus kann für neue Umgebungen während der Erstellung sowie für die vorhandenen Umgebungen in der Topologie-Assistenten ausgewählt werden: Stateless - gleichzeitig erstellt alle neuen Knoten aus der Basis-Bildvorlage
Stateful - folgerichtig kopiert das Dateisystem des Master-Container in die neuen Knoten

Die erste Option ist vergleichsweise schneller, während die zweite automatisch alle benutzerdefinierten Konfigurationen kopiert. Hiermit werden während der ersten Schicht-Erstellung alle Knoten gleichzeitig erstellt, um den Prozess zu beschleunigen (auch für den stateful-Modus, da noch keine Anpassungen vorgenommen wurden). Während des stateless-Modus beachten Sie folgende Funktionen auf den neuen Knoten innerhalb der Schicht: deployments - die vorhandenen Projektkontexte werden nicht übertragen
custom SSL - SSL-Zertifikate und Konfigurationen werden nicht kopiert
mount points - benutzerdefinierte Mounts werden nur dann verschoben, wenn das entsprechende Volumen konfiguriert ist
add-ons - auf der Schicht installierte Add-ons werden nicht verfügbar

Tip: Die Übertragung von benutzerdefinierten Dateien für den stateless-Modus kann manuell durchgeführt oder über die Cloud Scripting-Automatisierung konfiguriert werden (z.B. mithilfe der onBefore- und onAfterScaleOut-Ereignisse).

Horizontale Skalierung Besonderheiten Die Anzahl der gleichen-Typ-Servern innerhalb einer einzelnen Umgebungsschicht hängt von den Einstellungen des jeweiligen Hosting-Anbieters ab (normalerweise liegt diese Grenze bei 16 Knoten). Sie kann den genauen Wert unter Quotas & Preise > Kontaktgrenzen überprüfen. Alle neu hinzugefügten Server werden auf verschiedenen Hardware-Knoten erstellt, was eine erweiterte Zuverlässigkeit und hohe Verfügbarkeit bietet. Jede Umgebungsknotengruppe (Schicht) erhält einen dedizierten Namen, der, falls nötig, manuell angepasst werden kann. Bei mehreren Instanzen wird der Schichtname mit dem xN-Label ergänzt (wobei N die tatsächliche Knotenzahl ist). Die Synchronisierung mehrerer gleicher-Typ-Knoten innerhalb einer Schicht ermöglicht ihre gleichzeitige Verwaltung. Somit können alle Container gleichzeitig konfiguriert, die Logs und Statistiken überprüft, neu gestartet oder neu bereitgestellt werden, indem man die entsprechenden Icons verwendet. Um mit einem bestimmten Container zu arbeiten, sollte man die Schichtszeichenfolge ausbreiten, um die vollständige Liste ihrer Knoten zu sehen.

Jeder dieser Container ist eine isolierte Instanz, die eine eindeutige Knoten-ID hat und separat zugreifen und konfigurieren kann. Wenn Sie verschiedene Arten von Stacks skalieren, beachten Sie folgende Punkte: Bei der Skalierung des Anwendungsserver-Instanzbetriebssystems wird der Load Balancer-Knoten automatisch in der Umgebungsarchitektur hinzugefügt, wenn die Hochverfügbarkeit für den Anwendungsserver aktiviert wird. Das erforderliche NGINX-Load Balancer kann nicht horizontal skaliert werden (wenn vorher mehr Instanzen von NGINX verfügbar waren, werden sie automatisch auf eine einzelne Instanz reduziert). Bei der Skalierung von VPS-Knoten erhält jede Instanz eine separate öffentliche IP-Adresse. Maven ist der einzige Knoten, der horizontal nicht skaliert werden kann (da es keinen Sinn in dieser Operation gibt). Nun wissen Sie, wie leicht es ist, Instanzen in der Plattform horizontal zu skalieren und sind auf die Operationen spezifisch aufgeklärt. Sie können auch automatisch Nodes skalieren, um schnell und ohne Überbelegung von unbenutzten Ressourcen über Lastspitzen zu überwinden. Die Verwaltung von Knoten innerhalb der Schicht bietet die Plattform eine einfache Knotenverwaltung, bei der Sie nur die angeforderte Anzahl von Containern in einer Schicht angeben müssen. Dabei wird der Entfernungsprozess in umgekehrter Reihenfolge durchgeführt - also werden die neuesten Containern zuerst entfernt.

Auto-Klustering von Instanzen über Topologie-Assistent
Die Plattform bietet ein auf-Anforderung basierendes automatisches Klusterisierung für einige der verwalteten Vorlagen. Diese Automatisierung vereinfacht und beschleunigt die Erstellung eines zuverlässigen Produktionsbereitschaftsklusters für Ihr Projekt erheblich. In den folgenden Punkten werden die betrachtet: unterstützte Stack-Kombinationen (mit Klusterisierungseigenschaften) automatisches Klusterisierungsmangement Cloud-Skripting-Nutzung Vorlagen mit Unterstützung für automatisches Klusterisieren
Derzeit unterstützen die folgenden Vorlagen die neu hinzugefügte Klusterisierungsfunktion (mit zusätzlichen Stack-Kombinationen in Zukunft): Anwendungsserver - Tomcat/TomEE, GlassFish, Payara, Jenkins, WildFly SQL-Datenbanken - MySQL, MariaDB, Percona, PostgreSQL NoSQL-Datenbank - Couchbase, Redis, OpenSearch Speicherserver - Shared Storage Container Hinweis: Ihr spezifischer Dienstleister kann für einige zusätzlichen Stack-Kombinationen, die nicht in der Liste aufgeführt sind, die automatische Klusterisierung konfigurieren und implementieren.

Einrichten von Auto-Klustern mit Cloud-Skripting

Um die automatische Klustern-Einstellungen in Ihren JPS-Lösungen zu definieren, kann ein neues Cluster-Eigenschaft verwendet werden. Beispiel:

  1. Aktivieren oder deaktivieren des automatischen Klusterns für die spezifische Schicht.

1 2 "nodeGroup": "couchbase", "cluster": true | false
  1. Zusätzliche Parameter für das automatische Klustern können wie folgt bereitgestellt werden (z.B. muss ein Scheme für den Datenbank-Cluster ausgewählt werden):

1 2 3 4 "nodeGroup": "mysql", "cluster": { "scheme": "master" }
  1. Falls nötig, kann die Standard-JPS-Manifest mit den Klustern-Schritten durch ein benutzerdefiniertes ersetzt werden:

1 2 3 4 5 6 7 "nodeGroup": "mysql", "cluster": { "jps": "http://.../custom-manifest.jps", "settings": { "scheme": "master" } }
  1. Je nach den spezifischen Cluster-Anforderungen können möglicherweise Topologie-Beschränkungen erforderlich sein (z.B.):

Basierend auf den spezifischen Cluster-Anforderungen können möglicherweise Topologie-Beschränkungen erforderlich sein (z.B.):

"settings": { "scheme": "master" } }

  1. Je nach den spezifischen Anforderungen des Clusters können bestimmte Topologiebeschränkungen erforderlich sein (z.B., die Mindest-/Maximanzahl von Knoten, Skalierungsmodus usw.).

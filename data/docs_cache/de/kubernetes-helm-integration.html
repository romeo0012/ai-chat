Kubernetes-Cluster: Helm-Integration

Kubernetes bietet mehrere Optionen zur Bereitstellung von Anwendungen. Eine der häufigsten Methoden ist es, den Helm-Paket-Manager zu verwenden. Wenn Sie in Ihrem Kubernetes-Cluster eine beliebte oder relativ bekannte Lösung ausführen möchten, ist es wahrscheinlich, dass sie als vorkonfigurierter Paket befindlich ist und innerhalb von Minuten installiert werden kann. Helm hilft Ihnen, Kubernetes-Anwendungen aus ferngesteuerten Repositories sowie lokale Helm-Charts zu installieren. Helm ist auf allen Control-Plane-Knoten des Kubernetes-Clusters standardmäßig verfügbar und benötigt keine zusätzliche Konfiguration. Nur verbinden Sie sich mit dem Knoten (z.B. über Web SSH), und Sie können mit Helm arbeiten. Die Paketmanager-Version wird während der Upgrades des Kubernetes-Clusters automatisch aktualisiert. Helm arbeitet mit drei großen Konzepten: Eine Chart ist ein Helm-Paket, das alle notwendigen Ressourcendefinitionen enthält, um eine Anwendung, Werkzeug oder Dienst innerhalb eines Kubernetes-Clusters auszuführen. Ein Repository ist ein Ort, an dem Charts gesammelt und geteilt werden können. Eine Release ist eine Instanz einer Chart, die in einem Kubernetes-Cluster läuft. Eine Chart kann mehrfach in derselben Cluster installiert werden (mit einem eigenen eindeutigen Release-Namen), z.B. mehrere Datenbankinstanzen. Helm installiert Charts in Kubernetes, wodurch für jede Installation eine neue Release erstellt wird. Um neue Charts zu finden, können Sie Helm-Chart-Repositories durchsuchen.

In Kubernetes, die Erstellung einer neuen Release-Version für jede Installation erfolgt. Um neue Charts zu finden, können Sie die Helm-Chart-Repositorys durchsuchen. In diesem Leitfaden werden alle wichtigen Schritte bei der Arbeit mit Helm abgedeckt: Suche nach Charts und Arbeit mit Repositorys, Installation neuer Helm-Anwendungen, Verwaltung von bestehenden Anwendungen. Tip: Helm ist nicht nur für seine vorbereiteten Lösungen, sondern auch als Versionierung- und Standardisierungswerkzeug für Projektentwicklung nützlich. Zunächst, wenn Sie an einem kleinen Projekt arbeiten, reicht die skriptbasierte Bereitstellung für Ihre Anforderungen aus. Es kann jedoch schnell an Komplexität gewinnen, was mehr und mehr Anpassungen an Ihre YAML-Dateien erfordert. Beispielsweise erfordert auch die Bereitstellung in Staging- und Produktionsumgebungen Anpassungen wie Datenbank-URLs. In einem bestimmten Moment können Sie möglicherweise denken, dass es schwer ist, die Wechselwirkung und Abhängigkeiten der Komponenten zu verfolgen. Normalerweise bedeutet dies, dass die Komplexität Ihrer Umgebung Ihren eigenen Bereitstellungsskripts übersteigt. In solchen Fällen kann es eine gute Zeit sein, Helm als potenzielles Lösungskandidat in Betracht zu ziehen, das Ihre Heimgeschriebenen Skripte ersetzen könnte. Außerdem können Sie mit benutzerdefinierten Repositorien arbeiten. Helm kommt mit einer mächtigen helm search Befehl, der auf zwei verschiedene Quelltypen verwendet werden kann: helm search hub sucht den Artifact Hub (gemeinschaftliches Helm-Chart-Repository der Community), das helm-Charts aus mehreren Repositorien listet. Beispielhaft können Sie alle öffentlich verfügbaren Charts für WordPress finden, indem Sie folgendes ausführen:
1 helm search hub wordpress
helm search repo sucht die Repositorien, die Sie Ihrem lokalen Helm-Client hinzugefügt haben (mit helm repo add). Diese Suche wird über lokale Daten durchgeführt, und kein öffentlicher Netzwerkanschluss ist erforderlich.
Helm 3 (seit Kubernetes 1.18.10) liefert keine Standard-Chart-Repository mehr aus. Sie können die helm repo Befehle verwenden, um Repositorien hinzuzufügen, zu listen und zu entfernen. Beispielhaft, lassen wir uns die beliebten Bitnami-Repositorien hinzufügen:
1 helm repo add bitnami https://charts.bitnami.com/bitnami
Sie können sehen, welche Repositorien konfiguriert sind, mit dem helm repo list Befehl:
1 helm repo list
Da Chart-Repositorien häufig ändern, können Sie sicherstellen, dass Ihr Helm-Client auf dem neuesten Stand ist, indem Sie folgendes ausführen:
1 helm repo update
